## 📋 Таблица User Stories

| ID | Название | Статус | Формулировка US |
|----|----------|--------|-----------------|
| **US-01** | Автоматическое назначение роли GUEST при регистрации | [Done] ✅ | Как новый пользователь, я хочу чтобы мне автоматически назначилась роль GUEST при регистрации, чтобы я получил минимальный доступ к системе без дополнительных действий |
| **US-02** | Защита маршрутов дашборда от неавторизованного доступа | [Done] ✅ | Как незарегистрированный пользователь (гость), я хочу чтобы система перенаправила меня на страницу входа при попытке открыть раздел дашборда, чтобы я понимал, что для просмотра защищённого контента нужно авторизоваться |
| **US-03** | Контроль доступа к функциям приложения на основе роли | [To Do] | Как авторизованный пользователь с ролью MEMBER, я хочу чтобы система скрывала/блокировала функции, недоступные для моей роли, чтобы я не пытался выполнить действия, на которые у меня нет прав |
| **US-04** | Динамическое отображение навигационного меню на основе роли | [To Do] | Как авторизованный пользователь, я хочу чтобы навигационное меню отображало только пункты, доступные для моей роли, чтобы я видел только релевантный мне функционал |
| **US-05a** | Просмотр списка пользователей и их ролей (READ) | [To Do] | Как администратор СНТ, я хочу просматривать таблицу всех пользователей с их текущими ролями, чтобы я видел, какие права доступа имеют члены системы |
| **US-05b** | Назначение роли пользователю (CREATE) | [To Do] | Как администратор СНТ, я хочу назначать новую роль существующему пользователю, чтобы предоставить ему дополнительный доступ к функционалу системы |
| **US-05c** | Изменение роли пользователя (UPDATE) | [To Do] | Как администратор СНТ, я хочу изменять текущую роль пользователя на другую, чтобы корректировать права доступа при изменении статуса члена СНТ |
| **US-05d** | Отзыв роли у пользователя (DELETE) | [To Do] | Как администратор СНТ, я хочу отзывать роль у пользователя (удалять его связь с ролью), чтобы полностью лишать его доступа к защищённым ресурсам при необходимости |
| **US-06** | Обновление сессии при изменении роли пользователя | [To Do] | Как пользователь, чью роль изменили, я хочу чтобы моя сессия автоматически обновилась с новыми правами доступа, чтобы я мог сразу использовать расширенные/изменённые возможности без перелогининга |
| **US-07** | Обработка ошибок доступа 401/403 | [To Do] | Как пользователь без достаточных прав, я хочу получать корректный HTTP-ответ 401/403 при попытке доступа к запрещённому функционалу, чтобы система явно сигнализировала о причине отказа в доступе |
| **US-08** | Проверка и откат при потере роли пользователя | [To Do] | Как система, я хочу автоматически отзывать все привилегии у пользователя при потере его роли, чтобы он не мог получить доступ к ресурсам без активной роли |

### Этап блокировки (BLOCKER)

- **BLOCKER** — Остановка при повторяющихся ошибках валидации
  - Срабатывает после 3 неудачных попыток проверки на любом этапе
  - Обязательные действия:
    1. Остановить выполнение текущей US
    2. Создать файл `.roo/specs/us-<id>/blocker.md` с описанием проблемы
    3. Вывести отчёт пользователю
    4. Запросить ручное решение
