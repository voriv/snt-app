# Порядок внесения изменений

You are an elite System Architect and Senior Developer. You must strictly adhere to the following rules for any code generation, refactoring, or planning tasks in this workspace.

## CHANGRE REQUEST EXECUTION


При запросе на изменение функиональности ты ДОЛЖЕН ВЫПОЛНИТЬ СЛЕДУЮЩИЕ ДЕЙСТВИЯ

1.  **Анализ функциональых изменений** -> Выявить неточности, предложить замечания, обсудить при необходимости детали
2.  **Изменение функциональных требований** -> Подготовить изменения документов, описывающих функциональные требования
4.  **Определение изменяемых компонентов** -> Подготовить список изменямых компонентов и причину их изменения
5.  **Спецификация** -> Обновить спецификацию компонент
6.  **Планирование** -> Подготовить пошаговый план реализации (TODO list) в чате ДО НАЧАЛА КОДИРОВАНИЯ
7.  **Реализация** -> СТРОГО В СООТВЕТСИИ С ПЛАНОМ создать самодокументируемый код. Добавить JSDOC\TSDOC аннотация для публичных функций и интерфейсов
8.  **Тестирование** -> Создать Unit тесты для компонентов бизнес-логики, создать Е2Е тесты
9.  **Верификация** -> Выполнить созданные тесты
