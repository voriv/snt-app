# Тестовый промпт для Orchestrator: Уведомления о задолженности по взносам

> **Назначение:** Используйте этот промпт для тестирования полного E2E-пайплайна Orchestrator от business-analyst до tech-writer.
> **Сценарий:** Новый домен `Payment` — нет пересечений с существующим кодом.

---

## Промпт для Orchestrator

Скопируйте текст ниже и отправьте в режиме `orchestrator`:

```markdown
## Задача

Реализовать функционал "Уведомления о задолженности по взносам".

## Бизнес-контекст

В СНТ "Берёзки-НТ" ежегодно собираются членские взносы.
Председатель и бухгалтер тратят до 3 дней в месяц на ручное информирование
должников. Нужно автоматизировать этот процесс.

## Ключевые стейкхолдеры

- **Бухгалтер** — хочет видеть список должников и отправлять уведомления одной кнопкой
- **Садовод (член СНТ)** — хочет получать уведомления о задолженности и видеть историю платежей
- **Председатель** — хочет контролировать процесс взыскания

## Ожидаемый результат

1. Новая сущность `Payment` с информацией о платежах
2. API endpoint для просмотра задолженности текущего пользователя
3. API endpoint для администратора: создание уведомления о задолженности
4. Страница "Мои взносы" в личном кабинете
5. Страница "Управление взносами" в админ-панели
6. Уведомления (email/внутренние) при появлении новой задолженности

## Ограничения

- Все платежи в рублях (RUB)
- Финансовые данные видны только владельцу и администратору
- История платежей не удаляется — только soft delete
```

---

## Почему этот сценарий хорош для теста

| Критерий | Почему подходит |
|---|---|
| Новый домен | Нет пересечений с REQ-PLOT, REQ-AUTH и т.д. |
| Полный охват фаз | Spec → Plan → Code → Tests → Docs |
| Безопасно | Не затрагивает существующий код |
| Достаточно сложен | 3 стейкхолдера, 2 роли (user + admin), новая сущность |
| Граничные случаи | Финансовые данные требуют бизнес-правил |
