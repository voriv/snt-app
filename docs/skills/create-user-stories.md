# Skill: Создание User Stories (Create User Stories)

> **Исполнитель:** `product-owner` mode
> **Вход:** `docs/requirements/REQ-{SVC}-{NNN}.md`
> **Выход:** `docs/user-stories/US-{NN}-{slug}.md`

---

## Алгоритм

### Фаза 1 — Анализ REQ и формирование списка US
1. **Прочитай REQ** — открой файл требования из сообщения Orchestrator
2. **Выдели FR для декомпозиции** — определи функциональные требования, которые будут реализованы
3. **Определи количество US и их границы** — сколько User Stories нужно для покрытия всех FR
4. **Сформируй предварительный список US** — в виде таблицы (в сообщении пользователю):
   | # | US ID | Название | Покрывает FR | Scope |

### Фаза 2 — Обсуждение списка US
5. **Покажи список пользователю** — в формате таблицы
6. **Обсуди каждую US:**
   - Корректно ли выделена граница US (одно атомарное действие?)
   - Не пропущена ли US?
   - Не лишняя ли US?
7. **Принимай правки от пользователя** — обновляй список
8. **После утверждения** — зафиксируй ID для каждой US

### Фаза 3 — Для каждой US: черновик → обсуждение → финал
Для каждой US из утверждённого списка:

9. **Шаг A — Формулировка:**
   - Покажи черновик: «Как [роль], я хочу [действие], чтобы [ценность]»
   - Обсуди с пользователем, утверди

10. **Шаг B — Целевое состояние и Поведение:**
    - Покажи черновик: целевое состояние + B-1, B-2, ...
    - Обсуди с пользователем, утверди

11. **Шаг C — Критерии приёмки (AC):**
    - Покажи черновик: AC-1, AC-2, ... в формате Given/When/Then
    - Обсуди, утверди

12. **Шаг D — Граничные случаи (EC) и модель данных:**
    - Покажи черновик: EC-1, EC-2, ..., модель данных, BR
    - Обсуди, утверди

13. **Определи нумерацию** — найди макс ID среди существующих US в `docs/user-stories/`

14. **Запиши финальный файл** — `docs/user-stories/US-{NN}-{slug}.md` по шаблону [`docs/templates/user-story-template.md`](docs/templates/user-story-template.md)
15. **Сообщи об успехе**

### Фаза 4 — Финал
16. **Покажи сводку всех созданных US**
17. **Запроси approve**

## Правила декомпозиции

- Одна US = одно атомарное действие пользователя
- Одна US может покрывать несколько FR, если они логически связаны
- Если FR слишком крупный — разбей на несколько US с суффиксами (US-05-01, US-05-02)

## Советы для эффективного обсуждения

- **Не спеши создавать файлы** — сначала утверди список, потом по одной US
- **Черновики — в сообщении** — не создавай промежуточные `-draft.md` файлы
- **По блокам** — формулировка → поведение → AC → EC → финал
- **После каждого блока — жди подтверждения** — не переходи к следующему без явного согласия пользователя
