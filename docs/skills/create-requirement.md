# Skill: Создание требования (Create Requirement)

> **Исполнитель:** `business-analyst` mode
> **Вход:** Бизнес-идея от пользователя
> **Выход:** `docs/requirements/REQ-{SVC}-{NNN}.md`

---

## Алгоритм

### Шаг 0 — Обнаружение существующего черновика
0. **Проверить наличие `*-draft.md`** — просканировать `docs/requirements/` на файлы с суффиксом `-draft.md`
   - Если найден draft по теме задачи → открыть, определить текущую фазу по заполненным секциям и предложить продолжить
   - Если draft найден, но пользователь решает начать заново → работать с чистого листа
   - Если draft не найден → продолжить с Шага 1

### Фаза 1 — Уточнение
1. **Получить задачу** — прочитай сообщение от Orchestrator с бизнес-идеей
2. **Исследовать контекст:**
   a. Прочитать `docs/requirements/README.md` — проверить реестр требований и статусы
   b. Просмотреть существующие `REQ-*.md` (без -draft) в `docs/requirements/` на пересечения по содержанию
   c. Если REQ найден по теме и его статус = «Черновик» или «На согласовании» → предложить актуализировать существующий REQ
   d. Если нет пересечений → продолжить создание нового требования
3. **Задать уточняющие вопросы** — заполни пробелы в бизнес-контексте

### Фаза 2 — Черновик (Draft)
4. **Определить сервис** — выбери аббревиатуру: `AUTH`, `ROLES`, `PLOT`, `PROFILE`, `COMMS`, `USERS`, `NAV`
5. **Найти ID** — определи следующий номер для REQ (макс существующий + 1)
6. **Определить стейкхолдеров и бизнес-цели**
7. **Сформулировать BR, FR, NFR, EC, критерии приёмки**
8. **Записать черновик** — `docs/requirements/REQ-{SVC}-{NNN}-draft.md`
   - Если Шаг 0 нашёл существующий draft → работать с ним, не создавать новый

### Фаза 3 — Обсуждение бизнес-правил (поэлементно)
9. Для каждого BR — покажи пользователю, обсуди, дождись подтверждения
10. По результатам — обнови BR в черновике

### Фаза 4 — Обсуждение FR, NFR, EC (пакетно)
11. Покажи все FR блоком — обсуди, всё ли покрыто
12. Покажи все NFR блоком — обсуди ограничения
13. Покажи все EC блоком — обсуди граничные случаи
14. По результатам — обнови черновик

### Фаза 5 — Финал
15. **Чеклист перед финализацией:**
    - [ ] Все 7 секций шаблона заполнены
    - [ ] Есть минимум 1 BR, 1 FR, 1 EC
    - [ ] Критерии приёмки сформулированы как проверяемые утверждения
    - [ ] Нумерация BR/FR/EC последовательна
    - [ ] Нет пустых placeholder'ов `<!-- ... -->`
16. **Записать финальный файл** — `docs/requirements/REQ-{SVC}-{NNN}.md`
17. **Удалить черновик** — удали `-draft.md`
18. **Обновить статус в реестре** — открыть `docs/requirements/README.md` и добавить/обновить строку REQ со статусом «Согласовано»
19. **Запросить approve**

## Шаблон сообщения от Orchestrator

```markdown
## Задача
Создать бизнес-требование для функционала: {описание}

## Бизнес-контекст
{описание бизнес-проблемы}

## Ключевые стейкхолдеры
{кто будет использовать}
```
