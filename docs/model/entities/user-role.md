# UserRole

## Описание

Связующая таблица отношения M:N между пользователями и ролями. Один пользователь может иметь несколько ролей, одна роль может быть назначена нескольким пользователям.

## Поля

| Поле | Тип | Обязательное | Описание | Бизнес-правила |
|------|-----|-------------|----------|----------------|
| `user_id` | String | Да | Ссылка на пользователя | Часть составного первичного ключа; CASCADE при удалении пользователя |
| `role_id` | String | Да | Ссылка на роль | Часть составного первичного ключа; CASCADE при удалении роли |
| `created_at` | DateTime | Да | Дата назначения роли | Генерируется автоматически |

## Связи

| Сущность | Тип связи | Описание |
|----------|-----------|----------|
| User | belongs_to | Запись связывает пользователя с ролью |
| Role | belongs_to | Запись связывает роль с пользователем |

## Индексы

| Поля | Тип | Описание |
|------|-----|----------|
| (`user_id`, `role_id`) | primary key | Составной первичный ключ — одна роль назначается пользователю один раз |
| `role_id` | index | Для быстрого поиска участников роли |

## Бизнес-инварианты

- Комбинация (`user_id`, `role_id`) уникальна — роль назначается пользователю один раз
- При удалении пользователя удаляются все его назначения ролей (CASCADE)
- При удалении роли удаляются все её назначения пользователям (CASCADE)
- Перед удалением роли сервис проверяет, что это не последняя роль `SUPER_ADMIN` хотя бы у одного пользователя

## Конвенции именования

- **БД (PostgreSQL):** `user_roles`, `user_id`, `role_id`, `created_at`
- **Prisma:** `UserRole`, `userId`, `roleId`, `createdAt`
- **TypeScript домен:** `UserRoleData`, `userId: string`, `roleId: string`, `createdAt: Date`
