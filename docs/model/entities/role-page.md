# RolePage

## Описание

Связующая таблица отношения M:N между ролями и страницами. Определяет, к каким страницам имеет доступ роль. Назначение страницы роли автоматически предоставляет доступ всем пользователям с этой ролью.

## Поля

| Поле | Тип | Обязательное | Описание | Бизнес-правила |
|------|-----|-------------|----------|----------------|
| `role_id` | String | Да | Ссылка на роль | Часть составного первичного ключа; CASCADE при удалении роли |
| `page_id` | String | Да | Ссылка на страницу | Часть составного первичного ключа; CASCADE при удалении страницы |
| `created_at` | DateTime | Да | Дата назначения страницы роли | Генерируется автоматически |

## Связи

| Сущность | Тип связи | Описание |
|----------|-----------|----------|
| Role | belongs_to | Запись связывает роль со страницей |
| Page | belongs_to | Запись связывает страницу с ролью |

## Индексы

| Поля | Тип | Описание |
|------|-----|----------|
| (`role_id`, `page_id`) | primary key | Составной первичный ключ — страница назначается роли один раз |
| `page_id` | index | Для быстрого поиска ролей, имеющих доступ к странице |

## Бизнес-инварианты

- Комбинация (`role_id`, `page_id`) уникальна — страница назначается роли один раз
- При удалении роли удаляются все её назначения страниц (CASCADE)
- При удалении страницы удаляются все её назначения ролям (CASCADE)
- `SUPER_ADMIN` имеет доступ ко всем активным страницам через runtime-правило, независимо от записей в этой таблице
- Назначение неактивной страницы (`is_active=false`) роли не предоставляет доступ — проверка `is_active` страницы выполняется при проверке прав

## Конвенции именования

- **Prisma:** `RolePage`, `roleId`, `pageId`, `createdAt`
- **TypeScript домен:** `RolePageData`, `roleId: string`, `pageId: string`, `createdAt: Date`
