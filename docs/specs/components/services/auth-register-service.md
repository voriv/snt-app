# AuthService: register

## Статус: На обсуждении

---

## 1. Описание

### 1.1 Назначение

Метод `register` создаёт нового пользователя в системе с ролью `GUEST` и мгновенной активацией (без email-верификации на данном этапе).

### 1.2 Границы ответственности

| Входит | НЕ входит |
|--------|-----------|
| Валидация входных данных | Email-верификация (отложена) |
| Проверка уникальности email | Создание Member записи |
| Хэширование пароля | Отправка email-уведомлений |
| Создание User записи | Роутинг/редирект |

### 1.3 Связанные домены и сущности

| Домен | Сущность | Роль |
|-------|----------|------|
| Core | `User` | Создаваемая сущность |

## 2. Бизнес-правила

### 2.1 Правила валидации

| ID | Правило | Описание | Ошибка |
|----|---------|----------|--------|
| VR-001 | Email обязателен | Поле email не может быть пустым | `ValidationError` |
| VR-002 | Email валидный | Email должен соответствовать формату | `ValidationError` |
| VR-003 | Пароль обязателен | Поле password не может быть пустым | `ValidationError` |
| VR-004 | Длина пароля >= 6 | Минимальная длина пароля — 6 символов | `ValidationError` |

### 2.2 Правила бизнес-логики

| ID | Правило | Описание | Исключение |
|----|---------|----------|------------|
| BL-001 | Уникальность email | email не должен существовать в системе | `ConflictError` |
| BL-002 | Роль GUEST | Новый пользователь всегда получает роль GUEST | — |
| BL-003 | Активация | Новый пользователь активируется автоматически (isActive = true) | — |

## 3. API сервиса

### 3.1 register

Создаёт нового пользователя с ролью GUEST.

| Параметр | Тип | Обязательное | Описание |
|----------|-----|--------------|----------|
| email | string | да | Email пользователя |
| password | string | да | Пароль (мин. 6 символов) |

| Возвращает | Тип | Описание |
|------------|-----|----------|
| `Promise<RegisterResult>` | `RegisterResult` | Созданный пользователь с ролью GUEST |

| Выбрасывает | Когда | Код ошибки |
|-------------|-------|------------|
| `ValidationError` | Неверный email или пароль | `VALIDATION_ERROR` |
| `ConflictError` | Email уже существует | `CONFLICT` |

#### Пример вызова

| Шаг | Действие | Результат |
|-----|----------|-----------|
| 1 | `await authService.register({ email: 'user@example.com', password: 'secret123' })` | Валидация входных данных |
| 2 | `await this.userRepository.findByEmail(parsed.email)` | Проверка уникальности email |
| 3 | Если email существует | `ConflictError('user-email', 'Пользователь с таким email уже существует')` |
| 4 | `bcrypt.hash(password, 12)` | Хэширование пароля |
| 5 | `this.userRepository.create({ email, passwordHash, role: 'GUEST', isActive: true })` | Создание пользователя |

## 4. Входные данные

### 4.1 Типы входных данных

#### RegisterInput

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| email | string | да | Email пользователя |
| password | string | да | Пароль (мин. 6 символов) |

#### RegisterResult

| Поле | Тип | Описание |
|------|-----|----------|
| user | `User` | Созданный пользователь |

### 4.2 Zod схемы валидации

#### registerSchema

| Поле | Схема | Ограничение | Сообщение об ошибке |
|------|-------|-------------|---------------------|
| email | `z.string().email()` | Валидный email формат | "Неверный формат email" |
| password | `z.string().min(6)` | Мин. 6 символов | "Пароль должен содержать минимум 6 символов" |
