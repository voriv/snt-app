# Требования к спецификациям компонентов

## 1. Общие требования

### 1.1 Расположение
- Спецификации компонентов хранятся в `docs/specs/components/`
- Каждая спецификация — отдельный Markdown файл
- Именование файлов: `<тип>-<название>.md`

### 1.2 Структура директории
```
docs/specs/components/
├── README.md                    # Навигация и описание
├── ui/
│   ├── client/
│   │   ├── ui-button.md
│   │   └── ui-table.md
│   └── server/
│       ├── ui-user-profile.md
│       └── ui-page-content.md
├── api/
│   ├── api-create-user.md
│   └── api-get-charges.md
├── services/
│   ├── service-user.md
│   └── service-payment.md
└── repositories/
    ├── repository-user.md
    └── repository-charge.md
```

### 1.3 Метаданные спецификации (в начале каждого файла)

```markdown
---
тип: ui/client | ui/server | api | service | repository
название: ComponentName
статус: черновик | на обсуждении | согласовано | в реализации | завершено
автор: <имя>
дата-создания: YYYY-MM-DD
дата-обновления: YYYY-MM-DD
версия: X.Y.Z
---
```

### 1.4 Статусы спецификаций

| Статус | Описание |
|--------|----------|
| **Черновик** | Инициальное описание |
| **На обсуждении** | Требует согласования |
| **Согласовано** | Утверждена, готова к разработке |
| **В реализации** | Разрабатывается |
| **Завершено** | Реализована и проверена |

## 4. Спецификация API Router

### 4.1 Структура

```markdown
# API Endpoint: <Метод> <Path>

## Метаданные
(см. раздел 1.3)

## 1. Описание
Краткое описание назначения endpoint.

## 2. Endpoint

### URL
`<METHOD> /api/<version>/<resource>`

### Аутентификация
| Требование | Описание |
|------------|----------|
| Auth | 🔒 Требуется токен |
| Role | 👑 Роль: ADMIN / MEMBER / GUEST |

### Headers

| Заголовок | Тип | Обязательный | Описание |
|-----------|-----|--------------|----------|
| `Authorization` | `string` | Да | Bearer token |

### Query Parameters

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|----------|-----|--------------|--------------|----------|
| `limit` | `number` | Нет | 20 | Лимит записей |

### Request Body

| Поле | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `email` | `string` | Да | Email пользователя |

### Response

#### Успешный ответ (200/201)
```json
{
  "id": "string",
  "email": "string"
}
```

#### Ошибки

| Код | Тело | Описание |
|-----|------|----------|
| 400 | `{ "error": "string" }` | Неверный запрос |
| 401 | `{ "error": "Unauthorized" }` | Нет авторизации |
| 403 | `{ "error": "Forbidden" }` | Нет доступа |
| 404 | `{ "error": "Not found" }` | Ресурс не найден |
| 500 | `{ "error": "Internal error" }` | Серверная ошибка |

## 3. Бизнес-правила
- Правила обработки запроса
- Валидация данных

## 4. Зависимости

### Внутренние
| Компонент | Тип | Описание |
|-----------|-----|----------|
| `UserService.create()` | Service | Создание пользователя |

### Внешние
| Сервис | Описание |
|--------|----------|
| `email.send()` | Отправка email подтверждения |

## 5. Лимиты (Rate Limiting)
- Максимум запросов в минуту
- Threading policy

## 6. Примеры

```bash
curl -X POST /api/users -H "Authorization: Bearer ..." -d '{"email":"test@example.com"}'
# → 201 {"id":"abc123","email":"test@example.com"}
```

## 6. Спецификация Repository

### 6.1 Структура

```markdown
# Repository: <Название репозитория>

## Метаданные
(см. раздел 1.3)

## 1. Описание
Назначение репозитория и данные, которыми управляет.

## 2. Публичный API

### Методы

| Метод | Сигнатура | Возвращает |
|-------|-----------|------------|
| findMany | `findMany(filters, options): Promise<T[]>` | Массив записей |
| findById | `findById(id: string): Promise<T \| null>` | Запись или null |
| create | `create(data: CreateDto): Promise<T>` | Созданная запись |
| update | `update(id: string, data: UpdateDto): Promise<T>` | Обновлённая запись |
| delete | `delete(id: string): Promise<boolean>` | Успех операции |

**Параметры запроса findMany:** limit (50), offset (0), orderBy ('createdAt'), orderDir ('desc')

### Транзакции
- Поддержка транзакций через Prisma `$transaction`

### Индексы
| Поле | Тип | Описание |
|------|-----|----------|
| `email` | Unique | Быстрый поиск по email |

## 3. Зависимости

| Компонент | Тип | Для чего |
|-----------|-----|----------|
| `prisma` | ORM | Доступ к БД |
| `@prisma/client` | Внешний | ORM клиент |

## 4. Пример

```typescript
const users = await repo.findMany({ isActive: true }, { limit: 10, orderBy: 'name' });
```

## 7. Общие требования к оформлению

### 7.1 Язык
- Основной язык — Русский (описания, комментарии)
- Техническая терминология — на Английском (имена функций, типы)

### 7.2 Форматирование
- Markdown с использованием стандартных элементов
- Code blocks с указанием языка
- Таблицы для структурирования данных
- Mermaid диаграммы для сложных потоков

### 7.3 Ссылки
- На другие спецификации: `[<Название спецификации>](./<путь>.md)`
- На код: [`functionName()`](../../../src/path/to/file.ts:line)
- На FR требования: `[FR-01-001](../../../docs/requirements/01-user-management.md#fr-01-001)`

### 7.4 Версионирование
- Версия спецификации: `MAJOR.MINOR.PATCH`
