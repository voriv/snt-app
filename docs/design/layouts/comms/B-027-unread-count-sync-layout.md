## 0. Краткое резюме (что меняется визуально)

| Корневая причина | UI-изменение | AC | Задача |
|------------------|--------------|-----|--------|
| #1 (Navbar не обновляется после markAsRead) | Navbar и CommsTabs используют **единый хук `useUnreadCounts`** — глобальный бейдж обновляется при каждой навигации и после markAsRead | AC-9 | T4-1 |

| #3 (удалённые в счётчиках) | Подсчёт непрочитанных фильтрует `isDeleted: false` → удалённые сообщения **не влияют** на бейджи/счётчики | AC-11 | T1-1 |

> **Важно (границы макета):** задача B-027 — преимущественно **серверная логика + рефакторинг хук-механизма**. Здесь не создаётся новый экран или новый визуальный паттерн. Макет определяет:
> 1. **S-спецификации глобального бейджа** в Navbar (показать/скрыть, «99+», обнуление, синхронизация).
> 2. **Единый источник данных** (хук `useUnreadCounts`) — как его переиспользуют Navbar и CommsTabs, чтобы не было рассинхрона.
> 3. **Визуальные последствия** серверных фиксов для новичка (#2) и удалённых сообщений (#3).

### Механизм синхронизации (поток данных)

```
Navbar  ──► useUnreadCounts(pathname) ──► GET /comms/unread-counts ──► {messages, chats}
            │  ▲ pathname — триггер: при каждой навигации хук перезагружает счётчик
            │  │
            └──┘ (data → setCounts → badge)
```

> **Сценарий #1 (AC-9):** пользователь открыл диалог (markAsRead) → `lastReadAt` обновлён → пользователь переходит на дашборд → `pathname` меняется → `useUnreadCounts` перезагружает счётчик → глобальный бейдж показывает обновлённое значение **без перемонтирования Navbar**.
> Ранее (`useEffect([], ...)`) счётчик загружался только при mount навбара — бейдж оставался устаревшим (причина #1).

## 2. Единый хук `useUnreadCounts` — источник данных (T4-1)

> Новый хук [`src/hooks/useUnreadCounts.ts`](../../../src/hooks/useUnreadCounts.ts) — **единственный механизм загрузки счётчиков** для Navbar и CommsTabs. Устраняет дублирование inline-логики (сейчас в [`Navbar.tsx:56`](../../../src/components/layouts/Navbar.tsx:56) и [`CommsTabs.tsx:101`](../../../src/components/features/comms/CommsTabs/CommsTabs.tsx:101)).

### Контракт хука

| Вход | Тип | Описание |
|------|-----|----------|
| `refetchTrigger?` | `number` | Триггер повторной загрузки (для Navbar — `pathname`; для CommsTabs — существующий `refetchTrigger`) |

| Выход | Тип | Описание |
|-------|-----|----------|
| `counts` | `UnreadCounts \| null` | `{ messages, chats }` из `GET /comms/unread-counts` |
| `loading` | `boolean` | true во время загрузки |
| `error` | `string \| null` | сообщение об ошибке (`'Не удалось загрузить счётчики'` / `'Ошибка сети'`) |

### Поведение

- Вызов `GET /api/v1/comms/unread-counts` при изменении `refetchTrigger`.
- **Abort-механизм:** при демонтаже / смене триггера отменяет устаревший запрос (защита от гонок).
- **Silent fail:** при ошибке сети/API — `error` заполняется, но **не выбрасывает исключение**; бейджи скрываются, навигация не блокируется (AC-12, BR-10).

### Точки использования (AC-9, AC-1.7/1.8)

| Потребитель | Вызов | Зачем |
|-------------|-------|-------|
| `[Navbar]` | `useUnreadCounts(pathname)` | Суммарный глобальный бейдж; перезагрузка при навигации (AC-9) |
| `[CommsTabs]` | `useUnreadCounts(refetchTrigger)` | Бейджи на вкладках; перезагрузка после markAsRead (AC-5/AC-7) |

> **Итог (BR-12):** оба компонента читают **один и тот же API** через один хук → глобальный бейдж и вкладочные бейджи больше **не могут разойтись** (причина #1 устранена на уровне источника данных).

### Рефакторинг компонентов (для Component Spec)

| Файл | Текущее | Целевое |
|------|---------|---------|
| `Navbar.tsx` | inline `useEffect(loadUnread, [])` ([строка 56](../../../src/components/layouts/Navbar.tsx:56)) | `const { counts } = useUnreadCounts(pathname)`; `badge = (counts.messages ?? 0) + (counts.chats ?? 0)` |
| `CommsTabs.tsx` | inline `useEffect(loadCounts, [activeTab, refetchTrigger])` ([строка 101](../../../src/components/features/comms/CommsTabs/CommsTabs.tsx:101)) | `const { counts } = useUnreadCounts(refetchTrigger)`; состояние loading/error — из хука |

## 3. Новый участник чата — счётчик с нуля (AC-10)

> **Серверный фикс (T1-2):** при `addChatParticipant` и `createGroupChat` для участника инициализируется `lastReadAt = now()`. Визуальный результат для UI — **отсутствие бейджа** за историю, отправленную до вступления.

```ascii
Сценарий: пользователь C добавлен в чат «Общее собрание» (уже 10 сообщений от A и B)
                                          
  ┌────────────────────────────────────────────────────────────┐
  │  [Личные         ]  [Групповые      ]  [Объявления]        │
  │  [сообщения      ]  [чаты       ◌   ]                       │
  │                                         ^                   │
  │         чат "Общее собрание"           ЗДЕСЬ НЕТ БЕЙДЖА     │
  │         ┌─────────────────────────┐    (счётчик = 0)        │
  │         │ [Ик] Общее собрание     │                         │
  │         │    15 уч.               │  ← без "+10"             │
  │         └─────────────────────────┘                         │
  │                                                             │
  └────────────────────────────────────────────────────────────┘

После A отправляет новое сообщение C:
  ┌────────────────────────────────────────────────────────────┐
  │  [Групповые      ]  →  бейдж "+1" ← только НОВОЕ сообщение  │
  └────────────────────────────────────────────────────────────┘
```

### Компоненты и токены

| Элемент | Компонент | Токен | AC |
|---------|-----------|-------|----|
| Карточка чата (без бейджа) | `[ChatCard]` | `color.bg.primary` + `radius-md` + `shadow-sm` | AC-10 |
| (после нового сообщения) бейдж | `<Badge variant="danger">` | `color.danger` + `radius-full` | AC-10 |

### Состояния

| Состояние | Поведение |
|-----------|-----------|
| Loading | Счётчик новичка загружается → бейдж скрыт (BR-10) |
| Data (только история до вступления) | Бейдж **не отображается** — счётчик = 0 (AC-10) |
| Data (после нового входящего сообщения) | Бейдж показывает количество **новых** с момента вступления (AC-10) |
| Error | Бейдж скрыт, навигация не блокируется (BR-10) |

> **Проверка соответствия плану:** T1-2 устанавливает `lastReadAt = now()` при вступлении. Счётчик новичка начинает с 0 (BR-13). Это **влияет на отображение**: отсутствие бейджа за старую историю. E2E-тест #5 (T6-1) проверяет: до нового сообщения `chats = 0`, после отправки `chats = 1`.

## 4. Удалённые сообщения — не влияют на счётчики (AC-11)

> **Серверный фикс (T1-1):** все `prisma.message.count()` для непрочитанных добавляют `isDeleted: false`. Визуальный результат: удалённое сообщение **не увеличивает** ни один бейдж (на вкладке, на карточке, в глобальном бейдже).

```ascii
Сценарий: A отправил B 3 сообщения (B не прочитал) → у B "3".
          A удаляет 1 из них (isDeleted = true).

  ДО удаления:                                     ПОСЛЕ удаления:
  ┌───────────────────────────┐                  ┌───────────────────────────┐
  │ [Личные сообщения  +3 ]   │                  │ [Личные сообщения  +2 ]   │
  │ ┌──────────────────────┐  │                  │ ┌──────────────────────┐  │
  │ │ [Ава] Иван И.   +3  │  │                  │ │ [Ава] Иван И.   +2  │  │
  │ └──────────────────────┘  │                  │ └──────────────────────┘  │
  │ Глобальный бейдж: 3        │                  │ Глобальный бейдж: 2        │
  └───────────────────────────┘                  └───────────────────────────┘
       Удалённое сообщение                    Удалённое НЕ учитывается
       ещё учитывается (#3) → 🔴               → ✅ AC-11
```

### Компоненты и токены

| Элемент | Компонент | Токен | AC |
|---------|-----------|-------|----|
| Бейдж на вкладке | `<Badge variant="danger">` | `color.danger` + `radius-full` | AC-11, AC-1/AC-2 |
| Бейдж на карточке диалога/чата | `[ConversationCard]`/`[ChatCard]` + `<Badge>` | `color.danger` + `radius-full` | AC-11 |
| Глобальный бейдж | `<Badge variant="danger">` (Navbar) | `color.danger` + `radius-full` | AC-11 |

### Состояния

| Состояние | Поведение |
|-----------|-----------|
| Loading | Счётчики загружаются → бейджи скрыты (BR-10) |
| Data (есть удалённые, но нет новых) | Удалённые **не учитываются** → счётчик отражает только активные непрочитанные (AC-11) |
| Data (удалённые + новые непрочитанные) | Учитываются только **неудалённые** → счётчик меньше, чем без фикса (AC-11) |
| Error | Бейджи скрыты, навигация не блокируется (BR-10) |

> **Проверка соответствия плану:** T1-1 фильтрует `isDeleted: false` во всех 4 count (диалоги, чаты, DIRECT-глоб, GROUP-глоб). Это синхронизирует подсчёт с фактическим списком сообщений (`getMessagesWithReadStatus` уже фильтрует). E2E-тест #6 (T6-1) проверяет неизменность счётчика после удаления.

## 5. Темы оформления (Light / Dark / Green) — глобальный бейдж

> Бейджи (глобальный и вкладочные) должны использовать **CSS-переменные** `var(--theme-*)`. B-027 рефакторит хардкод-классы [`Navbar.tsx:136`](../../../src/components/layouts/Navbar.tsx:136) на токены.

| Токен | CSS-переменная | Light | Dark | Green | Назначение |
|-------|----------------|-------|------|-------|------------|
| `color.danger` (фон бейджа `/10`) | `var(--theme-danger)` | `#ef4444` | `#f87171` | `#fca5a5` | фон бейджа (с opacity 0.1) |
| `color.danger` (текст) | `var(--theme-danger)` | `#ef4444` | `#f87171` | `#fca5a5` | цифра в бейдже |
| `color.nav.bg` | `var(--theme-nav-bg)` | `#ffffff` | `#1f2937` | `#065f46` | фон навбара |
| `radius-full` | — | 9999px | 9999px | 9999px | скругление бейджа |

> **Проверка переключателем (US-19-05):** при смене темы глобальный бейдж и бейджи вкладок перекрашиваются только через CSS-переменные — без изменения разметки.

- **Границы:** B-027 не создаёт нового экрана/паттерна. Component Spec должен сфокусироваться на **T4-1**: новый хук `useUnreadCounts` и рефакторинг `Navbar` + `CommsTabs` для использования единого источника данных.
- **Токенизация бейджа:** текущий хардкод `bg-red-500 text-white` в [`Navbar.tsx:136`](../../../src/components/layouts/Navbar.tsx:136) заменить на `var(--theme-danger)` (+ radius-full) — как уже указано для `<Badge>` в [`badge.md`](../../components/badge.md).
- **Экспорт хука:** `useUnreadCounts` — default export с JSDoc (`@hook`, `@domain`, `@spec`).
- **Прежнее поведение сохраняется:** silent fail при ошибке сети, abort при демонтаже, скрытие бейджей при loading/error.
