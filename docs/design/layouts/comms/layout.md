## 8. API: GET /api/v1/comms/unread-counts

> Единый эндпоинт для получения счётчиков непрочитанных для вкладок и навбара.

### Response

```json
{
  "success": true,
  "data": {
    "messages": 3,
    "chats": 2
  }
}
```

### Состояния

| Состояние | Поведение |
|-----------|-----------|
| Loading | `useEffect` выполняет fetch. Бейджи скрыты до получения ответа. |
| Error | Бейджи не отображаются. Навигация не блокируется. |
| Success | Счётчики отображаются на соответствующих вкладках. |
| count > 99 | Показывается "99+" |

## 10. Примечания

### Для разработчика Component Spec

- **Feature-компоненты (абстрактные блоки)** — помечены как `[Name]` (например, `[CommsTabs]`, `[ConversationList]`). Component Spec должен раскрыть их в конкретные UI-компоненты.
- **`[CommsTabs]`** — клиентский компонент с `'use client'`, получает `activeTab` и `userRoles` через props.
- **`[CommsTab]`** — отдельная вкладка с Link к маршруту, иконкой и опциональным бейджем.

### Счётчики непрочитанных

- Загружаются через `GET /api/v1/comms/unread-counts` при монтировании `[CommsTabs]`.
- Обновляются при переключении вкладки (`activeTab change`).
- Ошибка загрузки не блокирует навигацию — бейджи скрыты.
- Бейдж показывает "99+" при count > 99.

### Условное отображение вкладки «Модерация»

- Вкладка рендерится только если `userRoles` включает `ADMIN` или `SUPER_ADMIN`.
- При прямом переходе MEMBER на `/dashboard/comms/moderation` — редирект на `/dashboard/comms/messages`.

### Адаптивность

| Breakpoint | Поведение |
|------------|-----------|
| Desktop (≥1024px) | Двухколоночный layout для messages/chats, полная панель вкладок |
| Tablet (≥768px) | Панель вкладок скроллируемая, одноколоночный layout |
| Mobile (<768px) | Вкладки в виде горизонтального скролла, контент на всю ширину |

### Доступность

- Панель вкладок: `role="tablist"`, каждая вкладка `role="tab"` + `aria-selected`
- Бейджи: `aria-label` с количеством непрочитанных
- Контент вкладки: `role="tabpanel"` + `aria-labelledby`
