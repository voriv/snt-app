# API системы общения (Comms)

## Обзор

API системы общения предоставляет конечные точки для управления личными сообщениями, групповыми чатами, объявлениями и модерацией. Все маршруты требуют авторизации и находятся под префиксом `/api/v1/`.

### Базовый URL

```
/api/v1
```

### Аутентификация

Все endpoints требуют авторизации через NextAuth. Токен передаётся через cookie.

### Формат ответов

Все ответы используют стандартизированную оболочку:

**Успешный ответ:**
```json
{
  "success": true,
  "data": { /* данные */ }
}
```

**Ошибка:**
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Описание ошибки"
  }
}
```

### Пагинация

Списки поддерживают пагинацию через query-параметры:

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|-------------|----------|
| `page` | number | 1 | Номер страницы |
| `limit` | number | 20 | Количество записей (макс. 100) |

## 1. Счётчики непрочитанных сообщений

### GET /api/v1/comms/unread-counts

Возвращает количество непрочитанных сообщений по категориям.

> **B-027:** Endpoint доработан для корректного учёта непрочитанных:
> - **Удалённые сообщения исключаются** (`isDeleted: false`) из всех count-запросов — как для глобальных счётчиков, так и для списков диалогов/чатов (AC-11 US-21-37, AC-1.7 US-21-01, AC-1.6 US-21-04).
> - **Новые участники** не получают счётчик = всей истории: `lastReadAt` инициализируется `now()` при вступлении в групповой чат и при создании чата/диалога (AC-10 US-21-37).

**Авторизация:** Требуется

**Пример запроса:**
```http
GET /api/v1/comms/unread-counts HTTP/1.1
```

**Пример ответа 200:**
```json
{
  "success": true,
  "data": {
    "messages": 5,
    "chats": 12
  }
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `messages` | number | Сумма непрочитанных в личных диалогах (DIRECT) |
| `chats` | number | Сумма непрочитанных в групповых чатах (GROUP) |

**Коды ошибок:**

| Код | Описание |
|-----|----------|
| 401 | Необ��одима авторизация |
| 500 | Не удалось загрузить счётчики |

## 2. Личные диалоги (Conversations)

### GET /api/v1/conversations

Возвращает список личных диалогов текущего пользователя с пагинацией и поиском.

**Авторизация:** Требуется

**Query параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `search` | string | Поисковый запрос по имени собеседника |
| `limit` | number | Количество записей (default: 20, max: 100) |
| `page` | number | Номер страницы (default: 1) |

**Пример запроса:**
```http
GET /api/v1/conversations?search=Иван&page=1&limit=20 HTTP/1.1
```

**Пример ответа 200:**
```json
{
  "success": true,
  "data": {

      {
        "id": "uuid",
        "type": "DIRECT",
        "participant": {
          "id": "uuid",
          "name": "Иван Петров",
          "email": "ivan@example.com"
        },
        "lastMessage": {
          "content": "Привет!",
          "createdAt": "2026-07-24T10:00:00Z"
        },
        "unreadCount": 3
      }
    ],
    "total": 15
  }
}
```

**Коды ошибок:**

| Код | Описание |
|-----|----------|
| 400 | Неверные параметры запроса |

### POST /api/v1/conversations

Начать новый личный диалог с пользователем.

**Авторизация:** Требуется

**Тело запроса:**

| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| `participantId` | string (UUID) | Да | ID собеседника |

**Пример запроса:**
```http
POST /api/v1/conversations HTTP/1.1
Content-Type: application/json

{
  "participantId": "uuid-sobеседника"
}
```

> **B-029:** Создание дублирующегося личного диалога запрещено. Ответ **201** возвращается только при создании **нового** диалога (`isNew: true`). Если диалог между этой парой пользователей уже существует, возвращается **409** `CONVERSATION_ALREADY_EXISTS` (даже при race condition — см. [comms-development.md](../guides/comms-development.md)).

**Пример ответа 201 (новый диалог создан):**
```json
{
  "success": true,
  "data": {
    "conversationId": "uuid-диалога",
    "isNew": true
  }
}
```

**Пример ответа 409 (диалог уже существует):**
```json
{
  "success": false,
  "error": {
    "code": "CONVERSATION_ALREADY_EXISTS",
    "message": "Диалог с этим пользователем уже существует"
  },
  "data": {
    "conversationId": "uuid-существующего-диалога",
    "isNew": false
  }
}
```

**Коды ошибок:**

| Код | Описание |
|-----|----------|
| 400 | Нельзя написать самому себе / Собеседник заблокирован |
| 401 | Необходима авторизация |
| 403 | Недостаточно прав |
| 409 | Диалог уже существует (`CONVERSATION_ALREADY_EXISTS`) |

### GET /api/v1/conversations/[id]/messages

Возвращает сообщения диалога со статусом прочтения каждого сообщения.

> **B-026:** Endpoint доработан — ответ теперь содержит поля статуса прочтения (`isReadByRecipient`, `readByCount`, `totalParticipants`). Для DIRECT-диалогов возвращается `isReadByRecipient`; для GROUP-чатов — `readByCount` и `totalParticipants`.

**Авторизация:** Требуется

**URL параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string (UUID) | ID диалога |

**Пример ответа 200 (DIRECT):**
```json
{
  "success": true,
  "data": [
    {
      "id": "uuid",
      "conversationId": "uuid",
      "senderId": "uuid",
      "senderName": "Иван Петров",
      "content": "Привет!",
      "replyToId": null,
      "isDeleted": false,
      "deletedBy": null,
      "deletedAt": null,
      "createdAt": "2026-07-24T10:00:00Z",
      "updatedAt": "2026-07-24T10:00:00Z",
      "isReadByRecipient": false
    }
  ]
}
```

**Пример ответа 200 (GROUP):**
```json
{
  "success": true,
  "data": [
    {
      "id": "uuid",
      "conversationId": "uuid",
      "senderId": "uuid",
      "senderName": "Иван Петров",
      "content": "Собрание в субботу",
      "replyToId": null,
      "isDeleted": false,
      "deletedBy": null,
      "deletedAt": null,
      "createdAt": "2026-08-01T11:00:00Z",
      "updatedAt": "2026-08-01T11:00:00Z",
      "isReadByRecipient": true,
      "readByCount": 3,
      "totalParticipants": 5
    }
  ]
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string (UUID) | ID сообщения |
| `conversationId` | string (UUID) | ID диалога |
| `senderId` | string (UUID) | ID отправителя |
| `senderName` | string \| null | Имя отправителя |
| `content` | string | Текст сообщения |
| `replyToId` | string (UUID) \| null | ID родительского сообщения (цитата) |
| `isDeleted` | boolean | Удалено ли сообщение |
| `deletedBy` | string (UUID) \| null | Кем удалено |
| `deletedAt` | string (ISO date) \| null | Когда удалено |
| `createdAt` | string (ISO date) | Дата создания |
| `updatedAt` | string (ISO date) | Дата обновления |
| `isReadByRecipient` | boolean | Прочитано ли собеседником (для DIRECT). Вычисляется как `participant.lastReadAt >= message.createdAt` |
| `readByCount` | number \| undefined | Количество прочитавших (только GROUP). Считаются участники с `lastReadAt >= message.createdAt`, исключая автора (BR-07) |
| `totalParticipants` | number \| undefined | Общее число получателей кроме автора (только GROUP) |

**Коды ошибок:**

| Код | Описание |
|-----|----------|
| 400 | Некорректный ID диалога (не UUID) |
| 401 | Необходима авторизация |
| 403 | Доступ запрещён |
| 404 | Диалог не найден / пользователь не является участником |
| 500 | Внутренняя ошибка сервера |

### PATCH /api/v1/conversations/[id]/read

> **B-026** (REQ-COMMS-003)

Отмечает все сообщения в личном диалоге (DIRECT) как прочитанные для текущего пользователя. Обновляет `ConversationParticipant.lastReadAt` текущего пользователя на текущее время. Идемпотентен — повторный вызов не возвращает ошибку (AC-4 US-39-01).

**Авторизация:** Требуется

**URL параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string (UUID) | ID диалога |

**Тело запроса:** Не требуется (пустое).

**Пример запроса:**
```http
PATCH /api/v1/conversations/uuid-диалога/read HTTP/1.1
```

**Пример ответа 200:**
```json
{
  "success": true
}
```

**Коды ошибок:**

| Код | Описание |
|-----|----------|
| 400 | Некорректный ID диалога (не UUID) |
| 401 | Необходима авторизация |
| 404 | Пользователь не является участником диалога (`PARTICIPANT_NOT_FOUND`) |
| 500 | Внутренняя ошибка сервера |

> **Поведение:**
> - Сообщения, отправленные самим пользователем, не влияют на счётчик непрочитанных (BR-02).
> - После успешного вызова клиент выполняет refetch `GET /api/v1/comms/unread-counts` для обновления бейджей (см. [`useMarkAsRead`](../../src/hooks/useMarkAsRead.ts)).
> - Ошибка сети не блокирует UI — сообщение обрабатывается как silent fail (BR-09, AC-6 US-39-01).

### PATCH /api/v1/chats/[id]/read

> **B-026** (REQ-COMMS-003)

Отмечает все сообщения в групповом чате (GROUP) как прочитанные для текущего пользователя. Групповые чаты хранятся как `conversation` с `type=GROUP`, поэтому используется тот же метод `markConversationAsRead`. Обновляет `ConversationParticipant.lastReadAt` текущего пользователя. Идемпотентен (AC-4 US-39-01).

**Авторизация:** Требуется

**URL параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string (UUID) | ID чата (conversation с type=GROUP) |

**Тело запроса:** Не требуется (пустое).

**Пример запроса:**
```http
PATCH /api/v1/chats/uuid-чата/read HTTP/1.1
```

**Пример ответа 200:**
```json
{
  "success": true
}
```

**Коды ошибок:**

| Код | Описание |
|-----|----------|
| 400 | Некорректный ID чата (не UUID) |
| 401 | Необходима авторизация |
| 404 | Пользователь не является участником чата (`PARTICIPANT_NOT_FOUND`) |
| 500 | Внутренняя ошибка сервера |

> **Поведение:**
> - Сообщения от других участников, появившиеся до момента открытия, помечаются прочитанными (BR-01).
> - Собственные сообщения не учитываются в счётчике (BR-02).
> - После успеха клиент refetch-ит `GET /api/v1/comms/unread-counts` для обновления бейджа вкладки «Групповые чаты» (AC-5 US-21-37).
> - Ошибка сети — silent fail, UI не блокируется (BR-09, AC-6 US-39-01).

| `category` | string | Нет | Категория: `important`, `planned`, `technical`, `info` |
| `enableDiscussion` | boolean | Нет | Включить обсуждение (создаёт чат) |

---

### PATCH /api/v1/announcements/[id]

Редактирует объявление (только ADMIN/SUPER_ADMIN).

### DELETE /api/v1/announcements/[id]

Удаляет объявление (только ADMIN/SUPER_ADMIN).
