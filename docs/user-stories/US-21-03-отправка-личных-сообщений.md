# US-21-03: Отправка личных сообщений

> Эпик: Система общения в СНТ (REQ-COMMS-001)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** отправлять текстовые сообщения с эмодзи, файлами и форматированием в личном диалоге,
**чтобы** обмениваться информацией с собеседником в удобном формате.

---

## Целевое состояние

Пользователь на странице `/dashboard/comms/messages/:conversationId` видит историю сообщений и форму отправки с поддержкой текста, эмодзи, базового форматирования (жирный, курсив, код) и прикрепления файлов. Каждое сообщение отображает статус: отправлено / доставлено / прочитано. Пользователь может удалять свои сообщения.

---

## Контекст

### Проблема

Пользователи не могут обмениваться сообщениями в личных диалогах. Отсутствует механизм отправки, отображения истории и управления сообщениями.

### Решение

Создать страницу диалога `/dashboard/comms/messages/:conversationId` с областью сообщений и формой отправки. Сообщения поддерживают текст, эмодзи, файлы и базовое форматирование. Статусы сообщений обновляются в реальном времени.

### Границы

- **Входит в US:** Отправка текстовых сообщений, эмодзи, файлы, форматирование, статусы (sent/delivered/read), удаление своих сообщений, история сообщений.
- **Явно исключено:** Цитирование (US-21-10), упоминания @username (US-21-09 для групповых чатов), голосовые сообщения.

## Функциональные требования

### FR-REQ-COMMS-001-02: Отправка текстовых сообщений

Система должна позволять отправлять текстовые сообщения в личном диалоге.

#### AC-1.1: Отправка текстового сообщения

- **Дано:** Пользователь в диалоге `/dashboard/comms/messages/:conversationId`
- **Когда:** Пользователь вводит текст и нажимает «Отправить» (или Enter)
- **Тогда:** Сообщение сохраняется через `POST /api/v1/conversations/:id/messages` и отображается в истории

#### AC-1.2: Базовое форматирование

- **Дано:** Пользователь вводит текст с форматированием
- **Когда:** Сообщение отправляется
- **Тогда:** Поддерживается: **жирный** (`**текст**`), *курсив* (`*текст*`), `код` (`` `код` ``)

#### AC-1.3: Эмодзи

- **Дано:** Пользователь вводит эмодзи в текст
- **Когда:** Сообщение отправляется
- **Тогда:** Эмодзи корректно отображаются в сообщении

#### AC-1.4: Прикрепление файлов

- **Дано:** Пользователь на странице диалога
- **Когда:** Пользователь прикрепляет файл (кнопка или drag-and-drop) и отправляет
- **Тогда:** Файл загружается через `POSTFormData /api/v1/conversations/:id/messages` и отображается как вложение

#### AC-1.5: Ограничения файлов

- **Дано:** Пользователь пытается прикрепить файл
- **Когда:** Размер файла > 10MB или тип не поддерживается
- **Тогда:** Отображается ошибка с указанием допустимых размеров и типов

### FR-REQ-COMMS-001-03: История сообщений

Система должна отображать историю личных сообщений в хронологическом порядке.

#### AC-1.6: Загрузка истории

- **Дано:** Пользователь открывает диалог `/dashboard/comms/messages/:conversationId`
- **Когда:** Страница загружается
- **Тогда:** История загружается через `GET /api/v1/conversations/:id/messages` и отображается в хронологическом порядке

#### AC-1.7: Статусы сообщений

- **Дано:** Пользователь отправил сообщение
- **Когда:** Сообщение проходит этапы доставки
- **Тогда:** Отображаются статусы: ⏳ отправлено → ✓ доставлено → ✓✓ прочитано

#### AC-1.8: Удаление своего сообщения

- **Дано:** Пользователь видит своё сообщение в диалоге
- **Когда:** Пользователь нажимает «Удалить» на своём сообщении
- **Тогда:** Сообщение удаляется через `DELETE /api/v1/messages/:id` (soft delete) и помечается как «Удалённое сообщение»

## Функциональные требования (продолжение)

### FR-REQ-COMMS-001-04: Отображение отправителя сообщений

Система должна корректно отображать отправителя сообщения в зависимости от роли текущего пользователя.

#### AC-1.9: Отображение «ВЫ» для сообщений текущего пользователя

- **Дано:** Пользователь просматривает диалог `/dashboard/comms/messages/:conversationId`
- **Когда:** Отображаются сообщения текущего пользователя
- **Тогда:** В месте имени отправителя отображается текст «ВЫ»

#### AC-1.10: Отображение имени и фамилии собеседника

- **Дано:** Пользователь просматривает диалог `/dashboard/comms/messages/:conversationId`
- **Когда:** Отображаются сообщения собеседника
- **Тогда:** В месте имени отправителя отображается «Имя Фамилия» собеседника (из `UserProfile.firstName` + `UserProfile.lastName`)

#### AC-1.11: Fallback на User.name при отсутствии имени в профиле

- **Дано:** У собеседника отсутствуют `firstName` и `lastName` в UserProfile, но есть `User.name`
- **Когда:** Отображается сообщение собеседника
- **Тогда:** В месте имени отправителя отображается `User.name`

#### AC-1.12: Fallback на email при отсутствии имени и User.name

- **Дано:** У собеседника отсутствуют данные имени и фамилии в профиле и `User.name` пустой
- **Когда:** Отображается сообщение собеседника
- **Тогда:** В месте имени отправителя отображается email собеседника (из `User.email`)

#### AC-1.13: Отображение «Удалённый пользователь» при удалённом аккаунте

- **Дано:** Отправитель сообщения удалён из системы
- **Когда:** Отображается сообщение удалённого пользователя
- **Тогда:** В месте имени отправителя отображается «Удалённый пользователь»

#### AC-1.14: Отображение имени и фамилии в карточке сообщения

- **Дано:** Пользователь просматривает сообщения в диалоге
- **Когда:** Отображается карточка сообщения собеседника
- **Тогда:** Над текстом сообщения отображается «Имя Фамилия» отправителя

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-01 | Авторизация | Только авторизованные пользователи | `auth()` в API |
| BR-02 | Приватность | Видны только участникам диалога | Проверка `conversation_participants` |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Диалог не найден | `EmptyState` с сообщением «Диалог не найден» + кнопка «На главную» |
| 2 | Не участник диалога | Ошибка 403 «У вас нет доступа к этому диалогу» |
| 3 | Пустое сообщение | Кнопка «Отправить» заблокирована |
| 4 | Сообщение > 4000 символов | Ошибка «Сообщение слишком длинное (макс. 4000 символов)» |
| 5 | Файл > 10MB | Ошибка «Файл слишком большой (макс. 10MB)» |
| 6 | Файл неподдерживаемого типа | Ошибка «Тип файла не поддерживается» |
| 7 | Медленная сеть | Индикатор «Отправка...» с возможностью отмены |
| 8 | Ошибка отправки | Сообщение в статусе «Ошибка» с кнопкой «Повторить» |
| 9 | Удаление чужого сообщения | Кнопка «Удалить» не отображается |

## Нефункциональные требования

- **Безопасность:** Файлы сканируются на вредоносный контент (TODO: интеграция с антивирусом). Размер ограничен 10MB.
- **Производительность:** Загрузка истории: < 500ms при до 100 сообщений. Ленивая подгрузка (infinite scroll).
- **Доступность:** Сообщения доступны с клавиатуры. ARIA-метки на статусных иконках.
- **Локализация:** Все сообщения на русском языке.
- **Адаптивность:** Корректное отображение на мобильных устройствах.
