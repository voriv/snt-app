# US-21-27: Просмотр списка объявлений

## Формулировка
**Как** пользователь СНТ,
**я хочу** видеть список всех опубликованных объявлений,
**чтобы** быть в курсе важных новостей, событий и изменений в жизни сообщества.

## Целевое состояние
Пользователь получает доступ к хронологическому списку всех активных объявлений с возможностью фильтрации и быстрого перехода к деталям.

### Границы
- Отображаются только опубликованные (active) объявления.
- Архивные объявления отображаются в отдельном разделе или по фильтру.
- Доступен минимальный набор данных на первом экране (заголовок, дата, автор).
- Полные детали объявления открываются на отдельной странице.

## Функциональные требования

### FR-REQ-COMMS-001-27: Отображение списка объявлений

#### AC-27.1: Загрузка и отображение списка
- **Дано:** Пользователь авторизован.
- **Когда:** Пользователь открывает страницу "Объявления" (`/dashboard/comms/announcements`).
- **Тогда:**
  - Отображается таблица/список с колонками: ID, Заголовок, Автор, Дата публикации, Статус.
  - По умолчанию сортировка: новые объявления сверху (published_at DESC).
  - Пагинация: по 20-50 записей на страницу.
  - Объявления помечены статусом (Published, Draft, Archived).

#### AC-27.2: Фильтрация по статусу
- **Дано:** Список объявлений загружен.
- **Когда:** Пользователь выбирает фильтр по статусу (Опубликованные, Архивные, Все).
- **Тогда:**
  - Список обновляется только с объявлениями, соответствующими выбранному статусу.
  - Статистика по каждому статусу отображается в реальном времени.

#### AC-27.3: Поиск по объявлению
- **Дано:** В списке отображаются объявления.
- **Когда:** Пользователь вводит текст в поле поиска (заголовок, часть текста).
- **Тогда:**
  - Система фильтрует список, показывая только совпадения.
  - Отображается количество найденных совпадений.
  - Подсветка совпадений в заголовке (опционально).

### FR-REQ-COMMS-001-28: Быстрый переход к деталям
- **Дано:** Пользователь видит список объявлений.
- **Когда:** Пользователь кликает на заголовок объявления или кнопку "Подробнее".
- **Тогда:**
  - Пользователь переходит на страницу деталей объявления (см. US-21-32).
  - Счетчик просмотров объявления увеличивается на 1.

### FR-REQ-COMMS-001-29: Просмотр списка автора
- **Дано:** В списке объявлений показан автор.
- **Когда:** Пользователь кликает на имя автора.
- **Тогда:**
  - Пользователь переходит на страницу карточки автора (если доступен).
  - Отображается информация об авторе (роль, контакты).

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-27-01 | Отображение только опубликованных | По умолчанию показывются только опубликованные объявления. | Фильтр по `status = 'published'` по умолчанию. |
| BR-27-02 | Пагинация | Пагинация применяется для больших списков. | Лимитирование результата на стороне БД. |
| BR-27-03 | Сортировка по дате | По умолчанию новые объявления сверху. | `ORDER BY published_at DESC`. |
| BR-27-04 | Доступность | Все пользователи (включая незарегистрированных) могут просматривать опубликованные объявления. | Проверка прав доступа на уровне API. |
| BR-27-05 | Подсветка важности | Важные объявления могут быть выделены визуально (badge "Важно"). | Проверка флага `isImportant`. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пустой список объявлений | Отображается сообщение "Объявлений пока нет". |
| 2 | Объявление с очень длинным заголовком | Заголовок обрезается с многоточием, полная версия при наведении. |
| 3 | Объявление от удаленного автора | Отображается "Автор удален" вместо имени. |
| 4 | Множество объявлений (>1000) | Пагинация применяется, отображается страница 1 из N. |
| 5 | Авторизованный vs неавторизованный пользователь | Неавторизованный видит только опубликованные, авторизованный — все статусы. |
| 6 | Быстрое добавление нового объявления | Страница может потребовать ручного обновления или использовать WebSocket. |

## Модель данных
Сущность `Announcement` (или `Announcement` в существующей модели).

**Таблица: `announcements`**
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Primary Key |
| `title` | String(200) | Заголовок объявления |
| `content` | Text | Полное содержание |
| `author_id` | UUID | Foreign Key -> users(id) |
| `published_at` | DateTime? | Дата публикации (NULL = черновик) |
| `archived_at` | DateTime? | Дата архивации |
| `status` | Enum | Draft, Published, Archived |
| `is_important` | Boolean | Важно ли объявление |
| `view_count` | Int | Количество просмотров |
| `created_at` | DateTime | Дата создания |
| `updated_at` | DateTime | Дата последнего обновления |

## Нефункциональные требования
- **Производительность:** Запрос списка объявлений < 300мс при до 10,000 записей.
- **Безопасность:** Проверка прав доступа на уровне API (черновики только для автора).
- **Доступность:** Список поддерживается скринридерами, сортировка доступна с клавиатуры.
- **Локализация:** Все статусы, названия на русском языке.
