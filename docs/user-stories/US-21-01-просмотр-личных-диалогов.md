# US-21-01: Просмотр списка личных диалогов

> Эпик: Система общения в СНТ (REQ-COMMS-001)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** просматривать список своих личных диалогов,
**чтобы** быстро находить и переходить к нужным беседам.

---

## Целевое состояние

После реализации пользователь сможет открыть страницу `/dashboard/comms/messages` и увидеть список своих личных диалогов в виде карточек. Каждая карточка показывает: аватар собеседника, имя собеседника, превью последнего сообщения, время последнего сообщения, счётчик непрочитанных. Переход по карточке открывает диалог на `/dashboard/comms/messages/:conversationId`.

---

## Контекст

### Проблема

В системе отсутствует инструмент для просмотра списка личных диалогов. Пользователи не могут увидеть, с кем у них есть активные беседы, и не могут быстро переключаться между ними.

### Решение

Создать страницу `/dashboard/comms/messages` со списком диалогов в виде карточек, загружаемых через `GET /api/v1/conversations`. Диалоги сортируются по времени последнего сообщения (новые сверху). Поиск по имени собеседника фильтрует список на клиенте.

### Границы

- **Входит в US:** Отображение списка диалогов в виде карточек, превью последнего сообщения, счётчик непрочитанных, поиск по имени собеседника (клиентский), переход к диалогу, бейдж непрочитанных на вкладке "Личные сообщения".
- **Явно исключено:** Отправка сообщений (US-21-03), начало нового диалога (US-21-02), групповые чаты (US-21-04..US-21-09).

---

## Поведение (User Behavior)

### B-1: Открытие страницы сообщений

Пользователь кликает на вкладку «Личные сообщения» в панели «Общение» (или переходит по `/dashboard/comms/messages`). Загружается страница с индикатором «Загрузка диалогов...». При успешной загрузке отображается список карточек диалогов. При отсутствии диалогов — `EmptyState` с кнопкой «Написать сообщение».

### B-2: Навигация по карточке диалога

Пользователь видит карточки диалогов, отсортированные по времени последнего сообщения (новые сверху). Клик на карточку — переход на страницу диалога `/dashboard/comms/messages/:conversationId`. На карточке отображается аватар собеседника, имя, превью последнего сообщения (60 символов), время и счётчик непрочитанных (если > 0).

### B-3: Поиск по диалогам

Пользователь вводит текст в поле поиска на странице `/dashboard/comms/messages`. При вводе минимум 2 символов список фильтруется по имени собеседника на стороне клиента (debounce 300ms). Если поиск не дал результатов — `EmptyState` с текстом «Ничего не найдено».

### B-4: Отображение бейджа непрочитанных на вкладке

При наличии непрочитанных сообщений на вкладке «Личные сообщения» отображается бейдж с общим количеством непрочитанных сообщений. Бейдж обновляется при загрузке страницы.

## Функциональные требования

### FR-REQ-COMMS-001-04: Отображение списка диалогов

Система должна отображать список активных диалогов пользователя на странице `/dashboard/comms/messages`.

#### AC-1.1: Загрузка списка диалогов

- **Дано:** Пользователь авторизован
- **Когда:** Пользователь открывает `/dashboard/comms/messages`
- **Тогда:** Список диалогов загружается через `GET /api/v1/conversations` и отображается в виде карточек

#### AC-1.2: Структура карточки диалога

- **Дано:** Диалоги успешно загружены
- **Когда:** Карточка рендерится
- **Тогда:** Карточка содержит: аватар собеседника, имя собеседника, превью последнего сообщения (обрезанное до 60 символов), время последнего сообщения, бейдж непрочитанных (если > 0)

#### AC-1.3: Переход к диалогу

- **Дано:** Пользователь видит список диалогов
- **Когда:** Пользователь кликает на карточку
- **Тогда:** Пользователь переходит на страницу диалога `/dashboard/comms/messages/:conversationId`

#### AC-1.4: Сортировка по времени

- **Дано:** Загружено несколько диалогов
- **Когда:** Список рендерится
- **Тогда:** Диалоги отсортированы по времени последнего сообщения (новые сверху)

### FR-REQ-COMMS-001-05: Поиск по диалогам

Система должна поддерживать поиск по диалогам (по имени собеседника).

#### AC-1.5: Поиск на клиенте

- **Дано:** Пользователь вводит текст в поле поиска
- **Когда:** Введено минимум 2 символа
- **Тогда:** Список фильтруется по имени собеседника (debounce 300ms, фильтрация на клиенте)

### FR-REQ-COMMS-001-06: Счётчик непрочитанных

Система должна отображать счётчик непрочитанных сообщений в навбаре.

#### AC-1.6: Бейдж на вкладке

- **Дано:** У пользователя есть непрочитанные сообщения
- **Когда:** Рендерится вкладка «Личные сообщения»
- **Тогда:** На вкладке «Личные сообщения» отображается бейдж с общим количеством непрочитанных

#### AC-1.7: Удалённые сообщения не учитываются в счётчике непрочитанных (B-027)

- **Дано:** В личном диалоге есть сообщения, которые были удалены
- **Когда:** Загружается список диалогов
- **Тогда:** Удалённые сообщения не учитываются в счётчике непрочитанных на карточке диалога

#### AC-1.8: Счётчик диалога синхронизируется с датой прочтения (B-027)

- **Дано:** Пользователь открыл диалог и сообщения были помечены прочитанными
- **Когда:** Список диалогов обновляется
- **Тогда:** Счётчик непрочитанных на карточке диалога соответствует действительному количеству непрочитанных на основе даты последнего прочтения

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-01 | Авторизация | Только авторизованные пользователи могут просматривать диалоги | `auth()` в API, `useSession()` на странице |
| BR-02 | Приватность | Личные сообщения видны только участникам диалога | Фильтрация на уровне Repository по `conversation_participants` |
| BR-10 | Удалённый пользователь | При удалении пользователя сообщения сохраняются, отправитель — «Удалённый пользователь» | Проверка `userId === null` при рендере |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ссылка на REQ | Ожидаемое поведение |
|---|----------|---------------|---------------------|
| 1 | Нет диалогов | EC-07 (Список диалогов пуст) | Отображается `EmptyState` с текстом «У вас пока нет диалогов» и кнопкой «Написать сообщение» → переход на US-21-02 |
| 2 | Собеседник заблокирован | BR-27 + EC-23 | Диалог с заблокированным пользователем скрыт из списка (или отображается с пометкой) |
| 3 | Собеседник удалён | BR-10 + EC-12 | Вместо имени отображается «Удалённый пользователь», аватар — заглушка |
| 4 | Медленная сеть | EC-10 | Отображается индикатор загрузки с текстом «Загрузка диалогов...» |
| 5 | Ошибка загрузки (сеть/API) | EC-10 | Сообщение об ошибке с кнопкой «Повторить» |

## Нефункциональные требования

- **Безопасность:** Доступ к `/dashboard/messages` и `GET /api/v1/conversations` требует авторизации. Диалоги видны только их участникам.
- **Производительность:** Загрузка списка диалогов: < 500ms при до 500 записей.
- **Доступность:** Карточки доступны с клавиатуры (tab-навигация). Бейджи непрочитанных имеют ARIA-метки.
- **Локализация:** Все сообщения на русском языке.
- **Адаптивность:** Карточки корректно отображаются на мобильных устройствах.
