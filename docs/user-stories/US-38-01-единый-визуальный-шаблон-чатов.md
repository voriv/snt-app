# US-38-01: Единый визуальный шаблон страниц чатов

> Эпик: Система общения в СНТ (REQ-COMMS-001, REQ-COMMS-002)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** видеть единую структуру страниц личного диалога и группового чата,
**чтобы** не путаться в интерфейсе при переключении между типами общения.

---

## Целевое состояние

После реализации страницы личного диалога (`/dashboard/comms/messages/:conversationId`) и группового чата (`/dashboard/comms/chats/:chatId`) используют **единый компонент-обёртку `ChatLayout`** с одинаковой структурой:

1. **Фиксированный заголовок сверху:**
   - Кнопка «Назад» (стрелка влево)
   - Название диалога/чата
   - Действия (для группового чата — просмотр участников, настройки; для личного — просмотр профиля)
   - Разделительная линия снизу, визуально отделяющая заголовок от зоны сообщений

2. **Скроллируемый список сообщений** посередине (единый компонент `MessageList` для обоих типов)

3. **Поле ввода**, прижатое к нижней части экрана (единый компонент `MessageInput`)

Групповой чат дополнительно поддерживает пагинацию и бесконечный скролл при просмотре истории сообщений (аналогично личному диалогу).

---

## Контекст

### Проблема

Страницы личного диалога ([`US-21-03-02`](US-21-03-02-просмотр-истории-сообщений-в-личном-диалоге.md)) и группового чата ([`US-21-09`](US-21-09-отправка-сообщения-в-групповой-чат.md)) были реализованы независимо. Их структура различается: разная компоновка заголовка, разное поведение скролла, разное позиционирование поля ввода. Групповой чат не поддерживает пагинацию истории. Это создаёт непоследовательный UX.

### Решение

Создать единый компонент-обёртку `ChatLayout`, который обеспечивает идентичную компоновку для обоих типов чатов. Адаптировать существующие страницы для использования этого шаблона. Добавить пагинацию для группового чата.

### Границы

- **Входит в US:** Единый `ChatLayout` (заголовок + список + ввод), разделитель заголовка, адаптация обеих страниц, пагинация и бесконечный скролл для группового чата.
- **Явно исключено:** Изменение фона зоны сообщений (US-38-02), изменение контрастности пузырьков (US-38-02), изменение поведения поля ввода (остаётся как есть из US-21-03-02/US-21-09), изменение API.

## Поведение (User Behavior)

### B-1: Открытие личного диалога

Пользователь кликает на диалог в списке личных сообщений. Система открывает страницу `/dashboard/comms/messages/:conversationId`, где отображается фиксированный заголовок с кнопкой «Назад» и именем собеседника, под ним — разделительная линия, затем — скроллируемый список сообщений, и внизу — поле ввода.

### B-2: Открытие группового чата

Пользователь кликает на чат в списке групповых чатов. Система открывает страницу `/dashboard/comms/chats/:chatId` с той же структурой: заголовок (кнопка «Назад», название чата, действия), разделительная линия, список сообщений, поле ввода. Визуально страница неотличима от личного диалога по структуре.

### B-3: Просмотр истории группового чата (пагинация)

Пользователь скроллит список сообщений вверх. При достижении начала загружается предыдущая порция сообщений (бесконечный скролл). Если сообщений больше нет — отображается индикатор «Начало переписки» или скрытая метка.

### B-4: Просмотр заголовка

При любом типе чата заголовок фиксирован и не скроллируется вместе с сообщениями. Он визуально отделён от списка сообщений разделительной линией.

## Критерии приёмки

### AC-1: Единая структура страниц

- **Given:** Пользователь авторизован
- **When:** Пользователь открывает страницу личного диалога `/dashboard/comms/messages/:conversationId` или группового чата `/dashboard/comms/chats/:chatId`
- **Then:** Обе страницы имеют идентичную структуру: фиксированный заголовок сверху, скроллируемый список сообщений посередине, поле ввода внизу

### AC-2: Единый компонент-обёртка

- **Given:** Система рендерит страницу чата
- **When:** Пользователь переходит на страницу любого типа чата
- **Then:** Обе страницы используют одинаковый компонент `ChatLayout`, обеспечивающий компоновку «заголовок + сообщения + ввод»

### AC-3: Структура заголовка

- **Given:** Пользователь на странице чата
- **When:** Заголовок отображается
- **Then:** Заголовок содержит кнопку «Назад» (слева), название чата/диалога (по центру) и кнопки действий (справа) — одинаковая структура для обоих типов

### AC-4: Разделитель заголовка

- **Given:** Пользователь на странице чата
- **When:** Заголовок отображается
- **Then:** Между заголовком и зоной сообщений отображается разделительная линия (например, `border-bottom` или отдельный элемент `Divider`)

### AC-5: Пагинация в групповом чате

- **Given:** Пользователь в групповом чате с более чем 20 сообщениями
- **When:** Пользователь скроллит список сообщений вверх и достигает начала
- **Then:** Автоматически загружается предыдущая порция сообщений (бесконечный скролл), аналогично личному диалогу

### AC-6: Фиксированный заголовок

- **Given:** Пользователь на странице чата
- **When:** Пользователь скроллит список сообщений
- **Then:** Заголовок остаётся фиксированным в верхней части экрана, не скроллируется вместе с сообщениями

### AC-7: Поле ввода внизу

- **Given:** Пользователь на странице чата
- **When:** Страница загружена
- **Then:** Поле ввода отображается внизу экрана, прижато к нижней части, не скроллируется вместе с сообщениями

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Поле ввода на мобильном экране (маленькая высота) | Список сообщений корректно заполняет оставшееся пространство между фиксированным заголовком и полем ввода |
| 2 | Очень длинное название чата в заголовке | Название обрезается многоточием (`text-overflow: ellipsis`), кнопки действий остаются видимыми |
| 3 | Нет сообщений в чате (пустой список) | Отображается EmptyState соответствующего компонента (как в US-21-03-02/US-21-09) |
| 4 | Быстрое переключение между чатами | При переходе по ссылке на другой диалог/чат структура страницы сохраняется, меняется только контент внутри `ChatLayout` |
| 5 | Прямой переход по URL несуществующего чата | Ошибка 404 или 403 (обрабатывается существующей логикой, не в scope данной US) |

## Нефункциональные требования

- **Производительность:** Загрузка страницы с `ChatLayout` не должна увеличивать время рендеринга более чем на 50ms по сравнению с текущей реализацией
- **Безопасность:** Авторизация сохраняется — проверка доступа к диалогу/чату остаётся на уровне API и маршрутизации
- **UX:** Разделительная линия заголовка должна быть визуально заметна (контраст не ниже 3:1 с фонами)
- **Адаптивность:** `ChatLayout` корректно работает на мобильных устройствах (заголовок адаптируется под узкий экран, поле ввода скрывает клавиатуру)
- **Доступность (a11y):** Заголовок имеет ARIA-роль `banner`, список сообщений — `log`, поле ввода — `textbox` с соответствующими label
