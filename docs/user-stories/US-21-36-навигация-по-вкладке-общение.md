# US-21-36: Навигация по вкладке "Общение"

> Эпик: Система общения в СНТ (REQ-COMMS-001)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** видеть вкладку "Общение" в навбаре с переключением между подразделами (Личные сообщения, Групповые чаты, Объявления, Модерация),
**чтобы** иметь единую точку входа для всех коммуникационных функций.

---

## Целевое состояние

После реализации:

1. В **навбаре** появляется пункт «Общение» (иконка чата/сообщений). При клике — переход на `/dashboard/comms`.

2. Страница `/dashboard/comms` содержит **панель вкладок (табов)**:
   - «Личные сообщения» (активна по умолчанию)
   - «Групповые чаты»
   - «Объявления»
   - «Модерация» (отображается только для ADMIN/SUPER_ADMIN)

3. **Маршрутизация:**
   - `/dashboard/comms` → редирект на `/dashboard/comms/messages`
   - `/dashboard/comms/messages` → список личных диалогов (US-21-01)
   - `/dashboard/comms/messages/:conversationId` → диалог (US-21-03)
   - `/dashboard/comms/messages/new` → новый диалог (US-21-02)
   - `/dashboard/comms/chats` → список чатов (US-21-04)
   - `/dashboard/comms/chats/:chatId` → чат (US-21-09)
   - `/dashboard/comms/chats/new` → новый чат (US-21-05)
   - `/dashboard/comms/announcements` → список объявлений (US-21-27)
   - `/dashboard/comms/announcements/:id` → детали объявления (US-21-32)
   - `/dashboard/comms/moderation` → панель модерации (US-21-19)

4. **Визуальное состояние:**
   - Активная вкладка выделена (подчёркивание/фон)
   - Контент под вкладками меняется без перезагрузки страницы (вложенный роутинг)
   - При переключении вкладки URL синхронизируется

5. **Вкладка «Модерация»** скрыта для пользователей без роли ADMIN/SUPER_ADMIN

6. **Счётчики непрочитанных** отображаются на вкладках «Личные сообщения» и «Групповые чаты» (US-21-37)

---

## Контекст

### Проблема

Ранее каждая коммуникационная функция имела отдельный маршрут: `/dashboard/messages`, `/dashboard/chats`, `/dashboard/announcements`, `/dashboard/moderation`. Это приводило к разрозненной навигации и отсутствию единой точки входа. Пользователю приходилось помнить отдельные URL для каждого подраздела.

### Решение

Создать единую вкладку «Общение» в навбаре (`/dashboard/comms`) с панелью табов и вложенным роутингом. Это централизует все коммуникации, упрощает навигацию и соответствует принципу единой точки входа (BR-42, BR-43).

### Границы

- **Входит в US:** Пункт «Общение» в навбаре, страница `/dashboard/comms` с панелью вкладок, вложенный роутинг подразделов, редирект с `/dashboard/comms` на `/dashboard/comms/messages`, скрытие вкладки «Модерация» для MEMBER.
- **Явно исключено:** Содержимое самих подразделов (список диалогов, чатов, объявлений, модерация) — реализуется в US-21-01..US-21-33. Счётчики непрочитанных — US-21-37.

## Поведение (User Behavior)

### B-1: Открытие вкладки «Общение»
Пользователь кликает на пункт «Общение» в навбаре. Система перенаправляет на `/dashboard/comms` с активной вкладкой «Личные сообщения» (FR-67). Если у пользователя нет роли ADMIN/SUPER_ADMIN — вкладка «Модерация» не отображается.

### B-2: Переключение между подразделами
Пользователь кликает на вкладку «Групповые чаты». URL меняется на `/dashboard/comms/chats`. Содержимое под вкладками заменяется на список групповых чатов. Активная вкладка визуально выделена.

### B-3: Прямой переход по URL
Пользователь вводит `/dashboard/comms/announcements` в адресной строке. Система открывает вкладку «Общение» с активной вкладкой «Объявления» и отображает список объявлений.

### B-4: Навигация внутри подраздела
Пользователь внутри вкладки «Личные сообщения» кликает на диалог — URL меняется на `/dashboard/comms/messages/:conversationId`. Подраздел остаётся активным, контент меняется в рамках вложенного роутинга.

## Критерии приёмки

### AC-1: Отображение вкладки «Общение» в навбаре
- **Given:** Пользователь авторизован
- **When:** Навбар рендерится
- **Then:** Отображается пункт «Общение» (иконка чата), при клике — переход на `/dashboard/comms`

### AC-2: Единая точка входа
- **Given:** Пользователь переходит на `/dashboard/comms`
- **When:** Страница загружается
- **Then:** Происходит редирект на `/dashboard/comms/messages`, активна вкладка «Личные сообщения»

### AC-3: Панель вкладок
- **Given:** Пользователь на `/dashboard/comms`
- **When:** Страница загружена
- **Then:** Отображаются вкладки: «Личные сообщения», «Групповые чаты», «Объявления». Активная вкладка визуально выделена

### AC-4: Переключение вкладок
- **Given:** Пользователь на вкладке «Личные сообщения»
- **When:** Пользователь кликает на вкладку «Групповые чаты»
- **Then:** URL меняется на `/dashboard/comms/chats`, отображается содержимое вкладки «Групповые чаты»

### AC-5: Прямой переход по URL подраздела
- **Given:** Пользователь вводит `/dashboard/comms/announcements` в адресной строке
- **When:** Страница загружается
- **Then:** Активна вкладка «Объявления», URL не меняется

### AC-6: Скрытие вкладки «Модерация» для MEMBER
- **Given:** Пользователь с ролью MEMBER
- **When:** Страница `/dashboard/comms` загружается
- **Then:** Вкладка «Модерация» не отображается

### AC-7: Отображение вкладки «Модерация» для ADMIN
- **Given:** Пользователь с ролью ADMIN или SUPER_ADMIN
- **When:** Страница `/dashboard/comms` загружается
- **Then:** Вкладка «Модерация» отображается

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-42 | Единая точка входа | Вкладка «Общение» является единой точкой входа для всех коммуникационных функций | Маршрутизация `/dashboard/comms` |
| BR-43 | Переключение подразделов | Внутри вкладки реализовано переключение между подразделами | UI tabs + nested routing |
| BR-01 | Авторизация | Только авторизованные пользователи могут открывать вкладку | `auth()` middleware |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пользователь неавторизован | Редирект на `/login` (middleware) |
| 2 | Пользователь переходит на несуществующий подраздел (`/dashboard/comms/invalid`) | Редирект на `/dashboard/comms/messages` |
| 3 | Пользователь с ролью MEMBER пытается открыть `/dashboard/comms/moderation` напрямую | Редирект на `/dashboard/comms/messages` или 403 |
| 4 | Медленная загрузка вкладки | Индикатор загрузки (спиннер) на контенте вкладки |
| 5 | Ошибка загрузки контента вкладки | Сообщение об ошибке с кнопкой «Повторить» в области контента |
| 6 | Быстрое переключение между вкладками | Показывается загрузка только для активной вкладки, предыдущие запросы отменяются |
| 7 | Пустой список диалогов/чатов/объявлений | Отображается EmptyState компонента соответствующей вкладки (обрабатывается US-21-01/04/27) |

## Модель данных

| Сущность | Описание | Статус |
|----------|----------|--------|
| — | Вкладка «Общение» не требует новых таблиц | Без изменений |
| — | Используются существующие сущности из REQ-COMMS-001 | Без изменений |

**Обоснование:** US-21-36 — это чисто UI/UX-концепция, которая организует навигацию и композицию существующих страниц под единой точкой входа `/dashboard/comms`. Никаких новых таблиц, полей или индексов не требуется.

**Что реализуется:**
- Компонент `CommsLayout` с панелью вкладок (tabs)
- Вложенный роутинг (nested routes) внутри `/dashboard/comms/*`
- Механизм редиректа с `/dashboard/comms` на `/dashboard/comms/messages`
- Условное отображение вкладки «Модерация» (по роли)

## Нефункциональные требования

- **Производительность:** Переключение вкладок < 100ms (без перезагрузки страницы, только смена отображаемого компонента)
- **Безопасность:** Проверка роли для отображения вкладки «Модерация». Редирект при попытке прямого доступа без прав
- **Доступность:** Вкладки имеют ARIA-роль `tablist`/`tab`/`tabpanel`, поддерживают навигацию стрелками (влево/вправо)
- **Локализация:** Названия вкладок на русском языке
- **SEO:** Маршруты `/dashboard/comms/*` не индексируются (закрыты авторизацией)
