# US-21-20: Просмотр деталей жалобы

## Формулировка
**Как** модератор,
**я хочу** видеть полную информацию по каждой жалобе, включая контекст сообщения, историю действий и возможность принятия решения,
**чтобы** эффективно обрабатывать жалобы и принимать обоснованные решения.

## Целевое состояние
Модератор получает детальный просмотр жалобы со всей контекстной информацией: само сообщение, пользователь, который отправил сообщение, автор жалобы, история модерации и доступные действия по обработке.

### Границы
- Просмотр доступен только модераторам с соответствующими правами.
- Детали жалобы включают только доступные данные (анонимные жалобы сохраняют анонимность автора).
- Не все модераторы имеют право выполнять все действия (например, только SUPER_ADMIN может блокировать).
- Если сообщение уже удалено — его содержимое недоступно, но метаданные сохраняются.

## Функциональные требования

### FR-REQ-COMMS-001-20: Детальный просмотр жалобы

#### AC-20.1: Отображение информации о жалобе
- **Дано:** Модератор авторизован и имеет доступ к жалобе.
- **Когда:** Модератор открывает страницу с деталями жалобы по ID.
- **Тогда:**
  - Отображается форма с полями: ID жалобы, Статус, Причина, Текст жалобы, Дата создания, Автор жалобы (если не анонимно), Дата последнего обновления.
  - Отображается блок "Сообщение, на которое пожаловались": текст сообщения, автор, дата отправки, ссылка на чат.
  - Отображается блок "Авторы" с информацией: кто отправил сообщение, кто подал жалобу (если не анонимно).

#### AC-20.2: Просмотр истории модерации
- **Дано:** Жалоба была обработана ранее одним или несколькими модераторами.
- **Когда:** Модератор открывает детали жалобы.
- **Тогда:**
  - Отображается chronological-лента событий: кто и когда менял статус, какие действия предпринял.
  - Каждое событие содержит: кто выполнил, дата/время, действие, комментарий (если был).
  - Последнее событие выделено визуально.

#### AC-20.3: Переход к消息 и пользователю
- **Дано:** Модератор видит ссылку на сообщение или пользователя в деталях жалобы.
- **Когда:** Модератор кликает на ссылку.
- **Тогда:**
  - Модератор открывается соответствующая страница сообщения или карточка пользователя.
  - Ссылка открывается в новой вкладке (опционально).

### FR-REQ-COMMS-001-21: Быстрые действия по жалобе
- **Дано:** Модератор находится на странице деталей жалобы.
- **Когда:** Модератор принимает решение по жалобе (например, подтверждает, отклоняет, назначает другому модератору).
- **Тогда:**
  - Модератор может выбрать действие из списка: "Подтвердить жалобу", "Отклонить жалобу", "Назначить другому модератору", "Дополнительно расследовать".
  - Модератор может добавить комментарий к действию (необязательно).
  - После подтверждения статус жалобы обновляется, действие записывается в историю.

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-20-01 | Доступ модератора | Только модераторы с правами могут просматривать детали. | Проверка роли в API (MODERATOR/SUPER_ADMIN). |
| BR-20-02 | Анонимность автора жалобы | Если жалоба анонимна — имя автора не отображается. | Проверка флага `reporter_is_anonymous`. |
| BR-20-03 | Удаленное сообщение | Если сообщение удалено — его содержимое не отображается. | Проверка `message_is_deleted`. |
| BR-20-04 | Комментарий к действию | Комментарий к действию модератора — опциональное поле. | `z.string().optional()` в валидаторе. |
| BR-20-05 | История действий | Любое действие модератора должно записываться в историю. | `ModerationAction` модель с записью каждого события. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Сообщение было удалено после жалобы | Отображается "Сообщение удалено", но метаданные (ID, время, автор) видны. |
| 2 | Пользователь, который отправил сообщение, заблокирован | Отображается "Пользователь заблокирован" вместо нормальной карточки. |
| 3 | Пользователь, который подал жалобу, заблокирован | Отображается "Пользователь заблокирован" вместо нормальной карточки. |
| 4 | Доступ к жалобе при снятом доступе модератора | API возвращает ошибку 403, UI показывает соответствующее сообщение. |
| 5 | Жалоба с огромным текстом | Текст обрезается до определенного лимита с кнопкой "Развернуть". |
| 6 | Множественные действия модераторов одновременно | Операции блокируются или применяются последовательно с записью в историю. |

## Модель данных
Сущность `ModerationReport` с связями на `Message`, `User` (reporter), `User` (moderator actions).

**Дополнительная таблица: `moderation_actions`**
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Primary Key |
| `report_id` | UUID | Foreign Key -> moderation_reports(id) |
| `moderator_id` | UUID | Foreign Key -> users(id) |
| `action_type` | Enum | StatusChange, Note, Escalate, Reassign |
| `new_status` | Enum | Новый статус (если изменение статуса) |
| `comment` | Text? | Комментарий модератора |
| `created_at` | DateTime | Дата/время действия |

## Нефункциональные требования
- **Производительность:** Загрузка деталей жалобы < 500мс (включая связанные данные).
- **Безопасность:** Проверка, что модератор имеет права на просмотр жалобы.
- **Доступность:** Все интерактивные элементы имеют aria-label, история модерации доступна для скринридеров.
- **Локализация:** Все сообщения, статусы, действия на русском языке.
