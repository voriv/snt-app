# US-06: Реализация страницы регистрации

---

## Формулировка

**Как** новый пользователь,
**я хочу** видеть форму регистрации с полями email/пароль/подтверждение пароля,
**чтобы** создать учётную запись.

---

## Целевое состояние

Система предоставляет страницу регистрации (`/register`) с формой, содержащей поля для ввода email, пароля и подтверждения пароля. Пользователь заполняет форму и нажимает кнопку "Зарегистрироваться". При успешной регистрации пользователь перенаправляется на страницу входа (`/login?registered=true`) с отображением сообщения об успешной регистрации. При ошибке (например, дублирование email) отображается понятное сообщение об ошибке.

Страница регистрации является публичной и доступна без авторизации. Авторизованные пользователи автоматически перенаправляются на дашборд (`/dashboard`).

## Модель данных

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| User | Пользователь системы; email уникален, password хешируется | `docs/model/entities/user.md` |
| Role | Системная/настраиваемая роль (RBAC); система имеет системные роли | `docs/model/entities/role.md` |
| UserRole | Связь M:N между пользователем и ролями | `docs/model/entities/user-role.md` |

### Ключевые инварианты модели

- `User.email` уникален — быстрый поиск при регистрации
- `User.password` (хеш) никогда не возвращается в ответе API и не покидает домен `auth`
- При создании пользователя автоматически назначается системная роль GUEST (US-01)

## Поведение (User Behavior)

### B-1: Отображение страницы регистрации

Неавторизованный пользователь переходит на URL `/register`. Система отображает форму регистрации с полями `email` (тип email), `password` (тип password), `confirmPassword` (тип password). Кнопка "Зарегистрироваться" активна только при валидных данных. При вводе данных пользователь видит inline-ошибки валидации.

### B-2: Успешная регистрация

Пользователь заполняет форму с корректными данными и нажимает кнопку "Зарегистрироваться". Система создаёт пользователя с автоматически назначенной ролью GUEST, перенаправляет на `/login?registered=true` с отображением сообщения "Учётная запись успешно создана".

### B-3: Регистрация с дублирующимся email

Пользователь заполняет форму с email, который уже зарегистрирован в системе. Система отображает ошибку "Пользователь с таким email уже зарегистрирован" и не создаёт новую учётную запись.

### B-4: Невалидные данные формы

Пользователь заполняет форму с ошибками (некорректный email, пароль короче 6 символов, пароли не совпадают). Система отображает inline-ошибки валидации для соответствующих полей и не отправляет запрос на сервер.

## Критерии приёмки

### AC-1: Отображение формы регистрации

- **Дано:** пользователь не авторизован
- **Когда:** пользователь переходит на URL `/register`
- **Тогда:** система отображает форму с полями `email`, `password`, `confirmPassword`
- **Тогда:** форма содержит кнопку "Зарегистрироваться"
- **Тогда:** форма валидируется на стороне клиента (email формат, required поля, совпадение паролей)

### AC-2: Успешная регистрация

- **Дано:** пользователь вводит корректные email, пароль (минимум 6 символов) и совпадающее подтверждение
- **Когда:** пользователь нажимает кнопку "Зарегистрироваться"
- **Тогда:** система создаёт учётную запись с автоматически назначенной ролью GUEST
- **Тогда:** пользователя перенаправляет на `/login?registered=true`
- **Тогда:** на странице входа отображается сообщение "Учётная запись успешно создана"

### AC-3: Дублирование email

- **Дано:** пользователь вводит email, который уже зарегистрирован в системе
- **Когда:** пользователь нажимает кнопку "Зарегистрироваться"
- **Тогда:** система возвращает ошибку "Пользователь с таким email уже зарегистрирован"
- **Тогда:** HTTP-статус ошибки — 409
- **Тогда:** учётная запись не создаётся

### AC-4: Невалидный формат email

- **Дано:** пользователь вводит некорректный формат email (например, без @)
- **Когда:** пользователь пытается отправить форму
- **Тогда:** система отображает ошибку валидации "Введите корректный email"
- **Тогда:** запрос на сервер не отправляется

### AC-5: Пароль короче минимума

- **Дано:** пользователь вводит пароль короче 6 символов
- **Когда:** пользователь пытается отправить форму
- **Тогда:** система отображает ошибку валидации "Пароль должен содержать минимум 6 символов"
- **Тогда:** запрос на сервер не отправляется

### AC-6: Пароли не совпадают

- **Дано:** пользователь вводит разные значения в полях пароля и подтверждения
- **Когда:** пользователь пытается отправить форму
- **Тогда:** система отображает ошибку валидации "Пароли не совпадают"
- **Тогда:** запрос на сервер не отправляется

### AC-7: Пустые поля

- **Дано:** пользователь заполняет не все обязательные поля формы
- **Когда:** пользователь пытается отправить форму
- **Тогда:** система отображает ошибку валидации "Это поле обязательно для заполнения"
- **Тогда:** запрос на сервер не отправляется

### AC-8: Статус загрузки при отправке

- **Дано:** пользователь заполнил валидную форму и нажимает кнопку "Зарегистрироваться"
- **Когда:** система отправляет запрос на сервер
- **Тогда:** кнопка блокируется и отображается индикатор загрузки
- **Тогда:** повторная отправка формы невозможна до завершения запроса

### AC-9: Авторизованный пользователь на странице регистрации

- **Дано:** пользователь авторизован (имеет валидную сессию)
- **Когда:** пользователь переходит на `/register`
- **Тогда:** система автоматически перенаправляет его на `/dashboard`

### AC-10: Ошибки сервера

- **Дано:** произошла ошибка на сервере (например, недоступность БД)
- **Когда:** система пытается зарегистрировать пользователя
- **Тогда:** система отображает сообщение "Произошла ошибка при регистрации. Попробуйте позже"
- **Тогда:** кнопка "Зарегистрироваться" разблокируется для повторной попытки

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-01 | Email должен быть уникальным | DB Constraint: `@unique` на `User.email` + проверка на сервере |
| BR-02 | Пароль должен содержать минимум 6 символов | Zod: `.min(6, 'Пароль должен содержать минимум 6 символов')` |
| BR-03 | Пароль и подтверждение должны совпадать | Zod: `.refine()` проверка на совпадение |
| BR-04 | При регистрации автоматически назначается роль GUEST | Service: транзакция с назначением роли GUEST (US-01) |
| BR-05 | Пароль не возвращается в ответе API | Service: возвращает `UserData` без поля `password` |

### Примеры валидаций

- **Валидация email (client-side + Zod):** 
  - Client: `z.string().email('Введите корректный email')`
  - Server: `email.toLowerCase().trim()` перед проверкой уникальности
- **Валидация пароля (client-side + Zod):** 
  - `z.string().min(6, 'Пароль должен содержать минимум 6 символов')`
- **Совпадение паролей (client-side + Zod):** 
  - `.refine((data) => data.password === data.confirmPassword, { message: 'Пароли не совпадают', path: ['confirmPassword'] })`

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Email уже зарегистрирован | Ошибка 409 с сообщением "Пользователь с таким email уже зарегистрирован" |
| 2 | Пароль короче 6 символов | Client-side валидация с сообщением "Пароль должен содержать минимум 6 символов" |
| 3 | Пароли не совпадают | Client-side валидация с сообщением "Пароли не совпадают" |
| 4 | Неверный формат email | Client-side валидация с сообщением "Введите корректный email" |
| 5 | Пустые обязательные поля | Client-side валидация с сообщением "Это поле обязательно для заполнения" |
| 6 | Медленная сеть (>3 сек без ответа) | Клиент отображает индикатор загрузки и сообщение об ошибке сети после таймаута |
| 7 | Сервер недоступен | Клиент отображает сообщение "Произошла ошибка при регистрации. Попробуйте позже" |
| 8 | Авторизованный пользователь на `/register` | Автоматический редирект на `/dashboard` через middleware |
| 9 | Попытка регистрации с email в верхнем регистре (`USER@EXAMPLE.COM`) | Приведение к нижнему регистру перед проверкой уникальности |
| 10 | Пробелы вокруг email | `trim()` перед валидацией и проверкой уникальности |
| 11 | Роль GUEST отсутствует в БД | Сервер возвращает ошибку 500 "Ошибка при регистрации" (транзакция откатывается) |
| 12 | Пароль содержит пробелы в начале/конце | Пробелы сохраняются как часть пароля (trim НЕ применяется) |

## Нефункциональные требования

- **Производительность:**
  - Время регистрации < 1000ms (включая хеширование пароля через bcrypt)
  - Валидация на клиенте мгновенная (< 50ms)
  - API ответ < 500ms для успешной регистрации

- **Безопасность:**
  - Пароли хешируются с использованием `bcrypt` с salt rounds ≥ 10
  - Email приводится к нижнему регистру и обрезается перед сохранением
  - Пароль никогда не возвращается в ответе API (`UserData` без `password`)
  - CSRF защита через `next-auth`
  - HTTPS обязателен для передачи учётных данных

- **UX:**
  - Форма валидируется на стороне клиента (real-time или on-submit)
  - Индикатор загрузки при отправке формы
  - Блокировка кнопки "Зарегистрироваться" во время отправки запроса
  - Сообщения об ошибках на русском языке
  - Редирект на `/login?registered=true` после успешной регистрации
  - Сообщения об успешной регистрации на странице входа

- **Доступность (a11y):**
  - Все поля имеют `label` или `aria-label`
  - Поддержка навигации с клавиатуры
  - Фокус на первом поле (email) при загрузке страницы
  - Inline-ошибки валидации с `aria-invalid="true"`
  - Сообщение об ошибке сервера с `role="alert"`

- **Надёжность:**
  - Транзакционность создания пользователя и роли GUEST
  - Обработка ошибок сети (таймаут, offline)
  - Повторная попытка при временных сбоях
