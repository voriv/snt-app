# US-22-05: Просмотр списка документов

> Эпик: Управление документами (REQ-DOCS-001)

---

## Формулировка

**Как** пользователь СНТ,
**я хочу** просматривать список документов с фильтрацией и поиском,
**чтобы** быстро находить нужные документы среди доступных мне.

---

## Целевое состояние

После реализации пользователь на странице `/dashboard/documents` видит список документов, к которым у него есть доступ (на основе роли). Список поддерживает фильтрацию по категории и типу, поиск по названию/описанию/тегам. Документы отсортированы по дате создания (новые сверху). Доступные действия: переход к деталям (клик), сортировка.

## Поведение (User Behavior)

### B-1: Открытие списка документов
Пользователь переходит на `/dashboard/documents`. Система загружает список документов, доступных по роли пользователя. Документы отображаются в виде таблицы/карточек с сортировкой по дате (новые сверху).

### B-2: Фильтрация по категории
Пользователь выбирает категорию из выпадающего фильтра «Все категории». Список фильтруется по выбранной категории и её подкатегориям.

### B-3: Фильтрация по типу
Пользователь выбирает тип из фильтра «Все типы». Список фильтруется по типу документа.

### B-4: Поиск по названию, описанию, тегам
Пользователь вводит текст в поле поиска. Система фильтрует документы по совпадению в полях title, description, tags (debounce 300ms).

### B-5: Пустое состояние
При отсутствии результатов поиска или документов — `EmptyState` с текстом «Документы не найдены» и подсказкой.

---

## Критерии приёмки

### AC-1: Загрузка списка документов по роли
- **Given** пользователь с ролью MEMBER авторизован
- **When** пользователь открывает `/dashboard/documents`
- **Then** загружаются только документы, где `visibleRoles` содержит 'MEMBER' (или 'ADMIN', если пользователь ADMIN); документы в статусе draft исключены

### AC-2: ADMIN видит все опубликованные документы
- **Given** пользователь с ролью ADMIN
- **When** пользователь открывает `/dashboard/documents`
- **Then** ADMIN видит все документы со статусом published (включая документы, доступные только MEMBER)

### AC-3: ADMIN видит черновики
- **Given** пользователь с ролью ADMIN
- **When** пользователь открывает `/dashboard/documents`
- **Then** ADMIN видит документы со статусом draft и published

### AC-4: Фильтрация по категории
- **Given** список документов загружен
- **When** пользователь выбирает категорию «Договоры»
- **Then** отображаются только документы в категории «Договоры» и её подкатегориях

### AC-5: Фильтрация по типу
- **Given** список документов загружен
- **When** пользователь выбирает тип «Протокол»
- **Then** отображаются только документы типа «Протокол»

### AC-6: Поиск по названию
- **Given** список документов загружен
- **When** пользователь вводит «собрание» в поле поиска
- **Then** отображаются документы, где title содержит «собрание» (case-insensitive)

### AC-7: Поиск по тегам
- **Given** документ имеет тег «2025»
- **When** пользователь вводит «2025» в поле поиска
- **Then** документ отображается в результатах

### AC-8: Пустое состояние при отсутствии результатов
- **Given** поиск не дал результатов
- **When** пользователь вводит «несуществующий_текст»
- **Then** отображается `EmptyState` с текстом «Документы не найдены»

### AC-9: Сортировка по дате (новые сверху)
- **Given** загружено несколько документов
- **When** список рендерится
- **Then** документы отсортированы по `createdAt` (DESC — новые сверху)

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-04 | Видимость по ролям | Runtime: фильтрация visibleRoles @> [role] |
| BR-07 | Draft не виден пользователям (только ADMIN) | Runtime: WHERE status != 'draft' OR userRole = 'ADMIN' |
| BR-11 | Поиск по названию, описанию, тегам | Runtime: ILIKE /全文索引 |

### Примеры валидаций
- **Параметры запроса**: `category, type, search, page, limit` — опциональные
- **Пагинация**: default limit 20, max 100

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Поиск без результатов (EC-06) | `EmptyState` «Документы не найдены» |
| 2 | Доступ к документу без прав (EC-03) | Документ исключён из списка (фильтрация на сервере) |
| 3 | Большое количество документов (>1000) | Пагинация; время отрисовки < 1с |
| 4 | Несколько фильтров одновременно | Фильтры комбинируются (AND) |

## Нефункциональные требования

- **Производительность**: поиск — < 500ms (NFR); отрисовка списка до 1000 записей — < 1с
- **Безопасность**: фильтрация по роли на сервере (никогда не возвращать недоступные документы)
- **UX**: debounce поиска 300ms; skeleton-загрузка; пагинация; `EmptyState`
