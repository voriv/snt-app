# US-20-03: Просмотр карточки пользователя

> Эпик: Управление пользователями (REQ-USERS-001)

---

## Формулировка

**Как** Супер-администратор (SUPER_ADMIN),
**я хочу** открывать карточку конкретного пользователя с детальной информацией о профиле и ролях,
**чтобы**全面了解 о пользователе и его правах в системе.

---

## Целевое состояние

После реализации US-20-03 администратор сможет кликнуть на строку пользователя в таблице `/dashboard/users` или перейти по URL `/dashboard/users/[id]`, чтобы увидеть карточку пользователя с разделами: профиль (email, имя, фамилия, дата регистрации) и роли (список назначенных ролей). При отсутствии данных — пустые состояния с пояснительными сообщениями.

---

## Контекст

### Проблема
На данный момент отсутствует возможность просмотра детальной информации о конкретном пользователе. Администратор видит только таблицу со списком, но не может открыть подробную карточку.

### Решение
Создать страницу `/dashboard/users/[id]` с карточкой пользователя, содержащей разделы «Профиль» и «Роли». Данные загружаются через новый API `GET /api/v1/users/[id]` (профиль) и `GET /api/v1/users/[id]/roles` (роли).

### Границы
- **Входит в US:** Отображение профиля пользователя, отображение назначенных ролей, пустые состояния, навигация из таблицы.
- **Явно исключено:** Связи с участками (US-20-04), редактирование профиля пользователя, редактирование ролей.

## Функциональные требования

### FR-REQ-USERS-001-05: Карточка пользователя

Система должна отображать карточку пользователя с детальной информацией на странице `/dashboard/users/[id]`.

#### AC-1.1: Открытие карточки пользователя
- **Дано:** Пользователь находится на странице `/dashboard/users`
- **Когда:** Пользователь кликает на строку пользователя в таблице
- **Тогда:** Происходит переход на `/dashboard/users/[id]` и загружается карточка

#### AC-1.2: Отображение профиля пользователя
- **Дано:** Пользователь с указанным ID существует и имеет профиль
- **Когда:** Загружается карточка `/dashboard/users/[id]`
- **Тогда:** Отображаются данные профиля: email, имя, фамилия, дата регистрации

#### AC-1.3: Пользователь не найден (EC-02)
- **Дано:** В базе нет пользователя с указанным ID
- **Когда:** Загружается страница `/dashboard/users/[неверный_id]`
- **Тогда:** Отображается ошибка 404 с сообщением «Пользователь не найден»

#### AC-1.4: У пользователя нет профиля (EC-03)
- **Дано:** Пользователь существует, но у него нет записи в `user_profiles`
- **Когда:** Загружается карточка `/dashboard/users/[id]`
- **Тогда:** Отображаются базовые данные из `User` (email, createdAt) и сообщение «Профиль пользователя не заполнен»

### FR-REQ-USERS-001-06: Отображение ролей пользователя

Система должна отображать роли пользователя в карточке пользователя.

#### AC-1.5: Отображение списка ролей
- **Дано:** У пользователя назначены роли
- **Когда:** Загружается карточка `/dashboard/users/[id]`
- **Тогда:** В разделе «Роли» отображается список назначенных ролей с именами

#### AC-1.6: У пользователя нет ролей (EC-04)
- **Дано:** У пользователя нет назначенных ролей
- **Когда:** Загружается карточка `/dashboard/users/[id]`
- **Тогда:** В разделе «Роли» отображается сообщение «Роли не назначены»

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пользователь не найден (EC-02) | Отображается сообщение «Пользователь не найden» с кнопкой «Вернуться к списку» |
| 2 | У пользователя нет профиля (EC-03) | Отображаются email и дата из User + сообщение «Профиль не заполнен» |
| 3 | У пользователя нет ролей (EC-04) | Раздел «Роли» содержит сообщение «Роли не назначены» |
| 4 | Пользователь без роли SUPER_ADMIN (EC-06) | Возврат 403 Forbidden |
| 5 | Медленная сеть (EC-08) | Скелетон-загрузка для карточки |

## Нефункциональные требования

- **Безопасность:** Доступ к `/dashboard/users/[id]` и соответствующим API требует роли SUPER_ADMIN.
- **Производительность:** Загрузка карточки пользователя: < 300ms.
- **Доступность:** Карточка доступна с клавиатуры. Разделы имеют заголовки `<h2>` с ARIA-метками.
- **Локализация:** Все сообщения на русском языке.
- **Адаптивность:** Карточка корректно отображается на мобильных устройствах (вертикальная компоновка).
