# US-21-25: Просмотр истории предупреждений пользователя

## Формулировка
**Как** модератор (или супер-администратор),
**я хочу** видеть полную историю предупреждений пользователя, включая детали каждого предупреждения,
**чтобы** принимать обоснованные решения о дальнейших действиях (блокировка, разблокировка, дополнительные меры).

## Целевое состояние
Модератор получает доступ к chronological-списку всех предупреждений пользователя с полным контекстом: тип нарушения, причина, дата выдачи, модератор, комментарий, статус (активно/истекло).

### Границы
- Просмотр доступен только модераторам и супер-администраторам.
- Отображаются только предупреждения текущего пользователя (или всех пользователей при фильтре).
- Просмотр не изменяет статус предупреждений.
- Активные предупреждения (не истекшие) отображаются в приоритетном порядке.

## Функциональные требования

### FR-REQ-COMMS-001-25: Отображение истории предупреждений

#### AC-25.1: Загрузка и отображение списка предупреждений
- **Дано:** Модератор авторизован и имеет доступ к странице истории предупреждений.
- **Когда:** Модератор открывает страницу `/dashboard/moderation/warnings` или карточку пользователя.
- **Тогда:**
  - Отображается таблица с колонками: ID предупреждения, Тип нарушения, Причина, Выдано модератором, Дата выдачи, Срок действия, Статус.
  - По умолчанию сортировка: новые предупреждения сверху (created_at DESC).
  - Активные предупреждения помечены визуально (цвет, badge).
  - Пагинация: по 20-50 записей на страницу.

#### AC-25.2: Фильтрация по статусу
- **Дано:** Список предупреждений загружен.
- **Когда:** Модератор выбирает фильтр по статусу (Активные, Истекшие, Все).
- **Тогда:**
  - Список обновляется только с предупреждениями, соответствующими выбранному статусу.
  - Статистика по каждому статусу отображается в реальном времени.
  - Активные предупреждения всегда отображаются вверху списка.

#### AC-25.3: Поиск по предупреждению
- **Дано:** В списке отображаются предупреждения.
- **Когда:** Модератор вводит текст в поле поиска (ID, тип нарушения, причина, модератор).
- **Тогда:**
  - Система фильтрует список, показывая только совпадения.
  - Отображается количество найденных совпадений.
  - Поисковый запрос сохраняется в URL для возможности общего доступа.

### FR-REQ-COMMS-001-26: Детальный просмотр предупреждения
- **Дано:** Модератор видит список предупреждений.
- **Когда:** Модератор кликает на ID предупреждения или кнопку "Посмотреть".
- **Тогда:**
  - Модератор переходит на страницу деталей предупреждения.
  - Отображается полный объект предупреждения: тип, причина, комментарий, модератор, даты.
  - Отображается контекст: пользователь, которому выдано предупреждение.

### FR-REQ-COMMS-001-27: Экспорт истории предупреждений
- **Дано:** Список предупреждений отфильтрован.
- **Когда:** Модератор нажимает кнопку "Экспорт в CSV".
- **Тогда:**
  - Система генерирует CSV файл с отфильтрованными данными.
  - Файл скачивается на устройство модератора.
  - Лимит экспорта: до 1000 записей за один раз.

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-25-01 | Доступ модератора | Просмотр может только модератор/SUPER_ADMIN. | Проверка роли в API. |
| BR-25-02 | Активные предупреждения | Предупреждение активно, если `created_at + validity_period > now`. | Валидация даты создания vs. срока действия. |
| BR-25-03 | Сортировка по дате | По умолчанию новые предупреждения сверху. | `ORDER BY created_at DESC`. |
| BR-25-04 | Пагинация | Пагинация применяется для больших списков (>50 записей). | Лимитирование результата на стороне БД. |
| BR-25-05 | Защита конфиденциальности | История предупреждений не доступна обычным пользователям. | Проверка прав доступа на уровне API и маршрута. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пустая история предупреждений | Отображается сообщение "Предупреждений не найдено". |
| 2 | Предупреждение с истекшим сроком | Помечается как "Истекло", отображается серым или с иконкой. |
| 3 | Предупреждение от несуществующего модератора | Отображается "Модератор удален" вместо имени. |
| 4 | Пользователь с >1000 предупреждений | Пагинация применяется, отображается страница 1 из N. |
| 5 | Попытка просмотра истории чужого пользователя без прав | API возвращает 403 Forbidden. |
| 6 | Быстрое обновление истории другими модераторами | Страница автоматически обновляется или требует ручного обновления. |

## Модель данных
Использование существующей таблицы `user_warnings` из US-21-24.

**Таблица: `user_warnings`**
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Primary Key |
| `user_id` | UUID | Foreign Key -> users(id) |
| `moderator_id` | UUID | Foreign Key -> users(id) |
| `violation_type` | String | Тип нарушения |
| `reason` | Text | Причина/комментарий |
| `created_at` | DateTime | Дата выдачи |
| `expires_at` | DateTime | Дата истечения (опционально) |

**Дополнительные поля для фильтров:**
- Вычисленное поле `is_active` = `expires_at IS NULL OR expires_at > now`.

## Нефункциональные требования
- **Производительность:** Запрос списка предупреждений < 300мс при до 10,000 записей.
- **Безопасность:** Проверка прав доступа на уровне API и маршрута.
- **Доступность:** Таблица поддерживается скринридерами, фильтрация доступна с клавиатуры.
- **Локализация:** Все статусы, типы нарушений на русском языке.
