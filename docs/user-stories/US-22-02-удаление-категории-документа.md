# US-22-02: Удаление категории документа

> Эпик: Управление документами (REQ-DOCS-001)

---

## Формулировка

**Как** администратор СНТ,
**я хочу** удалять категории документов,
**чтобы** поддерживать актуальную структуру категорий без «мёртвых» разделов.

---

## Целевое состояние

После реализации администратор сможет удалить категорию на странице `/dashboard/documents/categories`. Если в категории есть документы, система автоматически переносит их в родительскую категорию (или в «Без категории», если родительская отсутствует). Подкатегории перепривязываются к родительской категории удаляемой категории.

---

## Модель данных

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| DocumentCategory | Категория документов (self-reference иерархия) | Будет создана |
| Document | Документ с полем categoryId → DocumentCategory.id | Будет создана |

---

## Поведение (User Behavior)

### B-1: Удаление пустой категории
Администратор на странице категорий нажимает «Удалить» рядом с пустой категорией. Система подтверждает действие диалогом. При подтверждении категория удаляется.

### B-2: Удаление категории с документами
Администратор нажимает «Удалить» на категории, содержащей документы. Система предупреждает, что документы будут перенесены в родительскую категорию (или «Без категории»). При подтверждении категория удаляется, документы перепривязываются.

### B-3: Удаление категории с подкатегориями
Администратор удаляет категорию, у которой есть подкатегории. Подкатегории перепривязываются к родительской категории удаляемой. Документы в подкатегориях остаются в них.

---

## Критерии приёмки

### AC-1: Успешное удаление пустой категории
- **Given** существует категория «Тест» без документов и подкатегорий
- **When** администратор удаляет категорию «Тест»
- **Then** категория «Тест» удалена из БД и не отображается в списке

### AC-2: Удаление категории с документами — перенос в родительскую
- **Given** существует категория «Договоры аренды» (подкатегория «Договоры»), в ней 5 документов
- **When** администратор удаляет «Договоры аренды»
- **Then** все 5 документов перенесены в «Договоры» (parentId категории «Договоры»); категория «Договоры аренды» удалена

### AC-3: Удаление корневой категории — перенос в «Без категории»
- **Given** существует корневая категория «Архив» (parentId = null), в ней 3 документа
- **When** администратор удаляет категорию «Архив»
- **Then** все 3 документа получают categoryId = null («Без категории»); категория «Архив» удалена

### AC-4: Подкатегории перепривязываются к родителю
- **Given** категория «Договоры» имеет подкатегорию «Подаренные» с 2 документами
- **When** администратор удаляет «Договоры»
- **Then** подкатегория «Подаренные» получает parentId = null (становится корневой); документы в «Подаренных» остаются на месте

### AC-5: Защита от удаления несуществующей категории
- **Given** категория уже удалена
- **When** администратор повторно отправляет запрос на удаление
- **Then** система возвращает 404 «Категория не найдена»

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-03 | Категория может быть вложенной или корневой | DB: self-reference parentId |
| EC-02 | При удалении категории с документами — перенос в родительскую | Runtime: транзакционное обновление categoryId документов |

### Примеры валидаций
- **Транзакционность**: удаление категории, перенос документов и перепривязка подкатегорий — единая транзакция
- **Защита от каскада**: ручное управление переносом (не DB cascade delete)

---

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Удаление корневой категории с вложенными подкатегориями | Документы корневого → categoryId=null; подкатегории → parentId=null |
| 2 | Удаление категории с большим количеством документов (>1000) | Транзакция выполняется с пакетным обновлением; таймаут не должен превышать 10с |
| 3 | Одновременное удаление двух категорий с одинаковым родителем | Транзакции выполняются последовательно (serializable); ни один документ не теряется |
| 4 | Сбой БД во время транзакции переноса | Транзакция откатывается; категория остаётся (неполное удаление) |

## Нефункциональные требования

- **Производительность**: удаление категории с переносом < 1000 документов — < 2с
- **Безопасность**: только ADMIN; транзакционное выполнение
- **UX**: предупреждение о переносе документов; кнопка подтверждения; сообщения на русском языке
