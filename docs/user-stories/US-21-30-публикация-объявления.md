# US-21-30: Публикация объявления

## Формулировка
**Как** Модератор СНТ,
**я хочу** публиковать черновики объявлений,
**чтобы** они стали видны всем пользователям.

## Целевое состояние
После реализации модератор сможет:
- Выбрать черновик объявления для публикации.
- Подтвердить публикацию через модальное окно.
- Увидеть опубликованное объявление в списке опубликованных.
- Автоматически обновить дату публикации при публикации.

## Границы
- **Входит:** Публикация черновика объявления, подтверждение.
- **Не входит:** Создание объявлений (это US-21-28), редактирование (это US-21-29), удаление (это US-21-33).

## Функциональные требования
- **FR-REQ-COMMS-020-01:** Система должна предоставлять кнопку публикации для черновиков объявлений.
- **FR-REQ-COMMS-020-02:** Система должна показывать модальное окно подтверждения перед публикацией.
- **FR-REQ-COMMS-020-03:** Система должна изменять статус объявления с `draft` на `published`.
- **FR-REQ-COMMS-020-04:** Система должна устанавливать дату публикации (`published_at`) на момент публикации.
- **FR-REQ-COMMS-020-05:** Система должна мгновенно отображать опубликованное объявление в списке.

## Бизнес-правила
- **BR-01:** Только пользователи с ролью ADMIN или SUPER_ADMIN могут публиковать объявления.
- **BR-02:** Опубликовать можно только черновик (статус `draft`).
- **BR-03:** При публикации объявления автоматически указывается дата публикации и модератор.
- **BR-04:** Опубликованные объявления становятся видны всем авторизованным пользователям.
- **BR-05:** Нельзя опубликовать уже опубликованное или архивное объявление.

## Валидации
- Валидация прав доступа на уровне API.
- Валидация UUID объявления.
- Валидация статуса объявления (должен быть `draft`).

## Граничные случаи (Edge Cases)
- **EC-01:** Объявление уже опубликовано → Показывается уведомление "Объявление уже опубликовано".
- **EC-02:** Отмена публикации → Объяление остаётся черновиком.
- **EC-03:** Объяление не найдено → Показывается ошибка "Объявление не найдено".
- **EC-04:** Нет прав на публикацию → Показывается ошибка доступа.
- **EC-05:** Ошибка публикации → Показывается уведомление об ошибке, статус не меняется.
- **EC-06:** Архивное объявление → Нельзя опубликовать, показывается ошибка.

## Модель данных
**Таблица `announcements` (Объявления):**
- Поле `status` — обновление: `SET status = 'published'`.
- Поле `published_at` — обновление: `SET published_at = NOW()`.
- Поле `published_by` (опционально) — обновление: `SET published_by = ?`.

## Влияние на архитектуру

### Types
- Тип `PublishAnnouncementResponse`: `{ success: boolean, message: string }`

### Validators (Zod)
- Валидация не требуется на уровне тела запроса (id из URL).

### Errors
- `AnnouncementAccessDeniedError` (наследуется от `ForbiddenError`).
- `AnnouncementNotFoundError` (наследуется от `NotFoundError`).
- `AnnouncementNotDraftError` (наследуется от `BusinessRuleError`).

### Repository
- Методы:
  - `publishAnnouncement(id: string, publishedBy: string): Promise<void>`
  - `isAnnouncementDraft(id: string): Promise<boolean>`

### Service
- Логика:
  - Проверка прав доступа.
  - Проверка существования объявления.
  - Проверка статуса объявления (должен быть `draft`).
  - Обновление статуса и даты публикации.

### DI Container
- Регистрация `IAnnouncementRepository` и `AnnouncementService`.

### API
- **POST** `/api/v1/announcements/:id/publish`
  - Ответ 200: `{ success: true, message: "Объявление успешно опубликовано" }`
  - Ответ 403: `{ success: false, error: { code: "ACCESS_DENIED" } }`
  - Ответ 404: `{ success: false, error: { code: "ANNOUNCEMENT_NOT_FOUND" } }`
  - Ответ 409: `{ success: false, error: { code: "ANNOUNCEMENT_NOT_DRAFT" } }`

### UI
- Компонент `PublishAnnouncementButton` (кнопка публикации).
- Компонент `PublishAnnouncementModal` (модальное окно подтверждения).
- Компонент `AnnouncementStatusBadge` (индикатор статуса).
- Компонент `Notification` (уведомление об успехе/ошибке).

### Pages
- Страница `/dashboard/announcements` (список объявлений с кнопками публикации).
- Страница деталей черновика `/dashboard/announcements/:id` (кнопка публикации).

## Нефункциональные требования
- **Производительность:** Публикация объявления менее 500 мс.
- **Безопасность:** Проверка прав доступа (ADMIN/SUPER_ADMIN).
- **Юзабилити:** Чёткое подтверждение, мгновенное обновление UI.
