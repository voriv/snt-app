# US-4: Logout пользователя

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** выйти из системы,
**чтобы** завершить сеанс и освободить доступ к защищённым ресурсам с компьютера общего доступа.

---

## Контекст

**Проблема**: В приложении отсутствует возможность выхода из системы. Авторизованные пользователи не могут завершить сессию — отсутствует кнопка «Выйти» в навбаре и логика вызова `signOut()` из NextAuth.

**Решение**: Добавить кнопку «Выйти» во все страницы авторизованной зоны через [`AppLayout`](src/components/layouts/AppLayout.tsx:16). Реализовать модальное окно подтверждения выхода и вызов `signOut({ callbackUrl: '/' })`. После logout пользователь перенаправляется на стартовую страницу `/` (landing).

**Границы**:
- Входит: кнопка «Выйти» в навбаре, модальное окно подтверждения, вызов signOut, редирект на `/`, отображение имени/email пользователя в навбаре
- НЕ входит: изменение модели данных, новые API-эндпоинты, блокировка сессий, история сессий

---

## Модель данных

| Сущность | Описание |
|----------|----------|
| **User** | Поля `name` (nullable) и `email` используются для отображения в навбаре — имя пользователя или email как fallback |
| **Session** | JWT-сессия NextAuth уничтожается при logout через `signOut()` — новые поля/таблицы не нужны |

> Модель данных **не требует изменений** — logout работает через уничтожение сессии, а не через операции с базой данных.

---

## Функциональные требования

### FR-1: Отображение информации о пользователе в навбаре
В правой части навбара [`AppLayout`](src/components/layouts/AppLayout.tsx:16) отображается:
- Имя пользователя (`session.user.name`), если поле `name` задано и не `null`
- Email пользователя (`session.user.email`), если `name` не задан или `null`
- Кнопка «Выйти»

### FR-2: Подтверждение выхода
При нажатии на кнопку «Выйти» отображается модальное окно подтверждения:
- Текст: «Вы действительно хотите выйти?»
- Кнопка «Выйти» (вариант danger)
- Кнопка «Отмена»
- Закрытие по клику вне модального окна или по клавише Escape

### FR-3: Выполнение logout
При подтверждении в модальном окне:
- Вызывается `signOut({ callbackUrl: '/' })` из `next-auth/react`
- NextAuth уничтожает JWT-сессию и удаляет HttpOnly cookies
- Пользователь перенаправляется на маршрут `/`

### FR-4: Редирект после logout
После завершения `signOut` пользователь перенаправляется на маршрут `/` (стартовая страница, landing из US-1). Параметр `callbackUrl: '/'` обеспечивает редирект именно на стартовую страницу, а не на `/login`.

### FR-5: Доступность на всех страницах авторизованной зоны
Кнопка «Выйти» доступна на всех страницах внутри `/dashboard/*`, поскольку реализуется в [`AppLayout`](src/components/layouts/AppLayout.tsx:16), который используется как общий layout через [`dashboard/layout.tsx`](src/app/dashboard/layout.tsx:17).

### FR-6: Состояние загрузки при logout
Во время выполнения `signOut` кнопка «Выйти» в модальном окне блокируется и отображается индикатор загрузки. Повторный вызов `signOut` невозможен.

## Критерии приёмки

### AC-1: Отображение имени пользователя в навбаре
- **Given** авторизованный пользователь с заполненным полем `name`
- **When** открывается любая страница в `/dashboard/*`
- **Then** в правом углу навбара отображается имя пользователя и кнопка «Выйти»

### AC-2: Отображение email при отсутствии имени
- **Given** авторизованный пользователь без поля `name` (null)
- **When** открывается любая страница в `/dashboard/*`
- **Then** в правом углу навбара отображается email пользователя и кнопка «Выйти»

### AC-3: Открытие модального окна подтверждения
- **Given** пользователь видит кнопку «Выйти» в навбаре
- **When** нажимает на кнопку «Выйти»
- **Then** отображается модальное окно с текстом «Вы действительно хотите выйти?» и кнопками «Выйти» и «Отмена»

### AC-4: Закрытие модального окна без выхода
- **Given** открыто модальное окно подтверждения выхода
- **When** нажимает кнопку «Отмена»
- **Then** модальное окно закрывается, пользователь остаётся на текущей странице

### AC-5: Закрытие модального окна по клику вне
- **Given** открыто модальное окно подтверждения выхода
- **When** кликает вне области модального окна
- **Then** модальное окно закрывается, пользователь остаётся на текущей странице

### AC-6: Закрытие модального окна по Escape
- **Given** открыто модальное окно подтверждения выхода
- **When** нажимает клавишу Escape
- **Then** модальное окно закрывается, пользователь остаётся на текущей странице

### AC-7: Выполнение logout после подтверждения
- **Given** открыто модальное окно подтверждения выхода
- **When** нажимает кнопку «Выйти» (danger)
- **Then** вызывается `signOut({ callbackUrl: '/' })`, сессия уничтожается, пользователь перенаправляется на `/`

### AC-8: Состояние загрузки при logout
- **Given** пользователь нажал кнопку «Выйти» в модальном окне
- **When** запрос в процессе
- **Then** кнопка блокируется, отображается индикатор загрузки, повторный вызов невозможен

### AC-9: Отображение стартовой страницы после logout
- **Given** пользователь завершил logout
- **When** открыт маршрут `/`
- **Then** отображается landing page с названием «СНТ Берёзки-НТ» и кнопкой «Войти»

### AC-10: Middleware пропускает logout на landing
- **Given** пользователь не авторизован
- **When** переходит на `/`
- **Then** middleware разрешает доступ — это публичный маршрут

### AC-11: Доступность logout на всех страницах
- **Given** пользователь авторизован
- **When** открывается `/dashboard`, `/dashboard/members` или любой маршрут внутри `/dashboard/*`
- **Then** в навбаре отображается кнопка «Выйти»

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-1 | Показывать имя пользователя, если `name` не null | Runtime — условный рендеринг |
| BR-2 | Показывать email, если `name` равен null | Runtime — условный рендеринг |
| BR-3 | Logout требует подтверждения | UI — модальное окно обязательное |
| BR-4 | После logout редирект на `/` | NextAuth — `callbackUrl: '/'` |
| BR-5 | JWT сессия уничтожается при logout | NextAuth — `signOut()` |
| BR-6 | Повторный logout блокируется во время запроса | UI — блокировка кнопки, `isLoading` |

### Примеры валидаций
- **Имя пользователя**: приоритет отдаётся `name`, email — fallback
- **Модальное окно**: нельзя закрыть без явного выбора (отмена или подтверждение)
- **Блокировка повторного вызова**: `isLoading = true` блокирует кнопку

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Нестабильное соединение во время logout | NextAuth вернёт ошибку, модальное окно закроется, пользователь останется на странице с ошибкой |
| 2 | Пользователь быстро нажимает «Выйти» несколько раз | Блокировка кнопки через `isLoading` — повторные вызовы невозможны |
| 3 | Пользователь закрывает браузер без logout | Сессия сохранена в HTTP-only cookie, уничтожается при перезагрузке сервера или по истечении срока JWT |
| 4 | Несколько вкладок с открытым приложением | Logout в одной вкладке уничтожает сессию для всех — в других вкладках сессия неактивна |
| 5 | Пользователь перешёл на `/` до завершения logout | Middleware не блокирует, landing рендерится корректно |
| 6 | `session.user.name` пустая строка `""` | Считать за отсутствующее значение, показать email |
| 7 | Пользователь нажал «Отмена» и сразу снова «Выйти» | Модальное окно открывается заново |

## Обработка ошибок

| Ситуация | Код HTTP | Доменная ошибка | Сообщение пользователю |
|----------|----------|-----------------|------------------------|
| Ошибка при уничтожении сессии | — | SessionError | Не удалось выйти. Пожалуйста, попробуйте снова. |
| Таймаут запроса к `/api/auth/signout` | — | TimeoutError | Время ожидания истекло. Проверьте соединение и попробуйте снова. |

> Примечание: ошибки logout обрабатываются на клиенте через `try/catch` в обработчике кнопки. Нет HTTP-ответа, так как `signOut()` управляет сессией через client-side API.

## Нефункциональные требования

- **Производительность**: `signOut()` — локальная операция, очистка cookies и редирект < 200мс
- **Безопасность**:
  - HTTP-only cookies — недоступны через JavaScript на клиенте
  - JWT уничтожается на сервере (POST /api/auth/signout)
  - `callbackUrl: '/'` предотвращает редирект на конфиденциальные маршруты
- **UX**:
  - Модальное окно обязательно — защита от случайного выхода
  - Индикатор загрузки — визуальная обратная связь при logout
  - Адаптивная верстка — мобильные и десктоп

## Открытые вопросы

| # | Вопрос | Допущение |
|---|--------|-----------|
| 1 | Нужно ли показывать flash-сообщение «Вы вышли из системы» при переходе на `/`? | Нет — landing page не отображает flash-сообщения, пользователь и так видит, что не авторизован |
| 2 | Нужно ли блокировать доступ к `/dashboard/*` при открытом модальном окне? | Нет — пользователь может закрыть модал и продолжить работу |
| 3 | Нужно ли сохранять `callbackUrl` для возврата на исходную страницу после logout? | Нет — logout всегда завершает сессию, редирект на `/` универсален |
