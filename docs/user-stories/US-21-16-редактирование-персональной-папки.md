# US-21-16: Редактирование персональной папки

## Формулировка
**Как** пользователь системы чатов,
**я хочу** редактировать имя своей персональной папки,
**чтобы** обновлять категорию при изменении смысла переписки или при необходимости переименования.

## Целевое состояние
Пользователь может изменить имя существующей персональной папки. При редактировании сохраняются все ассоциированные чаты внутри папки.

### Границы
- Редактирование доступно только для собственных папок (не чужих, не системных).
- Имя новой папки должно быть уникальным для текущего пользователя.
- Имя папки не может быть пустым или содержать запрещенные символы.
- Система может ограничивать длину имени (максимум 50 символов).
- Перемещение папок между уровнями (системная ↔ персональная) не поддерживается в этой истории.

## Функциональные требования

### FR-REQ-COMMS-001-16: Редактирование имени папки

#### AC-16.1: Изменение имени на корректное
- **Дано:** Пользователь авторизован и имеет созданные папки.
- **Когда:** Пользователь нажимает кнопку "Редактировать" на папке, вводит новое уникальное имя и подтверждает.
- **Тогда:**
  - Система обновляет имя папки в базе данных.
  - В списке папок отображается новое имя.
  - Пользователь видит уведомление об успешном изменении.

#### AC-16.2: Отмена редактирования
- **Дано:** Пользователь находится в режиме редактирования имени папки.
- **Когда:** Пользователь нажимает кнопку "Отмена" или закрывает модальное окно.
- **Тогда:**
  - Режим редактирования закрывается без сохранения изменений.
  - Имя папки остается прежним.

#### AC-16.3: Валидация имени при редактировании
- **Дано:** Пользователь пытается изменить имя папки.
- **Когда:** Пользователь вводит:
  - Пустое имя.
  - Имя, которое уже существует у данного пользователя.
  - Имя, превышающее лимит символов (>50).
  - Имя, содержащее запрещенные символы.
- **Тогда:**
  - Система отображает понятное сообщение об ошибке.
  - Изменение не применяется.
  - Фокус остается в поле ввода.

### FR-REQ-COMMS-001-17: Проверка прав доступа
- **Дано:** Пользователь А не является владельцем папки, которая принадлежит Пользователю Б.
- **Когда:** Пользователь А пытается редактировать папку.
- **Тогда:**
  - Кнопка "Редактировать" не отображается.
  - При прямом API-вызове возвращается ошибка 403 Forbidden.

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-16-01 | Право владельца | Редактировать может только владелец папки | Проверка `user_id` при UPDATE |
| BR-16-02 | Уникальность имени | Новое имя должно быть уникальным для пользователя | `SELECT COUNT(*) = 1` при проверке |
| BR-16-03 | Запрет на пустое имя | Имя папки не может быть пустым после редактирования | Валидация на сервере и клиенте |
| BR-16-04 | Ограничение длины | Максимальная длина имени — 50 символов | `string.max(50)` в валидаторе |
| BR-16-05 | Сохранение чатов | При изменении имени чаты остаются в папке | UPDATE без затронутых `chat_folders` записей |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Папка была переименована во время ввода (другим устройством) | Конфликт, система отклоняет обновление или применяет последнее успешное изменение |
| 2 | Попытка переименовать в то же имя | Изменение отклоняется, пользователь получает сообщение "Новое имя должно отличаться от текущего" |
| 3 | Одновременное редактирование одной папки двумя пользователями | Серверная блокировка (optimistic locking через `updated_at`) |
| 4 | Отключение сети во время редактирования | Обработка таймаута, показ сообщения о проблеме сети |
| 5 | Попытка переименовать системную папку | Блокировка, кнопка "Редактировать" скрыта, при API-вызове — 403 |

## Модель данных

Сущность `user_folders` не требует изменений, только обновление существующего поля `name`:

```prisma
model UserFolder {
  id        String   @id @default(cuid())
  userId    String   @map("user_id")
  name      String   @map("name")
  sortOrder Int      @default(0) @map("sort_order")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@unique([userId, name]) // Гарантирует уникальность имени для пользователя
}
```

## Нефункциональные требования
- **Производительность:** Обновление папки < 200мс.
- **Безопасность:** API-эндпоинт проверяет, что `userId` в URL совпадает с сессией пользователя.
- **Доступность:**
  - Кнопка редактирования имеет `aria-label="Редактировать имя папки"`.
  - При ошибке фокус перемещается на проблемное поле.
- **Анимация:** Плавное обновление имени папки в списке (fade-in).

## Открытые вопросы
1. Нужно ли сохранять историю переименований? (Решение: Нет, в рамках US-21-16 не требуется).
2. Требуется ли подтверждение для переименования (как при удалении)? (Решение: Нет, достаточно inline-редактирования без ConfirmModal, так как это менее рискованное действие).
3. Как отображать ошибку "Имя уже занято" при inline-редактировании — через tooltip или toast? (Решение: toast-уведомление в нижней части экрана).
