# US-21-35: Отправка email-уведомлений

## Формулировка

**Как** пользователь СНТ,
**я хочу** получать email-уведомления о важных событиях,
**чтобы** не пропустить важные сообщения даже когда не использую приложение.

## Целевое состояние

После реализации пользователь сможет:
- Получать мгновенные email-уведомления о критических событиях (упоминания, личные сообщения)
- Отписываться от определённых типов уведомлений
- Видеть краткое содержание в email с ссылкой на полное сообщение
- Управлять настройками email-уведомлений в профиле

### Границы

**Входит:**
- Мгновенная отправка email при критических событиях
- Краткое содержание с возможностью перехода к полному сообщению
- Опция отписки от каждого типа уведомлений
- Управление настройками в профиле пользователя

**Не входит:**
- Ежедневные/еженедельные рассылки (отдельная US)
- Push-уведомления в браузере
- SMS-уведомления
- Настройка частоты рассылок

### FR-REQ-COMMS-024-01: Отправка email-уведомлений

Система должна отправлять email-уведомления о критических событиях.

#### AC-35.1: Отправка при упоминании
- **Дано:** Пользователь упомянут в сообщении (@username)
- **Дано:** Email-уведомления не отключены для типа "mention"
- **Когда:** Сообщение опубликовано
- **Тогда:** Пользователь получает email с темой "Вас упомянули в сообществе" и кратким содержанием

#### AC-35.2: Отправка при личном сообщении
- **Дано:** Пользователю пришло личное сообщение
- **Дано:** Email-уведомления не отключены для типа "new_message"
- **Когда:** Сообщение доставлено
- **Тогда:** Пользователь получает email с темой "Новое сообщение от [имя отправителя]"

#### AC-35.3: Краткое содержание
- **Дано:** Email отправляется
- **Когда:** Пользователь открывает email
- **Тогда:** Содержит:
  - Заголовок с указанием типа события
  - Краткое содержание сообщения (до 200 символов)
  - Имя отправителя
  - Ссылку на полное сообщение в приложении
  - Ссылку "Отписаться от этих уведомлений"

### FR-REQ-COMMS-024-02: Управление подпиской

Пользователь должен иметь возможность управлять подпиской на email-уведомления.

#### AC-35.4: Отписка от типа уведомлений
- **Дано:** Пользователь на странице настроек профиля
- **Когда:** Пользователь переключает переключатель "Email-уведомления для упоминаний"
- **Тогда:**
  - Настройка сохраняется в базе данных
  - Пользователь перестаёт получать email этого типа
  - Появляется подтверждение "Настройки сохранены"

#### AC-35.5: Отписка из email
- **Дано:** Пользователь получил email-уведомление
- **Когда:** Пользователь нажимает ссылку "Отписаться" в email
- **Тогда:**
  - Пользователь переходит на страницу подтверждения отписки
  - После подтверждения настройка сохраняется
  - Появляется сообщение "Вы отписались от этих уведомлений"

#### AC-35.6: Повторная подписка
- **Дано:** Пользователь отписался от типа уведомлений
- **Когда:** Пользователь переключает переключатель обратно на "вкл"
- **Тогда:** Подписка восстанавливается, email начинают приходить снова

### FR-REQ-COMMS-024-03: Настройки по умолчанию

Система должна использовать разумные настройки по умолчанию.

#### AC-35.7: Настройки по умолчанию при регистрации
- **Дано:** Пользователь проходит регистрацию
- **Когда:** Аккаунт создан
- **Тогда:** Email-уведомления включены для:
  - Личные сообщения
  - Упоминания @username
- **Тогда:** Email-уведомления выключены для:
  - Ответы в групповых чатах (чтобы не спамить)
  - Ответы в обсуждениях объявлений

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| **BR-01** | Email обязателен | У пользователя должен быть email в профиле | Проверка email перед отправкой |
| **BR-02** | Индивидуальная настройка | Каждый тип уведомлений настраивается отдельно | Поля `email_notifications_mention`, `email_notifications_new_message` |
| **BR-03** | Отписка мгновенная | Отписка применяется сразу | Прямое обновление настроек |
| **BR-04** | Краткое содержание | В email не более 200 символов | Обрезка контента перед отправкой |
| **BR-05** | Ссылка на приложение | Все email содержат ссылку на полное сообщение | Валидация URL |
| **BR-06** | Защита от спама | Не более 1 email в минуту на пользователя | Троттлинг в сервисе |
| **BR-07** | Дедупликация | Если много упоминаний подряд — один email | Буферизация уведомлений |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| **EC-01** | Нет email в профиле | Email не отправляется, показывается ошибка в логах |
| **EC-02** | Email-адрес заблокирован провайдером | Пытаемся повторно 3 раза с задержкой, затем пропускаем |
| **EC-03** | Пользователь отписался, но упомянули | Email не отправляется |
| **EC-04** | Много упоминаний за минуту (burst) | Один email через 5 минут с суммарным содержанием |
| **EC-05** | Ссылка в email не работает | Пользователь видит 404, но может открыть приложение и войти |
| **EC-06** | Email улетает в спам | Пользователь не видит, но другие типы приходят |
| **EC-07** | Пустое сообщение | Email не отправляется (техническая ошибка) |
| **EC-08** | Отписка через email у неавторизованного пользователя | Требует подтверждения через кнопку |

## Модель данных

### Текущая схема (предполагаемая)

```prisma
// Расширение модели User
model User {
  id              String   @id @default(cuid())
  email           String   @unique
  firstName       String
  lastName        String
  
  // Новые поля для email-уведомлений
  emailNotificationsMention   Boolean  @default(true) @map("email_notifications_mention")
  emailNotificationsNewMessage Boolean @default(true) @map("email_notifications_new_message")
  emailNotificationsChatMessage Boolean @default(false) @map("email_notifications_chat_message")
  
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")
}
```

**Обоснование:**
- Добавление флагов для каждого типа уведомлений
- Логичные значения по умолчанию для новых пользователей

### Конвенции именования

| Поле | Тип | Назначение |
|------|-----|------------|
| `email_notifications_mention` | Boolean | Упоминания @username |
| `email_notifications_new_message` | Boolean | Личные сообщения |
| `email_notifications_chat_message` | Boolean | Сообщения в чатах |

## Влияние на слои архитектуры

### Types
- Расширение типа `User` с полями email-настроек
- Тип `EmailNotificationType`: `mention | new_message | chat_message`
- Интерфейс `EmailNotificationSettings`

### Validators
- Валидация email-адреса перед отправкой
- Валидация настроек при обновлении

### Errors
- `EmailNotConfiguredError` — email не настроен
- `EmailSendingError` — ошибка отправки email

### Repository
- Метод `updateEmailNotifications(userId: string, settings: EmailNotificationSettings): Promise<void>`
- Метод `getEmailNotifications(userId: string): Promise<EmailNotificationSettings>`

### Service
- Метод `sendEmailNotification(userId: string, type: EmailNotificationType, content: EmailNotificationContent): Promise<void>`
- Метод `updateEmailNotifications(userId: string, settings: EmailNotificationSettings): Promise<void>`
- Метод `unsubscribeFromEmail(userId: string, type: EmailNotificationType): Promise<void>`

### DI
- Фабрика `createEmailService()` для отправки email

### API
- **GET /api/v1/user/email-notifications**
  - Auth: required
  - Response: 200 `{ success: true, data: EmailNotificationSettings }`
- **PATCH /api/v1/user/email-notifications**
  - Auth: required
  - Body: `{ emailNotificationsMention?: boolean, emailNotificationsNewMessage?: boolean, ... }`
  - Response: 200 `{ success: true, data: EmailNotificationSettings }`
- **POST /api/v1/emails/unsubscribe**
  - Body: `{ token: string }` (token из email)
  - Response: 200 `{ success: true }`

### UI
- **Компоненты:**
  - `EmailNotificationSettings` — форма настроек в профиле
  - `NotificationToggle` — переключатель для каждого типа
  - `UnsubscribeConfirmation` — страница подтверждения отписки

### Pages
- Страница `/dashboard/settings/notifications` — управление email-уведомлениями

## Нефункциональные требования

- **Производительность:** Отправка email < 1 секунды
- **Надёжность:** Автоматическая повторная попытка при ошибке (3 раза)
- **Анти-спам:** Троттлинг (максимум 1 email в минуту на пользователя)
- **Отказоустойчивость:** Если email не отправлен — логирование, без падения приложения
- **UX:** Чёткая тема email, понятный текст, рабочая ссылка

## Открытые вопросы

| # | Вопрос | Допущение |
|---|--------|-----------|
| 1 | Нужно ли подтверждение email перед отправкой? | Да, в стандартной аутентификации |
