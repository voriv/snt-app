# US-20-02: Поиск и сортировка пользователей

> Эпик: Управление пользователями (REQ-USERS-001)

---

## Формулировка

**Как** Супер-администратор (SUPER_ADMIN),
**я хочу** искать пользователей по email, имени и фамилии, а также сортировать список,
**чтобы** быстро находить конкретных пользователей в большом списке.

---

## Целевое состояние

После реализации US-20-02 администратор сможет вводить поисковый запрос в поле поиска над таблицей пользователей, а также кликать по заголовкам столбцов для сортировки по email, имени, фамилии и дате регистрации. Список автоматически фильтруется и переупорядочивается.

---

## Контекст

### Проблема
На странице `/dashboard/users` отображается полный список пользователей без возможности поиска и сортировки. В системах с большим количеством пользователей это затрудняет навигацию.

### Решение
Добавить в API `GET /api/v1/users` параметры `q` (поиск), `sort` (поле сортировки) и `order` (направление). На клиенте — поле поиска с debounce и кликабельные заголовки таблицы для сортировки.

### Границы
- **Входит в US:** Текстовый поиск по email/имени/фамилии, сортировка по 4 полям, пагинация, пустое состояние при поиске.
- **Явно исключено:** Фильтрация по ролям, расширенный поиск с несколькими критериями, экспорт данных.

## Функциональные требования

### FR-REQ-USERS-001-02: Поиск пользователей

Система должна поддерживать поиск пользователей по email, имени и фамилии.

#### AC-1.1: Поиск через поле ввода
- **Дано:** Пользователь находится на странице `/dashboard/users`
- **Когда:** Пользователь вводит текст в поле поиска
- **Тогда:** Список пересоздается через `GET /api/v1/users?q=<запрос>` с debounce ~300ms

#### AC-1.2: Поиск по email
- **Дано:** В базе есть пользователь с email `test@example.com`
- **Когда:** Пользователь вводит `test@example` в поле поиска
- **Тогда:** Пользователь с email `test@example.com` отображается в результатах

#### AC-1.3: Поиск по имени и фамилии
- **Дано:** В базе есть пользователь с именем `Иван` и фамилией `Петров`
- **Когда:** Пользователь вводит `Иван` или `Петров` в поле поиска
- **Тогда:** Пользователь Иванов Петров отображается в результатах

#### AC-1.4: Поиск без результатов (EC-07)
- **Дано:** В базе нет пользователей, соответствующих запросу
- **Когда:** Пользователь вводит несуществующий запрос в поле поиска
- **Тогда:** Отображается EmptyState с сообщением «Ничего не найдено по указанному запросу»

#### AC-1.5: Очистка поиска
- **Дано:** Активный поисковый запрос отображает отфильтрованный список
- **Когда:** Пользователь очищает поле поиска
- **Тогда:** Список пользователей обновляется до полного (без фильтра)

### FR-REQ-USERS-001-03: Сортировка пользователей

Система должна поддерживать сортировку списка пользователей по полям: email, имя, фамилия, дата регистрации.

#### AC-1.6: Сортировка по клику на заголовок
- **Дано:** Пользователь находится на странице `/dashboard/users`
- **Когда:** Пользователь кликает на заголовок столбца «Имя»
- **Тогда:** Список сортируется по имени по возрастанию (`?sort=firstName&order=asc`)

#### AC-1.7: Повторная сортировка (переключение направления)
- **Дано:** Список отсортирован по имени по возрастанию
- **Когда:** Пользователь повторно кликает на заголовок «Имя»
- **Тогда:** Список пере сортируется по имени по убыванию (`?sort=firstName&order=desc`)

#### AC-1.8: Визуальный индикатор сортировки
- **Дано:** Список отсортирован по полю «Фамилия» по возрастанию
- **Когда:** Отображается таблица
- **Тогда:** В заголовке «Фамилия» виден индикатор направления сортировки (стрелка вверх)

### FR-REQ-USERS-001-04: Пагинация списка

Система должна поддерживать пагинацию списка пользователей с дефолтным limit 25.

#### AC-1.9: Дефолтная пагинация
- **Дано:** В базе более 25 пользователей
- **Когда:** Пользователь открывает страницу `/dashboard/users`
- **Тогда:** Отображается первая страница с 25 записями

#### AC-1.10: Переключение страниц
- **Дано:** Пользователь находится на странице 1 из 3
- **Когда:** Пользователь кликает кнопку «Вперёд»
- **Тогда:** Загружается страница 2 (`?page=2&limit=25`)

#### AC-1.11: Пагинация с поиском
- **Дано:** Поиск отфильтровал список до 50 записей (2 страницы)
- **Когда:** Пользователь переходит на страницу 2
- **Тогда:** Загружается вторая страница отфильтрованных результатов

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-04 | Поиск по полям | Поиск поддерживает фильтрацию по email, firstName, lastName | Backend: ILIKE / WHERE ... OR ... |
| BR-05 | Сортировка по полям | Сортировка поддерживается по: email, firstName, lastName, createdAt | Whitelist допустимых полей на сервере |
| BR-06 | Пагинация | Дефолтный limit = 25, min = 1, max = 100 | Zod-валидация query параметров |

---

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Поиск без результатов (EC-07) | EmptyState с сообщением «Ничего не найдено по указанному запросу» |
| 2 | Пустой поисковый запрос | Список не фильтруется (полный список) |
| 3 | Специальные символы в поиске | Сервер игнорирует специальные символы или экранирует их |
| 4 | Неверный параметр sort | Игнорировать сортировку, использовать дефолтную (createdAt desc) |
| 5 | Page beyond total pages | Вернуть пустой список без ошибки |
| 6 | Медленная сеть (EC-08) | Индикатор загрузки над таблицей |

## Нефункциональные требования

- **Безопасность:** Whitelist полей сортировки на сервере для защиты от SQL-инъекций через ORDER BY.
- **Производительность:** Поиск < 300ms при до 1000 записей. Дебаунс на клиенте ~300ms.
- **Доступность:** Поле поиска имеет ARIA-label «Поиск пользователей». Индикатор сортировки доступен через aria-sort.
- **Локализация:** Все сообщения на русском языке.
