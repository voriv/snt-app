# US-21-21: Удаление сообщения по жалобе

## Формулировка
**Как** модератор,
**я хочу** удалять сообщения, нарушающие правила сообщества, по результатам рассмотрения жалобы,
**чтобы** очищать платформу от нарушающего контента и поддерживать порядок.

## Целевое состояние
Модератор может удалить сообщение из чата, подтвердив жалобу. После удаления сообщение становится недоступно для обычных пользователей, но сохраняется в административной истории для аудита.

### Границы
- Удаление доступно только модераторам с соответствующими правами.
- Удаленные сообщения не удаляются физически из БД (soft delete для аудита).
- Пользователь, отправивший сообщение, получает уведомление об удалении.
- Модератор должен оставить комментарий при удалении сообщения (почему было удалено).

## Функциональные требования

### FR-REQ-COMMS-001-21: Удаление сообщения по жалобе

#### AC-21.1: Удаление сообщения с подтверждением
- **Дано:** Модератор находится на странице деталей жалобы с подтвержденным нарушением.
- **Когда:** Модератор нажимает кнопку "Удалить сообщение", вводит комментарий и подтверждает удаление.
- **Тогда:**
  - Сообщение помечается как удаленное (`is_deleted = true`), но не удаляется физически.
  - Статус жалобы обновляется на "Resolved" (или "Завершено").
  - Модератор получает уведомление "Сообщение удалено".
  - Пользователь, отправивший сообщение, получает уведомление об удалении.

#### AC-21.2: Требуемый комментарий
- **Дано:** Модератор пытается удалить сообщение без комментария.
- **Когда:** Модератор нажимает "Удалить сообщение" без ввода комментария.
- **Тогда:**
  - Система отклоняет операцию.
  - Поле комментария подсвечивается как обязательное.
  - Отображается сообщение "Пожалуйста, укажите причину удаления".

#### AC-21.3: Отмена удаления
- **Дано:** Модератор нажал "Удалить сообщение".
- **Когда:** Модератор нажимает "Отмена" в диалоге подтверждения.
- **Тогда:**
  - Операция отменяется, сообщение остается доступным.
  - Диалог подтверждения закрывается без изменений.

### FR-REQ-COMMS-001-22: Ведение истории удаления
- **Дано:** Сообщение было удалено модератором.
- **Когда:** Модератор или супер-администратор запрашивает информацию об удаленном сообщении.
- **Тогда:**
  - Отображается запись с ID сообщения, датой удаления, ID модератора, причиной удаления.
  - Полный текст сообщения недоступен, только метаданные (или полный текст в админ-панели).

### FR-REQ-COMMS-001-23: Невозможность повторного удаления
- **Дано:** Сообщение уже было удалено.
- **Когда:** Модератор пытается удалить уже удаленное сообщение.
- **Тогда:**
  - Кнопка "Удалить" не отображается или заблокирована.
  - API возвращает ошибку 400 "Сообщение уже удалено".

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-21-01 | Право модератора | Удалять может только модератор/SUPER_ADMIN. | Проверка роли в API. |
| BR-21-02 | Комментарий обязателен | Удаление возможно только с комментарием. | Валидация `comment` как обязательного поля. |
| BR-21-03 | Soft delete | Удаленные сообщения сохраняются для аудита. | Изменение поля `is_deleted`, а не DELETE. |
| BR-21-04 | Уведомление автора | Автор сообщения должен получить уведомление об удалении. | Генерация события/уведомления после удаления. |
| BR-21-05 | Логирование | Все удаления должны быть записаны в историю модерации. | Создание записи в `moderation_actions` с типом `MessageDeleted`. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Попытка удаления сообщения, которое уже удалено | API возвращает 400, UI показывает "Сообщение уже удалено". |
| 2 | Удаление сообщения, которое было создано >30 дней назад | Удаление разрешено, но может быть помечено как "старое сообщение". |
| 3 | Удаление сообщения системным пользователем (бот) | Удаление разрешено, но может потребовать дополнительного подтверждения (опционально). |
| 4 | Удаление сообщения при сетевой ошибке | Операция откатывается, пользователь получает ошибку "Не удалось удалить сообщение". |
| 5 | Одновременное удаление одного сообщения двумя модераторами | Серверная блокировка, второй запрос получает ошибку 409. |
| 6 | Удаление сообщения из группового чата | Удаление выполняется, все участники чата получают уведомление. |

## Модель данных
Добавление поля `is_deleted` в таблицу сообщений и создание записи в `moderation_actions`.

**Обновление таблицы `messages`:**
```prisma
model Message {
  id          String   @id @default(cuid())
  chatId      String   @map("chat_id")
  senderId    String   @map("sender_id")
  content     String   @map("content")
  isDeleted   Boolean  @default(false) @map("is_deleted")
  deletedAt   DateTime? @map("deleted_at")
  deletedBy   String?  @map("deleted_by") // ID модератора
  // ... другие поля
}
```

**Запись в `moderation_actions`:**
```prisma
model ModerationAction {
  id          String   @id @default(cuid())
  reportId    String   @map("report_id")
  moderatorId String   @map("moderator_id")
  actionType  String   // "MessageDeleted"
  comment     String   @map("comment")
  createdAt   DateTime @default(now()) @map("created_at")
}
```

## Нефункциональные требования
- **Производительность:** Удаление сообщения < 200мс.
- **Безопасность:** API-эндпоинт проверяет, что модератор имеет права.
- **Аудит:** Все удаления должны быть логированы с указанием модератора и причины.
- **Доступность:** ConfirmModal имеет фокус на кнопке "Удалить", кнопка удаления имеет aria-label.
