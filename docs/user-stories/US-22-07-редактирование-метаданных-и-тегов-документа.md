# US-22-07: Редактирование метаданных и тегов документа

> Эпик: Управление документами (REQ-DOCS-001)

---

## Формулировка

**Как** администратор СНТ,
**я хочу** редактировать метаданные и теги существующего документа,
**чтобы** поддерживать актуальность информации и классификации документов.

---

## Целевое состояние

После реализации администратор на странице `/dashboard/documents/:id/edit` может редактировать: название, описание, категорию, тип, статус (draft/published/archived), видимость по ролям, теги. Изменения сохраняются атомарно. Архивированный документ (status = archived) недоступен для редактирования (BR-08).

---

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| Document | Основные метаданные | Будет создана |
| DocumentCategory | Категория | Будет создана |

## Поведение (User Behavior)

### B-1: Редактирование метаданных
Администратор открывает карточку документа, нажимает «Редактировать». Заполняет форму с текущими данными. Вносит изменения (например, меняет категорию). Нажимает «Сохранить». Система обновляет запись.

### B-2: Добавление/удаление тегов
Администратор в поле «Теги» добавляет новые теги (ввод текста → Enter) или удаляет существующие (кнопка ×). Система обновляет связи Document ↔ Tag.

### B-3: Изменение видимости по ролям
Администратор изменяет чекбоксы видимости (GUEST, MEMBER, ADMIN). Система обновляет `visibleRoles` в документе.

### B-4: Смена статуса
Администратор меняет статус: draft → published (публикация), published → archived (архивация).

### B-5: Отклонение редактирования архивированного
Администратор пытается открыть архивированный документ на редактирование. Система блокирует действие с сообщением «Архивированные документы недоступны для редактирования».

---

## Критерии приёмки

### AC-1: Успешное редактирование названия
- **Given** документ с названием «Старое»
- **When** администратор меняет название на «Новое» и сохраняет
- **Then** название обновлено; updatedAt изменён

### AC-2: Успешное изменение категории
- **Given** документ в категории «Протоколы»
- **When** администратор меняет категорию на «Договоры»
- **Then** categoryId обновлён

### AC-3: Добавление нового тега
- **Given** документ имеет теги «2024»
- **When** администратор добавляет тег «2025»
- **Then** документ имеет теги «2024», «2025»; новый тег создан в БД, если не существовал

### AC-4: Удаление тега
- **Given** документ имеет теги «2024», «2025»
- **When** администратор удаляет тег «2024»
- **Then** документ имеет тег «2025»; связь удалена (сам тег в БД остаётся, если используется другими)

### AC-5: Изменение видимости по ролям
- **Given** документ виден [ADMIN]
- **When** администратор добавляет MEMBER в видимые роли
- **Then** документ видим [ADMIN, MEMBER]

### AC-6: Архивация документа
- **Given** документ published
- **When** администратор меняет статус на archived
- **Then** статус = archived; документ недоступен для редактирования

### AC-7: Блокировка редактирования архивированного (BR-08)
- **Given** документ archived
- **When** администратор пытается открыть форму редактирования
- **Then** система блокирует с сообщением «Архивированные документы недоступны для редактирования»

### AC-8: Валидация пустого названия
- **Given** форма редактирования
- **When** администратор оставляет название пустым
- **Then** ошибка «Название документа обязательно»

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-04 | Видимость по ролям | DB: JSON array visibleRoles |
| BR-06 | Статусы: draft, published, archived | DB: enum |
| BR-07 | Draft не виден пользователям | Runtime |
| BR-08 | Archived недоступен для редактирования | Runtime: блокировка при status = 'archived' |

### Примеры валидаций
- **Название**: `title: z.string().min(1).max(255)`
- **Тип**: `documentType: z.string().min(1).max(50)`
- **Категория**: `categoryId: z.string().uuid().nullable()`
- **Видимость**: `visibleRoles: z.array(z.enum(['GUEST', 'MEMBER', 'ADMIN'])).min(1)`
- **Теги**: `tags: z.array(z.string().max(50)).max(10)`
- **Статус**: `status: z.enum(['draft', 'published', 'archived'])`

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Редактирование архивированного (EC-05) | Отклонение с сообщением «Архивированные документы недоступны для редактирования» |
| 2 | Несуществующий categoryId | Ошибка «Категория не найдена» |
| 3 | Сохранение без изменений | Обновление updatedAt; нет ошибки |
| 4 | Удаление тега, используемого другими документами | Связь удалена; тег в БД остаётся |
| 5 | Одновременное редактирование двумя админами | Последний сохранённый перезаписывает (optimistic concurrency без версии — допустимо) |
