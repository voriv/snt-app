# US-19-02: Частичное обновление профиля

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** редактировать данные своего профиля (имя, фамилия, отчество, телефон, биография) с частичным обновлением,
**чтобы** актуализировать персональную информацию, указывая только те поля, которые хочу изменить.

---

## Контекст

**Проблема:** Пользователи не могут обновлять данные своего профиля — на странице профиля отображаются данные только для чтения. У пользователя нет возможности изменить имя, фамилию, отчество, телефон или биографию после регистрации.

**Решение:** Реализовать форму частичного обновления профиля на странице `/dashboard/profile`. Форма позволяет редактировать поля профиля (firstName, lastName, middleName, phone, bio) с валидацией в реальном времени. Обновление отправляется через `PATCH /api/v1/profile` — передаются только изменённые поля, пустые значения для имени/фамилии трансформируются в `null`.

**Границы:**
- Включает: форму редактирования текстовых полей профиля (firstName, lastName, middleName, phone, bio), валидацию полей по бизнес-правилам, частичное обновление через PATCH API, состояния загрузки/ошибки/успеха, интеграцию со страницей профиля (US-19-01)
- Исключает: загрузку/удаление аватара (отдельная US-19-03), смену темы оформления (отдельная US-19-04), изменение email (BR-05 — не редактируется через профиль), автоматическое создание профиля (входит в US-19-01), ссылку на профиль в навигации (отдельная US-19-05)

---

## Целевое состояние

После реализации US авторизованный пользователь может на странице `/dashboard/profile` переключиться в режим редактирования, изменить одно или несколько полей (имя, фамилия, отчество, телефон, биография) и сохранить изменения. Система валидирует ввод в реальном времени: имя/фамилия/отчество должны содержать от 2 до 50 символов (если указаны), биография — не более 500 символов. Пустые значения для имени/фамилии сохраняются как `null` (отсутствие значения). При успешном сохранении форма возвращается в режим просмотра с обновлёнными данными. Email не редактируется и остаётся read-only из учётной записи пользователя.

## Поведение (User Behavior)

### B-1: Переход в режим редактирования
Авторизованный пользователь находится на странице `/dashboard/profile` в режиме просмотра. Нажимает кнопку «Редактировать». Страница переключается в режим редактирования: текстовые поля становятся доступными для ввода, появляются кнопки «Сохранить» и «Отмена». Текущие значения полей предзаполняются из загруженного профиля.

### B-2: Ввод и валидация в реальном времени
Пользователь изменяет одно или несколько полей. При вводе система подсвечивает ошибки валидации: имя/фамилия/отчество менее 2 или более 50 символов, биография более 500 символов. Поля с корректными значениями подсвечиваются как валидные. Поля можно очистить — пустое значение трактуется как отсутствие данных (null).

### B-3: Сохранение изменений
Пользователь нажимает «Сохранить». Кнопка блокируется, отображается индикатор загрузки. Система отправляет PATCH-запрос с изменёнными полями. При успехе — форма возвращается в режим просмотра с обновлёнными данными, показывается уведомление об успешном сохранении. При ошибке валидации (400) — подсвечиваются поля с ошибками. При сетевой ошибке — показывается уведомление с возможностью повтора.

### B-4: Отмена редактирования
Пользователь нажимает «Отмена». Если есть несохранённые изменения — система запрашивает подтверждение. При подтверждении форма возвращается в режим просмотра с исходными значениями. При отмене — остаётся в режиме редактирования.

### B-5: Попытка редактирования email
Поле email всегда отображается как read-only в форме редактирования. Пользователь не может изменить email через профиль — это делается через отдельную процедуру (BR-05).

## Критерии приёмки

### AC-2.1: Успешное частичное обновление профиля
- **Given** авторизованный пользователь с существующим профилем находится на странице `/dashboard/profile` в режиме редактирования
- **When** пользователь заполняет одно или несколько полей (например, firstName и phone) корректными значениями и нажимает «Сохранить»
- **Then** данные сохраняются через PATCH `/api/v1/profile`, форма возвращается в режим просмотра с обновлёнными значениями, показывается уведомление об успехе

### AC-2.2: Пустое имя/фамилия сохраняется как null
- **Given** пользователь находится в режиме редактирования и очищает поле «Имя» или «Фамилия»
- **When** пользователь нажимает «Сохранить»
- **Then** система отправляет пустое значение, которое трансформируется в `null` (BR-04), профиль обновляется, в режиме просмотра поле отображается как пустое/прочерк

### AC-2.3: Ошибка валидации — имя/фамилия менее 2 символов
- **Given** пользователь находится в режиме редактирования
- **When** вводит в поле «Имя» или «Фамилия» значение из 1 символа и нажимает «Сохранить»
- **Then** показывается ошибка валидации «Имя должно содержать минимум 2 символа», запрос не отправляется, форма остаётся в режиме редактирования

### AC-2.4: Ошибка валидации — имя/фамилия более 50 символов
- **Given** пользователь находится в режиме редактирования
- **When** вводит в поле «Имя» или «Фамилия» значение длиннее 50 символов и нажимает «Сохранить»
- **Then** показывается ошибка валидации «Имя не может превышать 50 символов», запрос не отправляется, форма остаётся в режиме редактирования

### AC-2.5: Email не редактируется
- **Given** пользователь находится в режиме редактирования профиля
- **When** просматривает форму
- **Then** поле email отображается как read-only (disabled), недоступно для изменения (BR-05)

### AC-2.6: Валидация биографии — не более 500 символов
- **Given** пользователь находится в режиме редактирования
- **When** вводит в поле «Биография» текст длиннее 500 символов и нажимает «Сохранить»
- **Then** показывается ошибка валидации «Биография не может превышать 500 символов», запрос не отправляется

### AC-2.7: Блокировка кнопки при сохранении
- **Given** пользователь нажал «Сохранить» и запрос отправляется
- **When** ожидается ответ сервера
- **Then** кнопка «Сохранить» заблокирована (disabled), отображается индикатор загрузки, повторные нажатия игнорируются

### AC-2.8: Отмена редактирования с подтверждением
- **Given** пользователь изменил одно или несколько полей в режиме редактирования
- **When** нажимает «Отмена»
- **Then** система запрашивает подтверждение через ConfirmModal; при подтверждении форма возвращается к исходным значениям в режиме просмотра

### AC-2.9: Обработка серверной ошибки валидации (400)
- **Given** пользователь отправил форму с данными, прошедшими клиентскую валидацию
- **When** сервер возвращает 400 с ошибками валидации
- **Then** поля с ошибками подсвечиваются, показываются серверные сообщения об ошибках

### AC-2.10: Обработка сетевой ошибки
- **Given** пользователь нажал «Сохранить»
- **When** запрос завершился сетевой ошибкой (таймаут, отсутствие соединения)
- **Then** показывается уведомление об ошибке с возможностью повтора, форма остаётся в режиме редактирования с введёнными данными

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-02 | Все поля профиля опциональны при частичном обновлении | Можно обновить только указанные поля; отсутствующие поля не затрагиваются | Zod: все поля `optional` в `userProfileUpdateSchema` |
| BR-03 | Имя/фамилия 2-50 символов, если указаны | Поля могут быть пустыми, но при наличии значения — от 2 до 50 символов | Zod: `optionalString({ description })` — min 2, max 50 |
| BR-04 | Пустое значение → null | Пустая строка для имени/фамилии/отчества/телефона/биографии трансформируется в `null` | Zod: `transform(val => val === '' ? null : val)` в `optionalString` |
| BR-05 | Email не редактируется через профиль | Email берётся из учётной записи User, поле недоступно для редактирования в форме профиля | UI: поле `email` — `disabled` / `readOnly` |

### Примеры валидаций
- **Имя (firstName):** опциональное, 2-50 символов, пустая строка → `null`. Сообщения: «Имя должно содержать минимум 2 символа», «Имя не может превышать 50 символов»
- **Фамилия (lastName):** опциональное, 2-50 символов, пустая строка → `null`. Сообщения: «Фамилия должна содержать минимум 2 символа», «Фамилия не может превышать 50 символов»
- **Отчество (middleName):** опциональное, 2-50 символов, пустая строка → `null`
- **Телефон (phone):** опциональный, формат E.164 или национальный, пустая строка → `null`
- **Биография (bio):** опциональная, max 500 символов, пустая строка → `null`. Сообщение: «Биография не может превышать 500 символов»
- **Email:** не входит в тело запроса, отображается только для чтения

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пустая форма — ни одно поле не изменено | Кнопка «Сохранить» заблокирована или запрос не отправляется; пользователь может нажать «Отмена» без подтверждения (нет изменений) |
| 2 | Параллельное обновление профиля с нескольких устройств | Побеждает последнее сохранение (last-write-wins); обновлённая страница отражает данные последнего успешного сохранения |
| 3 | Сетевая ошибка при сохранении | Показывается уведомление об ошибке сети; форма остаётся в режиме редактирования с введёнными данными; кнопка «Сохранить» снова активна |
| 4 | 409 Конфликт — данные на сервере отличаются от ожидаемых | Показывается уведомление о конфликте; рекомендуется перезагрузить профиль перед повторным сохранением |
| 5 | Таймаут сервера при сохранении (более 3 секунд) | Индикатор загрузки продолжает отображаться; при ошибке — уведомление с возможностью повтора |
| 6 | Сессия истекла во время сохранения | API возвращает 401; пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)` |
| 7 | Профиль не существует при попытке обновления | Сервер возвращает 404 `USER_PROFILE_NOT_FOUND`; показывается уведомление; рекомендуется перезагрузить страницу для автоматического создания профиля (US-19-01) |
| 8 | Пользователь деактивирован | Профиль доступен только для просмотра; форма редактирования недоступна |
| 9 | Ввод только пробелов в поле имени | Пробельные символы обрезаются (trim); если после trim значение пустое — сохраняется как `null`; если менее 2 символов — ошибка валидации |
| 10 | Серверная валидация отклоняет данные, прошедшие клиентскую | Поля с ошибками подсвечиваются серверными сообщениями; форма остаётся в режиме редактирования |

## Нефункциональные требования

- **Производительность:** Обновление профиля < 500ms; валидация в реальном времени не блокирует ввод
- **Безопасность:** Все операции требуют авторизации; валидация на сервере через Zod; защита от XSS при отображении биографии; профиль доступен только владельцу
- **UX:** Состояние загрузки (индикатор на кнопке «Сохранить»), валидация в реальном времени (подсветка ошибок при вводе), блокировка повторных отправок, адаптивная вёрстка (мобильные и десктоп)
- **Доступность:** Семантическая разметка формы, ARIA-метки для полей и ошибок, навигация с клавиатуры (Tab/Shift+Tab), focus-ring, контрастность по WCAG 2.1
- **Локализация:** Все подписи полей, сообщения валидации и уведомления на русском языке
