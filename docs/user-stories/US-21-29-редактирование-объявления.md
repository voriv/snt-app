# US-21-29: Редактирование объявления

## Формулировка
**Как** Модератор СНТ,
**я хочу** редактировать существующие объявления,
**чтобы** обновлять информацию при необходимости или исправлять ошибки.

## Целевое состояние
После реализации модератор сможет:
- Открыть существующее объявление для редактирования.
- Изменить заголовок, содержание, категорию объявления.
- Сохранить изменения в черновике или сразу опубликовать/опубликовать изменения.
- Увидеть обновлённое объявление в списке.

## Границы
- **Входит:** Редактирование заголовка, содержания, категории, статуса объявления.
- **Не входит:** Создание объявлений (это US-21-28), удаление объявлений (это US-21-33).

## Функциональные требования
- **FR-REQ-COMMS-019-01:** Система должна предоставлять форму для редактирования существующего объявления.
- **FR-REQ-COMMS-019-02:** Система должна заполнять форму текущими значениями редактируемого объявления.
- **FR-REQ-COMMS-019-03:** Система должна позволять изменять заголовок, содержание, категорию.
- **FR-REQ-COMMS-019-04:** Система должна позволять изменить статус публикации.
- **FR-REQ-COMMS-019-05:** Система должна автоматически обновлять короткое содержание при изменении заголовка/содержания.

## Бизнес-правила
- **BR-01:** Только пользователи с ролью ADMIN или SUPER_ADMIN могут редактировать объявления.
- **BR-02:** Авторов объявления могут редактировать только своё объявление (опционально, для SUPER_ADMIN).
- **BR-03:** Изменение статусаPublished → draft не скрывает объявление из списка немедленно.
- **BR-04:** Изменение заголовка должно быть уникальным среди черновиков одного автора.
- **BR-05:** При сохранении объявления обновляется поле `updated_at`.

## Валидации
- Валидация заголовка: 2-200 символов, обязательно.
- Валидация содержания: минимум 1 символ, обязательно.
- Валидация выбора категории: если выбрана, должна существовать.
- Валидация уникальности заголовка для черновиков автора (исключая текущее объявление).

## Граничные случаи (Edge Cases)
- **EC-01:** Объявление не найдено → Показывается сообщение "Объявление не найдено".
- **EC-02:** Нет прав на редактирование → Показывается ошибка доступа.
- **EC-03:** Пустой заголовок → Ошибка валидации "Заголовок обязателен".
- **EC-04:** Дубликат заголовка среди черновиков → Ошибка валидации "Объявление с таким заголовком уже существует".
- **EC-05:** Объяление опубликовано и редактируется → Уведомление о том, что изменения будут применены к опубликованному объявлению.
- **EC-06:** Ошибка сохранения → Показывается уведомление об ошибке, данные не применяются.

## Модель данных
**Таблица `announcements` (Объявления):**
- Поле `title` — обновление.
- Поле `content` — обновление.
- Поле `short_content` — обновление (автогенерация).
- Поле `category_id` — обновление.
- Поле `status` — обновление.
- Поле `updated_at` — обновление на `NOW()`.

## Влияние на архитектуру

### Types
- Тип `EditAnnouncementRequest`: `{ title?: string, content?: string, categoryId?: string, status?: 'draft' | 'published' }`
- Тип `AnnouncementResponse`: полный объект объявления.

### Validators (Zod)
- Схема валидации `editAnnouncementSchema`:
  - `title`: `z.string().min(2).max(200).optional()`
  - `content`: `z.string().min(1).optional()`
  - `categoryId`: `z.string().uuid().optional().nullable()`
  - `status`: `z.enum(['draft', 'published']).optional()`

### Errors
- `AnnouncementAccessDeniedError` (наследуется от `ForbiddenError`).
- `AnnouncementNotFoundError` (наследуется от `NotFoundError`).
- `AnnouncementValidation` (наследуется от `ValidationError`).
- `AnnouncementDuplicateError` (наследуется от `ConflictError`).

### Repository
- Методы:
  - `updateAnnouncement(id: string, data: EditAnnouncementData): Promise<Announcement>`
  - `titleExists(authorId: string, title: string, excludeId: string): Promise<boolean>`

### Service
- Логика:
  - Проверка прав доступа.
  - Проверка существования объявления.
  - Проверка уникальности заголовка (исключая текущее).
  - Генерация короткого содержания.
  - Обновление объявления.

### DI Container
- Регистрация `IAnnouncementRepository` и `AnnouncementService`.

### API
- **PATCH** `/api/v1/announcements/:id`
  - Тело: `{ "title": "..." | null, "content": "..." | null, "categoryId": "uuid" | null, "status": "draft" | "published" | null }`
  - Ответ 200: `{ success: true, data: AnnouncementResponse }`
  - Ответ 403: `{ success: false, error: { code: "ACCESS_DENIED" } }`
  - Ответ 404: `{ success: false, error: { code: "ANNOUNCEMENT_NOT_FOUND" } }`
  - Ответ 400: `{ success: false, error: { code: "VALIDATION_ERROR" } }`
  - Ответ 409: `{ success: false, error: { code: "DUPLICATE_TITLE" } }`

### UI
- Компонент `EditAnnouncementForm` (форма редактирования).
- Компонент `AnnouncementTitleInput` (поле заголовка).
- Компонент `AnnouncementContentEditor` (редактор содержания).
- Компонент `AnnouncementCategorySelector` (выбор категории).
- Компонент `AnnouncementStatusSwitch` (переключатель черновик/публикация).
- Компонент `Notification` (уведомление об успехе/ошибке).

### Pages
- Страница `/dashboard/announcements/:id/edit` (страница редактирования).
- Или интегрировано в страницу деталей объявления.

## Нефункциональные требования
- **Производительность:** Обновление объявления менее 500 мс.
- **Безопасность:** Проверка прав доступа (ADMIN/SUPER_ADMIN).
- **Юзабилити:** Понятная форма, валидация в реальном времени, предпросмотр изменений.
