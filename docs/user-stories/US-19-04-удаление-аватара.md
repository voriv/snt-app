# US-19-04: Удаление аватара

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** удалить свой аватар и сбросить его к значению по умолчанию,
**чтобы** убрать ранее загруженное изображение, если оно больше неактуально.

---

## Контекст

**Проблема:** Пользователи, загрузившие аватар, не могут его удалить — поле `avatar` остаётся заполненным, нет UI-кнопки для удаления. Пользователь не может вернуться к дефолтному аватару без замены на новое изображение.

**Решение:** Реализовать кнопку «Удалить аватар» на странице `/dashboard/profile` (рядом с компонентом загрузки из US-19-03). Удаление выполняется через `DELETE /api/v1/profile/avatar`. Перед удалением показывается `ConfirmModal` для подтверждения (необратимая операция). После успешного удаления аватар сбрасывается к дефолту в UI.

**Границы:**
- Включает: кнопку «Удалить аватар» (видна только если аватар загружен), подтверждение через `ConfirmModal`, вызов `apiClient.delete('/profile/avatar')`, обработку состояний загрузки/ошибки/успеха, обновление аватара в UI после удаления, интеграцию со страницей профиля (US-19-01) и компонентом загрузки (US-19-03)
- Исключает: загрузку аватара (отдельная US-19-03), редактирование других полей профиля (US-19-02), смену темы оформления (US-19-05)

---

## Целевое состояние

После реализации US авторизованный пользователь, у которого загружен аватар, может на странице `/dashboard/profile` нажать кнопку «Удалить аватар». Открывается `ConfirmModal` с предупреждением о необратимости. При подтверждении аватар удаляется через `DELETE /api/v1/profile/avatar`, в UI отображается дефолтный аватар. Если аватар не загружен — кнопка «Удалить» скрыта. При ошибке показывается уведомление, аватар остаётся без изменений.

## Поведение (User Behavior)

### B-1: Удаление аватара с подтверждением
Пользователь находится на странице `/dashboard/profile`, у него загружен аватар (поле `avatar` не null). Пользователь нажимает кнопку «Удалить аватар». Открывается `ConfirmModal` с текстом «Удалить аватар? Действие необратимо — для восстановления потребуется загрузить новое изображение». Кнопка подтверждения заблокирована во время запроса.

### B-2: Подтверждение удаления
Пользователь подтверждает удаление в `ConfirmModal`. Система отправляет `DELETE /api/v1/profile/avatar`. Кнопка блокируется, отображается индикатор загрузки. При успехе — аватар сбрасывается к дефолту в UI, `ConfirmModal` закрывается, показывается уведомление об успехе. При ошибке — показывается уведомление с описанием ошибки, аватар остаётся, `ConfirmModal` остаётся открытой.

### B-3: Отмена удаления
Пользователь нажимает «Отмена» в `ConfirmModal` или закрывает её. Удаление не выполняется, аватар остаётся без изменений, `ConfirmModal` закрывается.

### B-4: Нет аватара — кнопка скрыта
Если у пользователя нет аватара (поле `avatar` = null), кнопка «Удалить аватар» не отображается (или disabled).

## Критерии приёмки

### AC-4.1: Открытие ConfirmModal при удалении
- **Given** авторизованный пользователь с загруженным аватаром (avatar ≠ null) находится на странице `/dashboard/profile`
- **When** пользователь нажимает кнопку «Удалить аватар»
- **Then** открывается `ConfirmModal` с предупреждением о необратимости удаления

### AC-4.2: Успешное удаление аватара
- **Given** пользователь подтвердил удаление в `ConfirmModal`
- **When** запрос `DELETE /api/v1/profile/avatar` выполнен успешно
- **Then** аватар сбрасывается к дефолту в UI (без перезагрузки страницы), `ConfirmModal` закрывается, показывается уведомление об успехе

### AC-4.3: Нет аватара — кнопка скрыта
- **Given** у пользователя нет аватара (avatar = null)
- **When** пользователь видит страницу профиля
- **Then** кнопка «Удалить аватар» скрыта или отключена (disabled)

### AC-4.4: Отмена удаления через ConfirmModal
- **Given** открыт `ConfirmModal` подтверждения удаления
- **When** пользователь нажимает «Отмена» или закрывает модальное окно
- **Then** удаление не выполняется, аватар остаётся без изменений, `ConfirmModal` закрывается

### AC-4.5: Блокировка UI при удалении
- **Given** пользователь подтвердил удаление и запрос отправляется
- **When** ожидается ответ сервера
- **Then** кнопка подтверждения в `ConfirmModal` заблокирована (disabled), отображается индикатор загрузки, повторные нажатия игнорируются

### AC-4.6: Обработка сетевой ошибки
- **Given** пользователь подтвердил удаление
- **When** запрос завершился сетевой ошибкой (таймаут, отсутствие соединения)
- **Then** показывается уведомление об ошибке сети, аватар остаётся без изменений, `ConfirmModal` остаётся открытой, кнопка подтверждения снова активна

### AC-4.7: Сессия истекла во время удаления
- **Given** пользователь подтвердил удаление
- **When** сервер возвращает 401 (сессия истекла)
- **Then** пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)`

### AC-4.8: Серверная ошибка при удалении (500)
- **Given** пользователь подтвердил удаление
- **When** сервер возвращает 500
- **Then** показывается уведомление об ошибке сервера, аватар остаётся без изменений, `ConfirmModal` остаётся открытой

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-04 | Удаление аватара необратимо | После удаления аватар сбрасывается к дефолту (null); восстановление невозможно без новой загрузки (US-19-03) | UI: подтверждение через `ConfirmModal`; Service: `deleteAvatar()` устанавливает `avatar = null` |
| — | Кнопка удаления видна только при наличии аватара | Если `avatar` = null — кнопка скрыта/disabled | UI: условный рендеринг по `profile.avatar !== null` |

### Примеры валидаций
- **Подтверждение удаления:** обязательно через `ConfirmModal` (запрещён `window.confirm` согласно правилам проекта); текст предупреждения о необратимости
- **Проверка наличия аватара:** перед удалением сервер проверяет, что `avatar` не null; если уже null — операция идемпотентна (возвращает успех)

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Нет аватара (avatar = null) | Кнопка «Удалить» скрыта или disabled; пользователь не может инициировать удаление |
| 2 | Сетевая ошибка при удалении | Показывается уведомление об ошибке сети; аватар остаётся; `ConfirmModal` остаётся открытой; кнопка снова активна; возможен повтор |
| 3 | Таймаут сервера при удалении (более 3 секунд) | Индикатор загрузки продолжает отображаться; при ошибке — уведомление с возможностью повтора |
| 4 | Отмена удаления через ConfirmModal | Удаление не выполняется; аватар остаётся без изменений; `ConfirmModal` закрывается |
| 5 | Серверная ошибка (500) | Показывается уведомление об ошибке сервера; аватар остаётся; `ConfirmModal` остаётся открытой |
| 6 | Сессия истекла во время удаления | API возвращает 401; пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)` |
| 7 | Профиль не существует при удалении | Сервер возвращает 404 `USER_PROFILE_NOT_FOUND`; показывается уведомление; рекомендуется перезагрузить страницу (US-19-01 автосоздание) |
| 8 | Идемпотентность — повторное удаление уже null аватара | Сервер возвращает успех (200) с `avatarUrl: null`; UI уже показывает дефолтный аватар |
| 9 | Пользователь деактивирован | Профиль доступен только для просмотра; кнопка удаления недоступна |
| 10 | Параллельное удаление с нескольких устройств | Побеждает последнее; оба устройства обновляют UI после ответа сервера |

## Нефункциональные требования

- **Производительность:** Удаление аватара <500 ms; индикатор загрузки на кнопке подтверждения
- **Безопасность:** Все операции требуют авторизации; удаление только владельцем профиля; сервер проверяет сессию
- **UX:** Подтверждение через `ConfirmModal` (необратимая операция); индикатор загрузки; блокировка повторных отправок; уведомление об успехе/ошибке; адаптивная вёрстка
- **Доступность:** `ConfirmModal` доступен с клавиатуры (Tab, Enter, Esc); ARIA-метки для кнопки удаления; focus-ring; контрастность по WCAG 2.1
- **Локализация:** Все тексты `ConfirmModal`, уведомления и сообщения об ошибках на русском языке
