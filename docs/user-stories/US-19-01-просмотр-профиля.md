# US-19-01: Просмотр профиля пользователя

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** просмотреть свой профиль на отдельной странице,
**чтобы** видеть актуальную персональную информацию о себе: имя, фамилию, отчество, email, телефон, аватар, биографию и дату регистрации.

---

## Контекст

**Проблема:** Пользователи не могут просматривать свой профиль — данные профиля не отображаются ни на одной странице приложения. У пользователя нет возможности убедиться, что его персональные данные актуальны.

**Решение:** Реализовать страницу профиля `/dashboard/profile`, на которой отображается вся доступная информация о пользователе. При первом обращении, если профиль не существует, он создаётся автоматически.

**Границы:**
- Включает: отображение профиля (только чтение), автоматическое создание профиля при первом обращении, перенаправление неавторизованных пользователей
- Исключает: редактирование профиля (отдельная US), загрузку/удаление аватара (отдельная US), смену темы оформления (отдельная US), ссылку на профиль в навигации (отдельная US)

---

## Целевое состояние

После реализации US авторизованный пользователь может открыть страницу `/dashboard/profile` и увидеть все поля своего профиля. Если профиль ещё не создан в БД, система автоматически создаёт его при первом обращении и отображает пустые/дефолтные значения. Неавторизованный пользователь при попытке доступа перенаправляется на `/login`.

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| UserProfile | Профиль пользователя: имя, фамилия, отчество, телефон, аватар, биография, тема оформления, дата создания | `docs/model/entities/user-profile.md` |
| User | Учётная запись пользователя: email, дата регистрации | `docs/model/entities/user.md` |

## Поведение (User Behavior)

### B-1: Открытие страницы профиля
Авторизованный пользователь открывает `/dashboard/profile`. Система проверяет наличие сессии, загружает профиль через API. Если профиль существует — отображает все поля. Если профиль не найден — автоматически создаёт пустой профиль и отображает его с дефолтными значениями.

### B-2: Доступ неавторизованного пользователя
Неавторизованный пользователь (без сессии) пытается открыть `/dashboard/profile`. Система перенаправляет его на страницу `/login` с задержкой перед редиректом.

### B-3: Ошибка загрузки
При сетевой ошибке или ошибке сервера при загрузке профиля пользователю показывается сообщение об ошибке с возможностью повторить запрос.

---

## Критерии приёмки

### AC-1: Отображение профиля авторизованным пользователем
- **Given** пользователь авторизован и профиль существует в БД
- **When** пользователь открывает `/dashboard/profile`
- **Then** отображается вся информация профиля: имя, фамилия, отчество, email, телефон, аватар, биография, дата регистрации

### AC-2: Перенаправление неавторизованного пользователя
- **Given** пользователь не авторизован (нет сессии)
- **When** пользователь открывает `/dashboard/profile`
- **Then** пользователь перенаправляется на `/login` (через `router.replace` с задержкой)

### AC-3: Автоматическое создание профиля при первом обращении
- **Given** пользователь авторизован, но профиль не существует в БД
- **When** пользователь открывает `/dashboard/profile`
- **Then** система автоматически создаёт профиль и отображает страницу с дефолтными/пустыми значениями полей

### AC-4: Отображение email из учётной записи
- **Given** пользователь авторизован и открыл страницу профиля
- **When** профиль загружен
- **Then** email отображается из учётной записи пользователя (не из профиля), поле недоступно для редактирования

### AC-5: Состояние загрузки
- **Given** пользователь открыл страницу профиля
- **When** данные загружаются
- **Then** отображается индикатор загрузки до получения ответа API

### AC-6: Обработка сетевой ошибки
- **Given** пользователь открыл страницу профиля
- **When** запрос к API завершился сетевой ошибкой (таймаут, отсутствие соединения)
- **Then** показывается сообщение об ошибке загрузки с возможностью повторить запрос

### AC-7: Медленная сеть
- **Given** пользователь открыл страницу профиля
- **When** загрузка длится более 3 секунд
- **Then** продолжает отображаться индикатор загрузки

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-01 | Профиль доступен только авторизованным пользователям | Доступ к странице и API профиля требует активной сессии | Проверка `useSession()` на клиенте, `auth()` на сервере |
| BR-05 | Email берётся из учётной записи пользователя и не редактируется через профиль | Email отображается как read-only из данных аутентификации | Поле email не входит в форму редактирования |
| BR-08 | Профиль автоматически создаётся при первом обращении, если не существует | При GET-запросе, если профиль не найден, создаётся новый профиль с дефолтными значениями | Сервис: `getOrCreateProfile(userId)` |

### Примеры валидаций
- **Авторизация:** отсутствие сессии → редирект на `/login` через `setTimeout(() => router.replace('/login'), 100)`
- **Автоматическое создание:** вызов `userProfileService.getOrCreateByUserId(userId)` вместо `findByUserId`

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Профиль не существует при первом обращении | Профиль создаётся автоматически, отображается с пустыми/дефолтными значениями |
| 2 | Сетевая ошибка при загрузке профиля | Показывается сообщение "Ошибка загрузки данных" с кнопкой повтора |
| 3 | Таймаут запроса (более 3 секунд) | Продолжает отображаться индикатор загрузки; при ошибке — сообщение об ошибке |
| 4 | Сессия истекла во время загрузки | API возвращает 401, пользователь перенаправляется на `/login` |
| 5 | Пользователь деактивирован | Профиль доступен только для просмотра (без редактирования) |
| 6 | Профиль не найден после автоматического создания (состояние гонки) | Повторная попытка создания; если неуспешно — сообщение об ошибке |
| 7 | Пустые поля профиля (имя, фамилия, отчество не заполнены) | Поля отображаются как пустые/прочерк; email всегда отображается |

## Нефункциональные требования

- **Производительность:** Загрузка профиля < 300ms; автоматическое создание профиля не должно заметно задерживать отображение
- **Безопасность:** Все операции требуют авторизации; профиль доступен только владельцу; защита от XSS при отображении биографии
- **UX:** Состояние загрузки (индикатор), обработка ошибок с возможностью повтора, адаптивная вёрстка (мобильные и десктоп)
- **Доступность:** Семантическая разметка, ARIA-метки, навигация с клавиатуры, контрастность по WCAG 2.1
- **Локализация:** Все сообщения и подписи полей на русском языке
