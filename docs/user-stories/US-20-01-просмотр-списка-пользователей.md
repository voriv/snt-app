# US-20-01: Просмотр списка пользователей

> Эпик: Управление пользователями (REQ-USERS-001)

---

## Формулировка

**Как** Супер-администратор (SUPER_ADMIN),
**я хочу** просматривать список всех зарегистрированных пользователей в табличном виде,
**чтобы** иметь централизованный обзор всех участников системы.

---

## Целевое состояние

После реализации US-20-01 администратор с ролью SUPER_ADMIN сможет открыть страницу `/dashboard/users` и увидеть таблицу всех пользователей со столбцами: email, имя, фамилия, роли, дата регистрации. Пользователи без роли SUPER_ADMIN при попытке доступа получат ошибку 403 (Forbidden).

---

## Контекст

### Проблема
На данный момент в системе отсутствует единая страница со списком всех пользователей. Администратор не может получить обзор зарегистрированных пользователей, их профилей и назначенных ролей.

### Решение
Создать страницу `/dashboard/users` с таблицей пользователей, защищённую ролью SUPER_ADMIN. Данные будут загружаться из нового API `GET /api/v1/users`, который агрегирует информацию из таблиц `users`, `user_profiles` и `user_roles`.

### Границы
- **Входит в US:** Отображение списка пользователей, проверка роли SUPER_ADMIN, базовая пагинация, пустое состояние.
- **Явно исключено:** Поиск и сортировка (US-20-02), карточка пользователя (US-20-03), связи с участками (US-20-04), редактирование/удаление пользователей.

---

## Функциональные требования

### FR-REQ-USERS-001-01: Отображение списка пользователей

Система должна отображать список всех пользователей в табличном виде на странице `/dashboard/users`.

#### AC-1.1: Загрузка списка пользователей
- **Дано:** Пользователь авторизован с ролью SUPER_ADMIN
- **Когда:** Пользователь открывает страницу `/dashboard/users`
- **Тогда:** Система загружает список пользователей через `GET /api/v1/users` и отображает их в таблице

#### AC-1.2: Структура таблицы
- **Дано:** Список пользователей успешно загружен
- **Когда:** Таблица рендерится
- **Тогда:** Таблица содержит столбцы: email, имя, фамилия, роли, дата регистрации

#### AC-1.3: Отображение ролей
- **Дано:** У пользователя назначены роли
- **Когда:** Рендерится строка пользователя
- **Тогда:** Роли отображаются как список бейджей в столбце «Роли»

#### AC-1.4: Доступ заблокирован для не-администраторов
- **Дано:** Пользователь авторизован, но не имеет роли SUPER_ADMIN
- **Когда:** Пользователь пытается открыть `/dashboard/users`
- **Тогда:** Система возвращает ошибку 403 (Forbidden) с сообщением «Доступ запрещен»

### FR-REQ-USERS-001-08: Блокировка доступа

Система должна блокировать доступ к управлению пользователями для пользователей без роли SUPER_ADMIN.

#### AC-1.5: Блокировка на уровне API
- **Дано:** Пользователь не имеет роли SUPER_ADMIN
- **Когда:** Пользователь отправляет запрос `GET /api/v1/users`
- **Тогда:** API возвращает статус 403 с сообщением «Доступ запрещен»

#### AC-1.6: Блокировка на уровне страницы
- **Дано:** Пользователь не имеет роли SUPER_ADMIN
- **Когда:** Пользователь пытается перейти на `/dashboard/users`
- **Тогда:** Страница отображает сообщение об отсутствии доступа или редиректит на `/dashboard`

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Список пользователей пуст (EC-01) | Отображается EmptyState с сообщением «Пользователи не найдены» |
| 2 | Пользователь без роли SUPER_ADMIN (EC-06) | Возврат 403 Forbidden с сообщением «Доступ запрещен» |
| 3 | У пользователя нет профиля | Отображаются пустые значения в столбцах имя/фамилия |
| 4 | У пользователя нет ролей | Столбец «Роли» пустой или содержит прочерк |
| 5 | Медленная сеть (EC-08) | Отображается индикатор загрузки и сообщение «Загрузка данных...» |

## Нефункциональные требования

- **Безопасность:** Доступ к `/dashboard/users` и `GET /api/v1/users` требует роли SUPER_ADMIN. При 403 — клиентское сообщение «Доступ запрещен».
- **Производительность:** Загрузка списка пользователей: < 500ms при до 1000 записей.
- **Доступность:** Таблица доступна с клавиатуры (tab-навигация). Элементы управления имеют ARIA-метки.
- **Локализация:** Все сообщения на русском языке.
- **Адаптивность:** Таблица корректно отображается на мобильных устройствах.
