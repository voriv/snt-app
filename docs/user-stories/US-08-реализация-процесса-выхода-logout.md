# US-08: Реализация процесса выхода (Logout)

## 1. Контекст

### Проблема
В текущей реализации системы отсутствует механизм выхода из аккаунта. Пользователи не могут завершить сеанс работы с приложением, что создаёт риски безопасности при совместном использовании устройства.

### Решение
Реализовать полный процесс выхода (logout) с:
- Удалением сессии на сервере (invalidation)
- Очисткой клиентских токенов
- Перенаправлением на страницу входа
- Возвратом к странице, с которой был начат вход (если применимо)

### Границы
**Входит в область:**
- Кнопка выхода в интерфейсе (Navbar)
- API endpoint для завершения сессии
- Перенаправление после выхода

**Исключено:**
- Авто-выход по таймауту (это US-09 или US-11)
- Выход со всех устройств (logout all devices) — это продвинутая функциональность
- Детали реализации механизма сессий (next-auth internal)

---

## 2. Пользовательская история

**Как** Авторизованный пользователь,
**я хочу** иметь возможность выйти из системы,
**чтобы** закрыть свой сеанс и защитить свой аккаунт при совместном использовании устройства.

---

## 3. Функциональные требования

### FR-REQ-AUTH-008-01: Кнопка выхода в интерфейсе

Система должна отображать кнопку "Выйти" в навигационной панели для авторизованных пользователей.

#### AC-8.1.1: Отображение кнопки
- **Дано:** Пользователь авторизован и находится на странице дашборда
- **Когда:** Навигационная панель отрисовывается
- **Тогда:** Кнопка "Выйти" отображается в Navbar
- **И:** Кнопка имеет понятный текст "Выйти" или иконку выхода

#### AC-8.1.2: Поведение при нажатии
- **Дано:** Пользователь авторизован и видит кнопку "Выйти"
- **Когда:** Пользователь нажимает кнопку "Выйти"
- **Тогда:** Сессия пользователя удаляется
- **И:** Пользователь перенаправляется на страницу входа (/login)
- **И:** Сообщение об успехе отображается (опционально)

---

### FR-REQ-AUTH-008-02: API endpoint для завершения сессии

Система должна предоставлять API endpoint для удаления сессии пользователя.

#### AC-8.2.1: Удаление сессии
- **Дано:** Пользователь имеет активную сессии
- **Когда:** Отправлен POST запрос на /api/v1/auth/logout
- **Тогда:** Сессия пользователя удаляется на сервере
- **И:** Возвращается статус 200 OK

#### AC-8.2.2: Ответ API
- **Дано:** Запрос отправлен авторизованным пользователем
- **Когда:** Сессия успешно удалена
- **Тогда:** Возвращается JSON с { success: true }
- **И:** Статус код 200 OK

#### AC-8.2.3: Запрос от неавторизованного пользователя
- **Дано:** Пользователь не имеет активной сессии
- **Когда:** Отправлен POST запрос на /api/v1/auth/logout
- **Тогда:** Возвращается статус 200 OK (безопасный но-оп)
- **И:** Возвращается JSON с { success: true }

---

### FR-REQ-AUTH-008-03: Перенаправление после выхода

Система должна корректно перенаправлять пользователя после завершения сессии.

#### AC-8.3.1: Редирект на страницу входа
- **Дано:** Пользователь успешно вышел из системы
- **Когда:** Сессия удалена
- **Тогда:** Пользователь перенаправляется на страницу /login
- **И:** URL содержит callbackUrl, если это требуется

#### AC-8.3.2: Возврат на предыдущую страницу
- **Дано:** Пользователь нажал "Выйти" со страницы дашборда
- **Когда:** Сессия удалена
- **Тогда:** Пользователь перенаправляется на страницу /login
- **И:** callbackUrl не используется при выходе

## 4. Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-08-01 | Выход доступен только авторизованным | Кнопка "Выйти" отображается только когда пользователь авторизован | UI-условие: отображать только при session.status === 'authenticated' |
| BR-08-02 | Выход безопасен для неавторизованных | Запрос на выход от неавторизованного пользователя не должен вызывать ошибки | API возвращает 200 OK даже без сессии |
| BR-08-03 | Нет сообщения об ошибке при выходе | Процесс выхода не должен генерировать сообщения об ошибках при нормальных условиях | Всегда возвращать success: true |
| BR-08-04 | Перенаправление всегда на /login | После выхода пользователь всегда переходит на страницу входа, callbackUrl не сохраняется | URL редиректа всегда /login |

---

## 5. Исключения и Граничные кейсы (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пользователь нажал "Выйти" с уже истёкшей сессией | Возвращается 200 OK, перенаправление на /login |
| 2 | Пользователь попытался выйти во время загрузки страницы | Кнопка блокируется, событие выхода откладывается |
| 3 | Сетевая ошибка при отправке запроса на выход | Отображается сообщение об ошибке, кнопка разблокируется |
| 4 | Пользователь дважды нажал "Выйти" быстро | Обработка только одного запроса (debounce) |
| 5 | Выход во время отправки формы | Отмена отправки формы, перенаправление |

---

## 6. Нефункциональные требования (NFR)

### Безопасность
- **NFR-08-01:** Выход должен полностью удалять сессию на сервере (invalidation)
- **NFR-08-02:** Не должно быть возможности обхода выхода через прямое обращение к API
- **NFR-08-03:** Токен сессии должен быть удалён из HTTP-only cookie

### Производительность
- **NFR-08-04:** Время удаления сессии: < 100ms
- **NFR-08-05:** Перенаправление должно быть мгновенным

### Удобство использования (UX)
- **NFR-08-06:** Кнопка "Выйти" должна быть доступна на всех страницах дашборда
- **NFR-08-07:** Перезагрузка страницы после выхода должна перенаправлять на /login

## 7. Влияние на слои архитектуры

### Модель данных
- [ ] Без изменений — logout не требует изменения схемы БД

### Repository
- [ ] Без изменений — next-auth управляет сессиями на уровне БД

### Service
- [ ] Новая логика: вызов next-auth destroy() для удаления сессии

### API Layer
- [ ] Новый endpoint: POST /api/v1/auth/logout
- [ ] Обработка ответа 200 OK
- [ ] Обработка сетевых ошибок

### Frontend Components
- [ ] Navbar: добавить кнопку "Выйти" с обработчиком события
- [ ] Обработка состояний: loading, error, success
- [ ] Проверка авторизации через useSession()

### Страницы
- [ ] Страница /login: обработка callbackUrl после выхода (опционально)
