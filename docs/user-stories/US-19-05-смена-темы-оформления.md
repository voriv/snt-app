# US-19-05: Смена темы оформления

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** переключать тему оформления приложения (светлая/тёмная/зелёная),
**чтобы** настроить визуальный стиль интерфейса под свои предпочтения и условия просмотра.

---

## Контекст

**Проблема:** Тема оформления не сохраняется на сервере — при входе с другого устройства тема сбрасывается к дефолту. Существующий хук `useTheme` управляет темой локально (localStorage), но не синхронизирует выбор с сервером. Пользователь не может выбрать тему из расширенного списка (светлая/тёмная/зелёная) — доступен только toggle.

**Решение:** Реализовать компонент выбора темы (`ThemeSelector`) на странице `/dashboard/profile` и интегрировать `ThemeToggle` в Navbar с сохранением выбранной темы на сервере через `PATCH /api/v1/profile/theme`. При смене темы обновляется локальное состояние (через `useTheme`) и отправляется запрос на сервер. При следующем входе тема загружается из профиля пользователя.

**Границы:**
- Включает: компонент выбора темы (светлая/тёмная/зелёная) на странице профиля, интеграцию с существующим `ThemeToggle` в Navbar, сохранение темы на сервере через `PATCH /api/v1/profile/theme`, загрузку темы из профиля при входе, обновление локального состояния через `useTheme`
- Исключает: кастомные темы (только 3 предустановленные), настройку акцентных цветов, загрузку кастомных тем, редактирование других полей профиля (US-19-02), загрузку аватара (US-19-03)

---

## Целевое состояние

После реализации US авторизованный пользователь может выбрать тему оформления (светлая/тёмная/зелёная) на странице `/dashboard/profile` или через `ThemeToggle` в Navbar. Выбранная тема мгновенно применяется к интерфейсу (через `data-theme` атрибут) и сохраняется на сервере. При входе с другого устройства тема загружается из профиля пользователя и применяется автоматически. При ошибке сохранения показывается уведомление, но тема применяется локально (optimistic update).

## Поведение (User Behavior)

### B-1: Выбор темы на странице профиля
Пользователь находится на странице `/dashboard/profile`. В секции «Оформление» видит текущую тему и список из 3 вариантов (светлая/тёмная/зелёная) с превью. Выбирает тему. Тема мгновенно применяется к интерфейсу (optimistic update через `useTheme`). В фоне отправляется `PATCH /api/v1/profile/theme` для сохранения на сервере. При успехе — ничего не меняется. При ошибке — показывается уведомление, тема остаётся применённой локально.

### B-2: Переключение темы через Navbar
Пользователь находится на любой странице дашборда. Нажимает `ThemeToggle` в Navbar. Тема циклически переключается (light → dark → green → light). Тема мгновенно применяется. В фоне отправляется запрос на сервер для сохранения.

### B-3: Загрузка темы при входе
Пользователь входит в систему. При загрузке профиля (US-19-01) тема из `profile.theme` применяется через `useTheme.setTheme()`. Если тема в профиле отличается от локальной (localStorage) — приоритет у серверной темы. Локальная тема обновляется.

### B-4: Ошибка сохранения темы
При смене темы запрос на сервер завершился ошибкой. Тема остаётся применённой локально (optimistic update). Показывается уведомление «Не удалось сохранить тему на сервере». При следующем входе тема загрузится из сервера (может отличаться от последнего локального выбора).

## Критерии приёмки

### AC-5.1: Успешная смена темы на странице профиля
- **Given** авторизованный пользователь находится на странице `/dashboard/profile` в секции «Оформление»
- **When** пользователь выбирает тему (например, «Тёмная»)
- **Then** тема мгновенно применяется к интерфейсу (через `useTheme.setTheme()`), отправляется `PATCH /api/v1/profile/theme` с `{ theme: 'dark' }`, при успехе — тема сохраняется на сервере

### AC-5.2: Переключение темы через ThemeToggle в Navbar
- **Given** авторизованный пользователь находится на любой странице дашборда
- **When** нажимает `ThemeToggle` в Navbar
- **Then** тема циклически переключается (light → dark → green → light), применяется к интерфейсу, отправляется запрос на сервер для сохранения

### AC-5.3: Загрузка темы из профиля при входе
- **Given** пользователь входит в систему, на сервере сохранена тема (например, 'dark')
- **When** загружается профиль пользователя
- **Then** тема из `profile.theme` применяется через `useTheme.setTheme()`, локальная тема (localStorage) обновляется до серверной

### AC-5.4: Применение темы для текущей сессии
- **Given** пользователь сменил тему
- **When** тема применяется
- **Then** `data-theme` атрибут на `<html>` обновляется, все компоненты перерисовываются с новой темой, тема действует для текущей сессии

### AC-5.5: Ошибка сохранения темы — optimistic update
- **Given** пользователь выбрал тему, запрос отправляется
- **When** сервер возвращает ошибку (500, сетевая ошибка)
- **Then** тема остаётся применённой локально, показывается уведомление «Не удалось сохранить тему на сервере», интерфейс работает с выбранной темой

### AC-5.6: Ошибка валидации — неверное значение темы
- **Given** клиент отправляет тему, не входящую в список ('light', 'dark', 'green')
- **When** сервер возвращает 400 (THEME_INVALID)
- **Then** показывается уведомление об ошибке валидации, тема не сохраняется на сервере, локальная тема остаётся

### AC-5.7: Сессия истекла при смене темы
- **Given** пользователь сменил тему, запрос отправляется
- **When** сервер возвращает 401 (сессия истекла)
- **Then** пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)`

### AC-5.8: Синхронизация между устройствами
- **Given** пользователь сменил тему на устройстве A (например, 'dark')
- **When** входит на устройстве B
- **Then** тема с сервера ('dark') загружается и применяется на устройстве B

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-07 | Тема может быть одной из: светлая, тёмная, зелёная | Только 3 предустановленные темы; кастомные темы не поддерживаются | Zod: `updateThemeSchema` — enum `['light', 'dark', 'green']`; Сервер: `ThemeInvalidError` (400) при невалидном значении |
| — | Тема обязательна в профиле | Поле `theme` в `UserProfile` не может быть null; при создании профиля устанавливается дефолт 'light' | DB: `theme` NOT NULL DEFAULT 'light' |
| — | Серверная тема имеет приоритет над локальной при входе | При загрузке профиля тема с сервера перезаписывает локальную (localStorage) | Service/UI: `setTheme(profile.theme)` при загрузке профиля |

### Примеры валидаций
- **Значение темы:** `theme` ∈ `['light', 'dark', 'green']`; Zod-схема `updateThemeSchema` с `z.enum(['light', 'dark', 'green'])`; сообщение: «Тема должна быть одной из: светлая, тёмная, зелёная»
- **Серверная валидация:** `updateThemeSchema.parse({ theme })` в `UserProfileService.updateTheme()`; при ошибке — `ThemeInvalidError` (400, код `THEME_INVALID`)

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Неверное значение темы (не из списка) | Сервер возвращает 400 `THEME_INVALID`; показывается уведомление; тема не сохраняется; локальная тема остаётся |
| 2 | Сетевая ошибка при сохранении темы | Тема остаётся применённой локально (optimistic update); показывается уведомление «Не удалось сохранить тему на сервере»; при следующем входе тема загрузится с сервера (может отличаться) |
| 3 | Конфликт параллельного изменения (два устройства) | Побеждает последнее сохранение; при следующем входе каждое устройство загрузит актуальную тему с сервера |
| 4 | Неверный формат ответа сервера | Показывается уведомление об ошибке; тема остаётся локально применённой |
| 5 | Таймаут сервера при сохранении | Тема остаётся применённой локально; показывается уведомление об ошибке; возможен повтор при следующей смене |
| 6 | Сессия истекла при смене темы | API возвращает 401; пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)` |
| 7 | Профиль не существует при смене темы | Сервер возвращает 404 `USER_PROFILE_NOT_FOUND`; показывается уведомление; рекомендуется перезагрузить страницу (US-19-01 автосоздание) |
| 8 | localStorage недоступен (private mode) | Тема применяется через `data-theme` атрибут на `<html>` (in-memory); не сохраняется в localStorage; работает для текущей сессии |
| 9 | Пользователь деактивирован | Профиль доступен только для просмотра; смена темы недоступна (ThemeToggle/ThemeSelector disabled) |
| 10 | Быстрое многократное переключение | Дебаунс отправки запросов на сервер (например, 500ms); применяется последняя выбранная тема |

## Нефункциональные требования

- **Производительность:** Применение темы мгновенно (optimistic update); сохранение на сервере <500 ms; debounce 500ms при быстром переключении
- **Безопасность:** Все операции требуют авторизации; валидация на сервере через Zod (`updateThemeSchema`); тема сохраняется только для владельца профиля
- **UX:** Мгновенное применение темы (без ожидания сервера); уведомление при ошибке сохранения; 3 предустановленные темы с превью; адаптивная вёрстка
- **Доступность:** ARIA-метки для кнопок/переключателей темы; навигация с клавиатуры (Tab, Enter, стрелки для ThemeSelector); focus-ring; контрастность по WCAG 2.1 для всех тем
- **Локализация:** Все подписи тем («Светлая», «Тёмная», «Зелёная»), уведомления и сообщения об ошибках на русском языке
