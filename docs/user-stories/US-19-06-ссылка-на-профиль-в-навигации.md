# US-19-06: Отображение ссылки на профиль в навигации

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** видеть своё имя (или email) как ссылку на страницу профиля в навигационной панели,
**чтобы** быстро переходить к своему профилю с любой страницы дашборда.

---

## Контекст

**Проблема:** В навигационной панели (Navbar) отображается имя пользователя или email как статичный текст (не кликабельный). Существует ссылка «Профиль» в меню навигации, но имя/отображаемое имя пользователя не является ссылкой на профиль. Пользователю неочевидно, как быстро перейти к своему профилю.

**Решение:** Преобразовать отображаемое имя пользователя (или email, если имя пустое) в Navbar в кликабельную ссылку, ведущую на `/dashboard/profile`. Согласно BR-09, отображается имя пользователя (если заполнено) или email (если имя пустое). Для неавторизованного пользователя ссылка не отображается.

**Границы:**
- Включает: преобразование `userDisplayName` в Navbar в кликабельную ссылку на `/dashboard/profile`, условный рендеринг (только для авторизованных), отображение имени или email, обрезку длинных имён (truncate), активное состояние ссылки при нахождении на странице профиля
- Исключает: загрузку/удаление аватара (US-19-03, US-19-04), смену темы оформления (US-19-05), редактирование профиля (US-19-02), изменения в API (использует существующую сессию)

---

## Целевое состояние

После реализации US авторизованный пользователь видит в навигационной панели (Navbar) своё отображаемое имя (или email, если имя пустое) как кликабельную ссылку. При клике на имя/email происходит переход на `/dashboard/profile`. При нахождении на странице профиля ссылка подсвечивается как активная. Неавторизованный пользователь не видит ссылку на профиль. Длинные имена обрезаются (truncate) для сохранения целостности вёрстки.

## Поведение (User Behavior)

### B-1: Переход на профиль по клику на имя
Авторизованный пользователь находится на любой странице дашборда. В Navbar видит своё отображаемое имя (или email) как кликабельную ссылку. Нажимает на имя/email. Происходит переход на `/dashboard/profile`.

### B-2: Отображение email вместо имени
Если у пользователя поле `name` пустое (null) или не задано, в Navbar отображается email как кликабельная ссылка на `/dashboard/profile`.

### B-3: Активное состояние ссылки
Пользователь находится на странице `/dashboard/profile`. Ссылка-имя в Navbar подсвечена как активная (например, другой цвет/подчёркивание), показывая текущую страницу.

### B-4: Неавторизованный пользователь
Неавторизованный пользователь (без сессии) не видит ссылку на профиль в Navbar. Поле имени/email не отображается.

### B-5: Длинное имя
У пользователя очень длинное имя (например, более 20 символов). В Navbar имя обрезается (truncate) с многоточием, чтобы не ломать вёрстку. Полное имя доступно в `title` атрибуте (tooltip при наведении).

## Критерии приёмки

### AC-6.1: Имя отображается как ссылка на профиль
- **Given** авторизованный пользователь с заполненным `name` (например, «Иван Петров») находится на любой странице дашборда
- **When** видит Navbar
- **Then** отображаемое имя «Иван Петров» отображается как кликабельная ссылка, ведущая на `/dashboard/profile`

### AC-6.2: Email отображается как ссылка, если имя пустое
- **Given** авторизованный пользователь с пустым `name` (null) и заполненным `email` (например, «ivan@example.com»)
- **When** видит Navbar
- **Then** email «ivan@example.com» отображается как кликабельная ссылка, ведущая на `/dashboard/profile`

### AC-6.3: Неавторизованный пользователь не видит ссылку
- **Given** неавторизованный пользователь (без сессии) видит Navbar
- **When** просматривает Navbar
- **Then** ссылка на профиль (имя/email) не отображается

### AC-6.4: Переход на профиль по клику
- **Given** авторизованный пользователь видит своё имя как ссылку в Navbar
- **When** нажимает на имя/email
- **Then** происходит переход на `/dashboard/profile`

### AC-6.5: Активное состояние ссылки на странице профиля
- **Given** пользователь находится на странице `/dashboard/profile`
- **When** видит Navbar
- **Then** ссылка-имя подсвечена как активная (другой стиль — цвет/подчёркивание)

### AC-6.6: Обрезка длинного имени
- **Given** у пользователя длинное имя (более 20 символов, например «Александр Константинович Востоков»)
- **When** видит Navbar
- **Then** имя обрезается (truncate) с многоточием (например, «Александр Константи…»), вёрстка не ломается, полное имя доступно в `title` атрибуте (tooltip)

### AC-6.7: Нет ни имени, ни email
- **Given** у пользователя `name` = null и `email` = null/пустой (редкий случай)
- **When** видит Navbar
- **Then** ссылка на профиль не отображается (или отображается дефолтный текст «Профиль»)

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-09 | В навигации отображается имя пользователя или email | Если `name` заполнено — отображается имя; если `name` = null/пустое — отображается email | UI: `userDisplayName = session?.user?.name ?? session?.user?.email`; условный рендеринг |
| — | Ссылка видна только авторизованным | Неавторизованный пользователь не видит ссылку на профиль в Navbar | UI: условный рендеринг по `session?.user != null` |
| — | Длинные имена обрезаются | Имена длиннее порога (например, 20 символов) обрезаются с многоточием | UI: CSS `truncate` + `title` атрибут для tooltip |

### Примеры валидаций
- **Отображаемое имя:** `userDisplayName = session?.user?.name ?? session?.user?.email ?? null`; если null — ссылка не рендерится
- **Обрезка:** CSS класс `truncate` (Tailwind) или `max-w-[20ch] truncate`; `title={userDisplayName}` для tooltip с полным именем

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Неавторизованный пользователь | Ссылка на профиль (имя/email) не отображается в Navbar; пользователь не может перейти на профиль без авторизации |
| 2 | Нет ни имени, ни email (name = null, email = null/пустой) | Ссылка не отображается; либо отображается дефолтный текст «Профиль» как ссылка |
| 3 | Длинное имя (более 20 символов) | Имя обрезается (truncate) с многоточием; вёрстка не ломается; полное имя в `title` атрибуте (tooltip при наведении) |
| 4 | Имя состоит из одних пробелов | `name` после trim считается пустым; отображается email вместо имени |
| 5 | Очень длинный email | Email обрезается аналогично имени (truncate); полное значение в `title` |
| 6 | Сессия загружается (loading state) | Во время загрузки сессии (`status === 'loading'`) ссылка не отображается или отображается placeholder; после загрузки — актуальное имя/email |
| 7 | Пользователь на странице профиля | Ссылка-имя подсвечена как активная (current page indicator) |
| 8 | Мобильное устройство (узкий экран) | Имя/email может быть скрыто на очень узких экранах; отображается иконка/короткая версия; вёрстка адаптивная |
| 9 | Имя содержит спецсимволы или эмодзи | Имя отображается как есть (санитизировано через React); спецсимволы не ломают вёрстку |
| 10 | Параллельные сессии | Каждая сессия отображает актуальное имя/email из своей сессии; не влияет на другие сессии |

## Нефункциональные требования

- **Производительность:** Отображение ссылки мгновенное (данные из сессии, без API-запроса); навигация через `next/link` (client-side routing)
- **Безопасность:** Ссылка видна только авторизованным пользователям; данные берутся из проверенной сессии next-auth; нет XSS-рисков (React санитизирует вывод)
- **UX:** Быстрый переход на профиль с любой страницы; активное состояние ссылки показывает текущую страницу; обрезка длинных имён не ломает вёрстку; tooltip с полным именем; адаптивная вёрстка
- **Доступность:** Семантическая разметка (`<a>` через `next/link`); `aria-current="page"` для активной ссылки; `aria-label` с описанием («Перейти в профиль»); focus-ring; навигация с клавиатуры (Tab, Enter); контрастность по WCAG 2.1
- **Локализация:** Не требуется (отображается имя/email пользователя как есть)
