# US-NAV-03: Страница 404 и обработка несуществующих маршрутов

---

## Формулировка

**Как** пользователь,
**я хочу** видеть понятную страницу «не найдено» при переходе на несуществующий маршрут,
**чтобы** понимать, что страница не существует, и иметь возможность вернуться к корректному разделу.

---

## Контекст

### Проблема
При переходе на несуществующий маршрут (опечатка в URL, устаревшая ссылка) пользователь видит стандартную страницу 404 Next.js, которая не содержит контекстной информации и ссылок для возврата.

### Решение
Создать кастомную страницу 404 с понятным сообщением и кнопкой/ссылкой для возврата на дашборд (для авторизованных) или на главную (для неавторизованных).

### Границы
- **Включает:** Кастомную страницу 404 для всех несуществующих маршрутов, обработку исторических ссылок без раздела дашборда (EC-02), ссылку возврата на главную/дашборд
- **Исключает:** Защиту маршрутов (US-NAV-01), навигационную панель (US-NAV-02), вкладку «Общение» (US-NAV-04)

---

## Целевое состояние

После реализации US:

1. Для всех несуществующих маршрутов отображается **кастомная страница 404**.
2. Страница содержит **понятное сообщение** (например, «Страница не найдена»).
3. Для **авторизованных пользователей** на странице 404 отображается ссылка «Вернуться на дашборд» (`/dashboard`).
4. Для **неавторизованных пользователей** отображается ссылка «На главную» (`/`).
5. **Исторические ссылки** без раздела дашборда (EC-02) ведут на страницу 404 (не перенаправляются).
6. Страница 404 **не содержит navbar** (поскольку это не страница дашборда).

## Поведение (User Behavior)

### B-1: Несуществующий маршрут
Пользователь вводит в адресную строку несуществующий URL (например, `/dashboard/nonexistent-page`). Next.js отображает кастомную страницу 404 с сообщением «Страница не найдена» и ссылкой «Вернуться на дашборд».

### B-2: Историческая ссылка (EC-02)
Пользователь переходит по старой ссылке без раздела дашборда. Система отображает страницу 404 (не перенаправляет на другой маршрут).

### B-3: Неавторизованный пользователь на 404
Неавторизованный пользователь попадает на несуществующий маршрут. Отображается страница 404 со ссылкой «На главную».

---

## Критерии приёмки

### AC-NAV-03-1: Кастомная страница 404 для несуществующих маршрутов
- **Given** пользователь пытается открыть несуществующий маршрут (например, `/nonexistent`)
- **When** страница загружается
- **Then** отображается кастомная страница 404 с сообщением «Страница не найдена» и HTTP-статус 404

### AC-NAV-03-2: Ссылка на дашборд для авторизованных
- **Given** пользователь авторизован
- **When** пользователь видит страницу 404
- **Then** отображается ссылка «Вернуться на дашборд», ведущая на `/dashboard`

### AC-NAV-03-3: Ссылка на главную для неавторизованных
- **Given** пользователь не авторизован
- **When** пользователь видит страницу 404
- **Then** отображается ссылка «На главную», ведущая на `/`

### AC-NAV-03-4: Исторические ссылки без дашборда (EC-02)
- **Given** пользователь переходит по старой ссылке без раздела дашборда
- **When** маршрут не существует
- **Then** отображается страница 404 (редирект не выполняется)

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Исторические ссылки без раздела дашборда (EC-02) | Страница 404, не перенаправляется |
| 2 | Пользователь вводит `/dashboard/nonexistent` | Страница 404 внутри layout дашборда, если путь подпадает под `/dashboard/*`, но не существует |
| 3 | Пользователь вводит `/random-abc-123` | Страница 404 вне layout дашборда |
| 4 | Пользователь нажимает F5 на странице 404 | Страница 404 сохраняется (не редиректит) |
| 5 | SEO для страницы 404 | HTTP-статус 404 возвращается корректно |
