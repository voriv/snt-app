# US-21-33: Удаление объявления

## Формулировка

**Как** модератор СНТ,
**я хочу** удалять объявления навсегда,
**чтобы** избавляться от некорректной, нарушающей правила или устаревшей информации.

## Целевое состояние

После реализации пользователь сможет:
- Удалять опубликованные объявления навсегда (soft delete)
- Получать подтверждение перед удалением через модальное окно
- Видеть уведомление об успешном удалении
- Отслеживать, кто и когда удалил объявление (аудит-лог)

### Границы

**Входит:**
- Soft delete объявления (пометка `deleted_at`, `deleted_by`)
- Скрытие из всех списков опубликованных объявлений
- Запись в аудит-лог (кто удалил, когда)
- Сохранение чата обсуждения для чтения (не удаляется)

**Не входит:**
- Физическое удаление из базы данных
- Массовое удаление
- Автоматическое удаление по дате
- Восстановление удалённых объявлений (отдельная US)

### FR-REQ-COMMS-022-01: Удаление объявления

Удаление объявления должно позволять модератору удалить опубликованное объявление навсегда.

#### AC-33.1: Доступность операции
- **Дано:** Пользователь авторизован как модератор (ADMIN/SUPER_ADMIN)
- **Дано:** Объявление имеет статус `published`
- **Когда:** Пользователь нажимает кнопку "Удалить" в карточке объявления
- **Тогда:** Появляется модальное окно подтверждения

#### AC-33.2: Подтверждение удаления
- **Дано:** Модальное окно подтверждения отображается
- **Когда:** Пользователь подтверждает действие (вводит название объявления для подтверждения)
- **Тогда:** Объявление помечается как удалённое, закрывается модальное окно, показывается уведомление об успехе

#### AC-33.3: Скрытие из списков
- **Дано:** Объявление имеет `deleted_at` заполнен
- **Когда:** Загружается список опубликованных объявлений
- **Тогда:** Удалённое объявление не отображается

#### AC-33.4: Аудит-лог
- **Дано:** Объявление удалено
- **Когда:** Проверяется запись в истории
- **Тогда:** Сохраняется `deleted_by` (id пользователя) и `deleted_at` (время)

### FR-REQ-COMMS-022-02: Просмотр удалённых объявлений

Пользователь должен иметь возможность просматривать удалённые объявления через фильтр.

#### AC-33.5: Фильтр по статусу
- **Дано:** Пользователь на странице объявлений
- **Когда:** Выбирает фильтр "Удалённые"
- **Тогда:** Отображаются только объявления с заполненным `deleted_at`

#### AC-33.6: Недоступность для чтения
- **Дано:** Объявление имеет `deleted_at` заполнен
- **Когда:** Пользователь переходит по прямой ссылке на объявление
- **Тогда:** Отображается страница "Объявление не найдено" или "Объявление удалено"

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| **BR-01** | Только модераторы могут удалять | Удаление — операция модерации | Проверка роли ADMIN/SUPER_ADMIN |
| **BR-02** | Можно удалять только опубликованные объявления | Удаление черновиков не требуется | Проверка статуса (published) |
| **BR-03** | Подтверждение удаления | Требуется явное подтверждение через модальное окно | UI-валидация + ввод названия |
| **BR-04** | Аудит-лог обязателен | Записывается кто и когда удалил | Поля `deleted_by`, `deleted_at` |
| **BR-05** | Данные не удаляются физически | Soft delete вместо физического удаления | Проверка наличия записи в БД |
| **BR-06** | Чат обсуждения не удаляется | Чат остаётся доступным для чтения | Логика сервиса не удаляет `discussion_id` |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| **EC-01** | Попытка удаления черновика | Ошибка 400: "Черновики не подлежат удалению" |
| **EC-02** | Попытка удаления уже удалённого объявления | Ошибка 400: "Объявление уже удалено" |
| **EC-03** | Попытка удаления неавторизованным пользователем | Ошибка 401: "Требуется авторизация" |
| **EC-04** | Попытка удаления пользователем без прав | Ошибка 403: "Доступ запрещён" |
| **EC-05** | Удаление объявления с активным чатом обсуждения | Чат остаётся доступным для чтения |
| **EC-06** | Отмена подтверждения в модальном окне | Действие отменяется, статус не меняется |
| **EC-07** | Удаление через прямую ссылку после удаления | Страница "Объявление не найдено" |
| **EC-08** | Удаление архивированного объявления | Ошибка 400: "Сначала разархивируйте объявление" |

## Модель данных

### Текущая схема `announcements`

```prisma
model Announcement {
  id            String      @id @default(cuid())
  title         String
  short_content String?
  content       String
  status        String      // draft | published | archived
  category_id   String?
  discussion_id String?
  created_at    DateTime    @default(now())
  created_by    String
  updated_at    DateTime    @updatedAt
  updated_by    String
  published_at  DateTime?
  published_by  String?
  archived_at   DateTime?
  archived_by   String?
  deleted_at    DateTime?
  deleted_by    String?
}
```

### Изменения в модели

Модель данных не требует изменений — поля `deleted_at` и `deleted_by` уже присутствуют.

**Использование полей:**
- `deleted_at` — заполняется при soft delete
- `deleted_by` — ID пользователя, удалившего объявление

### Конвенции именования

| Поле | Тип | Назначение |
|------|-----|------------|
| `deleted_at` | DateTime? | Время удаления |
| `deleted_by` | String? | ID пользователя, удалившего объявление |

## Влияние на слои архитектуры

### Types
- Тип `Announcement` включает поля `deleted_at`, `deleted_by`
- Вычисляемое свойство `isDeleted: boolean` на основе `deleted_at`

### Validators
- Валидация статуса объявления перед удалением (только `published`)
- Проверка прав доступа в DTO
- Валидация подтверждения удаления (ввод названия)

### Errors
- `AnnouncementNotPublishedError` — объявление не опубликовано
- `AnnouncementAlreadyDeletedError` — объявление уже удалено
- `AnnouncementArchivedError` — сначала нужно разархивировать

### Repository
- Метод `deleteById(id: string, deletedBy: string): Promise<Announcement>`
- Обновление `deleted_at` и `deleted_by`

### Service
- Метод `deleteAnnouncement(announcementId: string, userId: string): Promise<Announcement>`
- Валидация статуса и прав
- Вызов `repository.deleteById()`

### DI
- Регистрация фабрики `createAnnouncementService()` (если не зарегистрирована)

### API
- **Endpoint:** `DELETE /api/v1/announcements/:id`
- **Auth:** required (ADMIN/SUPER_ADMIN)
- **Body:** нет (id в params)
- **Response:** 200 `{ success: true, data: Announcement }`

### UI
- **Компоненты:**
  - `DeleteAnnouncementButton` — кнопка в карточке
  - `DeleteAnnouncementModal` — модальное окно подтверждения с вводом названия
  - `AnnouncementsList` — обновление для фильтрации по статусу
- **Страница:** `/dashboard/announcements` — добавление фильтра

### Pages
- Страница `/dashboard/announcements` получает дополнительный фильтр `status`
- Страница `/dashboard/announcements/[id]` — обработка удаления (переадресация)

## Нефункциональные требования

- **Производительность:** Операция удаления < 500мс
- **Безопасность:** Проверка прав на уровне API и UI
- **Аудит:** Полная трассируемость операций (кто, когда)
- **UX:** Подтверждение через модальное окно с вводом названия для предотвращения ошибок
- **Доступность:** ARIA-метки для кнопок и модальных окон

## Открытые вопросы

| # | Вопрос | Допущение |
|---|--------|-----------|
| 1 | Нужно ли уведомлять участников чата обсуждения об удалении? | Нет, чат остаётся доступным |

| 3 | Можно ли массово удалять объявления? | Нет, только по одному |
| 4 | Нужно ли отправлять email участникам при удалении? | Нет, без уведомлений |
