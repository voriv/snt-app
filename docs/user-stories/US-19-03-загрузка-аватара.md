# US-19-03: Загрузка аватара

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** загрузить изображение в качестве аватара своего профиля,
**чтобы** персонализировать свою учётную запись и отображать выбранную картинку в интерфейсе приложения.

---

## Контекст

**Проблема:** Пользователи не могут загрузить аватар — поле `avatar` в профиле остаётся пустым, отображается дефолтный аватар. Нет UI-компонента для загрузки изображения.

**Решение:** Реализовать компонент загрузки аватара на странице `/dashboard/profile`. Пользователь выбирает файл изображения (JPG, PNG, GIF до 5 МБ), файл отправляется на сервер через `POST /api/v1/profile/avatar` (multipart/form-data). Сервер сохраняет файл и возвращает URL, который обновляет аватар в профиле.

**Границы:**
- Включает: UI-компонент загрузки аватара (input type=file + drag-and-drop), клиентскую валидацию размера и формата, отправку файла через `apiClient.postFormData`, обработку состояний загрузки/ошибки/успеха, обновление аватара в UI после загрузки, интеграцию со страницей профиля (US-19-01)
- Исключает: удаление аватара (отдельная US-19-04), сжатие/ресайз изображения на клиенте, предпросмотр с обрезкой (crop), смену темы оформления (US-19-05), изменение других полей профиля (US-19-02)

---

## Целевое состояние

После реализации US авторизованный пользователь может на странице `/dashboard/profile` загрузить изображение в качестве аватара. Пользователь нажимает на область аватара или кнопку «Загрузить», выбирает файл. Система проверяет размер (≤5 МБ) и формат (JPG/PNG/GIF) на клиенте перед отправкой. При успешной загрузке аватар обновляется в UI без перезагрузки страницы. При ошибке (превышен размер, неверный формат, сетевая ошибка) показывается уведомление с описанием ошибки, текущий аватар остаётся без изменений.

## Поведение (User Behavior)

### B-1: Выбор файла для загрузки
Пользователь находится на странице `/dashboard/profile`. Нажимает на область аватара или кнопку «Загрузить аватар». Открывается системный диалог выбора файла (`<input type="file" accept="image/jpeg,image/png,image/gif">`). Пользователь выбирает изображение.

### B-2: Клиентская валидация
После выбора файла система проверяет размер и формат на клиенте. Если размер >5 МБ — показывается ошибка «Размер файла превышает 5 МБ», файл не отправляется. Если формат не JPG/PNG/GIF — показывается ошибка «Поддерживаемые форматы: JPG, PNG, GIF», файл не отправляется.

### B-3: Загрузка на сервер
Файл проходит клиентскую валидацию. Кнопка загрузки блокируется, отображается индикатор загрузки. Система отправляет файл через `apiClient.postFormData('/profile/avatar', formData)`. При успехе — аватар обновляется в UI, показывается уведомление об успехе. При ошибке — показывается уведомление с описанием ошибки, текущий аватар без изменений.

### B-4: Drag-and-drop загрузка
Пользователь перетаскивает файл изображения на область аватара. Система подсвечивает область как принимающую drop. При отпускании файла — выполняется клиентская валидация и загрузка (B-2, B-3).

## Критерии приёмки

### AC-3.1: Успешная загрузка аватара
- **Given** авторизованный пользователь с существующим профилем находится на странице `/dashboard/profile`
- **When** пользователь выбирает файл изображения формата JPG/PNG/GIF размером менее 5 МБ
- **Then** файл загружается через `POST /api/v1/profile/avatar`, аватар обновляется в UI без перезагрузки страницы, показывается уведомление об успехе

### AC-3.2: Ошибка — превышен размер файла
- **Given** пользователь выбирает файл размером более 5 МБ
- **When** система проверяет размер на клиенте
- **Then** показывается ошибка «Размер файла превышает 5 МБ», файл не отправляется на сервер, текущий аватар без изменений

### AC-3.3: Ошибка — неподдерживаемый формат
- **Given** пользователь выбирает файл формата, отличного от JPG/PNG/GIF (например, BMP, WebP, PDF)
- **When** система проверяет формат на клиенте
- **Then** показывается ошибка «Поддерживаемые форматы: JPG, PNG, GIF», файл не отправляется, текущий аватар без изменений

### AC-3.4: Обработка сетевой ошибки
- **Given** пользователь выбрал корректный файл и инициировал загрузку
- **When** запрос завершился сетевой ошибкой (таймаут, отсутствие соединения)
- **Then** показывается уведомление об ошибке сети с возможностью повтора, текущий аватар без изменений, кнопка загрузки снова активна

### AC-3.5: Блокировка UI при загрузке
- **Given** пользователь инициировал загрузку файла
- **When** запрос отправляется и ожидается ответ сервера
- **Then** кнопка загрузки заблокирована (disabled), отображается индикатор загрузки, повторные нажатия игнорируются

### AC-3.6: Серверная ошибка при загрузке (500)
- **Given** пользователь отправил корректный файл
- **When** сервер возвращает 500 (IMAGE_UPLOAD_ERROR)
- **Then** показывается уведомление об ошибке сервера, текущий аватар без изменений, кнопка загрузки снова активна

### AC-3.7: Сессия истекла во время загрузки
- **Given** пользователь инициировал загрузку файла
- **When** сервер возвращает 401 (сессия истекла)
- **Then** пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)`

### AC-3.8: Drag-and-drop загрузка
- **Given** пользователь перетаскивает файл изображения на область аватара
- **When** отпускает файл в области drop
- **Then** выполняется клиентская валидация и загрузка (как при выборе через диалог)

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-06 | Максимальный размер файла 5 МБ | Файлы размером более 5 МБ (5 242 880 байт) отклоняются | Клиент: `file.size <= 5 * 1024 * 1024`; Сервер: `avatarFileSchema` + `FileTooLargeError` (413) |
| BR-06 | Поддерживаемые форматы: JPG, PNG, GIF | Файлы других форматов отклоняются | Клиент: проверка `file.type` ∈ `['image/jpeg', 'image/png', 'image/gif']`; Сервер: `avatarFileSchema` + `UnsupportedFileTypeError` (415) |

### Примеры валидаций
- **Размер файла:** `file.size` проверяется на клиенте до отправки; MIME-тип `image/jpeg` (JPG), `image/png` (PNG), `image/gif` (GIF); сообщение: «Размер файла превышает 5 МБ»
- **Формат файла:** `file.type` проверяется на клиенте; сообщение: «Поддерживаемые форматы: JPG, PNG, GIF»
- **Серверная валидация:** `avatarFileSchema` в `src/domains/userProfile/userProfile.validators.ts` повторно валидирует размер и тип; ошибки `FileTooLargeError` (413), `UnsupportedFileTypeError` (415)

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Неверный формат файла (BMP, WebP, SVG, PDF) | Клиентская валидация отклоняет файл; показывается ошибка «Поддерживаемые форматы: JPG, PNG, GIF»; файл не отправляется |
| 2 | Превышение размера (файл >5 МБ) | Клиентская валидация отклоняет файл; показывается ошибка «Размер файла превышает 5 МБ»; файл не отправляется |
| 3 | Сетевая ошибка при загрузке | Показывается уведомление об ошибке сети; текущий аватар без изменений; кнопка загрузки снова активна; возможен повтор |
| 4 | Таймаут сервера при загрузке (более 3 секунд) | Индикатор загрузки продолжает отображаться; при ошибке — уведомление с возможностью повтора |
| 5 | Серверная ошибка (500, IMAGE_UPLOAD_ERROR) | Показывается уведомление об ошибке сервера; текущий аватар без изменений; кнопка загрузки снова активна |
| 6 | Файл не выбран (пустой диалог выбора) | Ничего не происходит; диалог закрывается без действий |
| 7 | Профиль не существует при загрузке | Сервер возвращает 404 `USER_PROFILE_NOT_FOUND`; показывается уведомление; рекомендуется перезагрузить страницу (US-19-01 автосоздание) |
| 8 | Сессия истекла во время загрузки | API возвращает 401; пользователь перенаправляется на `/login` через `setTimeout(() => router.replace('/login'), 100)` |
| 9 | Пользователь перетаскивает несколько файлов | Берётся только первый файл; остальные игнорируются |
| 10 | Пользователь перетаскивает non-file объект | Drop игнорируется; валидация не выполняется |
| 11 | Файл с нулевым размером (0 байт) | Клиентская валидация отклоняет файл; показывается ошибка |
| 12 | Файл с корректным расширением, но неверным MIME-типом | Валидация по MIME-типу (`file.type`), а не по расширению; отклоняется если MIME не входит в список |

## Нефункциональные требования

- **Производительность:** Загрузка аватара <2 секунды для файлов до 5 МБ; клиентская валидация выполняется синхронно до отправки запроса
- **Безопасность:** Все операции требуют авторизации; валидация на сервере через Zod (`avatarFileSchema`); ограничение размера файла 5 МБ; проверка MIME-типа на сервере; защита от загрузки исполняемых файлов
- **UX:** Индикатор загрузки на кнопке/области аватара; превью выбранного файла перед загрузкой; блокировка повторных отправок; адаптивная вёрстка (мобильные и десктоп); drag-and-drop для удобства
- **Доступность:** Семантическая разметка (`<input type="file">`), ARIA-метки для области загрузки, навигация с клавиатуры (Tab/Enter для выбора файла), focus-ring, контрастность по WCAG 2.1
- **Локализация:** Все сообщения об ошибках и уведомления на русском языке

## Открытые вопросы

| # | Вопрос | Допущение |
|---|--------|-----------|
| 1 | Нужно ли показывать превью выбранного файла перед загрузкой? | Допущение: да — показывать превью после выбора файла, до отправки на сервер; пользователь видит, что загружает |
| 2 | Нужен ли предпросмотр с обрезкой (crop)? | Допущение: нет — обрезка не входит в данную US; пользователь загружает изображение как есть |
| 3 | Где хранить загруженные файлы — на сервере (public/uploads) или в облачном хранилище? | Допущение: на сервере в `public/uploads/avatars/` (если не указано иное); URL формируется как `/uploads/avatars/<userId>-<timestamp>.<ext>` |
| 4 | Нужна ли проверка, что файл является реальным изображением (magic bytes), а не переименованным? | Допущение: да — серверная валидация проверяет MIME-тип из содержимого файла, а не только из заголовка |
| 5 | Что делать со старым аватаром при загрузке нового? | Допущение: старый файл удаляется с сервера при загрузке нового (если не дефолтный) |
| 6 | Нужен ли optimistic update (обновление UI до ответа сервера)? | Допущение: без optimistic update — обновляем аватар только после успешного ответа |
