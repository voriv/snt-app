# US-39-02: Read Receipts — индикация статуса прочтения сообщений

> Эпик: Система общения в СНТ (REQ-COMMS-001)
> Требование: [REQ-COMMS-003](../requirements/REQ-COMMS-003.md)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** видеть под своими отправленными сообщениями индикатор статуса прочтения — галочки (одна/две) в личных диалогах или счётчик прочитавших в групповых чатах,
**чтобы** понимать, прочитал ли собеседник моё сообщение и сколько участников чата его увидели.

---

## Целевое состояние

После реализации под каждым отправленным пользователем сообщением отображается визуальный индикатор статуса прочтения:

**В личных диалогах:**
- **Одна галочка (✓)** — сообщение доставлено, но собеседник ещё не открывал этот диалог
- **Две галочки (✓✓)** — собеседник открыл диалог, сообщение прочитано

**В групповых чатах:**
- Под сообщением отображается текст «Прочитано: N из M», где N — количество участников, открывших чат после отправки сообщения, M — общее количество участников чата (кроме автора сообщения)

Статус прочтения вычисляется на основе `lastReadAt` участников: сообщение считается прочитанным участником, если `participant.lastReadAt >= message.createdAt`.

Обновление статуса происходит при перезагрузке страницы диалога/чата или при переключении между вкладками (обновление в реальном времени через WebSocket отложено).

## Модель данных

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| `Message` | Сообщение в личном диалоге. Поля: `id`, `conversationId`, `senderId`, `createdAt` | `docs/model/entities/` |
| `ChatMessage` | Сообщение в групповом чате. Поля: `id`, `chatId`, `senderId`, `createdAt` | `docs/model/entities/` |
| `ConversationParticipant` | Участник диалога. Поле `lastReadAt` — метка последнего прочтения | `docs/model/entities/` |
| `ChatParticipant` | Участник чата. Поле `lastReadAt` — метка последнего прочтения | `docs/model/entities/` |

**Механика вычисления статуса:**
- **Личный диалог:** Сообщение прочитано собеседником, если `ConversationParticipant.lastReadAt >= message.createdAt` для собеседника
- **Групповой чат:** Сообщение прочитано участником, если `ChatParticipant.lastReadAt >= message.createdAt`. Количество прочитавших = COUNT участников с `lastReadAt >= message.createdAt`

## Поведение (User Behavior)

### B-1: Отправка сообщения в личный диалог — статус «доставлено»
Пользователь отправляет сообщение в личный диалог. Под сообщением появляется одна галочка (✓) — «доставлено». Собеседник ещё не открывал диалог.

### B-2: Собеседник открывает диалог — статус меняется на «прочитано»
Собеседник открывает диалог (срабатывает US-39-01 — `lastReadAt` обновляется). При следующей перезагрузке страницы диалога отправителем под сообщением отображаются две галочки (✓✓) — «прочитано».

### B-3: Отправка сообщения в групповой чат — счётчик прочитавших
Пользователь отправляет сообщение в групповой чат с 5 участниками (включая автора). Под сообщением отображается «Прочитано: 0 из 4» (4 — участники кроме автора). По мере открытия чата другими участниками счётчик увеличивается: «Прочитано: 1 из 4», «Прочитано: 2 из 4» и т.д.

### B-4: Просмотр статуса прочтения своих сообщений
Пользователь открывает историю сообщений в личном диалоге. Под его отправленными сообщениями видны галочки: одна для непрочитанных собеседником, две для прочитанных. Сообщения собеседника не имеют галочек прочтения.

---

## Критерии приёмки

### AC-1: Одна галочка — доставлено, но не прочитано
- **Given:** Пользователь отправил сообщение в личный диалог
- **When:** Собеседник ещё не открывал этот диалог
- **Then:** Под сообщением отображается одна галочка (✓) с `aria-label="Доставлено"`

### AC-2: Две галочки — прочитано собеседником
- **Given:** Пользователь отправил сообщение в личный диалог, и собеседник открыл этот диалог
- **When:** Пользователь просматривает историю сообщений
- **Then:** Под сообщением отображаются две галочки (✓✓) с `aria-label="Прочитано"`

### AC-3: Счётчик прочитавших в групповом чате
- **Given:** Пользователь отправил сообщение в групповой чат с 5 участниками (4 кроме автора)
- **When:** 3 участника открыли чат после отправки сообщения
- **Then:** Под сообщением отображается «Прочитано: 3 из 4»

### AC-4: Статус обновляется при перезагрузке
- **Given:** Пользователь отправил сообщение, под ним одна галочка
- **When:** Собеседник открывает диалог, затем пользователь перезагружает страницу
- **Then:** Под сообщением отображаются две галочки

### AC-5: Сообщения собеседника не имеют индикатора прочтения
- **Given:** Пользователь просматривает историю личного диалога
- **When:** Встречает сообщение от собеседника
- **Then:** Под сообщением собеседника нет галочек прочтения (галочки только у своих сообщений)

### AC-6: Нулевой счётчик прочитавших в групповом чате
- **Given:** Пользователь отправил сообщение в групповой чат
- **When:** Никто из участников ещё не открыл чат
- **Then:** Под сообщением отображается «Прочитано: 0 из 4» (или соответствующее число участников кроме автора)

### AC-7: Доступность — aria-label для скринридеров
- **Given:** Пользователь со скринридером просматривает сообщения
- **When:** Экран читает индикатор прочтения
- **Then:** Озвучивается «Доставлено» для одной галочки, «Прочитано» для двух галочек, «Прочитано: N из M» для группового чата

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-06 | В личных диалогах: одна галочка = доставлено, две галочки = прочитано | UI-компонент |
| BR-07 | В групповых чатах: «Прочитано: N из M», где M — участники кроме автора | Server-side: `COUNT(participants WHERE lastReadAt >= message.createdAt)` |
| BR-09 | Ошибка при обновлении статуса прочтения не блокирует пользователя | Client-side: silent fail, показывать последнее известное состояние |

---

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | В групповом чате больше 100 участников | Под сообщением отображается «Прочитано: 47 из 123» (без ограничения отображения) |
| 2 | Собеседник открыл диалог, но не видит конкретное сообщение (за пределами видимости) | Статус «прочитано» активируется, так как диалог был открыт и `lastReadAt` обновлён |
| 3 | Пользователь отправляет сообщение сам себе в групповом чате | Сообщение не учитывается в счётчике непрочитанных для автора; в счётчике «из M» автор исключён |
| 4 | Новый участник добавлен в чат после отправки сообщения | M увеличивается, но N не меняется (новый участник ещё не читал это сообщение) |
| 5 | Участник покинул чат после отправки сообщения | M уменьшается, N остаётся прежним если он уже читал, или уменьшается если не читал |
| 6 | Ошибка загрузки статуса прочтения (сеть/API) | Галочки/счётчик не отображаются, но сообщения видны |

## Нефункциональные требования

- **Производительность:** Вычисление статуса прочтения не должно увеличивать время загрузки сообщений более чем на 500 мс
- **Доступность:** Статусы прочтения (галочки) должны иметь текстовую альтернативу (`aria-label`) для скринридеров: «Доставлено», «Прочитано», «Прочитано: N из M»
- **Локализация:** Текстовые метки статусов («Прочитано», «Доставлено») должны быть на русском языке

## Открытые вопросы

| # | Вопрос | Допущение |
|---|--------|-----------|
| 1 | Нужно ли обновлять статус прочтения в реальном времени (WebSocket)? | Нет, вне scope REQ-COMMS-003 — обновление при перезагрузке/переключении вкладок |
| 2 | Нужно ли показывать точное время прочтения? | Нет, только факт прочтения (галочки/счётчик) |
| 3 | Показывать ли индикатор «доставляется» (часы) до подтверждения сервером? | Нет, вне scope — после отправки сразу одна галочка |
