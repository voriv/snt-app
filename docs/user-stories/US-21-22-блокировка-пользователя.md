# US-21-22: Блокировка пользователя

## Формулировка
**Как** модератор,
**я хочу** блокировать пользователей, нарушающих правила сообщества,
**чтобы** предотвратить дальнейшие нарушения и защитить других пользователей.

## Целевое состояние
Модератор может заблокировать пользователя на определенный срок или навсегда. После блокировки пользователь теряет доступ к чату, может отправлять сообщения, но не может читать новые. Отображается статус "Заблокирован" в интерфейсе.

### Границы
- Блокировка доступна только модераторам и супер-администраторам.
- Блокировка может быть временной (срок) или постоянной (навсегда).
- Блокированный пользователь получает уведомление о блокировке.
- Модератор должен указать причину блокировки.
- Блокировка действует на все чаты системы (глобальная блокировка).

## Функциональные требования

### FR-REQ-COMMS-001-22: Блокировка пользователя

#### AC-22.1: Блокировка пользователя с указанием срока
- **Дано:** Модератор находится на странице карточки пользователя или видит кнопку "Заблокировать".
- **Когда:** Модератор нажимает "Заблокировать", выбирает срок блокировки (24ч, 7дней, 30дней, навсегда) и вводит причину.
- **Тогда:**
  - Пользователь получает статус "Заблокирован" с датой окончания блокировки (или "навсегда").
  - Пользователь теряет доступ к чату (не может читать/отправлять сообщения).
  - Блокировка записывается в историю пользователя.
  - Пользователь получает уведомление о блокировке.

#### AC-22.2: Блокировка с обязательным комментарием
- **Дано:** Модератор пытается заблокировать пользователя без указания причины.
- **Когда:** Модератор нажимает "Заблокировать" без ввода комментария.
- **Тогда:**
  - Система отклоняет операцию.
  - Поле "Причина блокировки" подсвечивается как обязательное.
  - Отображается сообщение "Пожалуйста, укажите причину блокировки".

#### AC-22.3: Блокировка на определенный срок
- **Дано:** Модератор выбирает временную блокировку (не навсегда).
- **Когда:** Модератор указывает срок блокировки (например, 7 дней).
- **Тогда:**
  - Система вычисляет дату окончания блокировки.
  - После даты окончания блокировка автоматически снимается.
  - Пользователь автоматически получает доступ обратно.

### FR-REQ-COMMS-001-23: Ведение истории блокировок
- **Дано:** Пользователь был заблокирован.
- **Когда:** Модератор или супер-администратор открывает карточку пользователя.
- **Тогда:**
  - Отображается история блокировок: кто заблокировал, когда, на какой срок, причина.
  - Статус текущей блокировки (если активна).

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-22-01 | Право модератора | Блокировать может только модератор/SUPER_ADMIN. | Проверка роли в API. |
| BR-22-02 | Комментарий обязателен | Блокировка возможна только с причиной. | Валидация `reason` как обязательного поля. |
| BR-22-03 | Срок блокировки | Срок может быть от 1 часа до навсегда. | Проверка `duration` в валидаторе. |
| BR-22-04 | Наложение новых блокировок | Новая блокировка продлевает текущую (или заменяет). | Проверка `isBlocked` и обновление `blockedUntil`. |
| BR-22-05 | Уведомление | Пользователь должен получить уведомление о блокировке. | Генерация уведомления после блокировки. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Попытка заблокировать уже заблокированного пользователя | Блокировка продлевается на новый срок или заменяется. |
| 2 | Блокировка пользователя, который сам модератор | Заблокировать может только SUPER_ADMIN, модератор получает ошибку 403. |
| 3 | Блокировка пользователя, который сам заблокирован другим модератором | Вторая блокировка продлевает первую или заменяет (конфликт разрешается последней операцией). |
| 4 | Блокировка пользователя, который сейчас в чате | Пользователь мгновенно теряется доступ к чату, текущие сообщения сохраняются. |
| 5 | Блокировка с сроком 0 секунд (ошибка) | Система интерпретирует как минимальный срок (например, 1 час) или возвращает ошибку. |
| 6 | Блокировка пользователя, который находится в процессе регистрации | Блокировка применяется к аккаунту после создания. |

## Модель данных
Обновление таблицы `users` для хранения статуса блокировки.

**Обновление таблицы `users`:**
```prisma
model User {
  id           String   @id @default(cuid())
  email        String   @unique @map("email")
  firstName    String   @map("first_name")
  lastName     String   @map("last_name")
  role         String   // GUEST, MEMBER, ADMIN, MODERATOR, SUPER_ADMIN
  isBlocked    Boolean  @default(false) @map("is_blocked")
  blockedAt    DateTime? @map("blocked_at")
  blockedUntil DateTime? @map("blocked_until") // NULL = навсегда
  blockedBy    String?  @map("blocked_by") // ID модератора
  // ... другие поля
}
```

**Таблица истории блокировок (опционально):**
```prisma
model UserBlockLog {
  id          String   @id @default(cuid())
  userId      String   @map("user_id")
  blockedBy   String   @map("blocked_by")
  reason      String   @map("reason")
  blockedAt   DateTime @default(now()) @map("blocked_at")
  blockedUntil DateTime @map("blocked_until")
  duration    Int      // Длительность в часах (для временных блокировок)
}
```

## Нефункциональные требования
- **Производительность:** Проверка статуса блокировки < 50мс (кэш если возможно).
- **Безопасность:** Проверка прав модератора на уровне middleware.
- **Аудит:** Все блокировки должны записываться в историю с причиной и модератором.
- **Доступность:** Modal блокировки имеет aria-label, кнопка блокировки имеет aria-label.
