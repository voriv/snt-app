# US-09: Управление состоянием сессии на клиенте

## 1. Контекст

### Проблема
В текущей реализации NextAuth предоставляет хук `useSession` из `next-auth/react`, но нет централизованной обёртки для:
- Упрощения доступа к данным сессии в компонентах
- Стандартизации обработки состояний (loading, error, data)
- Обработки ошибок и повторных попыток
- Унификации типов данных

### Решение
Создать кастомный хук `useSession`, который:
- Обёрнутый вокруг `next-auth` `useSession()`
- Возвращает унифицированную структуру с полями: `user`, `loading`, `error`, `refresh`
- Автоматически обрабатывает ошибки сети и кэширует данные
- Предоставляет метод `refresh()` для принудительного обновления сессии

### Границы
**Входит в область:**
- Создание хука `useSession` в `src/hooks/useSession.ts`
- Обработка состояний: loading, error, data
- Метод refresh для обновления сессии
- Типизированные возвращаемые значения

**Исключено:**
- Клиентская валидация токена — это делает next-auth
- Обработка ошибок на уровне сервера — это задача API handlers

## 2. Пользовательская история

**Как** разработчик клиентских компонентов,
**я хочу** иметь унифицированный хук для получения состояния сессии с обработкой ошибок и загрузок,
**чтобы** упростить работу с данными сессии в UI-компонентах и избежать дублирования кода.

## 3. Функциональные требования

### FR-REQ-SESSION-001: Получение данных сессии

Система должна предоставлять хук `useSession`, который возвращает актуальные данные сессии или ошибки.

#### AC-9.1.1: Возврат данных сессии
- **Дано:** Пользователь авторизован
- **Когда:** Хук `useSession` вызывается в клиентском компоненте
- **Тогда:**
  - `loading` = `false`
  - `data` = объект сессии { user: { id, email, name, roles }, expires }
  - `error` = `null`

#### AC-9.1.2: Обработка загрузки
- **Дано:** Хук `useSession` вызывается в клиентском компоненте
- **Когда:** Сессия ещё загружается (first paint или refresh)
- **Тогда:**
  - `loading` = `true`
  - `data` = `null`
  - `error` = `null`

#### AC-9.1.3: Обработка ошибок
- **Дано:** Произошла ошибка при получении сессии (сетевая ошибка, истёк токен)
- **Когда:** Хук `useSession` обрабатывает ошибку
- **Тогда:**
  - `loading` = `false`
  - `data` = `null`
  - `error` = объект с информацией об ошибке { message, code }

### FR-REQ-SESSION-002: Обновление сессии

Система должна предоставлять метод `refresh()` для принудительного обновления данных сессии.

#### AC-9.2.1: Обновление сессии
- **Дано:** Хук `useSession` вызывается в клиентском компоненте
- **Когда:** Вызван метод `refresh()`
- **Тогда:**
  - `loading` = `true`
  - После завершения: `loading` = `false`, `data` обновлён или `error` установлен

#### AC-9.2.2: Повторные попытки
- **Дано:** Ошибка при обновлении сессии
- **Когда:** Метод `refresh()` вызывается повторно
- **Тогда:**
  - Система пытается обновить сессию до 3 раз с интервалом 1 секунда
  - После 3 неудачных попыток возвращается финальная ошибка

### FR-REQ-SESSION-003: Подписка на изменения сессии

Система должна реагировать на изменения сессии в приложении.

#### AC-9.3.1: Автоматическое обновление при изменении сессии
- **Дано:** Сессия изменилась (logout, login, refresh token)
- **Когда:** NextAuth обновляет сессию
- **Тогда:** `useSession` автоматически обновляет данные через React Context

## 4. Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-09-01 | Сессия должна быть валидной | Все данные сессии должны быть валидны согласно схеме Session | Zod валидация при получении данных |
| BR-09-02 | Загрузка должна быть показана | При первой загрузке или refresh состояние loading должно быть true | UI-компоненты должны обрабатывать loading |
| BR-09-03 | Ошибки должны быть человеко-читаемыми | Все ошибки должны иметь понятные сообщения на русском языке | Локализация ошибок |
| BR-09-04 | Сессия должна обновляться при logout | После logout данные сессии должны быть сброшены | Метод refresh после logout |

## 5. Исключения и Граничные кейсы (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Нет подключения к интернету | Возвращается ошибка с кодом `NETWORK_ERROR` |
| 2 | Токен истёк | NextAuth автоматически refresh token или возвращает null |
| 3 | Multiple simultaneous calls | Каждый компонент получает свою копию данных, нет race conditions |
| 4 | Компонент размонтировался во время загрузки | useEffect отменяет запрос (cleanup) |
| 5 | Сессия содержит неполные данные | Ошибка валидации, возвращается null data |

## 6. Нефункциональные требования (NFR)

### Производительность
- **NFR-09-01:** Загрузка сессии < 200ms при наличии токена
- **NFR-09-02:** Обновление сессии через `refresh()` < 500ms

### Безопасность
- **NFR-09-03:** Не хранить sensitive данные в глобальном state
- **NFR-09-04:** Сессия не должна быть доступна вне React-компонентов

### Доступность
- **NFR-09-05:** Индикаторы загрузки должны быть доступны для screen readers
- **NFR-09-06:** Сообщения об ошибках должны быть доступны через aria-live

## 8. Типовая сигнатура хука

```typescript
interface SessionData {
  user: {
    id: string;
    email: string;
    name: string | null;
    roles: string[];
  };
  expires: string;
}

interface UseSessionReturn {
  data: SessionData | null;
  loading: boolean;
  error: SessionError | null;
  refresh: () => Promise<void>;
}

interface SessionError {
  code: string;
  message: string;
}

/**
 * Хук для получения состояния сессии пользователя
 * 
 * @returns {UseSessionReturn} Объект с данными сессии и методами управления
 * 
 * @spec
 * - data: объект сессии или null, если не авторизован
 * - loading: true во время загрузки сессии
 * - error: объект ошибки или null
 * - refresh(): метод для принудительного обновления сессии
 */
export function useSession(): UseSessionReturn;
```
