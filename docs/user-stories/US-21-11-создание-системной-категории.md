# US-21-11: Создание системной категории чатов

> Эпик: Система общения в СНТ (REQ-COMMS-001)

---

## Формулировка

**Как** администратор СНТ,
**я хочу** создавать системные категории для организации чатов по темам или участкам,
**чтобы** структурировать общение и упростить навигацию для всех пользователей.

---

## Целевое состояние

После реализации администратор сможет:
- Создавать системные категории (темы или названия участков)
- Задавать название и (опционально) описание категории
- Создавать подкатегории (1 уровень вложенности)
- Категории будут видны всем пользователям системы

---

## Контекст

### Проблема
Администраторы не имеют инструментария для структурирования чатов по темам или участкам. Чаты не имеют категоризации, что затрудняет поиск и навигацию.

### Решение
Создать административный интерфейс для управления системными категориями с поддержкой 1 уровня вложенности.

### Границы
- **Входит:** Создание категорий и подкатегорий (1 уровень), назначение категорий чатам, видимость всем пользователям.
- **Исключено:** Редактирование/удаление чужих категорий, делегирование прав на создание категорий.

---

## Функциональные требования

### FR-REQ-COMMS-001-15: Создание системной категории

Система должна позволять администраторам создавать системные категории для группировки чатов.

#### AC-11.1: Создание категории
- **Дано:** Администратор авторизован, открыта страница управления категориями
- **Когда:** Администратор заполняет форму создания категории
- **Тогда:** Категория создаётся в системе с указанным названием и опциональным описанием

#### AC-11.2: Валидация названия
- **Дано:** Администратор пытается создать категорию
- **Когда:** Название содержит менее 2 символов
- **Тогда:** Система отображает ошибку валидации
- **И тогда:** Название должно быть от 2 до 100 символов

#### AC-11.3: Уникальность названия
- **Дано:** Администратор пытается создать категорию
- **Когда:** Категория с таким названием уже существует на том же уровне вложенности
- **Тогда:** Система отображает ошибку дублирования

#### AC-11.4: Создание подкатегории
- **Дано:** Администратор находится на странице существующей категории
- **Когда:** Администратор выбирает опцию создания подкатегории
- **Тогда:** Создаётся подкатегория, связанная с родительской категорией (1 уровень вложенности)

#### AC-11.5: Иерархия категорий
- **Дано:** Система содержит категории и подкатегории
- **Когда:** Администратор просматривает структуру
- **Тогда:** Отображается дерево категорий с 1 уровнем вложенности
- **И тогда:** Нельзя создавать вложенность更深е 1 уровня (подкатегории не имеют своих подкатегорий)

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-11-01 | Роль | Только ADMIN и SUPER_ADMIN могут создавать системные категории | Проверка роли перед созданием |
| BR-11-02 | Уникальность | Название категории должно быть уникальным в пределах родительской категории | Проверка на уровне БД |
| BR-11-03 | Вложенность | Максимум 1 уровень вложенности (категория -> подкатегория) | Проверка при создании |
| BR-11-04 | Видимость | Все категории видны всем пользователям системы | Нет ограничений по доступу |
| BR-11-05 | Удаление | При удалении категории чаты перемещаются в "Без категории" | Автоматическое перемещение |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Попытка создать категорию с названием < 2 символов | Ошибка валидации |
| 2 | Попытка создать подкатегорию у подкатегории | Ошибка: "Нельзя создавать подкатегории у подкатегорий" |
| 3 | Попытка создать категорию с названием > 100 символов | Ошибка валидации |
| 4 | Попытка создать категорию с тем же названием в пределах одной родительской | Ошибка дублирования |
| 5 | Попытка администратора создать категорию | Ошибка: Недостаточно прав |

### Repository (реализация Prisma)

```typescript
/**
 * @repository CategoryRepository
 * @implements ICategoryRepository
 * @description Реализация репозитория категорий на базе Prisma
 */
export class CategoryRepository implements ICategoryRepository {
  constructor(private prisma: PrismaClient) {}

  async findAllRootCategories(): Promise<Category[]> {
    return this.prisma.category.findMany({
      where: { parentId: null },
      include: {
        children: true,
      },
      orderBy: { name: 'asc' },
    });
  }

  async findChildrenByParentId(parentId: string): Promise<Category[]> {
    return this.prisma.category.findMany({
      where: { parentId },
      orderBy: { name: 'asc' },
    });
  }

  async findById(id: string): Promise<Category | null> {
    return this.prisma.category.findUnique({
      where: { id },
    });
  }

  async existsByName(name: string, parentId: string | null): Promise<boolean> {
    const result = await this.prisma.category.findFirst({
      where: {
        name,
        parentId,
      },
    });
    return result !== null;
  }

  async create(data: CreateCategoryData): Promise<Category> {
    const { name, description, parentId } = data;

    // Проверка дубликата
    if (await this.existsByName(name, parentId)) {
      throw new CategoryAlreadyExistsError();
    }

    // Проверка вложенности
    if (parentId) {
      const parent = await this.findById(parentId);
      if (!parent) {
        throw new CategoryNotFoundInHierarchyError();
      }
      if (parent.parentId) {
        throw new NestedCategoryError();
      }
    }

    return this.prisma.category.create({
      data: {
        name,
        description: description || null,
        parentId,
      },
    });
  }

  async update(id: string, data: UpdateCategoryData): Promise<Category> {
    const existing = await this.findById(id);
    if (!existing) {
      throw new CategoryNotFoundError();
    }

    // Проверка уникальности при изменении названия
    if (data.name && data.name !== existing.name) {
      const exists = await this.existsByName(data.name, existing.parentId);
      if (exists) {
        throw new CategoryAlreadyExistsError();
      }
    }

    return this.prisma.category.update({
      where: { id },
      data: {
        ...(data.name !== undefined ? { name: data.name } : {}),
        ...(data.description !== undefined ? { description: data.description || null } : {}),
      },
    });
  }

  async delete(id: string): Promise<void> {
    await this.prisma.chat.updateMany({
      where: { category_id: id },
      data: { category_id: null },
    });

    await this.prisma.category.delete({
      where: { id },
    });
  }

  async getWithChildren(categoryId: string): Promise<CategoryWithChildren> {
    return this.prisma.category.findUnique({
      where: { id: categoryId },
      include: {
        children: true,
      },
    });
  }
}
```

### Service

```typescript
/**
 * @service CategoryService
 * @domain comms
 * @description Бизнес-логика управления системными категориями чатов
 *
 * @spec
 * - Валидация: через Zod-схемы из category.validators.ts
 * - Ошибки: CategoryAlreadyExistsError, NestedCategoryError, CategoryNotFoundError
 * - Зависимости: ICategoryRepository через DI
 */
export class CategoryService {
  constructor(private categoryRepository: ICategoryRepository) {}

  async findAllRootCategories(): Promise<Category[]> {
    return this.categoryRepository.findAllRootCategories();
  }

  async findChildrenByParentId(parentId: string): Promise<Category[]> {
    return this.categoryRepository.findChildrenByParentId(parentId);
  }

  async createCategory(data: CreateCategoryData, userId: string): Promise<Category> {
    // Проверка роли (admin/super_admin) должна быть выполнена до вызова
    return this.categoryRepository.create(data);
  }

  async updateCategory(id: string, data: UpdateCategoryData, userId: string): Promise<Category> {
    // Проверка роли должна быть выполнена до вызова
    return this.categoryRepository.update(id, data);
  }

  async deleteCategory(id: string, userId: string): Promise<void> {
    // Проверка роли должна быть выполнена до вызова
    await this.categoryRepository.delete(id);
  }
}
```
