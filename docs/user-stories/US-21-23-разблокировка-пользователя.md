# US-21-23: Разблокировка пользователя

## Формулировка
**Как** модератор (или супер-администратор),
**я хочу** разблокировать пользователей, у которых истек срок блокировки или по решению модерации,
**чтобы** они могли восстановить доступ к чату и繼續正常使用 систему.

## Целевое состояние
Модератор может вручную разблокировать пользователя до истечения срока блокировки или подтвердить автоматическую разблокировку после истечения срока. После разблокировки пользователь получает полный доступ к чату.

### Границы
- Разблокировка доступна только модераторам и супер-администраторам.
- Автоматическая разблокировка происходит после истечения срока блокировки.
- Ручная разблокировка может быть выполнена в любое время до истечения срока.
- Пользователь, который разблокирован, получает уведомление.
- Модератор должен оставить комментарий при ручной разблокировке.

## Функциональные требования

### FR-REQ-COMMS-001-23: Ручная разблокировка пользователя

#### AC-23.1: Разблокировка до истечения срока
- **Дано:** Пользователь заблокирован, модератор находится на странице карточки пользователя.
- **Когда:** Модератор нажимает "Разблокировать", вводит комментарий и подтверждает.
- **Тогда:**
  - Статус пользователя меняется на "Активен" (`isBlocked = false`).
  - `blockedUntil` устанавливается в `null` или текущее время.
  - Пользователь получает полный доступ к чату.
  - Пользователь получает уведомление о разблокировке.
  - Действие записывается в историю блокировок.

#### AC-23.2: Автоматическая разблокировка по истечении срока
- **Дано:** Пользователь заблокирован на определенный срок.
- **Когда:** Текущее время превышает `blockedUntil`.
- **Тогда:**
  - Система автоматически устанавливает `isBlocked = false`.
  - `blockedUntil` устанавливается в `null`.
  - Пользователь получает полный доступ к чату.
  - Может генерироваться уведомление о разблокировке (опционально).
  - Запись в истории блокировок помечается как "Автоматически разблокирован".

#### AC-23.3: Разблокировка навсегда заблокированного пользователя
- **Дано:** Пользователь заблокирован "навсегда" (`blockedUntil = null`, `isBlocked = true`).
- **Когда:** Модератор (только SUPER_ADMIN) нажимает "Разблокировать навсегда".
- **Тогда:**
  - Статус пользователя меняется на "Активен".
  - Все поля блокировки очищаются.
  - Пользователь получает полный доступ.
  - Действие записывается в историю с пометкой "Разблокирован супер-администратором".

### FR-REQ-COMMS-001-24: Ведение истории разблокировок
- **Дано:** Пользователь был разблокирован (ручно или автоматически).
- **Когда:** Модератор открывает карточку пользователя.
- **Тогда:**
  - Отображается запись о разблокировке: кто разблокировал, когда, комментарий (если ручной).
  - История блокировок полна и актуальна.

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-23-01 | Право модератора | Разблокировать может модератор/SUPER_ADMIN. | Проверка роли в API. |
| BR-23-02 | Комментарий для ручной разблокировки | Ручная разблокировка требует комментария. | Валидация `comment` для ручного действия. |
| BR-23-03 | Автоматическая разблокировка | Система должна автоматически разблокировать по истечении срока. | Крон-джоб или проверка перед каждым запросом API. |
| BR-23-04 | Уведомление | Пользователь должен получить уведомление о разблокировке. | Генерация уведомления после разблокировки. |
| BR-23-05 | История | Все разблокировки должны записываться в историю. | Создание записи в `UserBlockLog` с типом `Unblocked`. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Попытка разблокировать уже разблокированного пользователя | Операция отклоняется, отображается "Пользователь уже разблокирован". |
| 2 | Разблокировка пользователя, который не заблокирован | Операция отклоняется с ошибкой 400. |
| 3 | Разблокировка заблокированного модератора | Доступна только SUPER_ADMIN. |
| 4 | Разблокировка во время автоматической разблокировки | Конфликт обрабатывается: ручная разблокировка имеет приоритет. |
| 5 | Разблокировка пользователя, который находится в процессе блокировки другим модератором | Серверная блокировка или последняя операция побеждает. |
| 6 | Разблокировка пользователя с некорректным `blockedUntil` в прошлом | Автоматическая разблокировка должна произойти при следующем запросе. |

## Модель данных
Добавление записи в `UserBlockLog` с типом "Unblocked".

**Обновление таблицы `users`:**
```prisma
model User {
  // ... другие поля
  isBlocked    Boolean  @default(false) @map("is_blocked")
  blockedAt    DateTime? @map("blocked_at")
  blockedUntil DateTime? @map("blocked_until")
  blockedBy    String?  @map("blocked_by")
}
```

**Таблица истории блокировок (обновление):**
```prisma
model UserBlockLog {
  id          String   @id @default(cuid())
  userId      String   @map("user_id")
  blockedBy   String   @map("blocked_by")
  actionType  String   // "Blocked", "Unblocked"
  reason      String   @map("reason")
  blockedAt   DateTime @default(now()) @map("blocked_at")
  blockedUntil DateTime? @map("blocked_until")
}
```

## Нефункциональные требования
- **Производительность:** Автоматическая разблокировка должна обрабатываться в фоновом режиме (cron job).
- **Безопасность:** Проверка прав модератора на разблокировку.
- **Надежность:** Автоматическая разблокировка должна срабатывать даже при перезагрузке системы.
- **Аудит:** Все разблокировки должны записываться в историю с указанием модератора.
