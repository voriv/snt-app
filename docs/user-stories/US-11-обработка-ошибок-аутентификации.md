# US-11: Обработка ошибок аутентификации

## 1. Контекст

### Проблема
В текущей реализации страницы входа и регистрации отсутствуют обработанные ошибки с понятными пользовательскими сообщениями на русском языке. Пользователи не получают обратной связи о причинах неудачных попыток аутентификации или регистрации.

### Решение
Реализовать обработку ошибок на всех слоях — от доменных ошибок до пользовательских сообщений в UI. Все сообщения об ошибках должны быть на русском языке и сформулированы в понятной для пользователя форме.

### Границы
- **Включено:** Обработка ошибок валидации, ошибок аутентификации (неверный пароль, несуществующий email), ошибок сети
- **Исключено:** Обработка технических ошибок сервера (500), логирование ошибок для администраторов

## 2. Пользовательская история

**Как** пользователь приложения,
**я хочу** получать понятные сообщения об ошибках на русском языке,
**чтобы** понимать причину неудачи и знать, как её исправить.

## 3. Функциональные требования

### FR-REQ-AUTH-011-01: Обработка ошибок аутентификации

Система должна обрабатывать и отображать ошибки аутентификации с понятными сообщениями.

#### AC-11.1.1: Общие ошибки входа

- **Дано:** Пользователь вводит некорректные учётные данные
- **Когда:** Пользователь нажимает кнопку "Войти"
- **Тогда:** Система отображает сообщение "Неверный email или пароль"

**Примечание:** Сообщение должно быть общим для "неверный пароль" и "email не найден" — см. BR-03 в REQ-AUTH-001.

#### AC-11.1.2: Сообщение об ошибке

- **Дано:** Пользователь находится на странице входа
- **Когда:** Произошла ошибка аутентификации
- **Тогда:** Сообщение об ошибке отображается в верхней части формы и доступно для скринридеров

#### AC-11.1.3: Сохранение данных после ошибки

- **Дано:** Пользователь ввёл данные и получил ошибку
- **Когда:** Ошибка отображена
- **Тогда:** Поля формы сохраняют введённые данные для упрощения исправления

#### AC-11.1.4: Разблокировка кнопки после ошибки

- **Дано:** Пользователь получил ошибку аутентификации
- **Когда:** Ошибка отображена
- **Тогда:** Кнопка "Войти" разблокируется для повторной попытки

### FR-REQ-AUTH-011-02: Обработка ошибок валидации

Система должна валидировать входные данные и отображать ошибки.

#### AC-11.2.1: Валидация пустых полей

- **Дано:** Пользователь пытается отправить пустую форму
- **Когда:** Пользователь нажимает кнопку отправки
- **Тогда:** Система отображает сообщение "Заполните все обязательные поля"

#### AC-11.2.2: Inline валидация email

- **Дано:** Пользователь ввёл невалидный email
- **Когда:** Поле теряет фокус
- **Тогда:** Система отображает сообщение "Некорректный формат email"

#### AC-11.2.3: Inline валидация пароля

- **Дано:** Пользователь ввёл короткий пароль
- **Когда:** Поле теряет фокус
- **Тогда:** Система отображает сообщение "Минимум 6 символов"

### FR-REQ-AUTH-011-03: Обработка ошибок регистрации

Система должна обрабатывать и отображать ошибки регистрации.

#### AC-11.3.1: Дублирование email

- **Дано:** Пользователь пытается зарегистрироваться с существующим email
- **Когда:** Пользователь нажимает кнопку "Зарегистрироваться"
- **Тогда:** Система отображает сообщение "Пользователь с таким email уже зарегистрирован"

#### AC-11.3.2: Несоответствие паролей

- **Дано:** Пользователь ввёл разные пароли в поля "Пароль" и "Подтверждение пароля"
- **Когда:** Поле подтверждения теряет фокус
- **Тогда:** Система отображает сообщение "Пароли не совпадают"

#### AC-11.3.3: Обработка успешной регистрации

- **Дано:** Пользователь ввёл корректные данные
- **Когда:** Регистрация успешна
- **Тогда:** Система показывает сообщение "Успешная регистрация! Перенаправление на страницу входа..." и переходит на /login

### FR-REQ-AUTH-011-04: Локализация сообщений

Все сообщения должны быть на русском языке.

#### AC-11.4.1: Язык сообщений

- **Дано:** Пользователь находится на странице входа или регистрации
- **Тогда:** Все сообщения об ошибках на русском языке

## 4. Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-11.1 | Общее сообщение об ошибке входа | Система должна использовать одинаковое сообщение для "неверный пароль" и "email не найден" | Защита от атак перебором email |
| BR-11.2 | Пустые поля обязательны | Все поля формы обязательны для отправки | Client-side валидация |
| BR-11.3 | Формат email | Email должен соответствовать RFC 5322 | Email-валидатор |
| BR-11.4 | Минимальная длина пароля | Пароль должен содержать минимум 6 символов | Password-валидатор |
| BR-11.5 | Совпадение паролей | Поля "Пароль" и "Подтверждение пароля" должны совпадать | Password-confirmation validator |
| BR-11.6 | Уникальность email | Email должен быть уникальным в системе | DB constraint + service validation |

## 5. Исключения и Граничные кейсы (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | EC-11.1: Медленная сеть (более 3 секунд) | Показать индикатор загрузки, после таймаута — сообщение "Ошибка соединения с сервером" |
| 2 | EC-11.2: Сервер вернул 500 | Показать сообщение "Внутренняя ошибка сервера. Попробуйте позже" |
| 3 | EC-11.3: Пароль короче 6 символов | Показать inline-ошибку "Минимум 6 символов" |
| 4 | EC-11.4: Пароли не совпадают | Показать inline-ошибку "Пароли не совпадают" |
| 5 | EC-11.5: Email в верхнем регистре | Автоматически конвертировать в нижний регистр перед отправкой |
| 6 | EC-11.6: Email с ведущими/конечными пробелами | Обрезать пробелы перед отправкой |
| 7 | EC-11.7: Повторная попытка после ошибки | Кнопка должна быть разблокирована для повторного нажатия |
| 8 | EC-11.8: Отмена отправки | При повторном нажатии на кнопку после ошибки — форма должна быть готова к отправке |

## 6. Нефункциональные требования (NFR) и Ограничения

| Категория | Требование |
|-----------|-----------|
| **Локализация** | Все сообщения об ошибках на русском языке |
| **Доступность** | Ошибки доступны для скринридеров (aria-live="polite" / "assertive") |
| **Безопасность** | Не раскрывать, какой именно учётный данные неверен (email или пароль) |
| **UX** | Сообщение об ошибке должно быть над формой, а не внутри поля |

## 8. Типовая сигнатура обработчика ошибок

```typescript
/**
 * Обработка ошибки в UI-компоненте
 */
function useAuthError() {
  const [error, setError] = useState<string | null>(null);

  const handleError = useCallback((err: unknown) => {
    if (err instanceof BaseError) {
      setError(err.message);
      return;
    }
    
    // Network error handling
    if (err instanceof TypeError && err.message.includes('fetch')) {
      setError('Ошибка соединения с сервером');
      return;
    }

    // Generic error
    setError('Произошла неизвестная ошибка');
  }, []);

  return { error, setError, handleError };
}
```
