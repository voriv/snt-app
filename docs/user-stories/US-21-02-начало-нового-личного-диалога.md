# US-21-02: Начало нового личного диалога

> Эпик: Система общения в СНТ (REQ-COMMS-001)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** начать новый личный диалог с другим пользователем,
**чтобы** отправить первое сообщение и установить коммуникацию.

---

## Целевое состояние

Пользователь сможет нажать кнопку «Написать сообщение» на `/dashboard/comms/messages`, перейти на страницу выбора собеседника `/dashboard/comms/messages/new`, найти пользователя по имени/email через поиск, выбрать его и быть автоматически перенаправленным на страницу диалога `/dashboard/comms/messages/:conversationId`, готовую к отправке первого сообщения.

---

## Контекст

### Проблема

Пользователи не могут инициировать новые личные диалоги. Отсутствует механизм выбора собеседника и создания диалога.

### Решение

Создать страницу `/dashboard/comms/messages/new` со списком пользователей и поиском. При выборе пользователя система проверяет, существует ли уже диалог: если да — редирект в существующий, если нет — создание нового диалога и редирект к нему.

### Границы

- **Входит в US:** Страница выбора собеседника с поиском, проверка существования диалога, создание нового диалога, редирект к диалогу.
- **Явно исключено:** Отправка сообщений (US-21-03), групповые чаты.

---

## Функциональные требования

### FR-REQ-COMMS-001-01: Начало личного диалога

Система должна позволять пользователю начать личный диалог с другим пользователем.

#### AC-1.1: Открытие страницы выбора собеседника

- **Дано:** Пользователь авторизован и находится на `/dashboard/comms/messages`
- **Когда:** Пользователь нажимает кнопку «Написать сообщение»
- **Тогда:** Пользователь переходит на `/dashboard/comms/messages/new` с полем поиска и списком пользователей

#### AC-1.2: Поиск пользователя

- **Дано:** Пользователь на странице `/dashboard/comms/messages/new`
- **Когда:** Пользователь вводит текст в поле поиска (минимум 2 символа, debounce 300ms)
- **Тогда:** Список фильтруется по имени и email пользователей через `GET /api/v1/users/search?q=...`

#### AC-1.3: Выбор собеседника — создание нового диалога

- **Дано:** Пользователь выбрал собеседника, с которым нет активного диалога
- **Когда:** Пользователь кликает на пользователя
- **Тогда:** Система создаёт новый диалог через `POST /api/v1/conversations` и перенаправляет на `/dashboard/comms/messages/:conversationId`

#### AC-1.4: Выбор собеседника — редирект в существующий диалог

- **Дано:** Пользователь выбрал собеседника, с которым уже есть активный диалог
- **Когда:** Пользователь кликает на пользователя
- **Тогда:** Система перенаправляет на существующий диалог `/dashboard/comms/messages/:conversationId`

#### AC-1.5: Блокировка выбора себя

- **Дано:** Пользователь на странице выбора собеседника
- **Когда:** Система рендерит список
- **Тогда:** Текущий пользователь исключён из списка

#### AC-1.6: Блокировка выбора заблокированного пользователя

- **Дано:** Пользователь на странице выбора собеседника
- **Когда:** Система рендерит список
- **Тогда:** Заблокированные пользователи исключены из списка

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-01 | Авторизация | Только авторизованные пользователи | `auth()` в API, `useSession()` на странице |
| BR-27 | Блокировка | Заблокированный пользователь не может участвовать в чатах | Исключение из списка пользователей |
| Уникальность диалога | Диалог между двумя пользователями создаётся только один раз | Проверка существования перед созданием |

---

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Список пользователей пуст | `EmptyState` с текстом «Нет доступных пользователей» |
| 2 | Поиск не нашёл результатов | `EmptyState` с текстом «Пользователь не найден» |
| 3 | Ошибка при создании диалога | Сообщение об ошибке с кнопкой «Повторить» |
| 4 | Медленная сеть | Индикатор загрузки |
| 5 | Пользователь выбрал себя | Невозможно — исключён из списка |
