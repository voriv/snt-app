# US-21-26: Отмена предупреждения пользователю

## Формулировка
**Как** модератор (или супер-администратор),
**я хочу** отменять выданные предупреждения,
**чтобы** корректировать ошибки модерации и учитывать исправление поведения пользователя.

## Целевое состояние
Модератор может отменить выданное предупреждение, указав причину отмены. После отмены предупреждение помечается как аннулированное, не учитывается в общем счете предупреждений, но сохраняется в истории для аудита.

### Границы
- Отмена доступна только модераторам и супер-администраторам.
- Отменить можно только активные предупреждения (не истекшие).
- Отмененные предупреждения не удаляются, а помечаются как "Аннулировано" (soft delete).
- Модератор должен указать причину отмены.
- Пользователь получает уведомление об отмене предупреждения.
- Отмена записывается в историю с указанием модератора и причины.

## Функциональные требования

### FR-REQ-COMMS-001-26: Отмена предупреждения

#### AC-26.1: Отмена активного предупреждения
- **Дано:** Модератор находится на странице истории предупреждений пользователя и видит активное предупреждение.
- **Когда:** Модератор нажимает "Отменить предупреждение", вводит причину и подтверждает.
- **Тогда:**
  - Предупреждение помечается как "Аннулировано" (`isAnnulled = true`).
  - Предупреждение не учитывается в общем счете предупреждений пользователя.
  - `warningCount` пользователя уменьшается на 1.
  - Пользователь получает уведомление об отмене предупреждения.
  - Модератор видит уведомление "Предупреждение отменено".

#### AC-26.2: Требуемый комментарий
- **Дано:** Модератор пытается отменить предупреждение без указания причины.
- **Когда:** Модератор нажимает "Отменить" без ввода комментария.
- **Тогда:**
  - Система отклоняет операцию.
  - Поле "Причина отмены" подсвечивается как обязательное.
  - Отображается сообщение "Пожалуйста, укажите причину отмены".

#### AC-26.3: Отмена неактивного предупреждения
- **Дано:** Модератор видит истекшее предупреждение.
- **Когда:** Модератор пытается отменить истекшее предупреждение.
- **Тогда:**
  - Кнопка "Отменить" не отображается или заблокирована.
  - API возвращает ошибку 400 "Предупреждение не может быть отменено (истекло)".

### FR-REQ-COMMS-001-27: Ведение истории отмен
- **Дано:** Предупреждение было отменено модератором.
- **Когда:** Модератор открывает историю предупреждений пользователя.
- **Тогда:**
  - Отмененные предупреждения помечены визуально (цвет, статус "Аннулировано").
  - Отображается причина отмены и модератор, который отменил.
  - Уменьшение `warningCount` отражается в карточке пользователя.

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-26-01 | Право модератора | Отменять может только модератор/SUPER_ADMIN. | Проверка роли в API. |
| BR-26-02 | Комментарий обязателен | Отмена возможна только с причиной. | Валидация `reason` как обязательного поля. |
| BR-26-03 | Активное предупреждение | Отменить можно только активные предупреждения. | Проверка `is_active` перед отменой. |
| BR-26-04 | Soft delete | Отмененные предупреждения сохраняются для аудита. | Изменение поля `isAnnulled`, а не DELETE. |
| BR-26-05 | Уведомление | Пользователь должен получить уведомление об отмене. | Генерация уведомления после отмены. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Отмена предупреждения, которое уже отменено | Операция отклоняется с ошибкой 400 "Предупреждение уже отменено". |
| 2 | Отмена предупреждения, которое истекло | Операция отклоняется с ошибкой 400 "Предупреждение не может быть отменено (истекло)". |
| 3 | Отмена предупреждения, которое уже аннулировано другим модератором | Конфликт разрешается: операция отклоняется или применяется последняя. |
| 4 | Отмена предупреждения при сетевой ошибке | Операция не выполняется, пользователь получает ошибку "Не удалось отменить предупреждение". |
| 5 | Отмена предупреждения, которое было включено в автоматическую блокировку | `warningCount` уменьшается, блокировка пересчитывается (опционально). |
| 6 | Отмена предупреждения во время модерации другого пользователя | Серверная блокировка или последняя операция побеждает. |

## Модель данных
Добавление поля `isAnnulled` и `annulledBy` в таблицу `user_warnings`.

**Обновление таблицы `user_warnings`:**
```prisma
model UserWarning {
  id              String   @id @default(cuid())
  userId          String   @map("user_id")
  moderatorId     String   @map("moderator_id")
  violationType   String   @map("violation_type")
  reason          String   @map("reason")
  createdAt       DateTime @default(now()) @map("created_at")
  expiresAt       DateTime? @map("expires_at")
  isAnnulled      Boolean  @default(false) @map("is_annulled")
  annulledAt      DateTime? @map("annulled_at")
  annulledBy      String?  @map("annulled_by") // ID модератора, который отменил
  annulmentReason String?  @map("annulment_reason") // Причина отмены
}
```

**Обновление таблицы `users`:**
- `warningCount` должен учитывать только активные, неаннулированные предупреждения.

- **Производительность:** Отмена предупреждения < 200мс.

- **Аудит:** Все отмены должны записываться с указанием модератора и причины.
