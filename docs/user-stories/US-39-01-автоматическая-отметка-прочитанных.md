# US-39-01: Автоматическая отметка прочитанных сообщений при открытии диалога/чата

> Эпик: Система общения в СНТ (REQ-COMMS-001)
> Требование: [REQ-COMMS-003](../requirements/REQ-COMMS-003.md)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** чтобы при открытии личного диалога или группового чата все непрочитанные сообщения автоматически помечались как прочитанные,
**чтобы** мне не нужно было вручную отмечать каждое сообщение, и счётчики непрочитанных всегда были актуальными.

---

## Целевое состояние

После реализации при открытии любого личного диалога (`/dashboard/comms/messages/[conversationId]`) или группового чата (`/dashboard/comms/chats/[chatId]`) система автоматически вызывает API для обновления `lastReadAt` текущего пользователя в этом диалоге/чате. После успешного вызова:

- Все сообщения от других участников, существующие на момент открытия, считаются прочитанными для текущего пользователя
- Счётчик непрочитанных в списке диалогов/чатов обнуляется для этой беседы
- Счётчики на вкладках обновляются (уменьшаются)
- Статус прочтения (read receipts) обновляется у отправителей сообщений при следующей загрузке

Обновление `lastReadAt` идемпотентно: повторное открытие уже прочитанного диалога не вызывает ошибку и не меняет состояние.

---

## Модель данных

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| `ConversationParticipant` | Хранит `lastReadAt` — временную метку последнего прочтения диалога участником | `docs/model/entities/` (сущность в schema.prisma) |
| `ChatParticipant` | Хранит `lastReadAt` — временную метку последнего прочтения чата участником | `docs/model/entities/` (сущность в schema.prisma) |

**Механика:** При вызове API отметки прочитанных сервер обновляет `lastReadAt` участника на текущий timestamp. Сообщения с `createdAt <= lastReadAt` считаются прочитанными для данного участника.

---

## Поведение (User Behavior)

### B-1: Открытие личного диалога с непрочитанными сообщениями
Пользователь видит бейдж «3» на карточке диалога в списке. Пользователь кликает на диалог, открывается страница переписки. Клиент немедленно вызывает `PATCH /api/v1/conversations/:id/read`. Сервер обновляет `ConversationParticipant.lastReadAt = now()`. Бейдж на карточке диалога исчезает (обнуляется). Счётчик на вкладке «Личные сообщения» уменьшается на количество прочитанных.

### B-2: Открытие группового чата с непрочитанными сообщениями
Пользователь видит бейдж «5» на карточке чата в списке. Пользователь кликает на чат, открывается страница переписки. Клиент немедленно вызывает `PATCH /api/v1/chats/:id/read`. Сервер обновляет `ChatParticipant.lastReadAt = now()`. Бейдж на карточке чата исчезает. Счётчик на вкладке «Групповые чаты» уменьшается.

### B-3: Повторное открытие уже прочитанного диалога
Пользователь открывает диалог, в котором все сообщения уже прочитаны. Клиент вызывает `PATCH /api/v1/conversations/:id/read`. Сервер обновляет `lastReadAt` (идемпотентно). Счётчик остаётся нулевым, ошибки не возникает.

### B-4: Свои сообщения не учитываются
Пользователь отправил сообщение в диалог и затем покинул страницу. При повторном открытии диалога это сообщение не увеличивает счётчик непрочитанных для автора — оно исключено из подсчёта.

## Критерии приёмки

### AC-1: Отметка прочитанных при открытии личного диалога
- **Given:** У пользователя есть 3 непрочитанных сообщения в личном диалоге
- **When:** Пользователь открывает этот диалог
- **Then:** Клиент вызывает `PATCH /api/v1/conversations/:id/read`, сервер обновляет `lastReadAt`, все 3 сообщения помечаются прочитанными, бейдж на карточке диалога обнуляется

### AC-2: Отметка прочитанных при открытии группового чата
- **Given:** У пользователя есть 5 непрочитанных сообщений в групповом чате
- **When:** Пользователь открывает этот чат
- **Then:** Клиент вызывает `PATCH /api/v1/chats/:id/read`, сервер обновляет `lastReadAt`, все 5 сообщений помечаются прочитанными, бейдж на карточке чата обнуляется

### AC-3: Свои сообщения не влияют на счётчик
- **Given:** Пользователь отправил сообщение в диалог и покинул страницу
- **When:** Пользователь снова открывает этот диалог
- **Then:** Собственное сообщение не учитывается в счётчике непрочитанных для автора

### AC-4: Идемпотентность вызова API
- **Given:** Пользователь открывает диалог, в котором все сообщения уже прочитаны
- **When:** Клиент вызывает `PATCH /api/v1/conversations/:id/read`
- **Then:** Сервер обновляет `lastReadAt` без ошибки, счётчик остаётся нулевым

### AC-5: Обновление счётчиков на вкладках после прочтения
- **Given:** Счётчик на вкладке «Личные сообщения» показывает «5»
- **When:** Пользователь открывает диалог с 3 непрочитанными
- **Then:** Счётчик на вкладке обновляется до «2» после успешной отметки прочитанных

### AC-6: Ошибка сети при отметке не блокирует интерфейс
- **Given:** Сеть недоступна при открытии диалога
- **When:** Пользователь открывает диалог
- **Then:** Пользователь видит сообщения, статус прочтения обновится при следующем подключении

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-01 | При открытии диалога/чата все сообщения от других участников до момента открытия помечаются прочитанными | Server-side: `lastReadAt = now()` |
| BR-02 | Сообщения, отправленные самим пользователем, никогда не учитываются в счётчике непрочитанных | Server-side: `WHERE senderId != userId` |
| BR-03 | Непрочитанным считается сообщение от другого участника, появившееся после последнего захода пользователя в диалог/чат | Server-side: `messages.createdAt > participant.lastReadAt AND senderId != userId` |
| BR-04 | Если пользователь ни разу не открывал диалог/чат, все сообщения от собеседников считаются непрочитанными | `lastReadAt IS NULL` → все входящие непрочитаны |
| BR-05 | Ошибка при обновлении статуса прочтения не блокирует пользователя | Client-side: try/catch, silent fail |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Сеть недоступна при отправке статуса прочтения | Сообщения остаются видимыми, статус обновится при следующем подключении |
| 2 | Пользователь быстро переключается между диалогами | Система корректно помечает прочитанными тот диалог, который был открыт достаточно долго для загрузки |
| 3 | В групповом чате больше 100 участников | `lastReadAt` обновляется для текущего пользователя независимо от числа участников |
| 4 | Собеседник открыл диалог, но не видит конкретное сообщение (за пределами видимости) | Статус «прочитано» активируется, так как диалог был открыт |
| 5 | Пользователь заходит в диалог, в котором все уже прочитано | `lastReadAt` обновляется идемпотентно, счётчик остаётся нулевым |
| 6 | Пользователь отправляет сообщение сам себе в групповом чате | Сообщение не учитывается в счётчике непрочитанных для автора |

## Влияние на слои архитектуры

### Модель данных
- [x] Без изменений — используется существующее поле `lastReadAt` в `ConversationParticipant` и `ChatParticipant`

### Repository
- [ ] Новые методы:
  - `IConversationRepository.markAsRead(conversationId, userId): Promise<void>` — обновляет `ConversationParticipant.lastReadAt = now()`
  - `IChatRepository.markAsRead(chatId, userId): Promise<void>` — обновляет `ChatParticipant.lastReadAt = now()`

### Service
- [ ] Новые методы:
  - `CommsService.markConversationAsRead(conversationId, userId): Promise<void>`
  - `CommsService.markChatAsRead(chatId, userId): Promise<void>`
- [ ] Новые Zod-схемы: параметры валидации `conversationId`/`chatId` (UUID)
- [ ] Новые доменные ошибки: `ConversationNotFoundError`, `ChatNotFoundError`, `ParticipantNotFoundError`

### API

| Метод | Путь | Описание | Авторизация |
|-------|------|----------|-------------|

| PATCH | `/api/v1/chats/:id/read` | Отметка группового чата как прочитанного | Required (участник чата) |

---

## Нефункциональные требования

- **Производительность:** Обновление статуса прочтения должно происходить в течение 1 секунды после открытия диалога/чата
- **Отказоустойчивость:** Ошибка при обновлении статуса прочтения не блокирует основной интерфейс — пользователь продолжает видеть сообщения
- **Безопасность:** Только авторизованный участник диалога/чата может отметить его как прочитанный
