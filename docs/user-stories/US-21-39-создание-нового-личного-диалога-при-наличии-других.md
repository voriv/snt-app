# US-21-39: Создание нового личного диалога при наличии других диалогов

> Эпик: Система общения в СНТ (REQ-COMMS-004)

---

## Формулировка

**Как** зарегистрированный пользователь СНТ,
**я хочу** начать новый личный диалог с пользователем, с которым у меня ещё нет диалога, даже если у меня уже есть диалоги с другими пользователями,
**чтобы** я мог вступить в коммуникацию с новым собеседником, не теряя уже существующие диалоги.

---

## Целевое состояние

На странице `/dashboard/comms/messages/new` пользователь может выбрать собеседника, с которым у него ещё нет активного личного диалога. При выборе система через `POST /api/v1/conversations` создаёт новый диалог (`201 Created`, `{ conversationId, isNew: true }`) и перенаправляет на `/dashboard/comms/messages/:conversationId`, готовый к отправке первого сообщения. Наличие других диалогов с иными пользователями не препятствует созданию нового диалога.

---

## Контекст

### Проблема

Пользователь, у которого уже есть диалоги с другими пользователями, должен иметь возможность начать диалог с новым собеседником. Функциональность должна корректно работать на фоне существующих диалогов и не блокироваться ими.

### Решение

Страница выбора собеседника запрашивает список пользователей и список существующих диалогов. Для пользователей без диалога отображается кнопка «Написать». При клике система создаёт новый диалог через API и перенаправляет к нему.

### Границы

- **Входит в US:** отображение списка пользователей без диалога с кнопкой «Написать», создание нового диалога через API, редирект в новый диалог, учёт наличия других диалогов.
- **Явно исключено:** Открытие существующего диалога / запрет дублирования (US-21-38). Отправка сообщений (US-21-03). Выбор самого себя и заблокированных пользователей (покрывается US-21-02). Групповые чаты.

## Функциональные требования

### FR-REQ-COMMS-004-03: Создание нового диалога

#### AC-1: Создание нового диалога с новым собеседником

- **Дано:** Пользователь A имеет диалог с Пользователем C, но не имеет диалога с Пользователем B
- **Когда:** Пользователь A вызывает `POST /api/v1/conversations` с `{ participantId: "B" }`
- **Тогда:** Сервер создаёт новый диалог и возвращает `201` с `{ conversationId: "conv-new", isNew: true }`

### FR-REQ-COMMS-004-09: Загрузка списка диалогов для определения кнопок

#### AC-2: Определение кнопки «Написать» для пользователя без диалога

- **Дано:** Пользователь A заходит на `/dashboard/comms/messages/new` и имеет диалог с C, но не с B
- **Когда:** Страница загружает список пользователей и существующих диалогов
- **Тогда:** Рядом с Пользователем B отображается кнопка «Написать» (у B нет диалога), рядом с C — «Открыть диалог»

### FR-REQ-COMMS-004-03: Переход в созданный диалог

#### AC-3: Редирект в новый диалог после создания

- **Дано:** Пользователь A выбрал пользователя B, с которым нет диалога
- **Когда:** Пользователь A кликает «Написать» и API возвращает 201 с `{ conversationId: "conv-new", isNew: true }`
- **Тогда:** Клиент редиректит на `/dashboard/comms/messages/conv-new`

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-01 | Один диалог на пару | Между двумя пользователями существует не более одного личного диалога (type = DIRECT) | Unique constraint в БД |
| BR-04 | Проверка на сервере | Проверка существования выполняется на backend | Сервис + unique constraint |
| BR-05 | UX-отметка | Для пользователей без диалога — кнопка «Написать», с диалогом — «Открыть диалог» | Frontend |

### Примеры валидаций
- **Новый диалог (BR-01):** при отсутствии диалога создаётся новый; проверка существования выполняется предварительно.
- **Проверка на себя и блокировку** выполняется до создания (покрывается US-21-02).

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пользователь находится на `/dashboard/comms/messages/new`, имеет диалоги с другими пользователями | Все собеседники без диалога отображаются с кнопкой «Написать»; создание диалога с новым собеседником не затрагивает существующие |
| 2 | Список пользователей без диалога пуст | `EmptyState` «Нет доступных пользователей» — кнопка «Написать» отсутствует |
| 3 | Ошибка при создании диалога | Сообщение об ошибке с кнопкой «Повторить» |
| 4 | Медленная сеть при создании | Индикатор загрузки |
| 5 | Диалог создался, но редирект не выполнен | Пользователь вручную может перейти по списку диалогов |

## Нефункциональные требования

- **Производительность:** Список пользователей и существующих диалогов загружается параллельно; создание диалога < 100 мс.
- **Безопасность:** Валидация на сервере обязательна; только авторизованные пользователи.
- **Доступность:** Кнопки «Написать» и «Открыть диалог» имеют различающиеся `aria-label` для скринридеров.
- **Локализация:** Тексты на русском языке.
