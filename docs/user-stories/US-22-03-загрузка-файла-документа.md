# US-22-03: Загрузка файла документа

> Эпик: Управление документами (REQ-DOCS-001)

---

## Формулировка

**Как** администратор СНТ,
**я хочу** загружать файлы документов на сервер,
**чтобы** хранить юридические и информационные документы в приложении.

---

## Целевое состояние

После реализации администратор сможет загрузить файл (PDF, DOCX, изображения и др.) через форму на странице `/dashboard/documents/upload`. Система валидирует тип файла и размер файла против настроенного ограничения. При успешной загрузке файл сохраняется в защищённом хранилище, а в БД создаётся запись-черновик с базовыми метаданными (originalName, fileSize, mimeType).

---

## Модель данных

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| Document | Загрузка файла создаёт черновик записи в `documents` | Будет создана |

### Ключевые поля сущности Document (для загрузки)
- `id` — varchar (PK, cuid)
- `originalName` — varchar(255), not null (имя файла на диске пользователя)
- `storagePath` — varchar(500), nullable (путь в хранилище)
- `fileSize` — integer, not null (размер в байтах)
- `mimeType` — varchar(100), not null
- `status` — varchar, default: 'draft' (draft, published, archived)
- `uploadedById` — varchar, ref → users.id
- `createdAt` — timestamp
- `updatedAt` — timestamp

---

## Поведение (User Behavior)

### B-1: Загрузка файла через форму
Администратор открывает страницу загрузки (`/dashboard/documents/upload`), выбирает файл через drag-and-drop или кнопку «Выбрать файл». Система валидирует тип и размер файла. При успешной проверке файл загружается на сервер и сохраняется. Администратор получает подтверждение загрузки.

### B-2: Отклонение файла неподдерживаемого типа
Администратор пытается загрузить файл с расширением `.exe`. Система отображает ошибку «Файлы этого типа не поддерживаются» и отклоняет загрузку.

### B-3: Отклонение файла, превышающего лимит размера
Администратор пытается загрузить файл размером 150 МБ при лимите 100 МБ. Система отображает ошибку «Размер файла превышает допустимый лимит (100 МБ)» и отклоняет загрузку.

## Критерии приёмки

### AC-1: Успешная загрузка PDF-файла
- **Given** администратор авторизован и открыл страницу загрузки
- **When** администратор загружает PDF-файл «Протокол_собрания.pdf» (5 МБ)
- **Then** файл сохраняется в хранилище; в БД создаётся запись Document со статусом draft; администратор видит подтверждение «Файл успешно загружен»

### AC-2: Поддержка DOCX-файла
- **Given** администратор открыл страницу загрузки
- **When** администратор загружает DOCX-файл «Договор.docx» (2 МБ)
- **Then** файл сохраняется в хранилище; создаётся запись Document

### AC-3: Поддержка изображений (JPG/PNG)
- **Given** администратор открыл страницу загрузки
- **When** администратор загружает изображение «Схема_участков.png» (1 МБ)
- **Then** файл сохраняется в хранилище; создаётся запись Document

### AC-4: Отклонение файла неподдерживаемого типа
- **Given** администратор открыл страницу загрузки
- **When** администратор загружает файл «virus.exe»
- **Then** система возвращает ошибку «Файлы этого типа не поддерживаются. Допустимые типы: PDF, DOCX, JPG, PNG, GIF, BMP, WEBP»

### AC-5: Отклонение файла, превышающего лимит размера
- **Given** максимальный размер файла — 100 МБ (настроен в конфигурации)
- **When** администратор загружает файл размером 150 МБ
- **Then** система возвращает ошибку «Размер файла превышает допустимый лимит (100 МБ)»

### AC-6: Отклонение файла с нулевым размером
- **Given** администратор открыл страницу загрузки
- **When** администратор загружает пустой файл (0 байт)
- **Then** система возвращает ошибку «Файл не может быть пустым»

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-09 | Максимальный размер файла настраивается в конфигурации | Runtime: чтение из env/config; валидация перед записью |
| BR-06 | Статусы: draft, published, archived | DB: enum |
| BR-07 | Черновик не виден пользователям (только админам) | Runtime: фильтрация по status в API |

### Поддерживаемые типы файлов (MIME + extension)
| MIME | Расширение |
|------|-----------|
| application/pdf | .pdf |
| application/vnd.openxmlformats-officedocument.wordprocessingml.document | .docx |
| image/jpeg | .jpg, .jpeg |
| image/png | .png |
| image/gif | .gif |
| image/bmp | .bmp |
| image/webp | .webp |

### Примеры валидаций
- **Тип файла**: `mimeType` должен быть в белом списке (Zod + серверная проверка)
- **Размер файла**: `fileSize <= maxFileSize` (конфигурация)
- **Нулевой размер**: `fileSize > 0`

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Файл с нулевым размером | Отклонение с ошибкой «Файл не может быть пустым» (EC-07) |
| 2 | Файл с неподдерживаемым расширением | Отклонение с ошибкой (EC-04) |
| 3 | Файл, превышающий лимит размера | Отклонение с ошибкой (EC-01) |
| 4 | Файл с одинаковым именем уже существует | Сохранение с уникальным суффиксом (timestamp) в storagePath |
| 5 | Сбой сети во время загрузки | Прогресс-бар показывает «Ошибка загрузки. Попробуйте снова.» |
| 6 | Загрузка без авторизации | HTTP 401 Unauthorized |
