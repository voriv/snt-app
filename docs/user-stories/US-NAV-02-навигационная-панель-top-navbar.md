# US-NAV-02: Навигационная панель (top-navbar)

---

## Формулировка

**Как** авторизованный пользователь,
**я хочу** видеть навигационную панель (top-navbar) на всех страницах дашборда с ролевыми пунктами меню и ссылкой на профиль,
**чтобы** быстро переключаться между разделами системы с любой страницы.

---

## Контекст

### Проблема
Без единой навигационной панели пользователь вынужден использовать адресную строку браузера или навигацию внутри страниц для перехода между разделами. Разные роли видят одинаковые пункты меню, что создаёт неудобства.

### Решение
На всех страницах дашборда отображается top-navbar с пунктами меню, адаптированными под роль пользователя. Ссылка на профиль отображается в правой части панели. Навигация происходит без полной перезагрузки страницы (клиентский роутинг).

### Границы
- **Включает:** Top-navbar на всех страницах дашборда, ролевые пункты меню, ссылку на профиль, клиентскую навигацию без перезагрузки, индикатор загрузки (progress-bar) при навигации
- **Исключает:** Защиту маршрутов (US-NAV-01), страницу 404 (US-NAV-03), вкладку «Общение» (US-NAV-04), боковое меню (US-NAV-05), хлебные крошки (US-NAV-06), мобильное меню (US-NAV-07)

---

## Целевое состояние

После реализации US:

1. **Top-navbar** отображается на всех страницах дашборда (`/dashboard/*`).
2. В navbar присутствуют **ролевые пункты меню** — разные для разных ролей (GUEST, MEMBER, ADMIN, SUPER_ADMIN).
3. Справа отображается **ссылка на профиль пользователя** — имя или email (если имя пустое).
4. **Клиентская навигация** между страницами работает без полной перезагрузки (используя `next/link`).
5. **Активный пункт меню** визуально выделен.
6. **Индикатор загрузки (progress-bar)** отображается при навигации.
7. Для **неавторизованных пользователей** navbar не отображается.

## Модель данных

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|
| User | Учётная запись пользователя: `name`, `email` | `docs/model/entities/user.md` |
| Session | Сессия next-auth: `session.user.name`, `session.user.email` | `src/hooks/useSession.types.ts` |
| Role | Роль пользователя для определения видимых пунктов меню | `docs/model/entities/role.md` |

## Поведение (User Behavior)

### B-1: Навигация через navbar
Пользователь кликает на пункт «Участки» в navbar. Система выполняет клиентский переход на `/dashboard/plots` без перезагрузки страницы. Активный пункт меню меняется на «Участки».

### B-2: Ролевое меню
Пользователь с ролью ADMIN видит пункты «Участки», «Пользователи», «Документы», «Общение», «Платежи». Пользователь с ролью MEMBER видит «Участки», «Общение», «Документы». Пользователь с ролью GUEST — ограниченный набор.

### B-3: Ссылка на профиль
Авторизованный пользователь кликает на своё имя (или email) в правой части navbar. Происходит клиентский переход на `/dashboard/profile`.

### B-4: Неавторизованный пользователь
Неавторизованный пользователь видит только landing page без navbar.

## Критерии приёмки

### AC-NAV-02-1: Отображение navbar на страницах дашборда
- **Given** пользователь авторизован
- **When** пользователь переходит на любую страницу `/dashboard/*`
- **Then** top-navbar отображается в верхней части страницы с навигационными пунктами

### AC-NAV-02-2: Ссылка на профиль в navbar
- **Given** пользователь авторизован
- **When** navbar рендерится
- **Then** в правой части navbar отображается имя пользователя (или email) как кликабельная ссылка на `/dashboard/profile`

### AC-NAV-02-3: Клиентская навигация без перезагрузки
- **Given** пользователь находится на странице `/dashboard/plots`
- **When** пользователь кликает на пункт «Общение» в navbar
- **Then** происходит клиентский переход на `/dashboard/comms` без полной перезагрузки страницы (URL и контент меняются)

### AC-NAV-02-4: Ролевые пункты меню
- **Given** пользователь с ролью ADMIN
- **When** navbar рендерится
- **Then** отображаются все доступные пункты меню согласно настройкам ролей (BR-06)

### AC-NAV-02-5: Navbar не отображается для неавторизованных
- **Given** пользователь не авторизован
- **When** страница загружается
- **Then** navbar не отображается

### AC-NAV-02-6: Активное состояние пункта меню
- **Given** пользователь находится на странице `/dashboard/plots`
- **When** navbar рендерится
- **Then** пункт меню «Участки» подсвечен как активный

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-06 | Навигационная панель отображает пункты меню на основе роли пользователя | UI: рендеринг пунктов по `session.user.roles` |
| BR-07 | Ссылка на профиль пользователя отображается в навигационной панели | UI: `Link href="/dashboard/profile"` |
| BR-08 | При отсутствии имени пользователя в навигационной панели отображается email | UI: `session?.user?.name ?? session?.user?.email` |

---

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Пользователь без имени — отображается email (BR-08) | В navbar отображается email как ссылка на профиль |
| 2 | Длинное имя пользователя | Имя обрезается (truncate) с многоточием, полное имя в `title` атрибуте |
| 3 | Пользователь без роли | Отображается navbar с минимальным набором пунктов (только общедоступные) |
| 4 | Медленная загрузка сессии | Пока сессия загружается (`status === 'loading'`), отображается skeleton/placeholder |
| 5 | Ошибка при загрузке сессии | Navbar отображается в урезанном виде без ролевых пунктов |

## Нефункциональные требования

- **Производительность:** Клиентская навигация без полной перезагрузки (< 100ms); данные ролей из сессии без дополнительных API-запросов
- **Безопасность:** Пункты меню скрываются на основе роли (серверная + клиентская проверка); XSS-защита через React
- **UX:** Плавные переходы; активное состояние пунктов меню; индикатор загрузки; адаптивная верстка
- **Доступность:** Семантическая разметка (`<nav>`, `<a>`); `aria-current="page"` для активного пункта; навигация с клавиатуры (Tab, Enter); focus-ring
