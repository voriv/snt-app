# US-21-31: Архивация объявления

## Формулировка

**Как** модератор СНТ,
**я хочу** архивировать опубликованные объявления,
**чтобы** скрыть их из основного списка, но сохранить историю для последующего доступа.

## Целевое состояние

После реализации пользователь сможет:
- Архивировать опубликованные объявления с помощью модального окна подтверждения
- Скргать архивированные объявления из основного списка
- Просматривать архивированные объявления через отдельный фильтр
- Возвращать объявления из архива (разархивировать)
- Видеть информацию о том, кто и когда архивировал объявление

### Границы

**Входит:**
- Архивация опубликованных объявлений (смена статуса на `archived`)
- Разархивирование объявлений (возврат статуса `published`)
- Фильтрация по статусу архивации в списке объявлений
- Отображение статуса "Архивировано" в карточке объявления
- Сохранение истории архивации (кто, когда)
- Уведомление модераторов об успешной архивации/разархивировании

**Не входит:**
- Удаление объявлений (отдельная US)
- Автоматическая архивация по дате
- Массовая архивация нескольких объявлений сразу
- Архивация черновиков (только published)

### FR-REQ-COMMS-021-01: Архивация объявления

Пользователь должен иметь возможность архивировать опубликованное объявление.

#### AC-31.1: Доступность функции архивации
- **Дано:** Пользователь авторизован как модератор (ADMIN/SUPER_ADMIN)
- **Дано:** Объявление имеет статус `published`
- **Когда:** Пользователь открывает карточку объявления или список объявлений
- **Тогда:** Отображается кнопка "Архивировать"

#### AC-31.2: Модальное окно подтверждения
- **Дано:** Пользователь нажимает кнопку "Архивировать"
- **Когда:** Появляется модальное окно
- **Тогда:** Отображается сообщение: "Вы уверены, что хотите архивировать объявление '{название}'? После архивации оно будет скрыто из основного списка, но останется доступным в архиве."
- **Тогда:** Отображаются кнопки "Архивировать" и "Отмена"

#### AC-31.3: Успешная архивация
- **Дано:** Пользователь подтвердил архивацию
- **Когда:** Пользователь нажимает "Архивировать"
- **Тогда:**
  - Статус объявления меняется на `archived`
  - Заполняются поля `archived_by` (id пользователя) и `archived_at` (текущее время)
  - Объявление исчезает из основного списка
  - Появляется уведомление "Объявление '{название}' архивировано"
  - Модальное окно закрывается

#### AC-31.4: Повторная попытка архивации
- **Дано:** Объявление уже архивировано
- **Когда:** Пользователь нажимает "Архивировать"
- **Тогда:** Показывается ошибка: "Это объявление уже архивировано"

### FR-REQ-COMMS-021-02: Разархивация объявления

Пользователь должен иметь возможность возвращать архивированные объявления в активный список.

#### AC-31.5: Доступность функции разархивации
- **Дано:** Пользователь авторизован как модератор
- **Дано:** Объявление имеет статус `archived`
- **Когда:** Пользователь открывает список архивированных объявлений
- **Тогда:** Отображается кнопка "Разархивировать"

#### AC-31.6: Модальное окно подтверждения
- **Дано:** Пользователь нажимает кнопку "Разархивировать"
- **Когда:** Появляется модальное окно
- **Тогда:** Отображается сообщение: "Вы уверены, что хотите разархивировать объявление '{название}'? Оно появится в основном списке."
- **Тогда:** Отображаются кнопки "Разархивировать" и "Отмена"

#### AC-31.7: Успешная разархивация
- **Дано:** Пользователь подтвердил разархивацию
- **Когда:** Пользователь нажимает "Разархивировать"
- **Тогда:**
  - Статус объявления меняется на `published`
  - Очищаются поля `archived_by` и `archived_at` (опционально, можно сохранить для истории)
  - Объявление появляется в основном списке
  - Появляется уведомление "Объявление '{название}' разархивировано"
  - Модальное окно закрывается

### FR-REQ-COMMS-021-03: Фильтрация по статусу архивации

Пользователь должен иметь возможность фильтровать объявления по статусу архивации.

#### AC-31.8: Фильтр в списке объявлений
- **Дано:** Пользователь на странице списка объявлений
- **Когда:** Пользователь открывает фильтр статусов
- **Тогда:** Отображаются опции:
  - Все (по умолчанию)
  - Опубликованные
  - Архивированные
  - Черновики (если применимо)

#### AC-31.9: Отображение архивированных
- **Дано:** Пользователь выбрал фильтр "Архивированные"
- **Когда:** Применяется фильтр
- **Тогда:** Отображаются только объявления со статусом `archived`
- **Тогда:** Карточка объявления помечается визуально как "Архив" (например, серый фон или значок)

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| **BR-01** | Только модераторы | Архивировать/разархивировать могут только модераторы (ADMIN/SUPER_ADMIN) | Проверка роли |
| **BR-02** | Архивация только published | Нельзя архивировать черновики или уже архивированные объявления | Проверка статуса |
| **BR-03** | Сохранение истории | Записывается кто и когда архивировал | Поля `archived_by`, `archived_at` |
| **BR-04** | Подтверждение действия | Требуются два действия: кнопка + подтверждение в модальном окне | UI-валидация |
| **BR-05** | Статус `archived` не удаляет данные | Объявление остается в БД, просто меняется статус | Логика сохранения |
| **BR-06** | Разархивация возвращает в `published` | Возвращает статус к `published` и очищает архивные поля | Логика переключения |
| **BR-07** | Архивирование не влияет на чат обсуждения | Чат обсуждения остается активным | Логика изоляции |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| **EC-01** | Попытка архивации черновика | Ошибка: "Архивировать можно только опубликованные объявления" |
| **EC-02** | Попытка архивации уже архивированного | Ошибка: "Это объявление уже архивировано" |
| **EC-03** | Попытка архивации без прав модератора | Ошибка 403: "Доступ запрещён" |
| **EC-04** | Разархивация неархивированного объявления | Ошибка: "Это объявление не архивировано" |
| **EC-05** | Архивация в момент редактирования | Ошибка: "Сначала сохраните изменения в объявлении" |
| **EC-06** | Сетевая ошибка при архивации | Отображается ошибка, статус не меняется, показывается уведомление |
| **EC-07** | Массовая одновременная архивация | Блокировка на уровне сервиса (транзакция) |
| **EC-08** | Архивация с открытым чатом обсуждения | Чат сохраняется, но объявления в нём помечаются как архивные (опционально) |

## Модель данных

### Текущая схема (предполагаемая)

```prisma
// Предполагаемая структура объявления
model Announcement {
  id            String   @id @default(cuid())
  title         String
  short_content String?
  content       String
  status        String   // draft | published
  category_id   String?  @map("category_id")
  discussion_id String?  @map("discussion_id")
  created_at    DateTime @default(now()) @map("created_at")
  updated_at    DateTime @updatedAt @map("updated_at")
  created_by    String   @map("created_by")
  published_at  DateTime? @map("published_at")
  published_by  String?  @map("published_by")
}
```

### Изменения в модели

```prisma
model Announcement {
  // ... все предыдущие поля ...
  
  status        String   // draft | published | archived
  archived_at   DateTime? @map("archived_at")
  archived_by   String?  @map("archived_by")
  
  @@map("announcements")
}
```

**Обоснование:**
- Добавление статуса `archived` к текущим `draft` и `published`
- Поля `archived_at` и `archived_by` для аудита изменений
- Индексы по полю `status` для эффективной фильтрации

### Конвенции именования

| Поле | Тип | Назначение |
|------|-----|------------|
| `status` | String | Текущий статус объявления (`draft`, `published`, `archived`) |
| `archived_at` | DateTime? | Время архивации (NULL если не архивировано) |
| `archived_by` | String? | ID пользователя, архировавшего объявление |

 * @schema validateArchiveAnnouncement
 * @domain comms
 * @description Валидация перед архивацией объявления
 *
 * @spec
 * - Проверяет, что объявление существует

 * - Проверяет права пользователя
 */
export const validateArchiveAnnouncement = async (
  announcementId: string,
  userId: string,
  announcement: Announcement
): Promise<void> => {
  if (!announcement) {
    throw new AnnouncementNotFoundError(announcementId);
  }

  if (announcement.status !== 'published') {
    throw new AnnouncementInvalidStatusError(announcement.status, 'published');
  }

  // Проверка прав (упрощенно)
  // В реальной реализации будет проверка роли пользователя
};

### Service

```typescript
/**
 * @service AnnouncementService
 * @domain comms
 * @description Бизнес-логика управления объявлениями
 */
export class AnnouncementService {
  constructor(
    private readonly announcementRepository: IAnnouncementRepository,
    private readonly userRepository: IUserRepository // для проверки прав
  ) {}

  /**
   * Архивировать объявление
   */
  async archiveAnnouncement(
    announcementId: string,
    userId: string
  ): Promise<Announcement> {
    const announcement = await this.announcementRepository.findById(announcementId);
    
    if (!announcement) {
      throw new AnnouncementNotFoundError(announcementId);
    }

    await validateArchiveAnnouncement(announcementId, userId, announcement);

    const archivedAnnouncement = await this.announcementRepository.archive(
      announcementId,
      userId
    );

    return archivedAnnouncement;
  }

  /**
   * Разархивировать объявление
   */
  async unarchiveAnnouncement(
    announcementId: string,
    userId: string
  ): Promise<Announcement> {
    const announcement = await this.announcementRepository.findById(announcementId);
    
    if (!announcement) {
      throw new AnnouncementNotFoundError(announcementId);
    }

    await validateUnarchiveAnnouncement(announcementId, userId, announcement);

    const unarchivedAnnouncement = await this.announcementRepository.unarchive(
      announcementId,
      userId
    );

    return unarchivedAnnouncement;
  }
}
```

### API

- **POST /api/v1/announcements/:id/archive**
  - **Auth:** required (ADMIN/SUPER_ADMIN)
  - **Body:** пустое (id в URL)
  - **Response:** 200 `{ success: true, data: Announcement }`
  - **Errors:** 400
