# US-21-19: Просмотр списка жалоб на сообщения

## Формулировка
**Как** модератор,
**я хочу** видеть список всех полученных жалоб на сообщения с их статусом и деталями,
**чтобы** эффективно управлять поступающими сигналами о нарушениях и обрабатывать их.

## Целевое состояние
Модератор получает доступ к единому списку жалоб с возможностью фильтрации, сортировки и быстрого перехода к деталям. Все критические данные отображаются на первом экране.

### Границы
- Доступ только к роли MODERATOR или SUPER_ADMIN.
- Отображаются только жалобы, созданные в системе (не импортированные извне).
- История хранения жалоб определяется политикой компании (рекомендуется 1 год).
- Анонимность автора жалобы сохраняется (если он выбрал анонимность).

## Функциональные требования

### FR-REQ-COMMS-001-19: Отображение списка жалоб

#### AC-19.1: Загрузка и отображение списка
- **Дано:** Модератор авторизован и имеет соответствующие права.
- **Когда:** Модератор открывает страницу "Модерация" (`/dashboard/comms/moderation`).
- **Тогда:**
  - Отображается таблица с колонками: ID жалобы, Ссылка на сообщение, Автор сообщения, Автор жалобы, Причина, Статус, Дата создания.
  - По умолчанию сортировка: новые жалобы сверху (created_at DESC).
  - Пагинация: по 20-50 записей на страницу.

#### AC-19.2: Фильтрация по статусу
- **Дано:** Список жалоб загружен.
- **Когда:** Модератор выбирает фильтр по статусу (Новая, В работе, resolved, Отклонена).
- **Тогда:**
  - Список обновляется только с жалобами, соответствующими выбранному статусу.
  - Статистика по каждому статусу отображается в реальном времени.

#### AC-19.3: Поиск по жалобе
- **Дано:** В списке отображаются жалобы.
- **Когда:** Модератор вводит текст в поле поиска (ID, текст жалобы, ID пользователя).
- **Тогда:**
  - Система фильтрует список, показывая только совпадения.
  - Отображается количество найденных совпадений.

### FR-REQ-COMMS-001-20: Быстрый переход к деталям
- **Дано:** Модератор видит список жалоб.
- **Когда:** Модератор кликает на ссылку ID жалобы или кнопку "Посмотреть".
- **Тогда:**
  - Модератор переходит на страницу деталей жалобы (см. US-21-20).
  - Статус жалобы не меняется автоматически при просмотре.

### FR-REQ-COMMS-001-21: Экспорт списка
- **Дано:** Список жалоб отфильтрован.
- **Когда:** Модератор нажимает кнопку "Экспорт в CSV".
- **Тогда:**
  - Система генерирует CSV файл с отфильтрованными данными.
  - Файл скачивается на устройство модератора.

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| BR-19-01 | Минимальный набор данных | Каждая жалоба должна содержать ссылку на сообщение и причину. | Валидация при создании (US-21-19 не создает, но ссылается на процесс создания). |
| BR-19-02 | Анонимность | Если автор жалобы выбрал анонимность, имя не отображается. | Проверка флага `is_anonymous` в UI. |
| BR-19-03 | Лимиты экспорта | Нельзя экспортировать более 1000 записей за один раз. | Проверка на стороне клиента/сервера. |
| BR-19-04 | Доступность | Только роли MODERATOR, SUPER_ADMIN могут видеть список. | Проверка прав доступа в API. |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Сообщение, на которое поступила жалоба, было удалено | В списке отображается "Сообщение удалено", ссылка на него неактивна. |
| 2 | Жалоба на несуществующий чат | В системе отображается "Чат не найден", статус "Обработка". |
| 3 | Пустой список жалоб | Отображается сообщение "Жалоб не найдено". |
| 4 | Множественные жалобы на одно сообщение | Все жалобы отображаются отдельными строками, возможна группировка (опционально). |
| 5 | Запрос на экспорт при пустом списке | Экспорт пустого CSV файла (или предупреждение). |
| 6 | Быстрое обновление статусов другими модераторами | В списке всегда отображается актуальный статус (AJAX обновление или ручная перезагрузка). |

## Модель данных
Рекомендуется использовать существующую сущность `Report` (если создана в REQ-COMMS-001) или создать новую таблицу `moderation_reports`.

**Таблица: `moderation_reports`**
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Primary Key |
| `message_id` | UUID | Foreign Key -> messages(id) |
| `reporter_id` | UUID | Foreign Key -> users(id) |
| `reporter_is_anonymous` | Boolean | Была ли жалоба анонимной |
| `reason` | Text | Текст/Причина жалобы |
| `status` | Enum | New, InProgress, Resolved, Rejected, Ignored |
| `assigned_to` | UUID | ID модератора, которому назначена жалоба (опционально) |
| `created_at` | DateTime | Дата создания |
| `updated_at` | DateTime | Дата последнего обновления |
| `resolved_at` | DateTime | Дата разрешения (если статус Resolved/Rejected) |
| `resolved_by` | UUID | ID модератора, который обработал жалобу |

## Нефункциональные требования
- **Производительность:** Запрос списка должен занимать < 300мс при до 10,000 записей.
- **Безопасность:** Статус жалобы должен обновляться только авторизованным модератором.
- **Доступность:** Таблица должна поддерживаться скринридерами, колонки сортировки должны иметь aria-label.
- **Локализация:** Все сообщения и статусы на русском языке.
