# US-21-34: Просмотр внутренних уведомлений

## Формулировка

**Как** пользователь СНТ,
**я хочу** просматривать внутренние уведомления в навигации и на отдельной странице,
**чтобы** быть в курсе новых сообщений, ответов в обсуждениях и упоминаний.

## Целевое состояние

После реализации пользователь сможет:
- Видеть бейдж с количеством непрочитанных уведомлений в navbar
- Просматривать полный список уведомлений на отдельной странице
- Отмечать уведомления как прочитанные одним кликом
- Отслеживать события: новые сообщения, ответы в обсуждениях, упоминания @username
- Хранить уведомления за 120 дней

### Границы

**Входит:**
- Отображение бейджа с количеством непрочитанных в navbar
- Отдельная страница `/dashboard/notifications` для полного списка
- Отметка прочтения одним кликом
- Типы событий: новые сообщения, ответы в обсуждениях, упоминания
- Хранение уведомлений за 120 дней

**Не входит:**
- Push-уведомления в браузер
- Email-уведомления (отдельные US)
- Настройка частоты email-рассылки (отдельная US)
- Отписка от рассылок (отдельная US)

### FR-REQ-COMMS-023-01: Бейдж уведомлений в navbar

Пользователь должен видеть бейдж с количеством непрочитанных уведомлений в навигации.

#### AC-34.1: Отображение бейджа
- **Дано:** У пользователя есть непрочитанные уведомления
- **Когда:** Пользователь заходит на любую страницу приложения
- **Тогда:** В navbar отображается иконка колокольчика с бейджем, показывающим количество непрочитанных

#### AC-34.2: Обновление бейджа
- **Дано:** Пользователь находится на странице с уведомлениями
- **Когда:** Появляется новое уведомление
- **Тогда:** Бейдж обновляется автоматически без перезагрузки страницы

#### AC-34.3: Скрытие бейджа
- **Дано:** У пользователя нет непрочитанных уведомлений
- **Когда:** Пользователь заходит на страницу
- **Тогда:** Бейдж не отображается

### FR-REQ-COMMS-023-02: Просмотр списка уведомлений

Пользователь должен иметь возможность просматривать полный список уведомлений.

#### AC-34.4: Загрузка списка
- **Дано:** Пользователь переходит на страницу `/dashboard/notifications`
- **Когда:** Загружается страница
- **Тогда:** Отображается список всех уведомлений за последние 120 дней

#### AC-34.5: Сортировка по дате
- **Дано:** Пользователь просматривает список уведомлений
- **Когда:** Отображаются уведомления
- **Тогда:** Уведомления сортируются по дате (новые сверху)

#### AC-34.6: Типы уведомлений
- **Дано:** Пользователь просматривает список
- **Когда:** Отображается уведомление
- **Тогда:** Отображается иконка и текст в зависимости от типа:
  - Новое сообщение: иконка сообщения
  - Ответ в обсуждении: иконка обсуждения
  - Упоминание: иконка @

### FR-REQ-COMMS-023-03: Отметка прочтения

Пользователь должен иметь возможность отмечать уведомления как прочитанные.

#### AC-34.7: Отметка прочтения по клику
- **Дано:** Пользователь кликает на уведомление
- **Когда:** Уведомление отображается как непрочитанное
- **Тогда:** Уведомление помечается как прочитанное, бейдж обновляется

#### AC-34.8: Отметка всех как прочитанные
- **Дано:** Пользователь на странице уведомлений
- **Когда:** Пользователь нажимает кнопку "Отметить всё как прочитанное"
- **Тогда:** Все непрочитанные уведомления помечаются как прочитанные, бейдж исчезает

### FR-REQ-COMMS-023-04: Типы событий

Система должна генерировать уведомления для следующих событий.

#### AC-34.9: Новое личное сообщение
- **Дано:** Пользователь получил личное сообщение
- **Когда:** Сообщение отправлено и доставлено
- **Тогда:** Создаётся уведомление типа "new_message" с ссылкой на диалог

#### AC-34.10: Ответ в групповом чате
- **Дано:** Пользователь участвует в групповом чате
- **Когда:** Появляется новое сообщение в чате
- **Тогда:** Создаётся уведомление типа "new_chat_message" с ссылкой на чат

#### AC-34.11: Упоминание @username
- **Дано:** Пользователь упомянут в сообщении (@username)
- **Когда:** Сообщение опубликовано
- **Тогда:** Создаётся уведомление типа "mention" с ссылкой на сообщение

#### AC-34.12: Ответ в обсуждении объявления
- **Дано:** Объявление имеет чат обсуждения
- **Когда:** Появляется новое сообщение в обсуждении
- **Тогда:** Создается уведомление типа "new_discussion_message" с ссылкой на обсуждение

### FR-REQ-COMMS-023-05: Хранение уведомлений

Система должна хранить уведомления в течение определённого периода.

#### AC-34.13: Период хранения
- **Дано:** Уведомление старше 120 дней
- **Когда:** Загружается список уведомлений
- **Тогда:** Уведомление не отображается (автоматическое удаление)

## Бизнес-правила и валидация

| ID | Правило | Описание | Валидация |
|----|---------|----------|-----------|
| **BR-01** | Только авторизованные пользователи | Уведомления доступны только авторизованным | Проверка сессии |
| **BR-02** | Пользователь видит только свои уведомления | Не видно чужие уведомления | Фильтрация по userId |
| **BR-03** | Хранение 120 дней | Уведомления удаляются автоматически | Задача очистки |
| **BR-04** | Отметка прочтения моментальная | Не требуется подтверждение | Прямая отметка |
| **BR-05** | Реальное время | Обновление без перезагрузки | WebSocket или polling |
| **BR-06** | Ссылки в уведомлениях | Все ссылки рабочие, ведут на релевантные страницы | Проверка URL |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| **EC-01** | Нет непрочитанных уведомлений | Бейдж не отображается |
| **EC-02** | Большое количество уведомлений (> 100) | Пагинация (25 на страницу) |
| **EC-03** | Ссылка на удалённое сообщение | Уведомление помечается как "недоступно" |
| **EC-04** | Пользователь заблокирован | Уведомления не создаются |
| **EC-05** | Упоминание неавторизованного пользователя | Уведомление не создаётся |
| **EC-06** | Массовая отправка сообщений (> 100 за минуту) | Троттлинг уведомлений (максимум 1 в минуту) |
| **EC-07** | Чат обсуждения закрыт | Уведомления не создаются для новых сообщений |
| **EC-08** | Ссылка не работает через 120 дней | Уведомление удаляется автоматически |

## Модель данных

### Текущая схема (без уведомлений)

Уведомления не предусмотрены в базовой схеме — требуется новая таблица.

### Новая таблица `notifications`

```prisma
model Notification {
  id          String   @id @default(cuid())
  user_id     String   @map("user_id")
  type        String   // new_message, new_chat_message, mention, new_discussion_message
  title       String
  message     String
  link        String?  // ссылка на объект (диалог, чат, сообщение)
  is_read     Boolean  @default(false) @map("is_read")
  created_at  DateTime @default(now()) @map("created_at")
  
  @@index([user_id, is_read])
  @@index([user_id, created_at])
}
```

**Обоснование:**
- `user_id` — владелец уведомления
- `type` — тип события
- `title`, `message` — текст уведомления
- `link` — ссылка на объект (для перехода)
- `is_read` — флаг прочтения
- Индексы для эффективной фильтрации

### Конвенции именования

| Поле | Тип | Назначение |
|------|-----|------------|
| `user_id` | String | ID пользователя |
| `type` | String | Тип события |
| `title` | String | Заголовок уведомления |
| `message` | String | Текст уведомления |
| `link` | String? | Ссылка на объект |
| `is_read` | Boolean | Флаг прочтения |
| `created_at` | DateTime | Время создания |

## Влияние на слои архитектуры

### Types
- Новый тип `Notification` с полями: id, userId, type, title, message, link, isRead, createdAt
- Тип `NotificationType`: `new_message | new_chat_message | mention | new_discussion_message`
- Расширение `Notification` с вычисляемым `relativeTime: string`

### Validators
- Валидация типа уведомления при создании
- Валидация формата ссылки

### Errors
- `NotificationNotFoundError` — уведомление не найдено

### Repository
- Метод `createNotification(userId: string, type: string, title: string, message: string, link: string): Promise<Notification>`
- Метод `getUnreadCount(userId: string): Promise<number>`
- Метод `getNotifications(userId: string, limit: number, offset: number): Promise<PaginatedResponse<Notification>>`
- Метод `markAsRead(notificationId: string, userId: string): Promise<void>`
- Метод `markAllAsRead(userId: string): Promise<void>`
- Метод `deleteOldNotifications(olderThan: number): Promise<number>`

### Service
- Метод `createNotification(notification: CreateNotificationInput): Promise<Notification>`
- Метод `getUnreadCount(userId: string): Promise<number>`
- Метод `getNotifications(userId: string, limit: number, offset: number): Promise<PaginatedResponse<Notification>>`
- Метод `markNotificationAsRead(notificationId: string, userId: string): Promise<void>`
- Метод `markAllNotificationsAsRead(userId: string): Promise<void>`
- Метод `cleanupOldNotifications(): Promise<void>`

### DI
- Фабрика `createNotificationService()`

### API
- **GET /api/v1/notifications/unread-count**
  - Auth: required
  - Response: 200 `{ success: true, data: { count: number } }`
- **GET /api/v1/notifications**
  - Auth: required
  - Query: `limit?`, `offset?`
  - Response: 200 `{ success: true, data: { notifications: Notification[], total: number } }`
- **POST /api/v1/notifications/:id/read**
  - Auth: required
  - Response: 200 `{ success: true }`
- **POST /api/v1/notifications/mark-all-read**
  - Auth: required
  - Response: 200 `{ success: true }`
- **POST /api/v1/notifications/cleanup**
  - Auth: required (ADMIN)
  - Response: 200 `{ success: true, data: { deleted: number } }`

### UI
- **Компоненты:**
  - `NotificationBell` — иконка колокольчика с бейджем в navbar
  - `NotificationDropdown` — выпадающий список уведомлений из бейджа
  - `NotificationList` — полный список на странице
  - `NotificationItem` — отдельное уведомление
  - `MarkAllAsReadButton` — кнопка "Отметить всё как прочитанное"
  - `PaginationControls` — пагинация

### Pages
- Страница `/dashboard/notifications` — просмотр полного списка

## Нефункциональные требования

- **Производительность:** Загрузка списка уведомлений < 500мс
- **Реальное время:** Обновление без перезагрузки (WebSocket или polling 30 сек)
- **Безопасность:** Проверка авторизации на уровне API
- **UX:** Анимация появления нового бейджа
- **Доступность:** ARIA-метки для иконки и списка уведомлений
