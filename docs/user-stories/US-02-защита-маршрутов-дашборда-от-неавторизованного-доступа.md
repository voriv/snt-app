# US-02: Защита маршрутов дашборда от неавторизованного доступа

---

## Формулировка

**Как** незарегистрированный пользователь (гость),
**я хочу** чтобы система перенаправила меня на страницу входа при попытке открыть раздел дашборда,
**чтобы** я понимал, что для просмотра защищённого контента нужно авторизоваться.

---

## Целевое состояние

Все маршруты, начинающиеся с `/dashboard`, защищены от прямого доступа неавторизованными пользователями. При попытке гостя (пользователя без валидной сессии) перейти на любую страницу дашборда (`/dashboard`, `/dashboard/plots` и т.д.), система автоматически перенаправляет его на страницу входа `/login`.

Внутренняя проверка сессии (на уровне Middleware) гарантирует, что данные дашборда недоступны без авторизации, предотвращая просмотр конфиденциальной информации СНТ неавторизованными пользователями.

| Сущность | Описание | Ссылка на модель |
|----------|----------|------------------|

---

## Поведение (User Behavior)

### B-1: Попытка доступа гостя к дашборду
Гость, не авторизованный в системе, вводит URL дашборда в адресную строку браузера или переходит по прямой ссылке. Middleware проверяет отсутствие валидной сессии и перенаправляет пользователя на страницу `/login`.

### B-2: Доступ авторизованного пользователя
Авторизованный пользователь (с активной сессией) переходит на `/dashboard`. Middleware подтверждает валидность сессии, и Next.js рендерит соответствующую страницу Layout-а и контента.

---

## Критерии приёмки

### AC-1: Редирект гостя на страницу входа
- **Given** пользователь не авторизован (отсутствует или невалидна кука сессии)
- **When** пользователь пытается открыть URL `/dashboard/*`
- **Then** система перенаправляет его на `/login`

### AC-2: Отображение дашборда для авторизованных
- **Given** пользователь авторизован (валидная сессия)
- **When** пользователь открывает URL `/dashboard/*`
- **Then** система отображает соответствующую страницу дашборда (Layout + Content)

### AC-3: Защита API дашборда
- **Given** неавторизованный пользователь
- **When** делает запрос к API дашборда (`/api/v1/*`) без токена
- **Then** получает ошибку `401 Unauthorized`

---

## Бизнес-правила и валидация

| ID | Правило | Валидация |
|----|---------|-----------|
| BR-03 | Доступ к страницам контролируется на основе роли пользователя | Middleware/Client-Layout проверяет статус сессии и роли (наличие хотя бы одной разрешающей роли) |
| BR-06 | Роли хранятся в системе и ассоциируются с пользователями | Сессия пользователя содержит идентификатор, позволяющий проверить роли из БД или кэша |

---

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | У пользователя истёк срок сессии (недействительный токен) | Middleware перенаправляет на `/login` |
| 2 | Прямой переход на вложенную страницу (`/dashboard/plots`) без авторизации | Редирект на `/login` (потеря пути не критична, но идемпотентность входа важна) |
| 3 | Отключены куки в браузере | Редирект на `/login` (токен не отправляется) |
| 4 | Запрос к API без токена | Возврат HTTP 401 (Unauthorized) |
| 5 | Ошибка валидации сессии на сервере | Возврат HTTP 401 (Unauthorized) и перенаправление на `/login` (для SPA) |

## Нефункциональные требования

- **Безопасность:** Запрет доступа к защищённым маршрутам без верификации сессии на стороне сервера (Next.js Middleware).
- **Производительность:** Проверка сессии Middleware должна быть быстрой (минимальные накладные расходы, чтение куки).
- **UX:** Перенаправление происходит мгновенно, без задержек.
