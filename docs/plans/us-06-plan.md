## 📦 Задачи по слоям

### 1. UI: Страница регистрации (Отображение успеха и ошибок)

#### Задача US-06-T1-PAGE: Обновление страницы регистрации
| Параметр | Значение |
|----------|----------|
| **ID** | `US-06-T1-PAGE` |
| **Статус** | `[TODO]` |
| **Файл** | `src/app/(public)/register/page.tsx` |
| **Действие** | `Update` |

**Целевое состояние:**
- После успешной регистрации (`isSuccess === true`) форма скрывается, показывается сообщение об успехе и ссылка на вход.
- Интеграция сообщения об успехе со страницей входа (`/login?registered=true`) или внутреннее отображение (в зависимости на решения UI/UX).
- Обработка `apiError` выводится корректно в блоке ошибок.
- При ошибке форма очищается или блокируется до повторной попытки.

**Чек-лист:**
- [ ] Ввести состояние `isSuccess` в рендер.
- [ ] При `isSuccess` заменить форму на сообщение `alert` или карточку успеха.
- [ ] Добавить кнопку/ссылку "Перейти на страницу входа".
- [ ] Убедиться, что `apiError` обрабатывается корректно (текущая реализация уже есть, проверить UX).

### 2. UI: Компонент Input (Inline-ошибки и Accessibility)

#### Задача US-06-T2-UI: Улучшение компонента Input для inline-ошибок
| Параметр | Значение |
|----------|----------|
| **ID** | `US-06-T2-UI` |
| **Статус** | `[TODO]` |
| **Файл** | `src/components/ui/Input/Input.tsx` |
| **Действие** | `Update` |

**Целевое состояние:**
- Компонент корректно отображает ошибку, переданную через `error`, в том числе `aria-invalid="true"`.
- Добавлен `role="alert"` для сообщения об ошибке.
- Поле получает фокус при появлении ошибки (опционально, через focus management).
- Визуальная индикация (красная рамка, иконка) присутствует.

**Чек-лист:**
- [ ] Добавить `aria-invalid={!!error}` к `<input>`.
- [ ] Добавить `role="alert"` к блоку с ошибкой.
- [ ] Проверить цвет и отступы ошибки (Red-600, mt-1).
- [ ] Убедиться, что `error` проп работает корректно для всех полей формы.
