# REQ-USERS-001: Управление пользователями

## 1. Бизнес-контекст и Цель

*Администраторам СНТ необходим инструмент для просмотра и анализа всех зарегистрированных пользователей системы: их профилей, назначенных ролей и связей с участками.*

* **Бизнес-цель:** Предоставить администраторам возможность централизованного управления пользователями — просмотра списка, поиска, детальной информации о каждом пользователе и его роли в системе.
* **Стейкхолдеры / Пользователи:** Супер-администратор (SUPER_ADMIN) — единственный тип пользователя с доступом к управлению пользователями.

---

## 2. Бизнес-правила и Логика (Business Rules)

* **BR-01:** Доступ к странице списка пользователей имеют только пользователи с ролью SUPER_ADMIN
* **BR-02:** Доступ к карточке пользователя имеют только пользователи с ролью SUPER_ADMIN
* **BR-03:** Список пользователей отображает: email, имя, фамилию, роли, дату регистрации
* **BR-04:** Поиск пользователей поддерживает фильтрацию по email, имени и фамилии
* **BR-05:** Сортировка поддерживается по полям: email, имя, фамилия, дата регистрации
* **BR-06:** Пагинация списка использует дефолтный limit 25 записей на страницу
* **BR-07:** Карточка пользователя содержит разделы: профиль, роли, связи с участками
* **BR-08:** Связи пользователя с участками в карточке — только для просмотра (без редактирования)
* **BR-09:** Если у пользователя нет профиля, в карточке отображается сообщение об отсутствии данных
* **BR-10:** Если у пользователя нет ролей, в карточке отображается сообщение об отсутствии ролей
* **BR-11:** Если у пользователя нет связей с участками, в карточке отображается сообщение об отсутствии связей

---

## 3. Функциональные требования

* **FR-REQ-USERS-001-01:** Система должна отображать список всех пользователей в табличном виде на странице `/dashboard/users`
* **FR-REQ-USERS-001-02:** Система должна поддерживать поиск пользователей по email, имени и фамилии
* **FR-REQ-USERS-001-03:** Система должна поддерживать сортировку списка пользователей по полям: email, имя, фамилия, дата регистрации
* **FR-REQ-USERS-001-04:** Система должна поддерживать пагинацию списка пользователей с дефолтным limit 25
* **FR-REQ-USERS-001-05:** Система должна отображать карточку пользователя с детальной информацией на странице `/dashboard/users/[id]`
* **FR-REQ-USERS-001-06:** Система должна отображать роли пользователя в карточке пользователя
* **FR-REQ-USERS-001-07:** Система должна отображать связи пользователя с участками в карточке пользователя (только просмотр)
* **FR-REQ-USERS-001-08:** Система должна блокировать доступ к управлению пользователями для пользователей без роли SUPER_ADMIN

## 5. Нефункциональные требования (NFR) и Ограничения

* **Безопасность:**
  * Доступ к странице `/dashboard/users` и `/dashboard/users/[id]` требует роли SUPER_ADMIN
  * При попытке доступа пользователя без нужной роли — возврат ошибки 403 (Forbidden)
  * Все запросы к API проверяют права доступа на сервере
* **Производительность:**
  * Загрузка списка пользователей: < 500ms при до 1000 записей в базе
  * Поиск пользователей: < 300ms при до 1000 записей
  * Загрузка карточки пользователя: < 300ms
* **Доступность:**
  * Таблица пользователей должна быть доступна с клавиатуры (tab-навигация)
  * Элементы управления (поиск, сортировка, пагинация) должны иметь ARIA-метки
* **Локализация:**
  * Все сообщения об ошибках и UI-тексты на русском языке
* **Адаптивность:**
  * Таблица пользователей должна корректно отображаться на мобильных устройствах
  * Карточка пользователя должна быть адаптивной

## 6. Исключения и Граничные кейсы (Edge Cases)

* **EC-01:** Список пользователей пуст — система должна отобразить пустое состояние с сообщением «Пользователи не найдены»
* **EC-02:** Пользователь с указанным ID не найден — система должна отобразить ошибку 404 с сообщением «Пользователь не найден»
* **EC-03:** У пользователя нет профиля (UserProfile) — система должна отобразить карточку с базовыми данными из User и сообщением об отсутствии профиля
* **EC-04:** У пользователя нет назначенных ролей — система должна отобразить раздел ролей с сообщением «Роли не назначены»
* **EC-05:** У пользователя нет связей с участками — система должна отобразить раздел связей с сообщением «Связи с участками отсутствуют»
* **EC-06:** Пользователь без роли SUPER_ADMIN пытается получить доступ к странице списка — система должна вернуть ошибку 403 (Forbidden) и отобразить сообщение «Доступ запрещен»
* **EC-07:** Поиск не дает результатов — система должна отобразить пустое состояние с сообщением «Ничего не найдено по указанному запросу»
* **EC-08:** Медленная сеть (более 3 секунд без ответа) — система должна отобразить индикатор загрузки и сообщение «Загрузка данных...»

## 7. Критерии приёмки

1. Пользователь с ролью SUPER_ADMIN может открыть страницу `/dashboard/users` и увидеть таблицу всех пользователей
2. Таблица пользователей содержит столбцы: email, имя, фамилия, роли, дата регистрации
3. Поиск пользователей по email, имени или фамилии корректно фильтрует список
4. Сортировка по полям email, имя, фамилия, дата-registration работает корректно
5. Пагинация работает с дефолтным limit 25 записей на страницу
6. Пользователь с ролью SUPER_ADMIN может открыть карточку пользователя по URL `/dashboard/users/[id]`
7. Карточка пользователя содержит разделы: профиль, роли, связи с участками
8. Связи пользователя с участками отображаются только для просмотра
9. Пользователь без роли SUPER_ADMIN при попытке доступа получает ошибку 403
10. При пустом списке пользователей отображается сообщение «Пользователи не найдены»
11. При отсутствии пользователя по ID отображается ошибка 404
12. Все сообщения об ошибках и UI-тексты на русском языке
