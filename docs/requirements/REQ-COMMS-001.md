# REQ-COMMS-001: Система общения в СНТ

## 1. Бизнес-контекст и Цель

*Участникам СНТ и правлению необходим встроенный инструмент коммуникации для обмена сообщениями, обсуждения вопросов по участкам и получения официальных объявлений.*

* **Бизнес-цель:** Централизовать все виды коммуникации внутри СНТ — личные сообщения, групповые чаты и официальные объявления — в едином приложении, обеспечив прозрачность и удобство взаимодействия между пользователями.
* **Стейкхолдеры / Пользователи:**
  * Члены СНТ (пользователи с ролью MEMBER) — отправляют/получают личные сообщения, участвуют в чатах, читают объявления
  * Правление СНТ (пользователи с ролью ADMIN) — создают объявления, управляют чатами, общаются с членами СНТ
  * Супер-администраторы (SUPER_ADMIN) — полный доступ ко всем функциям системы общения

---

## 2. Бизнес-правила и Логика (Business Rules)

* **BR-01:** Только авторизованные пользователи могут отправлять сообщения и участвовать в чатах
* **BR-02:** Личные сообщения видны только участникам диалога
* **BR-03:** Объявления могут создавать только пользователи с ролью ADMIN или SUPER_ADMIN
* **BR-04:** Объявления могут быть с включенным обсуждением (создается автоматический чат) или без обсуждения
* **BR-05:** Чаты привязанные к участкам доступны только пользователям, имеющим связь с этим участком
* **BR-06:** Пользователь может покинуть общий чат, но не может удалить чат, созданный системой
* **BR-07:** Уведомления о новых сообщениях отправляются всем участникам диалога/чата
* **BR-08:** Пользователь может отключить email-уведомления в настройках профиля
* **BR-09:** История сообщений хранится неограниченно — автоматическое удаление запрещено
* **BR-10:** При удалении пользователя его сообщения сохраняются, но отправитель отображается как "Удалённый пользователь"
* **BR-11:** В чате можно упомянуть пользователя через @username — упомянутый получит уведомление
* **BR-12:** Объявления имеют статусы: черновик (draft), опубликовано (published), архивировано (archived)
* **BR-13:** Объявления категории "важное" отображаются с визуальным акцентом

### Двухуровневая модель категорий

* **BR-14:** Категории чатов имеют два уровня: **системные** (глобальные) и **персональные** (пользовательские)
* **BR-15:** Системные категории создают только пользователи с ролью ADMIN или SUPER_ADMIN
* **BR-16:** Системные категории видны всем пользователям системы
* **BR-17:** Персональные категории создаёт каждый пользователь для своей организации чатов
* **BR-18:** Персональные категории видны только их владельцу
* **BR-19:** Системная категория может содержать вложенные подкатегории (1 уровень вложенности)
* **BR-20:** Персональная категория не поддерживает вложенность (плоская структура)
* **BR-21:** Один чат может иметь одну системную категорию и/или находиться в одной персональной папке
* **BR-22:** При удалении системной категории чаты перемещаются в "Без категории" (системная)
* **BR-23:** При удалении персональной категории чаты перемещаются в "Без папки" (персональная)
* **BR-24:** Администратор может назначить системную категорию чату принудительно
* **BR-25:** Пользователь может переместить любой свой чат в системную или персональную категорию

### Модерация

* **BR-26:** Модерацию могут выполнять только пользователи с ролью ADMIN или SUPER_ADMIN
* **BR-27:** Заблокированный пользователь не может отправлять сообщения и участвовать в чатах
* **BR-28:** Заблокированный пользователь не может отправлять личные сообщения
* **BR-29:** Блокировка пользователя не удаляет его сообщения — они сохраняются с пометкой "Заблокированный пользователь"
* **BR-30:** Предупреждение фиксируется в истории модерации и видно модератору
* **BR-31:** Пользователь получает уведомление о предупреждении
* **BR-32:** Жалоба создаётся пользователем и рассматривается модератором
* **BR-33:** Жалоба имеет статусы: новая (pending), рассмотрена (resolved), отклонена (dismissed)
* **BR-34:** Один пользователь не может подать несколько жалоб на одно и то же сообщение
* **BR-35:** Удалённое сообщение не восстанавливается
* **BR-36:** Модератор может удалить сообщение любого пользователя в любом чате
* **BR-37:** Модератор может удалить пользователя из любого чата
* **BR-38:** При блокировке пользователя он автоматически удаляется из всех чатов

## 3. Функциональные требования

### Личные сообщения

* **FR-REQ-COMMS-001-01:** Система должна позволять пользователю начать личный диалог с другим пользователем
* **FR-REQ-COMMS-001-02:** Система должна позволять отправлять текстовые сообщения в личном диалоге
* **FR-REQ-COMMS-001-03:** Система должна отображать историю личных сообщений в хронологическом порядке
* **FR-REQ-COMMS-001-04:** Система должна отображать список активных диалогов пользователя на странице `/dashboard/messages`
* **FR-REQ-COMMS-001-05:** Система должна поддерживать поиск по диалогам (по имени собеседника)
* **FR-REQ-COMMS-001-06:** Система должна отображать счетчик непрочитанных сообщений в навбаре

### Групповые чаты

* **FR-REQ-COMMS-001-07:** Система должна создавать чат автоматически для каждого участка с более чем одним пользователем
* **FR-REQ-COMMS-001-08:** Система должна позволять администраторам создавать тематические чаты
* **FR-REQ-COMMS-001-09:** Система должна позволять добавлять/удалять участников чата (только создатель или администратор)
* **FR-REQ-COMMS-001-10:** Система должна позволять отправлять текстовые сообщения в групповом чате
* **FR-REQ-COMMS-001-11:** Система должна поддерживать упоминание пользователей через @username
* **FR-REQ-COMMS-001-12:** Система должна позволять закреплять важные сообщения в чате (только создатель или администратор)
* **FR-REQ-COMMS-001-13:** Система должна отображать список доступных чатов пользователя на странице `/dashboard/chats`
* **FR-REQ-COMMS-001-14:** Система должна поддерживать поиск по чатам (по названию)

### Категории чатов — системные (администратор)

* **FR-REQ-COMMS-001-15:** Система должна позволять администратору создавать системные категории для чатов
* **FR-REQ-COMMS-001-16:** Система должна позволять администратору редактировать системные категории
* **FR-REQ-COMMS-001-17:** Система должна позволять администратору удалять системные категории (чаты перемещаются в "Без категории")
* **FR-REQ-COMMS-001-18:** Система должна позволять администратору создавать подкатегории для системных категорий (1 уровень вложенности)
* **FR-REQ-COMMS-001-19:** Система должна позволять администратору назначать системную категорию чату
* **FR-REQ-COMMS-001-20:** Система должна отображать системные категории всем пользователям на странице `/dashboard/chats`

### Категории чатов — персональные (пользователь)

* **FR-REQ-COMMS-001-21:** Система должна позволять пользователю создавать персональные папки для чатов
* **FR-REQ-COMMS-001-22:** Система должна позволять пользователю редактировать персональные папки
* **FR-REQ-COMMS-001-23:** Система должна позволять пользователю удалять персональные папки (чаты перемещаются в "Без папки")
* **FR-REQ-COMMS-001-24:** Система должна позволять пользователю перемещать чаты в/из персональных папок
* **FR-REQ-COMMS-001-25:** Система должна отображать чаты сгруппированными по системным и персональным категориям

### Модерация — жалобы

* **FR-REQ-COMMS-001-26:** Система должна позволять пользователю подать жалобу на сообщение
* **FR-REQ-COMMS-001-27:** Система должна позволять выбирать причину жалобы (оскорбление, спам, реклама, другое)
* **FR-REQ-COMMS-001-28:** Система должна создавать уведомление для модератора при новой жалобе
* **FR-REQ-COMMS-001-29:** Система должна предотвращать дублирование жалоб от одного пользователя на одно сообщение

### Модерация — действия модератора

* **FR-REQ-COMMS-001-30:** Система должна позволять модератору удалять любое сообщение в любом чате
* **FR-REQ-COMMS-001-31:** Система должна позволять модератору удалять пользователя из любого чата
* **FR-REQ-COMMS-001-32:** Система должна позволять модератору заблокировать пользователя
* **FR-REQ-COMMS-001-33:** Система должна позволять модератору разблокировать пользователя
* **FR-REQ-COMMS-001-34:** Система должна позволять модератору выдать предупреждение пользователю с указанием причины
* **FR-REQ-COMMS-001-35:** Система должна позволять модератору рассмотреть жалобу и изменить её статус
* **FR-REQ-COMMS-001-36:** Система должна позволять модератору просмотреть историю жалоб

### Модерация — интерфейс

* **FR-REQ-COMMS-001-37:** Система должна отображать панель модерации на странице `/dashboard/moderation`
* **FR-REQ-COMMS-001-38:** Система должна отображать список активных жалоб на панели модерации
* **FR-REQ-COMMS-001-39:** Система должна отображать список заблокированных пользователей на панели модерации
* **FR-REQ-COMMS-001-40:** Система должна отображать историю действий модератора

### Объявления

* **FR-REQ-COMMS-001-41:** Система должна позволять администраторам создавать объявления
* **FR-REQ-COMMS-001-42:** Система должна поддерживать категории объявлений: важное, плановое, техническое, информационное
* **FR-REQ-COMMS-001-43:** Система должна позволять включать обсуждение для объявления (автоматическое создание чата)

* **FR-REQ-COMMS-001-45:** Система должна поддерживать статусы объявлений: черновик, опубликовано, архивировано
* **FR-REQ-COMMS-001-46:** Система должна отображать список объявлений на странице `/dashboard/announcements`
* **FR-REQ-COMMS-001-47:** Система должна позволять архивировать старые объявления (только администратор)

* **FR-REQ-COMMS-001-49:** Система должна генерировать внутренние уведомления при упоминании пользователя в чате

* **FR-REQ-COMMS-001-53:** Система должна отображать иконку уведомлений в навбаре с бейджем непрочитанных

* **FR-REQ-COMMS-001-58:** Система должна позволять пользователю настроить частоту email-уведомлений в профиле: немедленно, ежедневно, еженедельно
* **FR-REQ-COMMS-001-59:** Система должна позволять пользователю отключить email-уведомления полностью в профиле

## 5. Нефункциональные требования (NFR) и Ограничения

* **Безопасность:**
  * Все операции с сообщениями требуют авторизации
  * Проверка прав доступа на уровне API для каждого запроса
  * Личные сообщения доступны только участникам диалога
  * Чаты по участкам доступны только пользователям со связью с участком
* **Производительность:**
  * Загрузка списка сообщений: < 500ms при до 10,000 сообщений
  * Загрузка списка диалогов/чатов: < 300ms
  * Доставка внутреннего уведомления: < 1 секунды после события
  * Отправка email-уведомления: < 5 секунд (асинхронно)
* **Доступность:**
  * Интерфейс сообщений должен быть доступен с клавиатуры (tab-навигация)
  * Элементы управления (отправка, поиск, навигация) должны иметь ARIA-метки
  * Уведомления в навбаре должны иметь aria-live для скринридеров
* **Локализация:**
  * Все сообщения об ошибках и UI-тексты на русском языке
  * Email-уведомления на русском языке
* **Адаптивность:**
  * Интерфейс сообщений должен корректно отображаться на мобильных устройствах
  * Навбар с уведомлениями должен адаптироваться к мобильному экрану
* **Масштабируемость:**
  * Поддержка до 10,000 активных пользователей
  * Поддержка до 100,000 сообщений в базе данных

## 6. Исключения и Граничные кейсы (Edge Cases)

* **EC-01:** Пользователь пытается отправить сообщение без авторизации — система должна вернуть ошибку 401 (Unauthorized)
* **EC-02:** Пользователь пытается получить доступ к чужому личному диалогу — система должна вернуть ошибку 403 (Forbidden)
* **EC-03:** Пользователь пытается получить доступ к чату без прав — система должна вернуть ошибку 403 (Forbidden)
* **EC-04:** Пользователь пытается создать объявление без роли ADMIN/SUPER_ADMIN — система должна вернуть ошибку 403 (Forbidden)
* **EC-05:** Пользователь с указанным ID не найден — система должна вернуть ошибку 404 с сообщением «Пользователь не найден»
* **EC-06:** Диалог/чат не найден — система должна вернуть ошибку 404 с сообщением «Диалог не найден»
* **EC-07:** Список диалогов пуст — система должна отобразить EmptyState с призывом начать диалог
* **EC-08:** Список чатов пуст — система должна отобразить EmptyState с информацией о доступных чатах
* **EC-09:** Список объявлений пуст — система должна отобразить EmptyState с сообщением «Объявления отсутствуют»
* **EC-10:** Медленная сеть (более 3 секунд без ответа) — система должна отобразить индикатор загрузки и сообщение «Загрузка...»
* **EC-11:** Ошибка отправки email — система должна залогировать ошибку и продолжить работу (не прерывать основную операцию)
* **EC-12:** Пользователь удалил аккаунт — его сообщения сохраняются, но отправитель отображается как "Удалённый пользователь"
* **EC-13:** Поиск не дал результатов — система должна отобразить EmptyState с сообщением «Ничего не найдено»
* **EC-14:** Пользователь отключил email-уведомления — email не отправляется, только внутреннее уведомление создается

### Edge Cases для категорий

* **EC-15:** Пользователь без роли ADMIN пытается создать системную категорию — система должна вернуть ошибку 403 (Forbidden)
* **EC-16:** Пользователь пытается создать системную категорию с дублирующимся названием — система должна вернуть ошибку 409 с сообщением «Категория с таким названием уже существует»
* **EC-17:** Администратор удаляет системную категорию с чатами — чаты перемещаются в "Без категории", категория удаляется
* **EC-18:** Пользователь удаляет персональную папку с чатами — чаты перемещаются в "Без папки", папка удаляется
* **EC-19:** Пользователь пытается создать подкатегорию глубже 1 уровня — система должна вернуть ошибку 400 с сообщением «Максимальная глубина вложенности — 1 уровень»
* **EC-20:** Пользователь пытается получить доступ к чужой персональной папке — система должна вернуть ошибку 403 (Forbidden)

### Edge Cases для модерации

* **EC-21:** Пользователь без роли ADMIN пытается удалить сообщение — система должна вернуть ошибку 403 (Forbidden)
* **EC-22:** Пользователь без роли ADMIN пытается заблокировать пользователя — система должна вернуть ошибку 403 (Forbidden)
* **EC-23:** Заблокированный пользователь пытается отправить сообщение — система должна вернуть ошибку 403 с сообщением «Ваш аккаунт заблокирован»
* **EC-24:** Модератор пытается подать жалобу на уже удалённое сообщение — система должна вернуть ошибку 404 с сообщением «Сообщение не найдено»
* **EC-25:** Пользователь пытается подать вторую жалобу на то же сообщение — система должна вернуть ошибку 409 с сообщением «Жалоба уже подана»
* **EC-26:** Модератор разблокирует пользователя — пользователь автоматически добавляется обратно в общие чаты (не в личные диалоги)
* **EC-27:** Попытка выдачи предупреждения уже заблокированному пользователю — система должна вернуть ошибку 400 с сообщением «Пользователь уже заблокирован»

## 7. Критерии приёмки

1. Авторизованный пользователь может начать личный диалог с другим пользователем и обмениваться сообщениями
2. Личные сообщения видны только участникам диалога
3. Пользователь видит список своих диалогов на странице `/dashboard/messages`
4. Чат создается автоматически для участка с более чем одним пользователем
5. Администратор может создавать тематические чаты и управлять участниками
6. В чатах поддерживаются упоминания пользователей через @username
7. Администратор может создавать объявления с категориями и статусами
8. Объявление с включенным обсуждением имеет привязанный чат
9. Внутренние уведомления создаются при получении сообщения, упоминании и публикации объявления
10. Уведомления отображаются в навбаре с бейджем непрочитанных
11. Пользователь может отметить уведомления как прочитанные
12. Email-уведомления отправляются согласно настройкам пользователя
13. Пользователь может настроить частоту email-уведомлений в профиле
14. История сообщений сохраняется неограниченно
15. При удалении пользователя его сообщения сохраняются с пометкой "Удалённый пользователь"
16. Интерфейс адаптивен и корректно отображается на мобильных устройствах
17. Все сообщения об ошибках и UI-тексты на русском языке

### Критерии приёмки для категорий

18. Администратор может создать системную категорию, видимую всем пользователям
19. Администратор может создавать подкатегории (1 уровень вложенности) для системных категорий
20. Администратор может назначать системную категорию любому чату
21. Пользователь может создавать персональные папки для организации своих чатов
22. Пользователь может перемещать чаты между системными и персональными категориями
23. Удаление системной категории администратором не удаляет чаты — они перемещаются в "Без категории"
24. Удаление персональной папки пользователем не удаляет чаты — они перемещаются в "Без папки"
25. Пользователь не может видеть персональные папки других пользователей

### Критерии приёмки для модерации

26. Пользователь может подать жалобу на сообщение с выбором причины
27. Модератор видит все активные жалобы на странице `/dashboard/moderation`
28. Модератор может удалить сообщение любого пользователя
29. Модератор может заблокировать пользователя, после чего тот не может отправлять сообщения
30. Модератор может разблокировать пользователя
31. Модератор может выдать предупреждение с указанием причины
32. Заблокированный пользователь видит сообщение о блокировке при попытке отправить сообщение
33. История модерации доступна модераторам
