# REQ-NAV-001: SPA маршрутизация и навигация

## 1. Бизнес-контекст и Цель

*Система управления СНТ использует подход одностраничного приложения (SPA). Маршрутизация и навигация должны обеспечивать плавный пользовательский опыт с защитой маршрутов и контекстной навигацией.*

* **Бизнес-цель:** Обеспечить интуитивно понятную навигацию между разделами приложения с защитой защищённых маршрутов и контекстно-зависимым отображением элементов навигации.
* **Стейкхолдеры / Пользователи:** Все авторизованные пользователи, администраторы приложения.

## 2. Бизнес-правила и Логика (Business Rules)

* **BR-01:** Все страницы приложения являются интерактивными с возможностью обновления состояния
* **BR-02:** Главная страница доступна всем без авторизации
* **BR-03:** Страницы входа и регистрации доступны без авторизации
* **BR-04:** Все маршруты дашборда требуют авторизации — неавторизованные перенаправляются на страницу входа
* **BR-05:** Авторизованные пользователи перенаправляются с главной страницы на дашборд
* **BR-06:** Навигационная панель отображает пункты меню на основе роли пользователя
* **BR-07:** Ссылка на профиль пользователя отображается в навигационной панели
* **BR-08:** При отсутствии имени пользователя в навигационной панели отображается email
* **BR-09:** Вкладка "Общение" объединяет все виды коммуникаций (личные сообщения, групповые чаты) в один раздел навигации
* **BR-10:** Отдельные вкладки "Личные сообщения" и "Групповые чаты" из главной навигации удаляются

## 3. Функциональные требования

* **FR-01:** Система должна использовать маршрутизатор приложения для навигации
* **FR-02:** Система должна обрабатывать корневой маршрут как главную страницу для неавторизованных пользователей
* **FR-03:** Система должна обеспечивать навигацию к дашборду для авторизованных пользователей
* **FR-04:** Система должна защищать маршруты дашборда
* **FR-05:** Система должна обеспечивать навигацию через навигационную панель на всех страницах дашборда
* **FR-06:** Система должна отображать ссылку на профиль пользователя в навигационной панели
* **FR-07:** Система должна обеспечивать клиентскую навигацию с обновлением состояния
* **FR-08:** Система должна отображать страницу «не найдено» для несуществующих маршрутов
* **FR-09:** Система должна отображать вкладку "Общение" в навигационной панели дашборда
* **FR-10:** Система должна обеспечивать навигацию к разделу "Общение" на маршруте `/dashboard/comms`
* **FR-11:** Система должна обеспечивать переключение между подразделами "Общения" — личные сообщения и групповые чаты

## 5. Нефункциональные требования (NFR) и Ограничения

* **Производительность:**
  * Клиентская навигация: < 100ms (без полной перезагрузки страницы)
  * Загрузка страниц дашборда: < 1s с учётом загрузки данных
  * Предварительная загрузка критических страниц
* **UX:**
  * Плавные переходы между страницами
  * Сохранение состояния приложения при навигации
  * Индикаторы загрузки при навигации
* **Безопасность:**
  * Защита на уровне сервера
  * Проверка сессии на уровне компонентов
  * Двойная защита: серверная + клиентская
* **Доступность:**
  * Семантическая HTML-разметка (навигация, ссылки, основной контент)
  * Навигация с клавиатуры (Tab, Enter, Escape)
  * Управление фокусом при навигации

## 6. Исключения и Граничные кейсы (Edge Cases)

* **EC-01:** Прямой доступ к странице списка участков без авторизации — редирект на страницу входа с сохранением адреса
* **EC-02:** Исторические ссылки без раздела дашборда — ведут на страницу «не найдено», не перенаправляются
* **EC-03:** Механизм защиты маршрутов недоступен — страница отображается без редиректа
* **EC-04:** Сессия истекла во время навигации — редирект на страницу входа
* **EC-05:** Навигация при загрузке данных — показывается индикатор загрузки или прогресс-бар
* **EC-06:** Ошибка при загрузке страницы — отображается страница ошибки с кнопкой "Повторить"
* **EC-07:** Прямой доступ к старым URL `/dashboard/messages` и `/dashboard/chats` — редирект на `/dashboard/comms`

## 7. Критерии приёмки

1. Неавторизованный пользователь видит главную страницу
2. Авторизованный пользователь перенаправляется с главной страницы на дашборд
3. Неавторизованный пользователь перенаправляется с разделов дашборда на страницу входа
4. Навигационная панель отображается на всех страницах дашборда с навигационными пунктами
5. Ссылка на профиль отображается в навигационной панели авторизованного пользователя
6. Клиентская навигация между страницами работает без полной перезагрузки
7. Страница «не найдено» отображается для несуществующих маршрутов
8. Вкладка "Общение" отображается в навигационной панели вместо отдельных вкладок "Личные сообщения" и "Групповые чаты"
9. Переход по старым URL `/dashboard/messages` и `/dashboard/chats` перенаправляет на `/dashboard/comms`
10. В разделе "Общение" можно переключаться между личными сообщениями и групповыми чатами
