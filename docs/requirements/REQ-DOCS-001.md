# REQ-DOCS-001: Управление документами

## 1. Бизнес-контекст и Цель

*Приложение СНТ требует функционала управления документами — возможностью загружать, хранить, просматривать и управлять юридическими и информационными документами (договоры, справки, протоколы и пр.).*

 * **Бизнес-цель:** Централизовать хранение и управление документами СНТ, обеспечив удобный доступ к юридическим, финансовым и информационным документам для всех участников.
 * **Стейкхолдеры / Пользователи:**
   * Участники СНТ (просмотр своих документов)
   * Правление/Администраторы (загрузка и управление документами)
   * Бухгалтерия (финансовые документы)

## 2. Бизнес-правила и Логика (Business Rules)

 * **BR-01:** Типы документов могут быть расширены без изменения кода (настраиваемый список типов)
 * **BR-02:** Документ может находиться только в одной категории
 * **BR-03:** Категория может быть вложенной (подкатегория) или корневой
 * **BR-04:** Видимость документа определяется администратором и привязывается к роли пользователя (GUEST, MEMBER, ADMIN и т.д.)
 * **BR-05:** Документ может иметь только один статус одновременно
 * **BR-06:** Статусы документа: черновик (draft), опубликован (published), архивирован (archived)
 * **BR-07:** Документ в статусе "черновик" не виден пользователям (только администраторам)
 * **BR-08:** Документ в статусе "архивирован" недоступен для редактирования (только просмотр)
 * **BR-09:** Максимальный размер файла настраивается в конфигурации системы
 * **BR-10:** Документ может иметь теги (метки) для поиска и категоризации
 * **BR-11:** Поиск по документам выполняется по названию, описанию и тегам (не по содержимому файла)

## 3. Функциональные требования

### Категории документов

 * **FR-01:** Система должна позволять создавать категории для документов
 * **FR-02:** Система должна поддерживать иерархию категорий (вложенность)
 * **FR-03:** Система должна позволять удалять категории (при наличии документов — перенос в родительскую категорию или "Без категории")

### Загрузка документов

 * **FR-04:** Система должна позволять администраторам загружать документы
 * **FR-05:** Система должна поддерживать загрузку файлов различных типов (PDF, DOCX, изображения и др.)
 * **FR-06:** Система должна проверять размер загружаемого файла против настроенного ограничения
 * **FR-07:** Система должна позволять администратору назначать документу категорию, тип, видимость по ролям и теги при загрузке
 * **FR-08:** Система должна поддерживать добавление описания к документу

### Просмотр документов

 * **FR-09:** Система должна позволять пользователям просматривать документы, доступные по их роли
 * **FR-10:** Система должна отображать список документов с возможностью фильтрации по категории и типу
 * **FR-11:** Система должна поддерживать поиск документов по названию, описанию и тегам
 * **FR-12:** Система должна позволять просматривать детали документа (метаданные, предпросмотр)

### Управление доступом

 * **FR-13:** Система должна позволять администратору настраивать видимость документа по ролям пользователей
 * **FR-14:** Система должна проверять доступ пользователя к документу при каждом запросе

### Метаданные документов

 * **FR-15:** Система должна хранить метаданные документа: название, описание, тип, категория, статус, автор, дата создания, дата изменения
 * **FR-16:** Система должна позволять администратору редактировать метаданные документа

### Теги

 * **FR-17:** Система должна позволять администратору добавлять и удалять теги у документов
 * **FR-18:** Система должна поддерживать поиск по тегам

## 5. Нефункциональные требования (NFR) и Ограничения

 * **Безопасность:**
   * Проверка доступа к документу на основе роли пользователя
   * Валидация загружаемых файлов на сервере
   * Защита от загрузки вредоносных файлов
   * Хранение файлов в защищённом хранилище

 * **Производительность:**
   * Загрузка файла: < 5 секунд для файла до 100МБ
   * Поиск по документам: < 500мс
   * Отрисовка списка документов: < 1 секунда при до 1000 записей

 * **Масштабируемость:**
   * Поддержка до 10 000 документов без деградации производительности
   * Настраиваемый максимальный размер файла

 * **Локализация:** Все сообщения на русском языке

 * **Хранение:**
   * Файлы хранятся в отдельном хранилище (не в базе данных)
   * В базе данных хранятся только метаданные и ссылка на файл

## 6. Исключения и Граничные кейсы (Edge Cases)

 * **EC-01:** При загрузке файла, превышающего максимальный размер — отклонение с ошибкой
 * **EC-02:** При попытке удалить категорию с документами — перенос документов в родительскую категорию или "Без категории"
 * **EC-03:** При попытке доступа к документу без прав — возврат 403 (Forbidden)
 * **EC-04:** При загрузке файла с неподдерживаемым расширением — отклонение с ошибкой
 * **EC-05:** При попытке редактирования архивированного документа — отклонение с сообщением
 * **EC-06:** При поиске без результатов — отображение сообщения "Ничего не найдено"
 * **EC-07:** При загрузке файла с нулевым размером — отклонение с ошибкой

## 7. Критерии приёмки

1. Администратор может создать категорию для документов
2. Администратор может загрузить документ с метаданными (название, описание, категория, тип, теги)
3. Размер загружаемого файла проверяется против настроенного ограничения
4. Администратор может настроить видимость документа по ролям
5. Пользователь с ролью MEMBER видит только документы, доступные для его роли
6. Пользователь с ролью ADMIN видит все документы
7. Поиск по документам работает по названию, описанию и тегам
8. Документ в статусе "черновик" виден только администраторам
9. Документ в статусе "архивирован" недоступен для редактирования
10. При удалении категории документы переносятся в родительскую категорию
11. Максимальный размер файла настраивается в конфигурации
12. Список документов можно фильтровать по категории и типу
13. Метаданные документа можно редактировать (только администратору)
14. Теги можно добавлять и удалять у документов
15. Все сообщения об ошибках на русском языке
