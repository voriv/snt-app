# Управление пользователями

## Статус: На обсуждении

---

## 1. Цель

Обеспечить управление жизненным циклом пользователей системы: регистрацию, аутентификацию, управление ролями и доступом.

---

## 2. Область применения

Включает:
- Регистрацию новых пользователей
- Аутентификацию (вход по email/password)
- Управление сессиями (JWT, refresh token)
- Восстановление пароля
- Управление ролями (ADMIN, MEMBER, GUEST)
- Навигационный интерфейс для авторизованных пользователей (Side Bar)

Не включает:
- OAuth/социальную аутентификацию (отложено)
- SSO (отложено)
- Многофакторную аутентификацию (отложено)

---

## 3. Функциональные требования

### FR-01-001: Регистрация пользователя

**Описание:** Система должна позволять новым пользователям создавать учётную запись, вводя email и пароль. Новый пользователь автоматически получает роль `GUEST` и активируется без дополнительных шагов верификации.

**Критерии приёмки:**
1. При отправке формы регистрации с валидным email и паролем (≥6 символов) создаётся пользователь с ролью GUEST и `isActive = true`.
2. При попытке регистрации с уже существующим email система возвращает ошибку "Пользователь с таким email уже существует".
3. При невалидных входных данных система показывает конкретные ошибки валидации для каждого поля.
4. После успешной регистрации пользователь автоматически входит в систему (session создаётся).
5. На странице `/login` есть ссылка "Зарегистрироваться", ведущая на `/register`.

**Приоритет:** Высокий

**Связанные сущности:**
| Сущность | Домен | Операция |
|----------|-------|----------|
| User | Core | Create |

**Зависимости:**
- Не зависит от других FR

---

### FR-01-002: Вход в систему (Login)

**Описание:** Система должна позволять аутентифицированным пользователям входить в систему по email и паролю.

**Критерии приёмки:**
1. При отправке формы логина с валидными учетными данными создаётся сессия и пользователь перенаправляется на целевую страницу.
2. При неверном email или пароле система показывает общую ошибку "Неверный email или пароль" (без уточнения, что именно неверно).
3. При попытке входа неактивного пользователя (`isActive = false`) система показывает ошибку "Аккаунт заблокирован".
4. Пользователь остаётся в системе до истечения access token (1 час) или явного выхода.

**Приоритет:** Высокий

**Связанные сущности:**
| Сущность | Домен | Операция |
|----------|-------|----------|
| User | Core | Read, Verify |

**Зависимости:**
- Зависит от: FR-01-001 (регистрация создаёт пользователей)

---

### FR-01-003: Выход из системы (Logout)

**Описание:** Система должна позволять пользователю завершить активную сессию.

**Критерии приёмки:**
1. При вызове logout сессия пользователя удаляется.
2. Пользователь перенаправляется на страницу `/login`.
3. При попытке доступа к защищённым ресурсам после logout система требует повторной авторизации.

**Приоритет:** Высокий

**Связанные сущности:**
| Сущность | Домен | Операция |
|----------|-------|----------|
| User | Core | Session management |

**Зависимости:**
- Не зависит от других FR

---

### FR-01-004: Обновление сессии (Refresh Token)

**Описание:** Система должна автоматически обновлять access token с использованием refresh token.

**Критерии приёмки:**
1. При истечении access token система автоматически генерирует новый токен через `/api/auth/refresh`.
2. Старый refresh token отзывается и заменяется новым (token rotation).
3. При невалидном refresh token пользователь перенаправляется на страницу логина.

**Приоритет:** Высокий

**Связанные сущности:**
| Сущность | Домен | Операция |
|----------|-------|----------|
| User | Core | Session management |

**Зависимости:**
- Не зависит от других FR

---

### FR-01-005: Восстановление пароля

**Описание:** Система должна позволять пользователям сбрасывать пароль по email.

**Критерии приёмки:**
1. При запросе восстановления пароля с существующим email генерируется reset token (срок 1 час) и отправляется email со ссылкой для сброса.
2. При запросе восстановления пароля с несуществующим email система возвращает безопасный ответ "Если аккаунт существует, email отправлен".
3. При использовании reset token один раз он аннулируется.
4. Истёкший reset token не принимается.

**Приоритет:** Средний

**Связанные сущности:**
| Сущность | Домен | Операция |
|----------|-------|----------|
| User | Core | Update (resetToken, resetTokenExp) |

**Зависимости:**
- Зависит от: FR-01-002 (логин)

---

### FR-01-006: Боковая навигация (Side Bar)

**Описание:** Система должна предоставлять авторизованным пользователям боковую панель навигации (Side Bar) на каждой странице авторизованной зоны. Панель содержит разделы для быстрого доступа к основным функциям приложения.

**Критерии приёмки:**
1. Side Bar отображается только авторизованным пользователям (MEMBER, ADMIN).
2. Side Bar отображается на каждой странице авторизованной зоны.
3. Side Bar содержит три раздела: "Мои участки", "Все участки", "Информация и документы".
4. Раздел "Мои участки" содержит пункты "Информация" и "Взносы".
5. Раздел "Все участки" содержит пункты "Карты участков" и "Поиск участка".
6. Раздел "Информация и документы" содержит пункты "Новости", "Документы СНТ" и "Важная информация".
7. Активный пункт навигации выделяется визуально (подсветка текущего маршрута).
8. Side Bar поддерживает сворачивание/разворачивание (toggle).
9. Навигация по пунктам осуществляет переход по соответствующим маршрутам приложения.
10. Навигация доступна с клавиатуры (Tab, Enter, Escape).

**Приоритет:** Средний

**Связанные сущности:**
| Сущность | Домен | Операция |
|----------|-------|----------|
| User | Core | Read (проверка авторизации) |

**Зависимости:**
- Зависит от: FR-01-002 (авторизация необходима для отображения)
- Блокирует: FR-02-010 (управление участками — маршруты "Мои участки" и "Все участки")

## 4. Нефункциональные требования

### NFR-01-001: Безопасность

**Требования:**
- Пароли хэшируются через bcrypt (rounds = 12)
- JWT access token истекает через 1 час (HS256)
- Refresh token истекает через 7 дней
- Сессию можно отозвать через БД
- Защита от брутфорса (ограничение попыток входа)
- HTTP-only cookies для токенов
- SameSite = Strict для CSRF защиты

### NFR-01-002: Производительность

**Метрики:**

| Метрика | Целевое значение | Измерение |
|---------|------------------|-----------|
| Время регистрации API | ≤500ms (p95) | Промежуточное логирование |
| Время хэширования bcrypt | ~250ms | Локальный замер |
| Время входа API | ≤600ms (p95) | Промежуточное логирование |

### NFR-01-003: Доступность

**Требования:**
- Формы регистрации и входа соответствуют WCAG 2.1 уровень AA
- ARIA атрибуты для всех интерактивных элементов
- Навигация с клавиатуры (Tab, Enter, Escape)
