# REQ-PLOTUSER-001: Связи пользователей с участками

## 1. Бизнес-контекст и Цель

*Система управления СНТ требует функциональности для управления связями между пользователями и земельными участками: кто является владельцем, проживает или представляет интерес на конкретном участке.*

* **Бизнес-цель:** Обеспечить администраторов инструментами для учёта прав пользователей на участки (владельцы, проживающие, представители) с сохранением истории изменений.
* **Стейкхолдеры / Пользователи:** Администраторы СНТ, владельцы участков, проживающие, представители.

## 2. Бизнес-правила и Логика (Business Rules)

* **BR-01:** Пользователь и участок должны существовать перед созданием связи
* **BR-02:** Роль может быть только одной из: владелец, проживающий, представитель
* **BR-03:** Не может быть более одной активной связи одного пользователя с участком с той же ролью
* **BR-04:** Дата истечения должна быть в будущем, если указана
* **BR-05:** При создании/обновлении/деактивации связи автоматически создаётся запись в истории изменений
* **BR-06:** Права доступа: только текущий пользователь или администратор могут управлять связями
* **BR-07:** История создаётся транзакционно с основной записью — атомарность операции
* **BR-08:** Физическое удаление запрещено — только деактивация (статус "истёк")
* **BR-09:** Множественные роли на одном участке разрешены (один пользователь может быть владельцем и проживающим)
* **BR-10:** Множественные владельцы на одном участке разрешены

## 3. Функциональные требования

* **FR-01:** Система должна поддерживать создание связи пользователя с участком с валидацией бизнес-правил
* **FR-02:** Система должна поддерживать поиск связи по идентификатору
* **FR-03:** Система должна поддерживать поиск всех связей для пользователя (мои подключения)
* **FR-04:** Система должна поддерживать поиск всех связей для участка (список участников)
* **FR-05:** Система должна поддерживать обновление связи с автоматическим созданием записи в истории
* **FR-06:** Система должна поддерживать деактивацию связи (статус "истёк")
* **FR-07:** Система должна поддерживать пагинированный список связей с фильтрацией по пользователю, участку, роли, статусу
* **FR-08:** Система должна поддерживать фильтрацию участников участка по роли и статусу
* **FR-09:** Система должна поддерживать поиск участников по имени или email
* **FR-10:** Система должна поддерживать поиск связей пользователя по номеру участка или адресу
* **FR-11:** Система должна отображать историю изменений каждой связи

## 5. Нефункциональные требования (NFR) и Ограничения

* **Безопасность:**
  * Все операции требуют авторизации
  * Ролевой доступ: управление связями только для администратора или владельцев участка
  * Валидация всех входных данных на сервере
  * История изменений сохраняется для аудитора
* **Производительность:**
  * Загрузка списка участников: < 1 сек для до 100 участников
  * Поиск участников: < 200ms (с задержкой 300ms на клиенте)
  * Создание/обновление связи: < 300ms
* **Доступность:**
  * Семантическая разметка таблиц
  * ARIA-метки для фильтров и поиска
  * Навигация с клавиатуры
* **Локализация:** Все сообщения на русском языке
* **Адаптивность:** Таблица корректно отображается на мобильных устройствах

## 6. Исключения и Граничные кейсы (Edge Cases)

* **EC-01:** Участок не существует — система сообщает, что участок не найден
* **EC-02:** Пользователь не существует — система возвращает ошибку "Пользователь не найден"
* **EC-03:** Более 100 участников — пагинация: 25 элементов на страницу
* **EC-04:** Пользователь удалён из системы — отображается "[удалён]"
* **EC-05:** Параллельное изменение данных — обновление интерфейса, повторная загрузка данных через 5 секунд
* **EC-06:** Медленное соединение (более 5 секунд) — индикатор загрузки с анимацией
* **EC-07:** Попытка создать дублирующую активную связь — система сообщает о дублировании
* **EC-08:** Попытка деактивировать уже деактивированную связь — система возвращает ошибку
* **EC-09:** Компонент не может получить идентификатор участка — отображается сообщение об ошибке
* **EC-10:** Сервер не отвечает — показывается индикатор загрузки

## 7. Критерии приёмки

1. Администратор может создать связь пользователя с участком (роль: владелец/проживающий/представитель)
2. При создании связи автоматически создаётся запись в истории
3. Нельзя создать дублирующую активную связь для той же пары (пользователь, участок, роль)
4. Дата истечения должна быть в будущем
5. Пользователь может просмотреть все свои связи на странице моих подключений
6. Администратор может просмотреть всех участников участка на странице деталей участка
7. Фильтрация по роли и статусу работает корректно
8. Поиск по имени/email возвращает результаты моментально (менее 200ms)
9. Деактивация связи изменяет статус на "истёк" и создаёт запись в истории
10. История изменений доступна для каждой связи
