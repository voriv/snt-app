# REQ-INFRA-SEED-001: Seed данных для всего приложения

## 1. Бизнес-контекст и Цель

Система управления СНТ «Берёзки-НТ» требует реалистичных тестовых данных для разработки, демонстрации и QA-тестирования. Текущий seed-сценарий (`prisma/seed.ts`) покрывает только базовую инфраструктуру: роли (4 шт.), страницы (7 шт.), API endpoints (44 шт.), access_config_version и четырёх пользователей (3 SUPER_ADMIN + 1 MEMBER). Отсутствуют данные для ключевых доменов: участки, связи пользователь-участок, коммс (диалоги, сообщения), объявления, документы.

- **Бизнес-цель:** Обеспечить dev/demo окружение полным набором реалистичных данных для тестирования всех функциональных модулей приложения без необходимости ручного заполнения через UI.
- **Стейкхолдеры / Пользователи:** Разработчики, QA-инженеры, Product Owner (для демо), администраторы системы (для onboarding).

## 2. Бизнес-правила и Логика (Business Rules)

- **BR-01:** Seed должен быть идемпотентным — многократное выполнение не создаёт дубликатов данных.
- **BR-02:** Все сущности в seed должны использовать детерминированные идентификаторы (например, фиксированные email, plot_number), а не случайные cuid(), чтобы ссылки между сущностями были воспроизводимы.
- **BR-03:** Пароли всех seed-пользователей должны быть задокументированы в комментарии к seed-файлу и хешированы через bcrypt с тем же BCRYPT_SALT_ROUNDS, что и основная система.
- **BR-04:** Seed-данные должны отражать реалистичную структуру СНТ: участки с номерами «1», «2»…«20», кадастровыми номерами, площадями 6-12 соток, адресами в формате «ул. Садовая, д. N».
- **BR-05:** Пользователи seed должны покрывать все 4 роли системы: SUPER_ADMIN, ADMIN, MEMBER, GUEST.
- **BR-06:** Каждый seed-пользователь должен иметь связанный UserProfile с ФИО, телефоном и темой.
- **BR-07:** Связи пользователь-участок (PlotUserRole) должны включать разные роли на участке: owner (владелец), resident (проживающий), representative (представитель).
- **BR-08:** Коммс-данные должны включать: личные диалоги (DIRECT), групповые чаты (GROUP), чаты объявлений (ANNOUNCEMENT).
- **BR-09:** Сообщения должны покрывать кейсы: обычные сообщения, цитирование (replyToId), удалённые сообщения (isDeleted=true), различные отправители.
- **BR-10:** Объявления должны покрывать все статусы: DRAFT, PUBLISHED, ARCHIVED, включая важное объявление (isImportant=true).
- **BR-11:** Документы должны покрывать все статусы (DRAFT, PUBLISHED, ARCHIVED), категории с вложенностью (parent-child) и тэги.
- **BR-12:** Seed должен выполняться асинхронно без блокировки основной миграции БД.

## 3. Функциональные требования

### 3.1 Пользователи и профили

- **FR-01:** Seed должен создать не менее 10 пользователей, покрывающих все 4 роли (SUPER_ADMIN, ADMIN, MEMBER, GUEST).
- **FR-02:** Каждый пользователь должен иметь связанный UserProfile с заполненными полями first_name, middle_name, last_name, phone, theme.
- **FR-03:** Seed-пользователи должны включать как минимум одного ADMIN и одного GUEST (помимо существующих SUPER_ADMIN и MEMBER).
- **FR-04:** Email seed-пользователей должен использовать домен `@snt.local` с детерминированными именами (admin@snt.local, member1@snt.local и т.д.).

### 3.2 Участки (Plots)

- **FR-05:** Seed должен создать не менее 20 участков с номерами «1»…«20».
- **FR-06:** Каждый участок должен иметь: plot_number, cadastral_number (формат «50:XX:XXXX:XX»), area (6-12 соток), address.
- **FR-07:** Участки должны использовать уникальные ключи (plot_number, cadastral_number) для идемпотентности через upsert.

### 3.3 Связи пользователь-участок (PlotUserRole)

- **FR-08:** Seed должен создать связи между пользователями и участками, покрывающие все роли на участке (owner=0, resident=1, representative=2).
- **FR-09:** Каждый участок должен иметь как минимум одного владельца (owner).
- **FR-10:** Некоторые участки должны иметь нескольких участников (владелец + проживающий).
- **FR-11:** Связи должны включать различные статусы: «active», «inactive», «pending».
- **FR-12:** Для каждой созданной связи должен быть создан соответствующий记录 в PlotUserRoleHistory.

### 3.4 Коммс — Диалоги (Conversations)

- **FR-13:** Seed должен создать как минимум:
  - 5 личных диалогов (type=DIRECT) между парами пользователей.
  - 3 групповых чата (type=GROUP) с 3-5 участниками.
  - 1 чат объявления (type=ANNOUNCEMENT), связанный с объявлением.
- **FR-14:** Групповые чаты должны иметь title, description, createdBy и назначенных участников с ролями (OWNER, ADMIN, MEMBER).
- **FR-15:** Некоторые диалоги должны быть привязаны к участкам (plotId не null).

### 3.5 Коммс — Сообщения (Messages)

- **FR-16:** Seed должен создать не менее 30 сообщений, распределённых по разным диалогам.
- **FR-17:** Сообщения должны покрывать кейсы: обычные текстовые сообщения, сообщения с цитированием (replyToId), удалённые сообщения (isDeleted=true).
- **FR-18:** Сообщения должны быть от разных отправителей (senderId).
- **FR-19:** lastReadAt в ConversationParticipant должен быть установлен для имитации прочитанных/непрочитанных сообщений.

### 3.6 Объявления (Announcements)

- **FR-20:** Seed должен создать не менее 5 объявлений.
- **FR-21:** Объявления должны покрывать все статусы: DRAFT (1), PUBLISHED (3), ARCHIVED (1).
- **FR-22:** Как минимум одно объявление должно быть важным (isImportant=true).
- **FR-23:** Публикованные объявления должны иметь publishedAt в прошлом (например, 2-4 недели назад).
- **FR-24:** Объявления должны быть созданы разными авторами (ADMIN и SUPER_ADMIN).

### 3.7 Документы (Documents)

- **FR-25:** Seed должен создать не менее 3 категорий документов с поддержкой вложенности (parent-child).
- **FR-26:** Seed должен создать не менее 5 документов, распределённых по категориям.
- **FR-27:** Документы должны покрывать все статусы: DRAFT, PUBLISHED, ARCHIVED.
- **FR-28:** Seed должен создать не менее 3 тэгов документов и назначить их документам через DocumentTagLink.
- **FR-29:** Документы должны иметь реалистичные метаданные: title, original_name, mime_type, file_size.

## 4. Нефункциональные требования (NFR) и Ограничения

- **NFR-01 (Идемпотентность):** Seed должен использовать upsert по уникальным ключам (email, plot_number, method+path) для предотвращения дубликатов при повторном запуске.
- **NFR-02 (Производительность):** Время выполнения seed не должно превышать 30 секунд на локальной базе PostgreSQL.
- **NFR-03 (Безопасность):** Пароли должны быть хешированы через bcrypt. Никакие plaintext пароли не должны храниться в коде (за исключением констант в seed-файле с явным комментарием).
- **NFR-04 (Детерминизм):** seed должен использовать фиксированные значения для всех полей, кроме автогенерируемых дат (createdAt, updatedAt).
- **NFR-05 (Задокументированность):** В начале файла `prisma/seed.ts` должен быть блок-комментарий со списком всех созданных пользователей, их email и паролей.
- **NFR-06 (Разделение по доменам):** Seed-код должен быть структурирован по доменам (функции `seedUsers()`, `seedPlots()`, `seedComms()` и т.д.).
- **NFR-07 (Обработка ошибок):** При ошибке в любом разделе seed整个过程 должен остановиться с выводом ошибки в console.error.

## 5. Исключения и Граничные кейсы (Edge Cases)

- **EC-01:** Если seed выполняется на базе с уже существующими пользовательскими данными (не seed), система не должна удалять или изменять данные, созданные пользователями через UI.
- **EC-02:** Если связь пользователь-участок уже существует (например, пользователь зарегистрировался сам), seed должен пропустить создание этой связи без ошибки.
- **EC-03:** Если seed запускается без базы данных (ошибка подключения), процесс должен завершиться с кодом выхода 1 и понятным сообщением об ошибке.
- **EC-04:** Если уникальные ключи seed-сущностей конфликтуют с существующими данными (например, email admin@snt.local занят), seed должен использовать существующую запись без модификации.
- **EC-05:** Если seed-пользователь удалён через UI между запусками seed, следующий запуск должен воссоздать его с теми же данными.

## 6. Критерии приёмки

### AC-01: Идемпотентность
- **Given** база данных содержит seed-данные от предыдущего запуска,
- **When** выполняется `npm run seed`,
- **Then** количество записей в каждой таблице не увеличивается и seed завершается без ошибок.

### AC-02: Полный набор пользователей
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then** в таблице `user` не менее 10 записей, покрывающих все 4 роли (SUPER_ADMIN, ADMIN, MEMBER, GUEST).

### AC-03: Участки созданы корректно
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then** в таблице `plots` не менее 20 записей с уникальными plot_number «1»…«20».

### AC-04: Связи пользователь-участок созданы
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then** в таблице `plot_users` не менее 20 записей, покрывающих все роли (owner, resident, representative).

### AC-05: Коммс-данные созданы
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then**:
  - В `conversations` не менее 9 записей (5 DIRECT + 3 GROUP + 1 ANNOUNCEMENT).
  - В `messages` не менее 30 записей.
  - В `conversation_participants` соответствующие записи для всех диалогов.

### AC-06: Объявления созданы
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then** в `announcements` не менее 5 записей со всеми статусами (DRAFT, PUBLISHED, ARCHIVED).

### AC-07: Документы созданы
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then**:
  - В `document_categories` не менее 3 записей (включая вложенные).
  - В `documents` не менее 5 записей со всеми статусами.
  - В `document_tags` не менее 3 записей.
  - В `document_tag_links` соответствующие связи.

### AC-08: Профили пользователей заполнены
- **Given** чистая база данных,
- **When** выполняется `npm run seed`,
- **Then** каждый seed-пользователь имеет запись в `user_profiles` с first_name, last_name, phone.

### AC-09: Пароли документированы
- **Given** файл `prisma/seed.ts`,
- **When** открывается файл,
- **Then** в начале файла присутствует блок-комментарий с таблицей email → пароль для всех seed-пользователей.

### AC-10: Seed выполняется без ошибок
- **Given** чистая база данных и настроенный DATABASE_URL,
- **When** выполняется `npm run seed`,
- **Then** процесс завершается с кодом 0 и выводит итоговый лог «Seeding completed!».
