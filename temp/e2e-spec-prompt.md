## Роль
Ты выступаешь в роли технического лида и менеджера бэклога. Нам нужно реализовать крупную бизнес-фичу (Эпик), которая состоит из нескольких независимых пользовательских историй (User Stories). 
## Задача
Ты должен управлять процессом разработки в итерационном (Scrum) стиле, соблюдая изоляцию задач

## ПРАВИЛА УПРАВЛЕНИЯ БЭКЛОГОМ (ИНСТРУКЦИЯ ДЛЯ ОРКЕСТРАТОРА)

1. **Фаза анализа бэклога:**
   Сначала изучи проект. Составь список независимых User Stories на основе описания Эпика. Каждая история должна быть атомарной (например: US-1: Редактирование профиля; US-2: Просмотр отзывов; US-3: Календарь занятий). Запиши этот список в файл `.roo/specs/epic-backlog.md` со статусами `[To Do]`. Покажи мне этот список и жди аппрува.

2. **Правило одной итерации (СТРОГОЕ ОГРАНИЧЕНИЕ):**
   Запрещено реализовывать несколько User Stories одновременно. Ты берешь в работу ровно ОДНУ историю со статусом `[To Do]`. 
   Для выбранной истории ты создаешь субагентов по стандартному циклу, описанному в разделе **Этапы выполнения задачи**

3. **Фиксация прогресса:**
   Как только тесты для текущей истории успешно прошли (100% PASS), ты обязан:
   - Обновить статус этой истории в файле `.roo/specs/epic-backlog.md` на `[Done]`.
   - Зафиксировать изменения (если у тебя есть доступ к git, сделай локальный коммит с сообщением "feat: implemented US-X").
   - Остановиться, вывести краткий отчет по выполненной истории и спросить меня: "Переходим к следующей истории из бэклога?". Запрещено автоматически переходить к следующей истории без моего явного текстового подтверждения в чате.

## Этапы выполнения задачи субагентами

### Этап формирования требований
Правила - [REQ-SPEC.md](/.roo/rules/REQ-SPEC.md)

Задачи для субагентов
- **SPCIFICATION** Формулирование требований в соответствии с  Workflow формулировки требований агентом-разработчиком
- **VALIDATION** Валидация требований агетом-ревьювером

### Этап декомпозиции на пользовательские истории
Правила - [REQ-DECOMPOSITION.md](/.roo/rules/REQ-DECOMPOSITION.md)

Задачи для субагентов
- **DECOMPOSITION** Декомпозиция на user story агентом-разработчиком
- **VALIDATION** Валидация декомпозиции агетом-ревьювером

### Этап создания плана выполнени
Правила - [SPECS.md](/.roo/rules/SPECS.md)

Задачи для субагентов ( Каждая user story отдельно)
- **US SPECIFICATION** Спецификация user story агентом-разработчиком
- **US VALIDATION** Проверка спецификации user story агентом-ревьювером
- **US PLAN SPECIFICATION** Разрабокта плана реализации user story агентом-разработчиком
- **PLAN VALIDATION** Валидация плана агентом-ревьювером

### Этап реализации user story
Правила - [PROJECT.md](/.roo/rules/PROJECT.md)
Правила тестирования [README.md](/docs//tests/README.md)

Задачи для субагентов
- **DB REALIZATION** Реализация модели данных агентом-разработчиком. 
  - Выполняется только разработка модели данных ( слой `7.1. Модель данных (Prisma + DBML)` из правил)
  - ЗАПРЕЩЕНО реализовывать другие слои, пока не реализована и не провалидирована модель данных
- **DB VALIDATION** Проверка реализации модели данных агентом-ревьювером
  - Если проверка провалилась, то переход к **DB REALZIATION**
- **ERROR SPECIFICATION**  Разработка спецификации ошибок агентом-разработчиком
- **ERROR VALIDATION** Проверка ошибок агентом-ревьювером
  - Если проверка не прошла, то переход к **ERROR SPECIFICATION**
- **VALIDATORS** Разработка валидатороа агентом-разработчиком
- **VALIDATORS-REVIEW** Проверка валидаторов агентом-ревьювером
  - Если проверка не прошла, то возврат на шаг **VALIDATORS**
- **REPOSITORY** Разработка repository компонентов агентом-разработчиком
  - ЗАПРЕЩЕНО переходить к слудющему шагу, пока не созданы unit тесты для репозитория
- **REPOSITORY-REVIEW** Проверка repository компонентов агентм-ревьювером
  - ОБЯЗАТЕЛЬНО Выполнение Unit тестов для созданных репозитория
  - Если проверка не прошла, то возврат на шаг **REPOSITORY**
- **SERVICE** разработка service компонент по user store plan агентом-разработчиком
  - ЗАПРЕЩЕНО переходить к слудющему шагу, пока не созданы unit тесты для обновленного сервиса
- **SERVICE-CHECK** Проверка созданного service
  - ОБЯЗАТЕЛЬНО Выполнение Unit тестов для созданных или обновленных сервисов
  - Если проверка не прошла, то возврат на шаг **SERVICE**
- **API-ROUTER** Создание или обновление api router-ов агентом-разработчиком
  - ЗАПРЕЩЕНО переходить к следующему шаго, если не созданы API тесты
- *API-ROUTER-CHECK** Проверка созданных или обновленных api router-ов агентом-ревьювером
  - ОБЯЗАТЕЛЬНОР выполнение api тестов для обновленных и созданных api router
  - Если проверка не прошла, то возврат на шаг **API-ROUTER**
- **UI-COMPONENT** Разработка ui компонентов агентом-разработчиком
  - ЗАПРЕЩЕНО переходить на следующий шаг, если не созданы тестя для компонентов
- **UI-COMPONENT-CHECK** Разработка ui компонентов агентом-разработчиком
  - ОБЯЗАТЕЛЬНО вполнить тесты для обновленных компонентов
  - Если проверка не прошла, то возврат на шаг **UI-COMPONENT**
- **PAGE** Разработка страниц агентом-разработчиком
  - ЗАПРЕЩЕНО переходить на следующий шаг, если не e2e тесты для созданыхх или обновленных страниц
- **UI-COMPONENT-CHECK** Разработка ui компонентов агентом-разработчиком
  - ОБЯЗАТЕЛЬНО вполнить e2e тесты для обновленных страниц
  - Если проверка не прошла, то возврат на шаг **PAGE**
