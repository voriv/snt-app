# US-13: Просмотр списка участков

## Формулировка

**As a** член СНТ (Member),  
**I want to** просматривать список всех земельных участков в таблице, —  
**So that** я мог видеть общую информацию об участках и навигировать к деталям.

## Контекст

### Проблема
Пользователи не имеют централизованного представления всех земельных участков СНТ.

### Решение
Создать страницу `/dashboard/plots` с таблицей участков и навигацией из Navbar.

### Границы
- Модуль работает в контексте авторизованного пользователя
- Отображение данных определяется ролями (RBAC из US-8, US-9)
- Не включает CRUD-операции — только просмотр списка

## Модель данных

### Сущность Plot (чтение)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | String | Уникальный идентификатор |
| `plot_number` | String | Номер участка |
| `cadastral_number` | String? | Кадастровый номер |
| `area` | Decimal | Площадь (м²) |
| `address` | String? | Адрес |
| `note` | String? | Примечание |

## Функциональные требования

### FR-1: Навигация к разделу

Пользователь может перейти к списку участков из Navbar.

#### AC-1.1: Пункт меню «Участки»
- **Дано:** Пользователь авторизован и находится на dashboard
- **Когда:** Пользователь открывает Navbar
- **Тогда:** Отображается пункт меню «Участки» со ссылкой на `/dashboard/plots`
- **Иначе:** Если у пользователя нет разрешения на просмотр участков — пункт скрыт (RBAC)

#### AC-1.2: Переход на страницу
- **Дано:** Пользователь кликает на «Участки» в Navbar
- **Когда:** Клик по ссылке
- **Тогда:** Открывается страница `/dashboard/plots`

### FR-2: Отображение таблицы участков

Пользователь видит таблицу со списком участков.

#### AC-2.1: Структура таблицы
- **Дано:** Пользователь на странице `/dashboard/plots`
- **Когда:** Данные успешно загружены
- **Тогда:** Отображается таблица с колонками:
  | Колонка | Содержание | Сортировка |
  |---------|-----------|------------|
  | № участка | `plot_number` | По возрастанию |
  | Кадастр | `cadstral_number` или «—» | — |
  | Площадь | `area` м² | — |
  | Адрес | `address` или «—» | — |
- **Иначе:** Каждая колонка имеет заголовок

#### AC-2.2: Состояние загрузки
- **Дано:** Страница `/dashboard/plots` загружается
- **Когда:** Запрос к API активен (`isLoading = true`)
- **Тогда:**
  - Отображается скелетон таблицы или спиннер
  - Кнопка «Добавить участок» заблокирована (`disabled`)
- **Иначе:** Загрузка продолжается не более 3 секунд (fallback)

#### AC-2.3: Пустое состояние
- **Дано:** Запрос к API возвращает пустой массив
- **Когда:** `data.length === 0`
- **Тогда:** Отображается `EmptyState` с:
  - Заголовком: «Участки не найдены»
  - Описанием: «Добавьте первый участок, чтобы начать учет»
  - Кнопкой: «Добавить участок» (если есть право на создание)

#### AC-2.4: Состояние ошибки
- **Дано:** Запрос к API завершился ошибкой
- **Когда:** HTTP-статус ≠ 200 или исключение
- **Тогда:** Отображается:
  - Сообщение: «Ошибка загрузки списка участков»
  - Кнопка: «Повторить попытку»
  - Логирование ошибки в консоль

### FR-3: Загрузка данных

Пользователь получает данные через API.

#### AC-3.1: GET-запрос
- **Дано:** Пользователь на странице `/dashboard/plots`
- **Когда:** Страница монтируется
- **Тогда:** Выполняется `GET /api/v1/plots` через `apiClient`
- **Иначе:** Ответ имеет формат `{ success: true, data: Plot[] }`


## Бизнес-правила и валидация

| ID | Правило | Описание |
|----|---------|----------|
| BR-1 | Авторизация | Страница доступна только авторизованным пользователям |
| BR-2 | RBAC | Доступ к странице определяется разрешением на просмотр участков |
| BR-3 | Пустой список | Если нет участков — показывается `EmptyState` |

## Граничные случаи (Edge Cases)

| Сценарий | Ожидаемое поведение |
|----------|-------------------|
| 0 участков в БД | Показывается `EmptyState` с предложением добавить |
| 1000+ участков | Таблица отображается полностью (без пагинации в MVP) |
| Участок с null полями (address, cadstral_number) | Отображается «—» |
| Ошибка сети при загрузке | Показывается сообщение «Ошибка загрузки. Повторить попытку.» |
| Медленная сеть (> 3 сек) | Показывается спиннер, данные загружаются асинхронно |

## Обработка ошибок

| Код | Ситуация | Сообщение | Действие |
|-----|----------|-----------|----------|
| 401 | Не авторизован | — | Редирект на `/login` |
| 403 | Нет прав на просмотр | «У вас нет прав для просмотра участков» | Скрыть страницу |
| 500 | Внутренняя ошибка сервера | «Ошибка загрузки списка участков» | Показать кнопку «Повторить» |

## Влияние на слои архитектуры

### Модель данных

**Обновление `prisma/schema.prisma`:**
```prisma
model Plot {
  id              String      @id @default(cuid())
  plot_number     String      @unique @map("plot_number")
  cadstral_number String?     @unique @map("cadstral_number") @db.VarChar(20)
  area            Decimal     @map("area") @db.Decimal(10, 2)
  address         String?     @map("address")
  note            String?     @map("note")
  created_at      DateTime    @default(now()) @map("created_at")
  updated_at      DateTime    @updatedAt @map("updated_at")

  @@map("plots")
}
```

### Repository

**`src/domains/plot/plot.repository.interface.ts`:**
```typescript
export interface IPlotRepository {
  findAll(): Promise<Plot[]>;
}
```

**`src/domains/plot/plot.repository.prisma.ts`:**
```typescript
export class PlotRepositoryPrisma implements IPlotRepository {
  async findAll(): Promise<Plot[]> {
    return this.prisma.plot.findMany({
      orderBy: { plot_number: 'asc' },
    });
  }
}
```

### Service

**`src/domains/plot/plot.service.ts`:**
```typescript
/**
 * @service PlotService
 * @domain plots
 * @description Бизнес-логика управления земельными участками
 */
export class PlotService {
  async findAll(): Promise<Plot[]> {
    return this.plotRepository.findAll();
  }
}
```

### API

**`src/app/api/v1/plots/route.ts`:**
```typescript
/**
 * @route GET /api/v1/plots
 * @auth required
 * @description Возвращает список всех участков
 *
 * @response 200 { success: true, data: Plot[] }
 * @response 500 { success: false, error: { code: string, message: string } }
 */
export async function GET() {
  const service = createPlotService();
  try {
    const plots = await service.findAll();
    return NextResponse.json({ success: true, data: plots });
  } catch (error) {
    // Error handling
  }
}
```
