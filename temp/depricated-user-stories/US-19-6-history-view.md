# US-19-6: Просмотр истории изменений связей пользователь-участок

## Формулировка

**Как** Администратор СНТ,  
**я хочу** просматривать полную историю изменений связей пользователей с участками,  
**чтобы** контролировать кто, когда и какие изменения внёс в права доступа.

---

## Контекст

### Проблема
После создания, редактирования или удаления связей отсутствует возможность отследить кто, когда и какие изменения вносил. Нет аудита действий администраторов.

### Решение
Создать интерфейс просмотра полной истории всех изменений для каждой связи с детализацией по каждому изменению.

### Границы
- **Входит:** Просмотр истории для одной конкретной связи
- **Входит:** Отображение всех изменений (роль, статус, comment, expires_at)
- **Входит:** Фильтрация по дате, типу изменения, пользователю
- **Входит:** Поиск по причинам изменений
- **НЕ входит:** Создание изменений (US-19-1, US-19-4, US-19-5)
- **НЕ входит:** Редактирование истории (запрещено)
- **НЕ входит:** Экспорт истории в CSV (не в MVP)

### Точки входа в интерфейс

| Номер | Точка входа | Маршрут | Описание |
|-------|-------------|---------|----------|
| TV-1 | Кнопка "История" | `/dashboard/plots/[id]` | В таблице участников (строка) |
| TV-2 | Кнопка "История" | `/dashboard/my-connections` | В таблице связей пользователя |
| TV-3 | Кнопка "История" | `/dashboard/plots/[id]/participants` | В модальном окне редактирования |
| TV-4 | Вкладка "История" | При редактировании | Внутри формы редактирования |
| TV-5 | Детальная страница | `/dashboard/plot-user-history/[id]` | Отдельная страница истории |

## Функциональные требования

### FR-1: Отображение списка изменений

Система отображает список всех изменений для конкретной связи.

#### AC-1.1: Открытие истории
- **Дано:** Пользователь находится на странице участка `/dashboard/plots/[id]`
- **Когда:** Пользователь нажимает кнопку "История" для конкретной связи
- **Тогда:** Открывается модальное окно или новая страница с полной историей
- **Иначе:** История загружается в модальном окне

#### AC-1.2: Столбцы таблицы истории
- **Дано:** Таблица истории загружена
- **Когда:** Пользователь видит таблицу
- **Тогда:** Отображаются колонки:

| Колонка | Содержание |
|---------|------------|
| Дата | changed_at в формате DD.MM.YYYY HH:MM |
| Пользователь | Фамилия Имя (email) кто внёс изменение |
| Тип изменения | Текст: "Создание", "Редактирование", "Деактивация", "Удаление" |
| Старые значения | Формат: `role: 1 → 2` |
| Новые значения | Формат: `role: 1 → 2` |
| Причина | changed_reason или "Без причины" |

#### AC-1.3: Сортировка по умолчанию
- **Дано:** Таблица истории загружена
- **Когда:** Пользователь видит список
- **Тогда:** Записи отсортированы по changed_at (новые сверху)
- **Иначе:** Можно сортировать по любой колонке

---

### FR-2: Детализация изменения

Система показывает детализированную информацию о каждом изменении.

#### AC-2.1: Развертывание записи
- **Дано:** В таблице есть запись истории
- **Когда:** Пользователь нажимает на запись (или кнопку "Подробнее")
- **Тогда:** Запись разворачивается с полной детализацией
- **Иначе:** Сворачивается обратно при повторном клике

#### AC-2.2: Детали изменения
- **Дано:** Запись развернута
- **Когда:** Пользователь видит детали
- **Тогда:** Отображается:
  - Дата и время изменения (DD.MM.YYYY HH:MM:SS)
  - Пользователь, который внёс изменение (с avatar)
  - Список всех изменённых полей с old → new
  - Причина изменения (если указана)
  - IP адрес (опционально, если есть)
- **Иначе:** Базовая информация в строке таблицы

#### AC-2.3: Визуализация изменений
- **Дано:** Запись развернута
- **Когда:** Пользователь видит детали
- **Тогда:** Изменения выделены цветом:
  - Новые значения: зелёный текст
  - Старые значения: красный текст
  - Неизменённые поля: серый текст, зачёркнуты
- **Иначе:** Визуальная индикация облегчает чтение

---

### FR-3: Фильтрация по типу изменения

Система позволяет фильтровать историю по типу изменения.

#### AC-3.1: Фильтр "Все типы"
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбрал "Все типы" из фильтра
- **Тогда:** Отображаются все изменения (создание, редактирование, деактивация, удаление)
- **Иначе:** Фильтр по умолчанию — "Все типы"

#### AC-3.2: Фильтр "Создание"
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбрал "Создание" из фильтра
- **Тогда:** Отображаются только записи типа "Создание"
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.3: Фильтр "Редактирование"
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбрал "Редактирование" из фильтра
- **Тогда:** Отображаются только записи типа "Редактирование"
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.4: Фильтр "Деактивация"
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбрал "Деактивация" из фильтра
- **Тогда:** Отображаются только записи типа "Деактивация" (soft delete)
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.5: Фильтр "Удаление"
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбрал "Удаление" из фильтра
- **Тогда:** Отображаются только записи типа "Удаление" (hard delete)
- **Иначе:** Количество отображаемых строк уменьшается

---

### FR-4: Фильтрация по дате

Система позволяет фильтровать историю по дате изменения.

#### AC-4.1: Диапазон дат
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбирает диапазон дат
- **Тогда:** Отображаются только изменения в выбранном диапазоне
- **Иначе:** По умолчанию показывает все записи за последние 90 дней

#### AC-4.2: Быстрые фильтры даты
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбирает "Сегодня", "За неделю", "За месяц"
- **Тогда:** Отображаются изменения в выбранном диапазоне
- **Иначе:** Выбор диапазона вручную

---

### FR-5: Фильтрация по пользователю

Система позволяет фильтровать историю по пользователю, который внёс изменение.

#### AC-5.1: Фильтр "Все пользователи"
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбрал "Все пользователи" из фильтра
- **Тогда:** Отображаются все изменения от всех пользователей
- **Иначе:** Фильтр по умолчанию — "Все пользователи"

#### AC-5.2: Фильтр по конкретному пользователю
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь выбирает конкретного пользователя из списка
- **Тогда:** Отображаются только изменения этого пользователя
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-5.3: Поиск по пользователю
- **Дано:** Пользователь вводит текст в поле поиска пользователей
- **Когда:** Пользователь вводит имя/email
- **Тогда:** Фильтруется список пользователей по запросу
- **Иначе:** Результат отображается моментально (< 200 мс)

---

### FR-6: Поиск по причине изменения

Система позволяет искать записи по причине изменения.

#### AC-6.1: Поле поиска
- **Дано:** Пользователь открыл историю изменений
- **Когда:** Пользователь видит поле "Поиск по причине"
- **Тогда:** Поле отображается над таблицей
- **Иначе:** Поле пустое по умолчанию

#### AC-6.2: Поиск по тексту причины
- **Дано:** Пользователь вводит текст в поле поиска
- **Когда:** Пользователь вводит текст
- **Тогда:** Фильтруются записи где changed_reason содержит текст
- **Иначе:** Результат отображается моментально

---

### FR-7: Отображение информации о пользователях

Система показывает детализированную информацию о пользователе, который внёс изменение.

#### AC-7.1: Отображение имени
- **Дано:** В истории есть запись
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается формат: "Фамилия Имя (email)"
- **Иначе:** Если нет user_profile — отображается только "email"

#### AC-7.2: Avatar пользователя
- **Дано:** Пользователь имеет avatar в user_profile
- **Когда:** Пользователь видит запись истории
- **Тогда:** Отображается avatar пользователя
- **Иначе:** Отображается avatar по умолчанию с инициалами

#### AC-7.3: Подсветка администраторов
- **Дано:** Пользователь, который внёс изменение, имеет роль ADMIN
- **Когда:** Пользователь видит запись истории
- **Тогда:** Рядом с именем отображается бейдж "ADMIN"
- **Иначе:** Бейдж не отображается

---

### FR-8: Периодическое обновление

Система автоматически обновляет историю при появлении новых записей.

#### AC-8.1: Автообновление
- **Дано:** Пользователь открыл историю
- **Когда:** Прошло 30 секунд с последнего обновления
- **Тогда:** Запрашиваются новые данные через API
- **Иначе:** Пользователь видит только свежие записи

#### AC-8.2: Индикатор нового
- **Дано:** Появилась новая запись в истории
- **Когда:** Пользователь видит таблицу
- **Тогда:** Первая запись подсвечена "Новая запись"
- **Иначе:** Индикатор исчезает после прокрутки

## Бизнес-правила и валидация

| ID | Правило | Описание | Источник |
|----|---------|----------|----------|
| BR-1 | История неизменяема | Записи истории нельзя редактировать или удалять | DB constraint |
| BR-2 | Все изменения фиксируются | Каждое изменение создаёт запись в истории | Transaction |
| BR-3 | Права доступа | Просмотр истории доступен ADMIN + владельцам связей | Проверка прав |
| BR-4 | Отображение только активных | По умолчанию показываются только активные записи | UI фильтр |
| BR-5 | Сортировка по дате | Новые записи сверху | Сервисная логика |
| BR-6 | Маска даты | changed_at в формате DD.MM.YYYY HH:MM | Форматирование в UI |
| BR-7 | Права на просмотр | ADMIN видит историю всех, пользователи — только свою | Проверка прав |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Нет записей в истории | Отображается EmptyState: "История изменений пуста" |
| 2 | Пользователь удалён из системы | Отображается "[удалён]" вместо имени |
| 3 | Более 100 записей истории | Пагинация: 25 элементов на страницу |
| 4 | Связь уже удалена | История сохраняется, связь отмечена как удалённая |
| 5 | Параллельное изменение данных | Оптимистичное обновление UI, refetch через 5 сек |
| 6 | Медленное соединение (> 5 сек) | Показывается индикатор загрузки skeleton |
| 7 | Ссылка на несуществующую связь | 404 NotFound — редирект на список |
| 8 | Пользователь не имеет прав | 403 Forbidden — показ ошибки |

| 500 | Внутренняя ошибка сервера | `BaseError` | "Ошибка загрузки истории. Попробуйте позже" |

**`src/app/api/v1/plot-users/[id]/history/route.ts`:**

```typescript
/**
 * @route GET /api/v1/plot-users/[id]/history
 * @auth required
 * @description Возвращает историю изменений для конкретной связи
 *
 * @query type=creation|update|expire|delete&from=YYYY-MM-DD&to=YYYY-MM-DD&user_id=id
 * @response 200 { success: true, data: PlotUserRoleHistory[] }
 * @response 401 { success: false, error: { code: string, message: string } }
 * @response 403 { success: false, error: { code: string, message: string } }
 * @response 404 { success: false, error: { code: string, message: string } }
 */
export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const { user } = await auth();
  const service = createPlotUserRoleService();
  try {
    const { searchParams } = new URL(request.url);
    const filter = {
      type: searchParams.get('type') as any,
      from: searchParams.get('from'),
      to: searchParams.get('to'),
      user_id: searchParams.get('user_id'),
    };
    const history = await service.getHistory(params.id, filter);
    return NextResponse.json({ success: true, data: history });
  } catch (error) {
    // Error handling
  }
}
```

## Примечания для реализации

1. **Использование Suspense:** HistoryList должен быть обернут в Suspense для плавной загрузки
2. **Автообновление:** Использовать setInterval для периодического рефреша (каждые 30 сек)
3. **Оптимистичное обновление:** Новые записи появляются сразу после создания
4. **Развёртывание записей:** Аккордеон для развёртывания деталей изменения
5. **Визуализация diff:** old → new с цветовым кодированием
6. **Адаптивность:** Таблица должна корректно отображаться на мобильных
7. **Доступность:** Все интерактивные элементы должны быть доступны с клавиатуры
8. **Виртуализация:** При > 500 записей использовать react-window для производительности
9. **Оптимизация запросов:** Пагинация и debounce для поиска
