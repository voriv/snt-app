# US-16: Удаление участка

## Формулировка

**As a** Администратор СНТ,  
**I want to** удалять земельные участки, —  
**So that** я мог удалять неактуальные или ошибочно созданные записи.

## Контекст

### Проблема
Невозможно удалить ошибочно созданный или неактуальный участок из системы.

### Решение
Создать операцию удаления с подтверждением через `ConfirmDialog` и проверкой связанных данных (договоры, платежи).

### Границы
- Удаление доступно только пользователям с ролью ADMIN (или специфическим правом RBAC)
- Проверка наличия связанных активных договоров перед удалением
- Подтверждение удаления через модальное окно

## Модель данных

### Сущность Plot (удаление)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | String | Уникальный идентификатор (используется для удаления) |
| `plot_number` | String | Номер участка (отображается в подтверждении) |



## Функциональные требования

### FR-1: Кнопка удаления

Пользователь видит кнопку удаления в строке таблицы.

#### AC-1.1: Отображение кнопки
- **Дано:** Пользователь на странице `/dashboard/plots` (US-13)
- **Когда:** Таблица участков загружена
- **Тогда:**
  - В каждой строке таблицы есть кнопка «Удалить» (иконка корзины 🗑️)
  - Кнопка отображается только если у пользователя есть право на удаление (RBAC: `plots:delete`)
- **Иначе:** Если нет права — кнопка скрыта

#### AC-1.2: Бейдж статуса (опционально)
- **Дано:** Участок имеет активные договоры
- **Когда:** Таблица загружена
- **Тогда:**
  - Рядом с номером участка отображается бейдж «Есть договоры» (если есть active agreements)
  - Это предупреждает пользователя перед попыткой удаления

### FR-2: Подтверждение удаления

Пользователь подтверждает удаление участка.

#### AC-2.1: Диалог подтверждения
- **Дано:** Пользователь нажимает кнопку «Удалить»
- **Когда:** Клик по кнопке
- **Тогда:** Открывается `ConfirmDialog` с:
  - Заголовком: «Подтверждение удаления»
  - Сообщением: «Вы уверены, что хотите удалить участок №[plot_number]? Это действие нельзя отменить.»
  - Кнопкой «Отмена» (primary)
  - Кнопкой «Удалить» (variant="danger")
- **Иначе:** Диалог закрывается при клике вне области или на «Отмена»

#### AC-2.2: Предпроверка связанных данных
- **Дано:** Пользователь нажал «Удалить» в диалоге
- **Когда:** Клиент подтверждает действие
- **Тогда:**
  - Выполняется `GET /api/v1/plots/:id/check` для проверки активных договоров
  - Если есть активные договоры — показывается: «Невозможно удалить участок с активными договорами»
  - Если договоров нет — выполняется удаление
- **Иначе:** (альтернатива) Проверка на сервере при DELETE-запросе

### FR-3: Выполнение удаления

Пользователь удаляет участок.

#### AC-3.1: DELETE-запрос
- **Дано:** Пользователь подтвердил удаление
- **Когда:** Предпроверка пройдена (или её нет)
- **Тогда:** Выполняется `DELETE /api/v1/plots/:id`
- **Иначе:** Запрос выполняется с `Authorization` заголовком (сессия)

#### AC-3.2: Успешное удаление
- **Дано:** `DELETE /api/v1/plots/:id` вернул `204 No Content`
- **Когда:** Ответ успешный
- **Тогда:**
  - Диалог закрывается
  - Строка участка удаляется из таблицы (optimistic update)
  - Показывается уведомление: «Участок №[plot_number] успешно удалён»
- **Иначе:** Список обновляется без перезагрузки страницы

#### AC-3.3: Ошибка — есть активные договоры
- **Дано:** Участок имеет активные договоры
- **Когда:** Сервер возвращает `409 Conflict`
- **Тогда:**
  - Сообщение: «Невозможно удалить участок с активными договорами. Сначала закройте договоры.»
  - Диалог закрывается
  - Строка в таблице остаётся
- **Иначе:** Показывается бейдж «Есть договоры»

#### AC-3.4: Ошибка удаления
- **Дано:** Сервер вернул ошибку (500 или другую)
- **Когда:** DELETE-запрос завершился ошибкой
- **Тогда:**
  - Сообщение: «Ошибка удаления участка. Попробуйте позже.»
  - Строка в таблице остаётся
  - Ошибка логируется

## Бизнес-правила и валидация

| ID | Правило | Описание | Источник |
|----|---------|----------|----------|
| BR-1 | RBAC | Удаление только для пользователей с правом `plots:delete` | RBAC из US-8, US-9 |
| BR-2 | Активные договоры | Нельзя удалить участок с активными договорами | Бизнес-правило |
| BR-3 | Подтверждение | Удаление требует явного подтверждения через ConfirmDialog | UX паттерн |
| BR-4 | Необратимость | Удаление необратимо — данные не архивируются | Бизнес-правило |

## Граничные случаи (Edge Cases)

| Сценарий | Ожидаемое поведение |
|----------|-------------------|
| Участок создан и ошибочно удалён | Данные удалить полностью — восстановление невозможно |
| Участок без активных договоров, но с платежами | Удаление разрешено, платежи сохраняются |
| Параллельное удаление другим пользователем | Второй запрос получает 404 (участок уже удалён) |
| Удаление во время загрузки страницы | Состояние гонки — DELETE может прийти после refetch |

## Обработка ошибок

| Код | Ситуация | Сообщение | Действие |
|-----|----------|-----------|----------|
| 401 | Не авторизован | — | Редирект на `/login` |
| 403 | Нет прав на удаление | «У вас нет прав для удаления участков» | Скрыть кнопку |
| 404 | Участок не найден | «Участок не найден» | Убрать строку из таблицы |
| 409 | Есть активные договоры | «Невозможно удалить участок с активными договорами» | Показать предупреждение |
| 500 | Внутренняя ошибка | «Ошибка удаления участка» | Показать alert |

```typescript
export class PlotRepositoryPrisma implements IPlotRepository {
  async delete(id: string): Promise<void> {
    await this.prisma.plot.delete({ where: { id } });
  }

  async hasActiveAgreements(plotId: string): Promise<boolean> {
    const count = await this.prisma.agreement.count({
      where: { plot_id: plotId, status: 'active' },
    });
    return count > 0;
  }
}
```

### Service

**`src/domains/plot/plot.service.ts` (добавление метода):**
```typescript
/**
 * Удалить участок
 * @param id - ID участка
 * @throws {PlotNotFoundError} если участок не найден
 * @throws {PlotHasActiveAgreementsError} если есть активные договоры
 */
async delete(id: string): Promise<void> {
  const existing = await this.plotRepository.findById(id);
  if (!existing) {
    throw new PlotNotFoundError(`Участок с ID ${id} не найден`);
  }
  
  if (await this.plotRepository.hasActiveAgreements(id)) {
    throw new PlotHasActiveAgreementsError(
      `Невозможно удалить участок с активными договорами`
    );
  }
  
  await this.plotRepository.delete(id);
}
```

### API

**`src/app/api/v1/plots/[id]/route.ts` (добавление DELETE):**
```typescript
/**
 * @route DELETE /api/v1/plots/:id
 * @auth required
 * @role ADMIN
 * @description Удаляет участок
 *
 * @response 204 No content
 * @response 403 { success: false, error: { code: string, message: string } }
 * @response 404 { success: false, error: { code: string, message: string } }
 * @response 409 { success: false, error: { code: string, message: string } }
 */
export async function DELETE(
  _request: NextRequest,
  { params }: { params: { id: string } }
) {
  const service = createPlotService();
  try {
    await service.delete(params.id);
    return new NextResponse(null, { status: 204 });
  } catch (error) {
    // Error handling
  }
}
```
