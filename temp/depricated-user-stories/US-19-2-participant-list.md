# US-19-2: Просмотр участников участка

## Формулировка

**Как** Администратор СНТ,  
**я хочу** просматривать список всех пользователей, связанных с участком,  
**чтобы** видеть кто является владельцем, проживает или представляет интересующий меня участок.

---

## Контекст

### Проблема
После создания связей между пользователями и участками нет возможности просмотреть полный список участников конкретного участка. Информация о ролях распределена и недоступна централизованно.

### Решение
Создать интерфейс просмотра всех активных и неактивных связей для выбранного участка с фильтрацией по роли и статусу.

### Границы
- **Входит:** Просмотр списка всех связей для конкретного участка
- **Входит:** Отображение ролей и статусов каждой связи
- **Входит:** Фильтрация по роли и статусу
- **Входит:** Поиск по имени пользователя в списке
- **НЕ входит:** Просмотр связей по пользователю (US-19-3)
- **НЕ входит:** Редактирование связей из этого интерфейса (US-19-4)
- **НЕ входит:** Удаление связей из этого интерфейса (US-19-5)

### Точки входа в интерфейс

| Номер | Точка входа | Страница | Описание |
|-------|-------------|----------|----------|
| TV-1 | Кнопка "Участники" | `/dashboard/plots/[id]` | Секция ниже информации об участке |
| TV-2 | Кнопка "Управление участниками" | `/dashboard/plots/[id]` | В карточке каждого участника |
| TV-3 | Блок "Владельцы/Жители" | `/dashboard/plots/[id]` | На странице детального просмотра |
| TV-4 | Кнопка "Показать всех" | `/dashboard/plots/[id]` | При открытии модального окна |
| TV-5 | Вкладка "Участники" | `/dashboard/plots/[id]` | Навигация по вкладкам страницы |

## Функциональные требования

### FR-1: Отображение списка участников

Система отображает список всех связей для выбранного участка.

#### AC-1.1: Открытие списка участников
- **Дано:** Пользователь находится на странице участка `/dashboard/plots/[id]`
- **Когда:** Пользователь открывает секцию "Участники" (клавиатурой или кликом)
- **Тогда:** Загружается и отображается таблица со всеми связями для этого участка
- **Иначе:** Секция отображается сразу после загрузки страницы

#### AC-1.2: Столбцы таблицы
- **Дано:** Таблица участников загружена
- **Когда:** Пользователь видит таблицу
- **Тогда:** Отображаются колонки:

| Колонка | Содержание |
|---------|------------|
| № | Порядковый номер связи |
| Пользователь | Фамилия Имя (email) |
| Роль | Текст: "Владелец", "Проживает", "Представитель" |
| Статус | Бейдж с цветом: активен (зелёный), ожидание (жёлтый), истёк (серый) |
| Срок действия | "Бессрочно" или дата в формате DD.MM.YYYY |
| Комментарий | Текст комментария (третирование при > 50 символов) |
| Назначен | Дата создания связи DD.MM.YYYY |
| Действия | Кнопки "Редактировать" и "Удалить" (только ADMIN) |

#### AC-1.3: Сортировка по умолчанию
- **Дано:** Таблица загружена
- **Когда:** Пользователь видит список
- **Тогда:** Связи отсортированы:
  1. Сначала активные (status='active')
  2. Затем ожидания (status='pending')
  3. Затем истёкшие (status='expired')
- **Иначе:** Внутри групп сортировка по assigned_at (новые сверху)

---

### FR-2: Отображение информации о пользователе

Система показывает детализированную информацию о каждом пользователе.

#### AC-2.1: Отображение имени
- **Дано:** В таблице есть связь
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается формат: "Фамилия Имя (email)"
- **Иначе:** Если нет user_profile — отображается только "email"

#### AC-2.2: Отсутствие профиля пользователя
- **Дано:** Пользователь не имеет user_profile
- **Когда:** Пользователь видит связь
- **Тогда:** Отображается: "email" без имени и фамилии
- **Иначе:** Никаких ошибок не возникает

#### AC-2.3: Телефон в подсказке
- **Дано:** Пользователь имеет профиль с телефоном
- **Когда:** Пользователь наводит курсор на имя пользователя
- **Тогда:** Показывается tooltip: "Имя Фамилия, email, +Телефон"
- **Иначе:** Tooltip не показывается если телефона нет

---

### FR-3: Фильтрация по роли

Система позволяет фильтровать список по типу роли.

#### AC-3.1: Фильтр "Все роли"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Все роли" из фильтра
- **Тогда:** Отображаются все связи (owner, resident, representative)
- **Иначе:** Фильтр по умолчанию — "Все роли"

#### AC-3.2: Фильтр "Только владельцы"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Только владельцы" из фильтра
- **Тогда:** Отображаются только связи с role=1
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.3: Фильтр "Только проживающие"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Только проживающие" из фильтра
- **Тогда:** Отображаются только связи с role=2
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.4: Фильтр "Только представители"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Только представители" из фильтра
- **Тогда:** Отображаются только связи с role=3
- **Иначе:** Количество отображаемых строк уменьшается

---

### FR-4: Фильтрация по статусу

Система позволяет фильтровать список по статусу связи.

#### AC-4.1: Фильтр "Все статусы"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Все статусы" из фильтра
- **Тогда:** Отображаются все связи (active, pending, expired)
- **Иначе:** Фильтр по умолчанию — "Все статусы"

#### AC-4.2: Фильтр "Активные"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Активные" из фильтра
- **Тогда:** Отображаются только связи с status='active'
- **Иначе:** Бейджи статусов окрашиваются в зелёный

#### AC-4.3: Фильтр "Ожидание"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Ожидание" из фильтра
- **Тогда:** Отображаются только связи с status='pending'
- **Иначе:** Бейджи статусов окрашиваются в жёлтый

#### AC-4.4: Фильтр "Истёкшие"
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь выбрал "Истёкшие" из фильтра
- **Тогда:** Отображаются только связи с status='expired'
- **Иначе:** Бейджи статусов окрашиваются в серый

---

### FR-5: Поиск по участникам

Система позволяет искать пользователей в списке по имени или email.

#### AC-5.1: Поле поиска
- **Дано:** Пользователь открыл список участников
- **Когда:** Пользователь видит поле "Поиск по имени или email"
- **Тогда:** Поле отображается справа от фильтров
- **Иначе:** Поле пустое по умолчанию

#### AC-5.2: Поиск по имени
- **Дано:** Пользователь вводит "Иван" в поле поиска
- **Когда:** Пользователь вводит текст
- **Тогда:** Фильтруются строки где first_name или last_name содержит "Иван"
- **Иначе:** Результат отображается моментально (< 200 мс)

#### AC-5.3: Поиск по email
- **Дано:** Пользователь вводит "ivan@example.com" в поле поиска
- **Когда:** Пользователь вводит текст
- **Тогда:** Фильтруются строки где email содержит "ivan@example.com"
- **Иначе:** Результат отображается моментально

#### AC-5.4: Подсветка совпадений
- **Дано:** Пользователь ввёл текст поиска
- **Когда:** Результат отфильтрован
- **Тогда:** Найденные части имени/email выделяются жирным шрифтом
- **Иначе:** Подсветка исчезает при очистке поля

---

### FR-6: Отображение пустого состояния

Система корректно обрабатывает случаи отсутствия участников.

#### AC-6.1: Нет ни одной связи
- **Дано:** У участка нет ни одной связи (plot_users пусто для plot_id)
- **Когда:** Пользователь открывает страницу участка
- **Тогда:** Отображается EmptyState: "У этого участка пока нет участников"
- **Иначе:** Показывается кнопка "Добавить первого участника" (ссылка на US-19-1)

#### AC-6.2: Фильтр не находит совпадений
- **Дано:** У участка есть участники
- **Когда:** Пользователь применил фильтр, который ничего не находит
- **Тогда:** Отображается EmptyState: "По вашему запросу ничего не найдено"
- **Иначе:** Кнопка "Сбросить фильтры"

---

### FR-7: Отображение срока действия

Система показывает срок действия связи в понятном формате.

#### AC-7.1: Бессрочная связь
- **Дано:** expires_at = null
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "Бессрочно"
- **Иначе:** Серый текст (muted)

#### AC-7.2: Срочная связь
- **Дано:** expires_at = "2025-12-31"
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "31.12.2025"
- **Иначе:** Формат DD.MM.YYYY

#### AC-7.3: Истёкшая связь
- **Дано:** expires_at < today
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается дата в формате DD.MM.YYYY
- **Иначе:** Дополнительно — серая строка (strikethrough)

## Бизнес-правила и валидация

| ID | Правило | Описание | Источник |
|----|---------|----------|----------|
| BR-1 | Отображение только активного | По умолчанию показываются только активные связи | UI фильтр по умолчанию |
| BR-2 | Порядок сортировки | Активные → Ожидание → Истёкшие | Сервисная логика сортировки |
| BR-3 | Маска имени | Фамилия Имя (email) | Форматирование в UI |
| BR-4 | Отображение бессрочности | expires_at=null → "Бессрочно" | UI condition |
| BR-5 | Права доступа | Кнопки "Редактировать" и "Удалить" только для ADMIN | Проверка роли в UI |
| BR-6 | Пагинация | При > 200 элементов — пагинация 25/страницу | UI pagination |
| BR-7 | Поиск моментальный | Поиск по имени < 200 мс | UI debounce 300ms |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Участок не существует | 404 NotFound — редирект на список участков |
| 2 | Пользователь не авторизован | 401 Unauthorized — редирект на login |
| 3 | Более 100 участников | Пагинация: 25 элементов на страницу |
| 4 | Пользователь удалён из системы | user_id не найдётся — отображается "[удалён]" вместо имени |
| 5 | Пользователь с пустым profile | Отображается только email |
| 6 | Параллельное изменение данных | Оптимистичное обновление UI, refetch через 5 сек |
| 7 | Медленное соединение (> 5 сек) | Показывается индикатор загрузки skeleton |
| 8 | Неправильный format expires_at | ISO 8601 формат гарантируется сервером |
| 9 | Компонент не может получить plot_id | Error boundary — показ ошибки |
| 10 | API не отвечает | Skeleton loader с анимацией пульсации |

### API

**`src/app/api/v1/plots/[id]/participants/route.ts`:**

```typescript
/**
 * @route GET /api/v1/plots/[id]/participants
 * @auth required
 * @description Возвращает список всех участников участка
 *
 * @query filter=active|pending|expired&role=1|2|3&search=query
 * @response 200 { success: true, data: PlotUserRole[] }
 * @response 401 { success: false, error: { code: string, message: string } }
 * @response 403 { success: false, error: { code: string, message: string } }
 * @response 404 { success: false, error: { code: string, message: string } }
 */
export async function GET(
  request: NextRequest, 
  { params }: { params: { id: string } }
) {
  const service = createPlotUserRoleService();
  try {
    const { searchParams } = new URL(request.url);
    const filter = {
      status: searchParams.get('status') as any,
      role: searchParams.get('role') ? parseInt(searchParams.get('role')!) : undefined,
      search: searchParams.get('search'),
    };
    const participants = await service.findByPlot(params.id, filter);
    return NextResponse.json({ success: true, data: participants });
  } catch (error) {
    // Error handling: convert domain errors to HTTP responses
  }
}
```

## Интеграционные моменты

### Точки входа в интерфейс (детально)

#### TV-1: Кнопка "Участники" на странице участка
- **Расположение:** Внизу страницы `/dashboard/plots/[id]`
- **Компонент:** `<SectionHeader title="Участники" addButton>`
- **Действие:** Открывает секцию с ParticipantList
- **Отображение:** Сразу под информацией об участке

#### TV-2: Кнопка "Управление участниками"
- **Расположение:** В карточке каждого участника на странице
- **Компонент:** `<ParticipantCard actions>`
- **Действие:** Перенаправляет на `/dashboard/plots/[id]/participants` или открывает модальное окно

#### TV-3: Вкладка "Участники"
- **Расположение:** Навигация по вкладкам на странице участка
- **Компонент:** `<Tabs>` с вкладками "Информация", "Участники", "Документы"
- **Действие:** Показывает ParticipantList на соответствующей вкладке

#### TV-4: Кнопка "Показать всех"
- **Расположение:** В секции "Владельцы" на главной странице
- **Компонент:** `<Link href="/dashboard/plots/[id]/participants">Показать всех</Link>`
- **Действие:** Перенаправление на полный список

#### TV-5: В контексте формы редактирования
- **Расположение:** `/dashboard/plots/[id]/edit`
- **Компонент:** `<Section title="Участники">ParticipantList editable</Section>`
- **Действие:** Редактирование связей напрямую из формы

## Примечания для реализации

1. **Использование Suspense:** ParticipantList должен быть обернут в Suspense для плавной загрузки
2. **Оптимистичное обновление:** После успешной операции обновления нужно сразу обновлять UI
3. **Рефреш данных:** При изменении через другие US-19-* нужно автоматически обновлять список
4. **Адаптивность:** Таблица должна корректно отображаться на мобильных устройствах
5. **Доступность:** Все интерактивные элементы должны быть доступны с клавиатуры
