# US-18: Карточка участка

## Формулировка

**As a** член СНТ (Member) или Администратор,  
**I want to** просматривать детальную карточку земельного участка, —  
**So that** я мог увидеть полную информацию об участке и navigate к связанным данным.

## Контекст

### Проблема
В таблице списка участков отображается только базовая информация. Для просмотра полных деталей (примечание, история изменений) нужен отдельный экран.

### Решение
Создать страницу `/dashboard/plots/:id` с детальной информацией об участке и ссылками на связанные данные.

### Границы
- Страница доступна для просмотра всем авторизованным пользователям
- Навигация: кликабельный номер участка в таблице (US-13)
- Не включает управление связанными договорами и платежами (отдельные US)

## Модель данных

### Сущность Plot (детальная информация)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | String | Уникальный идентификатор |
| `plot_number` | String | Номер участка |
| `cadstral_number` | String? | Кадастровый номер |
| `area` | Decimal | Площадь (м²) |
| `address` | String? | Адрес |
| `note` | String? | Примечание / описание |
| `created_at` | DateTime | Дата создания |
| `updated_at` | DateTime | Дата последнего обновления |

## Функциональные требования

### FR-1: Навигация к карточке

Пользователь может перейти к карточке участка из списка.

#### AC-1.1: Кликабельный номер участка
- **Дано:** Пользователь на странице `/dashboard/plots` (US-13)
- **Когда:** Номер участка (`plot_number`) отображается в таблице
- **Тогда:**
  - Номер отображается как ссылка (цвет синий, подчёркивание)
  - Клик по номеру → переход на `/dashboard/plots/:id`
- **Иначе:** Используется компонент `<Link>` из Next.js для клиентской навигации

#### AC-1.2: Состояние загрузки карточки
- **Дано:** Пользователь кликнул на номер участка
- **Когда:** Запрос к API активен
- **Тогда:**
  - Отображается скелетон карточки или спиннер
  - URL обновляется на `/dashboard/plots/:id`
- **Иначе:** Back button в Navbar возвращает к списку

### FR-2: Отображение данных карточки

Пользователь видит полную информацию об участке.

#### AC-2.1: Структура карточки
- **Дано:** Пользователь на странице `/dashboard/plots/:id`
- **Когда:** Данные загружены
- **Тогда:** Отображается карточка (Card-компонент) с секциями:

```
┌─────────────────────────────────────┐
│  Участок №42              [✏️] [🗑️] │
├─────────────────────────────────────┤
│  Кадастровый номер:                 │
│  50:00:0000001:42                   │
│                                     │
│  Площадь:                           │
│  12.5 м²                            │
│                                     │
│  Адрес:                             │
│  д. Березки, уч. 42                 │
│                                     │
│  Примечание:                        │
│  Земельный участок для огорода      │
│                                     │
│  Привязка:                          │

│                                     │
│  Создан: 01.01.2024                 │
│  Изменён: 15.06.2024                │
└─────────────────────────────────────┘
```

#### AC-2.2: Заголовок карточки
- **Дано:** Карточка загружена
- **Когда:** Данные отображаются
- **Тогда:** В заголовке:
  - Текст: «Участок №[plot_number]»
  - Кнопка «Редактировать» (✏️) — переход на форму редактирования (US-15)
  - Кнопка «Удалить» (🗑️) — подтверждение удаления (US-16)
- **Иначе:** Кнопки доступны в зависимости от RBAC-прав

#### AC-2.3: Поля карточки
- **Дано:** Основные поля отображаются
- **Когда:** Данные загружены
- **Тогда:**
  | Поле | Отображение | Если null |
  |------|-------------|-----------|
  | Кадастровый номер | `cadstral_number` | «Не указан» |
  | Площадь | `area` м² | «Не указана» |
  | Адрес | `address` | «Не указан» |
  | Примечание | `note` (переносы строк сохранены) | «Не указано» |
  | Создан | `created_at` (DD.MM.YYYY) | — |
  | Изменён | `updated_at` (DD.MM.YYYY) | — |

#### AC-2.4: Форматирование дат
- **Дано:** Поля `created_at` и `updated_at`
- **Когда:** Данные отображаются
- **Тогда:**
  - Формат: `DD.MM.YYYY` (например, «01.01.2024»)
  - Если нужно точное время: `DD.MM.YYYY HH:mm`

### FR-3: Ссылки на связанные данные (placeholder)

Пользователь видит секции для будущих интеграций.

#### AC-3.1: Секция «Договоры»
- **Дано:** Карточка участка загружена
- **Когда:** Данные отображаются
- **Тогда:**
  - Отображается секция «Договоры» с заголовком и счётчиком
  - Текст: «Договоры (0)» или «Договоры (3)» если есть
  - Ссылка ведёт на `/dashboard/plots/:id/agreements` (заглушка)
- **Иначе:** Секция показывается даже если договоров нет

## Бизнес-правила и валидация

| ID | Правило | Описание |
|----|---------|----------|
| BR-1 | Авторизация | Страница доступна только авторизованным пользователям |
| BR-2 | RBAC | Просмотр доступен всем авторизованным ролям |
| BR-3 | Кнопки действий | Редактировать/Удалить отображаются в зависимости от прав |
| BR-4 | 404 | Если участок не найден — редирект на `/dashboard/plots` |

## Граничные случаи (Edge Cases)

| Сценарий | Ожидаемое поведение |
|----------|-------------------|
| Участок не найден (404) | Показывается `not-found.tsx` или сообщение с кнопкой «Назад к списку» |
| Участок с null всеми опциональными полями | Все поля показывают «Не указано» / «Не указан» |
| Навигация по History API (Back) | Возврат на `/dashboard/plots` с сохранением состояния |
| Параллельное обновление участка | При перезагрузке страницы — актуальные данные |

## Обработка ошибок

| Код | Ситуация | Сообщение | Действие |
|-----|----------|-----------|----------|
| 401 | Не авторизован | — | Редирект на `/login` |
| 404 | Участок не найден | «Участок не найден» | Кнопка «Назад к списку» |
| 500 | Внутренняя ошибка | «Ошибка загрузки данных участка» | Кнопка «Повторить» |

## Влияние на слои архитектуры

### API

**`src/app/api/v1/plots/[id]/route.ts` (GET, уже определён в US-15):**
```typescript
/**
 * @route GET /api/v1/plots/:id
 * @auth required
 * @description Возвращает участок по ID
 *
 * @response 200 { success: true, data: Plot }
 * @response 404 { success: false, error: { code: string, message: string } }
 */
export async function GET(
  _request: NextRequest,
  { params }: { params: { id: string } }
) {
  const service = createPlotService();
  try {
    const plot = await service.findById(params.id);
    return NextResponse.json({ success: true, data: plot });
  } catch (error) {
    if (error instanceof PlotNotFoundError) {
      return NextResponse.json(
        { success: false, error: { code: 'NOT_FOUND', message: 'Участок не найден' } },
        { status: 404 }
      );
    }
    return NextResponse.json(
      { success: false, error: { code: 'INTERNAL_ERROR', message: 'Внутренняя ошибка сервера' } },
      { status: 500 }
    );
  }
}
```

### Service

**`src/domains/plot/plot.service.ts` (добавление метода):**
```typescript
/**
 * Найти участок по ID
 * @param id - ID участка
 * @throws {PlotNotFoundError}
 */
async findById(id: string): Promise<Plot | null> {
  const plot = await this.plotRepository.findById(id);
  if (!plot) {
    throw new PlotNotFoundError(`Участок с ID ${id} не найден`);
  }
  return plot;
}
```
