# US-19-3: Просмотр связей пользователя с участками

## Формулировка

**Как** Член СНТ (Member) или Администратор,  
**я хочу** просматривать все участки, к которым я привязан,  
**чтобы** видеть свои права, роли и срок действия связей на каждом участке.

---

## Контекст

### Проблема
Пользователь не может увидеть полную картину своих связей с участками. Нет единого списка всех участков, где пользователь имеет какие-либо права (владелец, житель, представитель).

### Решение
Создать интерфейс просмотра всех связей пользователя с участками, включая информацию о ролях, статусе и сроке действия.

### Границы
- **Входит:** Просмотр всех связей текущего авторизованного пользователя
- **Входит:** Отображение ролей и статусов для каждого участка
- **Входит:** Фильтрация по роли, статусу и участку
- **Входит:** Поиск по номеру участка или адресу
- **НЕ входит:** Просмотр связей по участку (US-19-2)
- **НЕ входит:** Редактирование связей из этого интерфейса (US-19-4)
- **НЕ входит:** Просмотр истории изменений (US-19-6)

### Точки входа в интерфейс

| Номер | Точка входа | Маршрут | Описание |
|-------|-------------|---------|----------|
| TV-1 | Профиль пользователя | `/dashboard/profile` | Вкладка "Мои участки" |
| TV-2 | Дашборд | `/dashboard` | Блок "Мои участки" на главной |
| TV-3 | Навигация | `/dashboard/my-connections` | Отдельная страница "Мои связи" |
| TV-4 | Карточка пользователя | `/dashboard/users/[id]` | Секция "Связи с участками" |
| TV-5 | Блок навигации | Top navbar | Ссылка "Мои участки" |

## Функциональные требования

### FR-1: Отображение списка связей пользователя

Система отображает список всех связей текущего пользователя.

#### AC-1.1: Открытие списка
- **Дано:** Пользователь авторизован и находится на странице профиля `/dashboard/profile` или `/dashboard/my-connections`
- **Когда:** Пользователь открывает секцию "Мои связи"
- **Тогда:** Загружается и отображается таблица со всеми связями для этого пользователя
- **Иначе:** Секция отображается сразу после загрузки страницы

#### AC-1.2: Столбцы таблицы
- **Дано:** Таблица загружена
- **Когда:** Пользователь видит таблицу
- **Тогда:** Отображаются колонки:

| Колонка | Содержание |
|---------|------------|
| Участок | Номер и адрес участка |
| Кадастр | Кадастровый номер (если есть) |
| Роль | Текст: "Владелец", "Проживает", "Представитель" |
| Статус | Бейдж с цветом: активен (зелёный), ожидание (жёлтый), истёк (серый) |
| Срок действия | "Бессрочно" или дата в формате DD.MM.YYYY |
| Комментарий | Текст комментария (третирование при > 50 символов) |
| Назначен | Дата создания связи DD.MM.YYYY |
| Детали | Кнопка "Подробнее" |

#### AC-1.3: Сортировка по умолчанию
- **Дано:** Таблица загружена
- **Когда:** Пользователь видит список
- **Тогда:** Связи отсортированы:
  1. Сначала активные (status='active')
  2. Затем ожидания (status='pending')
  3. Затем истёкшие (status='expired')
- **Иначе:** Внутри групп сортировка по assigned_at (новые сверху)

---

### FR-2: Отображение информации об участке

Система показывает детализированную информацию об участке.

#### AC-2.1: Отображение номера участка
- **Дано:** В таблице есть связь
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "Уч. [plot_number]"
- **Иначе:** Ссылка на страницу `/dashboard/plots/[id]`

#### AC-2.2: Отображение адреса
- **Дано:** plot.address не null
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "Уч. [plot_number] — [address]"
- **Иначе:** Отображается только номер

#### AC-2.3: Отображение кадастрового номера
- **Дано:** plot.cadastral_number не null
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "Кадастр: [cadastral_number]"
- **Иначе:** Кадастровый номер не отображается

#### AC-2.4: Кнопка "Подробнее"
- **Дано:** В таблице есть связь
- **Когда:** Пользователь нажимает "Подробнее"
- **Тогда:** Открывается модальное окно с полной информацией об участке
- **Иначе:** Переход на страницу `/dashboard/plots/[id]`

### FR-3: Фильтрация по роли

Система позволяет фильтровать список по типу роли.

#### AC-3.1: Фильтр "Все роли"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Все роли" из фильтра
- **Тогда:** Отображаются все связи (owner, resident, representative)
- **Иначе:** Фильтр по умолчанию — "Все роли"

#### AC-3.2: Фильтр "Только владельцы"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Только владельцы" из фильтра
- **Тогда:** Отображаются только связи с role=1
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.3: Фильтр "Только проживающие"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Только проживающие" из фильтра
- **Тогда:** Отображаются только связи с role=2
- **Иначе:** Количество отображаемых строк уменьшается

#### AC-3.4: Фильтр "Только представители"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Только представители" из фильтра
- **Тогда:** Отображаются только связи с role=3
- **Иначе:** Количество отображаемых строк уменьшается

---

### FR-4: Фильтрация по статусу

Система позволяет фильтровать список по статусу связи.

#### AC-4.1: Фильтр "Все статусы"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Все статусы" из фильтра
- **Тогда:** Отображаются все связи (active, pending, expired)
- **Иначе:** Фильтр по умолчанию — "Все статусы"

#### AC-4.2: Фильтр "Активные"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Активные" из фильтра
- **Тогда:** Отображаются только связи с status='active'
- **Иначе:** Бейджи статусов окрашиваются в зелёный

#### AC-4.3: Фильтр "Ожидание"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Ожидание" из фильтра
- **Тогда:** Отображаются только связи с status='pending'
- **Иначе:** Бейджи статусов окрашиваются в жёлтый

#### AC-4.4: Фильтр "Истёкшие"
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь выбрал "Истёкшие" из фильтра
- **Тогда:** Отображаются только связи с status='expired'
- **Иначе:** Бейджи статусов окрашиваются в серый

---

### FR-5: Фильтрация по участку

Система позволяет фильтровать список по номеру участка или адресу.

#### AC-5.1: Поле поиска
- **Дано:** Пользователь открыл список связей
- **Когда:** Пользователь видит поле "Поиск по номеру участка или адресу"
- **Тогда:** Поле отображается справа от фильтров
- **Иначе:** Поле пустое по умолчанию

#### AC-5.2: Поиск по номеру
- **Дано:** Пользователь вводит "42" в поле поиска
- **Когда:** Пользователь вводит текст
- **Тогда:** Фильтруются строки где plot_number содержит "42"
- **Иначе:** Результат отображается моментально (< 200 мс)

#### AC-5.3: Поиск по адресу
- **Дано:** Пользователь вводит "Березки" в поле поиска
- **Когда:** Пользователь вводит текст
- **Тогда:** Фильтруются строки где plot.address содержит "Березки"
- **Иначе:** Результат отображается моментально

#### AC-5.4: Подсветка совпадений
- **Дано:** Пользователь ввёл текст поиска
- **Когда:** Результат отфильтрован
- **Тогда:** Найденные части номера/адреса выделяются жирным шрифтом
- **Иначе:** Подсветка исчезает при очистке поля

---

### FR-6: Отображение пустого состояния

Система корректно обрабатывает случаи отсутствия связей.

#### AC-6.1: Нет ни одной связи
- **Дано:** У пользователя нет ни одной связи (plot_users пусто для user_id)
- **Когда:** Пользователь открывает страницу профиля
- **Тогда:** Отображается EmptyState: "Вы пока не привязаны ни к одному участку"
- **Иначе:** Показывается ссылка "Найти участок для привязки"

#### AC-6.2: Фильтр не находит совпадений
- **Дано:** У пользователя есть связи
- **Когда:** Пользователь применил фильтр, который ничего не находит
- **Тогда:** Отображается EmptyState: "По вашему запросу ничего не найдено"
- **Иначе:** Кнопка "Сбросить фильтры"

---

### FR-7: Отображение срока действия

Система показывает срок действия связи в понятном формате.

#### AC-7.1: Бессрочная связь
- **Дано:** expires_at = null
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "Бессрочно"
- **Иначе:** Серый текст (muted)

#### AC-7.2: Срочная связь
- **Дано:** expires_at = "2025-12-31"
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается: "31.12.2025"
- **Иначе:** Формат DD.MM.YYYY

#### AC-7.3: Истёкшая связь
- **Дано:** expires_at < today
- **Когда:** Пользователь видит строку
- **Тогда:** Отображается дата в формате DD.MM.YYYY
- **Иначе:** Дополнительно — серая строка (strikethrough)

---

### FR-8: Просмотр истории изменений связи

Система позволяет просмотреть историю изменений для каждой связи.

#### AC-8.1: Кнопка "История"
- **Дано:** В таблице есть связь
- **Когда:** Пользователь нажимает "История" в строке
- **Тогда:** Открывается модальное окно с полной историей изменений
- **Иначе:** Ссылка на US-19-6 (появится позже)

## Бизнес-правила и валидация

| ID | Правило | Описание | Источник |
|----|---------|----------|----------|
| BR-1 | Отображение только активного | По умолчанию показываются только активные связи | UI фильтр по умолчанию |
| BR-2 | Порядок сортировки | Активные → Ожидание → Истёкшие | Сервисная логика сортировки |
| BR-3 | Маска номера участка | Уч. [plot_number] | Форматирование в UI |
| BR-4 | Отображение бессрочности | expires_at=null → "Бессрочно" | UI condition |
| BR-5 | Поиск по номеру и адресу | plot_number, plot.address | Поиск в UI |
| BR-6 | Права доступа | Только текущий пользователь (или ADMIN) | Проверка user_id в API |

## Граничные случаи (Edge Cases)

| # | Ситуация | Ожидаемое поведение |
|---|----------|---------------------|
| 1 | Участок удалён из системы | plot.id не найдётся — отображается "[удалён]" вместо номера |
| 2 | Пользователь не авторизован | 401 Unauthorized — редирект на login |
| 3 | Более 100 связей | Пагинация: 25 элементов на страницу |
| 4 | Участок с пустыми данными | Отображается "Уч. [id]" без номера и адреса |
| 5 | Параллельное изменение данных | Оптимистичное обновление UI, refetch через 5 сек |
| 6 | Медленное соединение (> 5 сек) | Показывается индикатор загрузки skeleton |
| 7 | Неправильный format expires_at | ISO 8601 формат гарантируется сервером |
| 8 | Кнопка "Подробнее" не работает | Ссылка на страницу `/dashboard/plots/[id]` |

### API

**`src/app/api/v1/plot-users/route.ts`:**

```typescript
/**
 * @route GET /api/v1/plot-users
 * @auth required
 * @description Возвращает список всех связей текущего пользователя
 *
 * @query status=active|pending|expired&role=1|2|3&search=query
 * @response 200 { success: true, data: PlotUserRole[] }
 * @response 401 { success: false, error: { code: string, message: string } }
 */
export async function GET(request: NextRequest) {
  const { user } = await auth(); // get current user from session
  const service = createPlotUserRoleService();
  try {
    const { searchParams } = new URL(request.url);
    const filter = {
      status: searchParams.get('status') as any,
      role: searchParams.get('role') ? parseInt(searchParams.get('role')!) : undefined,
      search: searchParams.get('search'),
    };
    const connections = await service.findByUser(user.id, filter);
    return NextResponse.json({ success: true, data: connections });
  } catch (error) {
    // Error handling
  }
}
```

/**

    // Error handling
  }
}

## Интеграционные моменты

### Точки входа в интерфейс (детально)

#### TV-1: Профиль пользователя — вкладка "Мои участки"
- **Расположение:** Страница `/dashboard/profile`
- **Компонент:** `<Tabs>` с вкладками "Информация", "Безопасность", "Мои участки"
- **Поведение:** Показывает UserConnectionsList на соответствующей вкладке
- **Автоматическая подгрузка:** user_id берётся из session

#### TV-2: Дашборд — блок "Мои участки"
- **Расположение:** Страница `/dashboard`
- **Компонент:** `<Section title="Мои участки">UserConnectionsList limited</Section>`
- **Поведение:** Показывает до 5 последних активных связей
- **Дополнительно:** Кнопка "Показать все" — ссылка на `/dashboard/my-connections`

#### TV-3: Отдельная страница "Мои связи"
- **Маршрут:** `/dashboard/my-connections`
- **Компонент:** `<UserConnectionsList userId={user.id} />`
- **Поведение:** Полная таблица со всеми связями
- **Дополнительно:** Навигация из DashboardLayout

#### TV-4: Карточка пользователя
- **Маршрут:** `/dashboard/users/[id]` (только ADMIN)
- **Компонент:** `<Section title="Связи с участками">UserConnectionsList userId={params.id} />`
- **Поведение:** ADMIN может видеть связи любого пользователя

#### TV-5: Навигация — Top navbar
- **Расположение:** Верхняя панель навигации
- **Компонент:** `<NavLink href="/dashboard/my-connections">Мои участки</NavLink>`
- **Поведение:** Быстрый переход к списку связей
- **Дополнительно:** Счётчик активных связей

## Примечания для реализации

1. **Использование Suspense:** UserConnectionsList должен быть обернут в Suspense для плавной загрузки
2. **Оптимистичное обновление:** После успешной операции US-19-1/US-19-4/US-19-5 нужно сразу обновлять UI
3. **Рефреш данных:** При создании новой связи через US-19-1 нужно автоматически обновлять список
4. **Адаптивность:** Таблица должна корректно отображаться на мобильных устройствах
5. **Доступность:** Все интерактивные элементы должны быть доступны с клавиатуры
6. **Авторизация:** Для TV-1, TV-2, TV-3, TV-5 — только текущий user; для TV-4 — ADMIN
7. **Пагинация:** Реализовать через UI компонент с 25 элементами на страницу
