# US-17: Поиск по участкам

## Формулировка

**As a** член СНТ (Member) или Администратор,  
**I want to** искать земельные участки по номеру, кадастровому номеру и описанию, —  
**So that** я мог быстро найти нужный участок в списке.

## Контекст

### Проблема
При большом количестве участков (> 50) пользователю сложно найти нужный участок в длинном списке.

### Решение
Добавить строку поиска с тремя фильтрами: по номеру участка, кадастровому номеру и текстовому поиску по примечанию.

### Границы
- Поиск работает на странице `/dashboard/plots` (US-13)
- Поиск выполняется на стороне сервера (API query params)
- Результат поиска заменяет основной список в таблице

## Модель данных

### API-запрос поиска

| Параметр | Тип | Обязательное | Описание |
|----------|-----|-------------|----------|
| `number` | String | Нет | Поиск по номеру участка (partial match) |
| `cadstral` | String | Нет | Поиск по кадастровому номеру (partial match) |
| `note` | String | Нет | Текстовый поиск по примечанию |
| `limit` | Number | Нет | Лимит результатов (по умолчанию 100) |

### API-ответ

```json
{
  "success": true,
  "data": [
    {
      "id": "clxxx123",
      "plot_number": "42",
      "cadstral_number": "50:00:0000001:42",
      "area": 12.5,
      "address": "д. Березки, уч. 42",
      "note": "Земельный участок"
    }
  ],
  "total": 1
}
```

## Функциональные требования

### FR-1: Компонент поиска

Пользователь видит строку поиска над таблицей.

#### AC-1.1: Поля поиска
- **Дано:** Пользователь на странице `/dashboard/plots`
- **Когда:** Страница загружена
- **Тогда:** Отображается компонент `PlotSearch` с тремя полями:
  | Поле | Тип | Placeholder | Иконка |
  |------|-----|-------------|--------|
  | № участка | text | "Поиск по номеру..." | 🔍 |
  | Кадастровый номер | text | "Поиск по кадастру..." | 📋 |
  | Описание | text | "Поиск по описанию..." | 📝 |
- **Иначе:** Поля расположены горизонтально, кнопка «Очистить» справа

#### AC-1.2: Сброс поиска
- **Дано:** Пользователь ввёл значения в поля поиска
- **Когда:** Пользователь нажимает «Очистить»
- **Тогда:**
  - Все поля поиска очищаются
  - Загружается полный список участков (без фильтров)
- **Иначе:** (альтернатива) Поля очищаются по крестику в каждом поле

### FR-2: Поиск по номеру участка

Пользователь может найти участок по частичному совпадению номера.

#### AC-2.1: Поиск при вводе
- **Дано:** Пользователь вводит значение в поле «№ участка»
- **Когда:** Пользователь ввёл ≥ 2 символа или нажал Enter
- **Тогда:** Выполняется `GET /api/v1/plots/search?number=42`
- **Иначе:** Если введено 0-1 символов — поиск не выполняется

#### AC-2.2: Частичное совпадение
- **Дано:** Поиск по номеру `42`
- **Когда:** В БД есть участки №42, №421, №142
- **Тогда:**
  - Участок №42 — первое совпадение
  - Участок №421 — второе (начинается с 42)
  - Участок №142 — третье (содержит 42)
- **Иначе:** Поиск case-insensitive (регистронезависимый)

#### AC-2.3: Отсутствие результатов
- **Дано:** По номеру ничего не найдено
- **Когда:** API возвращает `{ success: true, data: [] }`
- **Тогда:** Таблица показывает «Ничего не найдено»
- **Иначе:** Кнопка «Очистить» активна

### FR-3: Поиск по кадастровому номеру

Пользователь может найти участок по кадастровому номеру.

#### AC-3.1: Поиск при вводе
- **Дано:** Пользователь вводит значение в поле «Кадастровый номер»
- **Когда:** Пользователь ввёл ≥ 3 символа или нажал Enter
- **Тогда:** Выполняется `GET /api/v1/plots/search?cadstral=50:00`
- **Иначе:** Если введено < 3 символов — поиск не выполняется

#### AC-3.2: Частичное совпадение
- **Дано:** Поиск по кадастру `50:00`
- **Когда:** В БД есть участки с кадастрами `50:00:0000001:42`, `50:01:0000002:43`
- **Тогда:**
  - `50:00:0000001:42` — найдено (содержит `50:00`)
  - `50:01:0000002:43` — не найдено (не содержит `50:00`)
- **Иначе:** Поиск case-insensitive

### FR-4: Текстовый поиск по описанию

Пользователь может найти участок по тексту в примечании.

#### AC-4.1: Поиск при вводе
- **Дано:** Пользователь вводит значение в поле «Описание»
- **Когда:** Пользователь ввёл ≥ 2 символа или нажал Enter
- **Тогда:** Выполняется `GET /api/v1/plots/search?note=земель`
- **Иначе:** Если введено 0-1 символов — поиск не выполняется

#### AC-4.2: Частичное совпадение
- **Дано:** Поиск по описанию «земель»
- **Когда:** В БД есть участок с note «Земельный участок для огорода»
- **Тогда:**
  - «Земельный участок» — найдено (содержит «земель»)
  - Поиск case-insensitive
- **Иначе:** Поиск по `ILIKE '%запрос%'` в SQL

### FR-5: Комбинированный поиск

Пользователь может искать по нескольким полям одновременно.

#### AC-5.1: Фильтрация по всем полям
- **Дано:** Пользователь ввёл значения во все три поля
- **Когда:** Значения введены в ≥ 2 полях
- **Тогда:**
  - Запрос: `GET /api/v1/plots/search?number=42&cadstral=50:00&note=земель`
  - Результаты должны соответствовать ВСЕМ непустым фильтрам (AND-логика)
- **Иначе:** Каждый непустой фильтр добавляется в запрос

#### AC-5.2: Debounce поиска
- **Дано:** Пользователь активно вводит текст
- **Когда:** Ввод продолжается
- **Тогда:**
  - Запрос отправляется с задержкой 300мс после прекращения ввода (debounce)
  - Предыдущие незавершённые запросы отменяются (AbortController)
- **Иначе:** Пользователь не видит мерцания результатов при быстром вводе

## Бизнес-правила и валидация

| ID | Правило | Описание |
|----|---------|----------|
| BR-1 | Минимальная длина | Номер: ≥ 2 символа, Кадастр: ≥ 3 символа, Описание: ≥ 2 символа |
| BR-2 | AND-логика | Несколько фильтров объединяются через AND |
| BR-3 | Debounce | Задержка поиска 300мс для избежания лишних запросов |
| BR-4 | Отмена предыдущих запросов | Новые запросы отменяют предыдущие (AbortController) |

## Граничные случаи (Edge Cases)

| Сценарий | Ожидаемое поведение |
|----------|-------------------|
| Специальные символы в поиске (%, _) | Экранируются в SQL-запросе |
| Очень длинный поисковый запрос (> 100 символов) | Обрезается до 100 символов |
| Поиск во время загрузки списка | Поиск завершает загрузку, затем выполняется |
| Быстрая смена поисковых запросов | AbortController отменяет предыдущие запросы |

## Обработка ошибок

| Код | Ситуация | Сообщение | Действие |
|-----|----------|-----------|----------|
| 400 | Неверный формат запроса | «Ошибка поиска» | Показать alert |
| 500 | Внутренняя ошибка сервера | «Ошибка поиска. Попробуйте позже.» | Показать alert |

```typescript
/**
 * Поиск участков по фильтрам
 * @param filters - Объект с фильтрами поиска
 */
async search(filters: PlotSearchFilters): Promise<Plot[]> {
  const { number, cadstral, note } = filters;
  const hasFilters = number || cadstral || note;
  
  if (!hasFilters) {
    return this.findAll();
  }
  
  return this.plotRepository.search({ number, cadstral, note });
}
```

### API

**`src/app/api/v1/plots/search/route.ts` (новый файл):**
```typescript
/**
 * @route GET /api/v1/plots/search
 * @auth required
 * @description Ищет участки по фильтрам
 *
 * @query number - Поиск по номеру участка (optional)
 * @query cadstral - Поиск по кадастровому номеру (optional)
 * @query note - Текстовый поиск по описанию (optional)
 *
 * @response 200 { success: true, data: Plot[], total: number }
 */
export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url);
  const number = searchParams.get('number');
  const cadstral = searchParams.get('cadstral');
  const note = searchParams.get('note');
  
  const service = createPlotService();
  const plots = await service.search({ number: number || undefined, cadstral: cadstral || undefined, note: note || undefined });
  return NextResponse.json({ success: true, data: plots, total: plots.length });
}
```
