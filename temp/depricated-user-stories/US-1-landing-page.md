# US-1: Стартовая страница неавторизованной зоны

---

## Формулировка

**Как** неавторизованный посетитель,
**я хочу** увидеть стартовую страницу с описанием приложения СНТ Берёзки-НТ,
**чтобы** понять назначение системы и перейти к авторизации.

---

## Контекст

**Проблема**: При открытии приложения пользователь попадает напрямую на дашборд, который требует авторизации. Отсутствует публичная стартовая страница, которая знакомит с приложением и направляет к входу.

**Решение**: Создать landing page на маршруте `/` — точку входа в приложение для неавторизованных пользователей. Страница содержит название, описание и кнопку перехода к авторизации. Авторизованные пользователи автоматически перенаправляются на `/dashboard`.

**Границы**:
- Входит: landing page, layout публичной зоны, middleware для редиректов, реструктуризация маршрутов дашборда
- НЕ входит: дизайн login-страницы, регистрация, восстановление пароля, контент-менеджмент landing-страницы

---

## Функциональные требования

### FR-1: Отображение стартовой страницы на маршруте `/`
При переходе на корневой маршрут `/` неавторизованный пользователь видит стартовую страницу. Страница является Server Component и не требует авторизации.

### FR-2: Содержимое стартовой страницы
Страница отображает:
- Название приложения: «СНТ Берёзки-НТ»
- Краткое описание: назначение системы управления садоводческим товариществом
- Кнопка «Войти» — ведёт на маршрут `/login`

### FR-3: Layout публичной зоны
Страница использует отдельный layout с шапкой и подвалом, отличный от авторизованной зоны. Шапка содержит название приложения. Подвал содержит базовую информацию.

### FR-4: Редирект авторизованного пользователя
Если пользователь авторизован и переходит на `/`, он автоматически перенаправляется на `/dashboard`. Редирект выполняется на уровне middleware.

### FR-5: Реструктуризация маршрутов дашборда
Текущий маршрут `/` для дашборда перемещается на `/dashboard`. Все защищённые маршруты находятся под префиксом `/dashboard/`:
- `/dashboard` — главная страница дашборда
- `/dashboard/members` — члены СНТ
- `/dashboard/plots` — участки
- и т.д.

### FR-6: Middleware авторизации
Создаётся `middleware.ts`, реализующий логику доступа:
- `/` и `/login` — доступны всем; авторизованные пользователи перенаправляются с `/` на `/dashboard`
- `/dashboard/*` — требуют авторизации; неавторизованные пользователи перенаправляются на `/login`

## Критерии приёмки

### AC-1: Неавторизованный пользователь видит landing
- **Given** пользователь не авторизован
- **When** открывает `/`
- **Then** отображается стартовая страница с названием, описанием и кнопкой «Войти»

### AC-2: Переход к авторизации
- **Given** пользователь на стартовой странице
- **When** нажимает кнопку «Войти»
- **Then** происходит переход на `/login`

### AC-3: Авторизованный пользователь перенаправляется
- **Given** пользователь авторизован
- **When** открывает `/`
- **Then** происходит редирект на `/dashboard`

### AC-4: Дашборд доступен по новому маршруту
- **Given** пользователь авторизован
- **When** открывает `/dashboard`
- **Then** отображается дашборд с навигацией

### AC-5: Неавторизованный доступ к дашборду
- **Given** пользователь не авторизован
- **When** открывает `/dashboard` или любой вложенный маршрут
- **Then** происходит редирект на `/login`

### AC-6: Layout публичной зоны
- **Given** пользователь на стартовой странице или странице логина
- **When** страница загружена
- **Then** отображается layout с шапкой сверху и подвалом снизу

## Бизнес-правила и валидация

| ID   | Правило                                                    | Валидация                     |
|------|------------------------------------------------------------|-------------------------------|
| BR-1 | Стартовая страница доступна без авторизации                | Middleware — пропуск без проверки |
| BR-2 | Авторизованный пользователь не должен видеть landing      | Middleware — редирект на `/dashboard` |
| BR-3 | Все маршруты `/dashboard/*` требуют авторизации           | Middleware — редирект на `/login` |
| BR-4 | Контент стартовой страницы — статический, не из БД        | Server Component без запросов к БД |

### Примеры валидаций
- **Авторизация**: проверяется через `auth()` в middleware — наличие сессии
- **Редирект**: HTTP 307 Temporary Redirect через `Response.redirect()`
- **Обязательные элементы страницы**: название, описание, кнопка «Войти» — отсутствие любого = ошибка рендера

## Граничные случаи (Edge Cases)

| #  | Ситуация                                    | Ожидаемое поведение                              |
|----|---------------------------------------------|--------------------------------------------------|
| 1  | Сессия истекла пока пользователь на landing | При нажатии «Войти» попадёт на `/login` — корректное поведение |
| 2  | Прямой доступ к `/dashboard/members` без авторизации | Редирект на `/login` через middleware |
| 3  | Авторизованный пользователь вручную вводит `/` | Редирект на `/dashboard` |
| 4  | Устаревшие ссылки вида `/members` | Приводят к 404 — не редиректятся автоматически |
| 5  | Middleware недоступен — ошибка загрузки      | Next.js fallback — отображается страница как есть без редиректа |

## Обработка ошибок

| Ситуация                          | Код HTTP | Доменная ошибка         | Сообщение пользователю    |
|-----------------------------------|----------|-------------------------|---------------------------|
| Неавторизован на `/dashboard/*`  | 307      | —                       | Редирект на `/login`      |
| Авторизован на `/`                | 307      | —                       | Редирект на `/dashboard`  |
| Устаревший маршрут `/members`     | 404      | —                       | Страница не найдена       |

> Примечание: данная US не содержит доменных ошибок — редиректы обрабатываются на уровне middleware, 404 — стандартная страница Next.js.

## Нефункциональные требования

- **Производительность**: Landing page — Server Component без запросов к БД. Должен рендериться статически. LCP < 1.5с.
- **Безопасность**: Middleware обеспечивает защиту `/dashboard/*` от неавторизованного доступа. Публичные маршруты не требуют авторизации.
- **UX**: Кнопка «Войти» визуально выделена как primary action. Переход к авторизации — в один клик. Адаптивная верстка — мобильные и десктоп.
- **SEO**: Корневая страница индексируется. Установлены title и description через metadata.
