## Рекомендация

### Если VPS 1 GB RAM → Вариант A

**TypeScript + Fastify + PostgreSQL + Prisma**

Причины:
- Оптимальный баланс скорости разработки и функциональности
- PostgreSQL — полнотекстовый поиск, jsonb, опыт команды
- Один язык — TypeScript везде
- 210-330 MB RAM — оставляет запас для ОС и кэша

### Если VPS 512 MB RAM → Вариант B

**TypeScript + Fastify + SQLite + Prisma**

Причины:
- Минимальные требования к ресурсам — 60-80 MB RAM
- Возможность миграции на PostgreSQL через Prisma при апгрейде VPS
- Простой бэкап — копирование файла

### Вариант C не рекомендуется

Несмотря на минимальное потребление памяти и опыт команды в C++, скорость разработки в 3-5 раз ниже. Для СНТ-приложения скорость доставки важнее пиковой производительности.

### Вариант D не рекомендуется для старта

Overengineering. Если появятся узкие места — C++ модуль через N-API можно добавить точечно позже.

## Стратегия миграции SQLite → PostgreSQL

Если начать с Варианта B и потом мигрировать на A:

1. Использовать Prisma с provider = sqlite
2. Все запросы через Prisma Client — нет сырого SQL
3. При миграции: изменить provider на postgresql в schema.prisma
4. Пересоздать миграции: npx prisma migrate dev
5. Перенести данные: скрипт экспорта/импорта через Prisma
6. Добавить PostgreSQL на VPS, настроить pg_dump

Это один из ключевых преимуществ Prisma — смена БД требует минимальных изменений в коде.
