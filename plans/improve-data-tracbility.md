# Улучшение наблюдаемости качества данных

## Роль
Ты опытный архитектор

## Контекст

Staging-service - ETL сервис выгрузки архитектукрных данных.

Одна из задач сервиса это наблюдаемость происхождения данных.

**Типовые запросы к происхождению данных**
1. Я обновил данные в источники, а в результате их нет
2. Данные были, но пропали
3. Откуда возникли те или иные значения

**Проблема**
1. Нет руководства, как искать причину отсутсвия данных
2. Пользователь staging-service не знает структуру хранения, но знает часть имени сущности, которая должна была попасть в результат работы staging-service
3. Аннотации (notice) могут быть не читаемыми. То есть не понятно, что они означают
4. Аннотации могут отсутствовать, если разработчик забыл их добавить
5. Не понятно, как использовать аннотации

## Задача

1. Разработать набор предложений к реализации для повышения наблюдаеомсти происхождения или исчезновения данных
2. Сфомировать план улучшения качества данных

## Порядок выполнения

1. Изучи архитектуру staging-service
2. Задай 2-7 уточняющих вопроса, если они есть
3. Сформируй гипотезы и предложения, которые позволят быстро неаходит причины расхождений в данных
4. Обсуди гипотезы и предложения
5. Сформируй план
   
## Ожидаемый результат
1. Есть набор гипотез и предложений
2. Каждая гипотеза или предложение имеет обоснование и набор примеров, когда она сработает
3. Есть план по проверки и внедрению гипотезы/предложения
