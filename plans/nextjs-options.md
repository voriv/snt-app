# Варианты использования Next.js

## Вариант 1: Static Export — чистый SPA

Фронтенд собирается в статические файлы, отдаётся nginx. Все данные через API.

### Плюсы
- 0 MB RAM на сервере для фронтенда
- CDN-ready, максимальная скорость отдачи
- Простота деплоя — замена файлов

### Минусы
- Нет SSR — слабый SEO для публичных страниц
- Первый экран — loading пока JS загрузится
- Нет Server Actions, ISR

### RAM итого: ~210 MB (Fastify 60-80 + PG 150-250)

---

## Вариант 2: Standalone SSR + отдельный Fastify API

Next.js сервер с SSR + отдельный Fastify для API. WebSocket отдельным процессом.

### Плюсы
- SSR — отличный SEO, быстрый первый экран
- Server Components — меньше JS в браузере
- ISR для полустатичных страниц
- Разделение фронт/бэк — независимое масштабирование

### Минусы
- Next.js сервер 80-150 MB RAM
- SSR нагружает CPU
- Два процесса — сложнее деплой

### RAM итого: ~340-480 MB (Next 80-150 + Fastify 60-80 + PG 150-250)

---

## Вариант 3: Next.js API Routes — без Fastify

Next.js standalone сервер. API Routes вместо Fastify. WebSocket отдельным процессом.

### Плюсы
- Один процесс вместо двух — проще деплой
- Server Actions — мутации без REST
- Меньше кода — нет дублирования типов

### Минусы
- API Routes медленнее Fastify — overhead Next.js
- Нет middleware как в Fastify
- WebSocket всё равно нужен отдельный процесс
- Monolith — сложнее масштабировать

### RAM итого: ~260-450 MB (Next 80-150 + WS 30-50 + PG 150-250)

---

## Сравнение

| Критерий | 1: Static | 2: SSR+Fastify | 3: API Routes |
|----------|:---------:|:--------------:|:-------------:|
| RAM итого | ~210 MB | ~340-480 MB | ~260-450 MB |
| SEO | слабый | отличный | отличный |
| Первый экран | loading | сразу | сразу |
| CPU нагрузка | мин | высокая | средняя |
| Скорость dev | высокая | высокая | максимальная |
| Деплой | прост | средний | простой |
| В 1GB RAM | комфорт | впритык | возможно |

---

## Рекомендация

**Вариант 2 (SSR + Fastify)** — если SEO критично для публичных страниц СНТ: документы, объявления, результаты голосований должны индексироваться.

**Вариант 1 (Static Export)** — если SEO не важен, приложение закрытое для членов СНТ, приоритет — минимальные ресурсы.

**Вариант 3 (API Routes)** — компромисс, но Fastify даёт больше контроля над API.

### Ключевой вопрос

Приложение СНТ имеет два типа страниц:
1. **Публичные** — объявления, документы, результаты голосований — нужен SEO
2. **Приватные** — личный кабинет, бухгалтерия, чаты — SEO не нужен

Если публичные страницы важны → Вариант 2 или 3.
Если приложение полностью закрытое → Вариант 1.
